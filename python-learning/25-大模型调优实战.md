# 第二十五章 大模型调优实战：SFT、LoRA/QLoRA 与对齐

> 本章目标：第 24 章训出的预训练模型只会"续写文本"，**不会听指令**。让它变有用的关键是**后训练（Post-training）**。本章走完整条调优链路：先判断"到底该不该调优"，再用可运行代码完成 **数据工程 → SFT 全量微调 → LoRA/QLoRA 参数高效微调 → 偏好对齐(DPO) → 训练诊断 → 评测回归 → 合并权重与部署**，最后用第 16 章的 Golden Set 做微调前后对比，防止"业务变好、通用能力崩了"。
>
> 前置知识：第 14 章（过拟合/验证集）、第 16 章（Golden Set / LLM-as-Judge）、第 19 章（LLM 基础）、第 23 章（本地部署与量化）、第 24 章（预训练与训练显存）。
>
> 环境准备：`pip install torch transformers datasets peft accelerate bitsandbytes trl evaluate`，Python 3.10+。示例默认用**小模型**（如 `Qwen/Qwen2.5-0.5B` 或 `HuggingFaceTB/SmolLM-135M`）以便单卡/CPU 验证；训练建议 8GB+ NVIDIA GPU，QLoRA 可把 7B 塞进 8~12GB。

## 25.1 先问：真的需要调优吗？

**调优是成本最高、反馈最慢的手段**。80% 的"模型不好用"其实靠 Prompt / RAG / 工具就能解决。

```text
模型回答不好
   │
   ├─ 缺知识 / 知识过时？ ────────────► RAG（第 11 章）✅ 首选
   ├─ 输出格式不对 / 语气不对？ ──────► Prompt + 结构化输出（第 19 章）✅ 首选
   ├─ 需要执行动作 / 查实时数据？ ────► Function Calling / MCP（第 10、13 章）✅
   ├─ 需要固定业务流程 / 多步决策？ ──► 编排（第 12、17、20 章）✅
   ├─ 需要外部系统写操作？ ──────────► 工具 + 权限（别交给模型）✅
   │
   ├─ 以上都做了，但模型仍：
   │    · 不懂领域术语/黑话
   │    · 稳定地犯同一类风格/格式错误
   │    · 需要压缩成本（用小模型替代大模型做专门任务）
   │    · 数据不能出内网，且要固定行为
   │        └──► 【微调】本章 ⭐
   │
   └─ 需要全新语言/全新基础能力？ ────► 继续预训练 / 从零训练（第 24 章）⚠️ 最贵
```

| 手段 | 改权重 | 成本 | 迭代速度 | 主要解决 |
| --- | --- | --- | --- | --- |
| Prompt 工程 | ❌ | 几乎零 | 分钟 | 格式、语气、约束 |
| Few-shot | ❌ | 低 | 分钟 | 模式模仿 |
| RAG | ❌ | 中 | 小时 | 知识、时效、可溯源 |
| **LoRA/QLoRA 微调** | ✅ 少量 | **中低** | 小时~天 | **风格、格式、领域行为** ⭐ |
| 全量 SFT | ✅ 全部 | 高 | 天 | 深度行为改造 |
| 继续预训练 | ✅ 全部 | 很高 | 周 | 新领域/新语言 |
| 从零预训练 | ✅ 全部 | 极高 | 月 | 新基础模型 |

> **调优不能教知识**：微调擅长让模型"用某种方式说话/按某种格式输出"，**不擅长**往模型里灌大量新事实。灌知识请用 RAG；把事实硬塞进权重，会造成幻觉和不可维护。这是最重要的判断原则。

## 25.2 调优方法全景

### 25.2.1 按训练阶段分

| 阶段 | 名称 | 数据 | 目标 |
| --- | --- | --- | --- |
| 领域自适应 | **继续预训练 (CPT)** | 纯文本语料 | 补领域语言/术语 |
| 指令微调 | **SFT** | `(instruction, input, output)` 三元组 | 学会听指令、按格式回答 |
| 偏好对齐 | **RLHF / DPO / GRPO** | `(prompt, chosen, rejected)` 偏好对 | 让回答更符合人类偏好（有用/无害/诚实） |
| 能力蒸馏 | **Distillation** | 教师模型输出 | 小模型学大模型 |
| 合并 | **Model Merge / MoE 化** | 多组权重 | 合并能力，不训练 |

### 25.2.2 按参数更新方式分（本章重点）

| 方式 | 更新参数占比 | 7B 训练显存（粗估） | 特点 |
| --- | --- | --- | --- |
| **全量微调 Full FT** | 100% | 100GB+（多卡） | 效果上限高，但贵、易灾难性遗忘 |
| **LoRA** | 0.1%~1% | ~16~24GB | ⭐ 冻结主干，只训低秩旁路矩阵 |
| **QLoRA** | 0.1%~1% | **~8~12GB** | ⭐⭐ LoRA + 4bit 量化主干，消费级卡可跑 7B |
| Adapter / Prefix / Prompt Tuning | <1% | 低 | 更早的 PEFT 方法，现多被 LoRA 取代 |

### 25.2.3 LoRA 原理（一张图 + 一个公式）

冻结预训练权重 \(W_0 \in \mathbb{R}^{d \times k}\)，在旁边加一条**低秩旁路**：

\[
W = W_0 + \underbrace{B A}_{\Delta W} \cdot \frac{\alpha}{r},
\qquad B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d,k)
\]

```text
        ┌──────────────────────────┐
   x ──►│  冻结的 W0（不更新）     │──┐
        └──────────────────────────┘  ├──► + ──► 输出
        ┌──────────────────────────┐  │
   x ──►│ A (r×k) → B (d×r) 可训练 │──┘
        └──────────────────────────┘
              r 常取 8/16/32/64
```

**为什么有效**：微调时权重的"变化量" \(\Delta W\) 往往是低秩的（内在维度低），用两个小矩阵相乘就能近似。以 7B 模型为例，\(r=16\) 时只训约几千万参数（<1%）。

| 参数 | 含义 | 常用值 |
| --- | --- | --- |
| `r` | 秩，越大表达力越强、参数越多 | 8 / 16 / 32 / 64 |
| `lora_alpha` | 缩放系数，与 r 一起决定 \(\alpha/r\) | 常设 `2r` 或 16/32 |
| `target_modules` | 对哪些层加旁路 | Attention 的 `q_proj,k_proj,v_proj,o_proj`；更强则加 MLP |
| `lora_dropout` | 防过拟合 | 0.05~0.1 |
| `bias` | 是否训 bias | `"none"` |

**QLoRA 额外三件套**（把 7B 塞进消费级卡的关键）：

1. **4-bit NF4 量化**主干权重（冻结，不更新）；
2. **双重量化**（量化常数量化常数）再省一点；
3. **Paged Optimizer**：显存峰值时把优化器状态分页到 CPU，防 OOM。

> ⚠️ **量化 ≠ 训练**：第 23 章的量化是为了**推理**省显存；QLoRA 是**在量化主干上训练旁路**。两者都叫"量化"，目的不同。

**LoRA 最大的工程优势**：产物只是一个几十 MB 的 **adapter**，可以为不同业务各训一个，运行时热插拔切换；主干权重永远只有一份。

## 25.3 数据工程：调优成败的 80%

> **本章最重要的一节**。工具调用十分钟能学会，数据准备要花掉整个项目 80% 的时间。

### 25.3.1 指令数据格式

**Alpaca 格式**（简单，适合单轮）：

```json
{"instruction": "把用户问题分类", "input": "我的订单什么时候发货", "output": "物流查询"}
```

**ShareGPT / ChatML 格式**（多轮，推荐，与现代 chat template 对齐）：

```json
{
  "messages": [
    {"role": "system", "content": "你是电商客服助手，回答不超过 50 字。"},
    {"role": "user", "content": "订单 OD123 什么时候发货？"},
    {"role": "assistant", "content": "订单 OD123 预计 24 小时内发货，可在「我的订单」查看物流。"}
  ]
}
```

**偏好数据（DPO）**：

```json
{
  "prompt": "用户说要退款，怎么回？",
  "chosen": "已为您提交退款申请，预计 1~3 个工作日原路退回。",
  "rejected": "不知道，自己去看帮助页面。"
}
```

### 25.3.2 数据质量六条铁律

| # | 铁律 | 违反后果 |
| --- | --- | --- |
| 1 | **质量 > 数量**：几百条高质量样本常胜过几万条噪声 | 模型学会噪声和坏格式 |
| 2 | **答案风格一致**：全部用同一套人称/格式/长度 | 输出摇摆不定 |
| 3 | **覆盖 正常/边界/拒答/异常** 四类 | 遇到没见过的输入就胡说 |
| 4 | **去污染**：评测集样本绝不能进训练集 | 分数虚高，上线翻车（呼应第 16 章） |
| 5 | **去重 + 同源不跨集**：同一来源的近似样本要么全在训练、要么全在验证 | 数据泄漏 |
| 6 | **许可与隐私**：确认语料可商用、清除 PII/密钥 | 法律风险 + 模型背出敏感信息 |

> 呼应第 19 章：**模型会忠实模仿数据里的坏习惯**。数据里全是"根据我的知识…"，微调后它就永远这么开头。

### 25.3.3 可运行的数据准备脚本

```python
# 1_build_dataset.py —— 构建并切分指令数据集
import json, hashlib, random
from pathlib import Path

random.seed(42)

def load_jsonl(path):
    return [json.loads(l) for l in Path(path).read_text(encoding="utf-8").splitlines() if l.strip()]

def norm(s: str) -> str:
    return " ".join(s.lower().split())

def dedup(rows, key="messages"):
    seen, out = set(), []
    for r in rows:
        h = hashlib.md5(norm(json.dumps(r[key], ensure_ascii=False)).encode()).hexdigest()
        if h not in seen:
            seen.add(h); out.append(r)
    return out

def validate(rows):
    """基本校验：角色交替、assistant 非空、长度合理"""
    ok = []
    for i, r in enumerate(rows):
        msgs = r.get("messages", [])
        if not msgs or msgs[-1]["role"] != "assistant":
            print(f"跳过 #{i}: 末条不是 assistant"); continue
        if not msgs[-1]["content"].strip():
            print(f"跳过 #{i}: 答案为空"); continue
        if any(len(m["content"]) > 4000 for m in msgs):
            print(f"跳过 #{i}: 超长"); continue
        ok.append(r)
    return ok

raw = load_jsonl("data/raw_instructions.jsonl")
rows = validate(dedup(raw))
random.shuffle(rows)

# 先切分再去重也行，但务必「同源样本不跨集」；这里按样本随机切足够教学用
n_train = int(len(rows) * 0.9)
train, val = rows[:n_train], rows[n_train:]

for name, part in [("train", train), ("val", val)]:
    with open(f"data/{name}.jsonl", "w", encoding="utf-8") as f:
        for r in part:
            f.write(json.dumps(r, ensure_ascii=False) + "\n")
print(f"train={len(train)} val={len(val)}  (原始 {len(raw)} → 去重校验后 {len(rows)})")
```

> **规模参考**：格式/风格类任务 200~1000 条就能见效；领域行为 1000~10000 条；**别一上来就造十万条低质数据**。先用 100 条跑通全流程，确认有效再扩。

## 25.4 环境与显存：先算能不能跑

### 25.4.1 训练显存粗估（呼应第 24 章 24.6.1）

| 方式 | 权重 | 梯度 | 优化器状态 | 激活 | 7B 粗估 |
| --- | --- | --- | --- | --- | --- |
| 全量 BF16 | 14GB | 14GB | 28GB | 数 GB+ | **60GB+** |
| LoRA BF16 | 14GB | ~0.1GB | ~0.2GB | 数 GB | ~18~24GB |
| **QLoRA 4bit** | **~4GB** | ~0.1GB | ~0.2GB | 数 GB | **~8~12GB** ⭐ |

```python
# 2_vram_estimate.py
def estimate(params_b, mode="qlora", seq_len=1024, batch=1):
    if mode == "full":
        w, g, opt = params_b * 2, params_b * 2, params_b * 4
    elif mode == "lora":
        w, g, opt = params_b * 2, params_b * 0.02, params_b * 0.04
    else:  # qlora
        w, g, opt = params_b * 0.5, params_b * 0.02, params_b * 0.04
    act = 1.5 + seq_len / 1024 * batch * 1.0
    return round(w + g + opt + act + 1.5, 1)

for p in [0.5, 1.5, 7, 14]:
    print(f"{p}B: full={estimate(p,'full')}GB  lora={estimate(p,'lora')}GB  qlora={estimate(p)}GB")
```

> 数据是粗量级估算，实际受序列长、batch、梯度检查点、框架实现影响。**先用小模型跑通，再放大规模**。

### 25.4.2 硬件决策

| 显存 | 能做什么 |
| --- | --- |
| 无 GPU / 8GB 内存 | 只调 API；或用 0.1B 级模型 CPU 跑通代码（极慢，仅验证流程） |
| **8~12GB** | **7B QLoRA**（r=8, seq=512~1024, batch=1 + 梯度累积）⭐ |
| 16~24GB | 7B LoRA 全 BF16 / 14B QLoRA，可放宽上下文 |
| 40GB+ | 全量 SFT 小模型 / 多卡实验 |
| 多卡 A100/H100 | 继续预训练、全量微调、DPO 大模型 |

> Windows 上 `bitsandbytes` 支持曾有限制；若装不上，可用 WSL2 / Linux，或改用非量化的 LoRA（小模型）。第 23 章的 WSL/Docker 思路同样适用。

## 25.5 SFT 全流程（Transformers + Trainer）

### 25.5.1 完整代码

```python
# 3_sft.py —— 监督微调（先不加 LoRA，理解全貌；小模型可跑）
import json, torch
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM, AutoTokenizer,
    TrainingArguments, Trainer, DataCollatorForSeq2Seq,
)

MODEL_ID = "Qwen/Qwen2.5-0.5B-Instruct"   # 换成小模型可在 CPU 验证流程
OUT = "outputs/sft"

tok = AutoTokenizer.from_pretrained(MODEL_ID)
if tok.pad_token is None:
    tok.pad_token = tok.eos_token          # ⚠️ 必须有 pad token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    torch_dtype=torch.bfloat16 if torch.cuda.is_bf16_supported() else torch.float32,
    device_map="auto",
)
model.config.use_cache = False             # 训练时关 KV Cache，否则与梯度检查点冲突
model.gradient_checkpointing_enable()      # 用时间换显存


def format_example(ex):
    """用模型自带的 chat template，别手写提示词格式"""
    text = tok.apply_chat_template(
        ex["messages"], tokenize=False, add_generation_prompt=False
    )
    return {"text": text}


ds = load_dataset("json", data_files={
    "train": "data/train.jsonl", "validation": "data/val.jsonl",
})

MAX_LEN = 512

def tokenize(ex):
    r = tok(ex["text"], truncation=True, max_length=MAX_LEN,
            padding=False, return_tensors=None)
    # 只让模型在「回答部分」计算 loss（可选但推荐）：
    # 简化版先全序列算 loss，进阶见下方说明
    r["labels"] = r["input_ids"].copy()
    return r

ds = ds.map(format_example).map(tokenize, remove_columns=ds["train"].column_names)

args = TrainingArguments(
    output_dir=OUT,
    num_train_epochs=3,                 # ⚠️ 指令数据 2~3 轮即可，多了过拟合
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,      # 等效 batch=8
    learning_rate=2e-4,                 # 全量 SFT 常用 1e-5~2e-5；小模型/LoRA 用 1e-4~2e-4
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,
    weight_decay=0.0,
    logging_steps=10,
    eval_strategy="epoch",              # 每轮验证，盯住过拟合
    save_strategy="epoch",
    save_total_limit=2,
    bf16=torch.cuda.is_bf16_supported(),
    report_to="none",                   # 接 wandb 时改成 "wandb"
    seed=42,
)

trainer = Trainer(
    model=model, args=args,
    train_dataset=ds["train"], eval_dataset=ds["validation"],
    data_collator=DataCollatorForSeq2Seq(tok, model=model, padding=True,
                                         label_pad_token_id=-100),
)
trainer.train()
trainer.save_model(OUT)
tok.save_pretrained(OUT)                # ⚠️ tokenizer 必须一起保存
print("SFT 完成:", OUT)
```

### 25.5.2 三个关键细节

**① 用 `apply_chat_template`，别自己拼提示词**

不同模型的对话模板不同（`<|im_start|>`、`[INST]`…）。拼错模板是"微调后模型突然变笨"的头号原因。

**② 只在回答部分算 loss（Completion-only）**

全序列算 loss 会让模型花力气学「用户的问题怎么说」。更规范的做法是把 prompt 部分的 label 设为 `-100`（PyTorch cross_entropy 默认忽略）：

```python
def tokenize_completion_only(ex):
    prompt = tok.apply_chat_template(ex["messages"][:-1], tokenize=False,
                                     add_generation_prompt=True)
    answer = ex["messages"][-1]["content"] + tok.eos_token
    p_ids = tok(prompt, add_special_tokens=False)["input_ids"]
    a_ids = tok(answer, add_special_tokens=False)["input_ids"]
    ids = (p_ids + a_ids)[:MAX_LEN]
    labels = ([-100] * len(p_ids) + a_ids)[:MAX_LEN]
    return {"input_ids": ids, "labels": labels}
```

**③ `-100` 是 label 的忽略值**，配合 `DataCollatorForSeq2Seq` 的 `label_pad_token_id=-100`，padding 部分也不参与 loss。

### 25.5.3 超参速查

| 超参 | 全量 SFT | LoRA/QLoRA | 说明 |
| --- | --- | --- | --- |
| `learning_rate` | 1e-5 ~ 2e-5 | **1e-4 ~ 2e-4** | LoRA 需要更大 lr |
| `num_train_epochs` | 2~3 | 2~4 | 数据少时别贪多 |
| `effective batch` | 32~128 | 8~32 | `per_device × accum × GPU数` |
| `warmup_ratio` | 0.03 | 0.03 | 防起步炸 |
| `max_len` | 1024~4096 | 512~2048 | 越长显存越大 |
| `lr_scheduler` | cosine | cosine | 常用 |

## 25.6 LoRA / QLoRA 完整实战 ⭐

```python
# 4_qlora.py —— 消费级显卡微调 7B（显存不足就换 0.5B 模型）
import torch, json
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig,
    TrainingArguments, Trainer, DataCollatorForSeq2Seq,
)
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

MODEL_ID = "Qwen/Qwen2.5-0.5B-Instruct"    # 有 8~12G 显存可换 7B
OUT = "outputs/qlora-adapter"

# ---------- ① 4bit 量化配置（QLoRA 核心）----------
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # NF4：正态分布最优的 4bit 类型
    bnb_4bit_use_double_quant=True,          # 双重量化
    bnb_4bit_compute_dtype=torch.bfloat16,   # 计算时反量化到 bf16
)

tok = AutoTokenizer.from_pretrained(MODEL_ID)
if tok.pad_token is None:
    tok.pad_token = tok.eos_token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID, quantization_config=bnb, device_map="auto",
)
model = prepare_model_for_kbit_training(model)   # 归一化 dtype、开梯度检查点
model.config.use_cache = False

# ---------- ② LoRA 配置 ----------
lora = LoraConfig(
    r=16,
    lora_alpha=32,                # 常设 2r
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    # 想更强可加 MLP: ["gate_proj","up_proj","down_proj"]
)
model = get_peft_model(model, lora)
model.print_trainable_parameters()
# 典型输出: trainable params: 8.6M || all params: 500M || trainable%: 1.7%

# ---------- ③ 数据 ----------
MAX_LEN = 512
def build(ex):
    prompt = tok.apply_chat_template(ex["messages"][:-1], tokenize=False,
                                     add_generation_prompt=True)
    answer = ex["messages"][-1]["content"] + tok.eos_token
    p = tok(prompt, add_special_tokens=False)["input_ids"]
    a = tok(answer, add_special_tokens=False)["input_ids"]
    return {
        "input_ids": (p + a)[:MAX_LEN],
        "labels": ([-100] * len(p) + a)[:MAX_LEN],
    }

ds = load_dataset("json", data_files={"train": "data/train.jsonl",
                                     "validation": "data/val.jsonl"})
ds = ds.map(build, remove_columns=ds["train"].column_names)

# ---------- ④ 训练 ----------
args = TrainingArguments(
    output_dir=OUT,
    num_train_epochs=3,
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,
    gradient_checkpointing=True,
    learning_rate=2e-4,                 # ⚠️ LoRA 用比全量 SFT 大一个量级的 lr
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,
    logging_steps=10,
    eval_strategy="epoch",
    save_strategy="epoch",
    save_total_limit=2,
    bf16=torch.cuda.is_bf16_supported(),
    optim="paged_adamw_8bit",           # QLoRA 的分页优化器，防 OOM
    report_to="none",
    seed=42,
)

trainer = Trainer(
    model=model, args=args,
    train_dataset=ds["train"], eval_dataset=ds["validation"],
    data_collator=DataCollatorForSeq2Seq(tok, padding=True,
                                         label_pad_token_id=-100),
)
trainer.train()
model.save_pretrained(OUT)              # ⚠️ 只保存 adapter（几十 MB）
tok.save_pretrained(OUT)
print("Adapter 已保存:", OUT)
```

## 25.7 偏好对齐：DPO 入门

SFT 教模型"怎么答"，DPO 教模型"哪种答更好"。相比 RLHF（要训 Reward Model + PPO），**DPO 不需要单独的奖励模型**，直接用偏好对优化，工程上简单得多，已成为主流入门方案。

**核心思想**（不展开推导）：增大 `chosen` 相对 `rejected` 的对数概率优势，同时用 KL 约束别偏离参考模型太远。

\[
\mathcal{L}_{DPO} = -\log \sigma\!\left(\beta \log \tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}
                                   - \beta \log \tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)
\]

```python
# 7_dpo.py —— DPO 骨架（需先有 SFT/LoRA 模型）
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel
from trl import DPOConfig, DPOTrainer

BASE  = "Qwen/Qwen2.5-0.5B-Instruct"
SFT   = "outputs/qlora-adapter"

tok = AutoTokenizer.from_pretrained(BASE)
if tok.pad_token is None: tok.pad_token = tok.eos_token

model = AutoModelForCausalLM.from_pretrained(BASE, torch_dtype="auto", device_map="auto")
model = PeftModel.from_pretrained(model, SFT, is_trainable=True)
ref   = AutoModelForCausalLM.from_pretrained(BASE, torch_dtype="auto", device_map="auto")

# 偏好数据：{"prompt":..., "chosen":..., "rejected":...}
ds = load_dataset("json", data_files={"train": "data/preferences.jsonl"})["train"]

cfg = DPOConfig(
    output_dir="outputs/dpo",
    beta=0.1,                       # KL 约束强度，越大越保守
    learning_rate=5e-6,             # ⚠️ DPO lr 远小于 SFT
    num_train_epochs=1,             # 偏好数据易过拟合，通常 1 轮
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,
    max_length=512, max_prompt_length=256,
    bf16=True, logging_steps=10, report_to="none",
)

trainer = DPOTrainer(
    model=model, ref_model=ref, args=cfg,
    train_dataset=ds, processing_class=tok,
)
trainer.train()
trainer.save_model("outputs/dpo")
```

| 方法 | 需要奖励模型 | 复杂度 | 适用 |
| --- | --- | --- | --- |
| **DPO** | ❌ | 低 ⭐ | 有成对偏好数据 |
| RLHF (PPO) | ✅ | 高 | 大规模对齐、细粒度奖励 |
| GRPO | ❌（用规则/组采样打分） | 中 | 可自动验证的任务（数学、代码） |
| KTO / IPO / ORPO | 变体 | 低~中 | 只有好/坏单边标注时 |

> **给初学者的建议**：先把 SFT + LoRA 跑通并评测达标，再碰 DPO。**没有可靠评测就做对齐，等于在黑暗里调参**（第 16 章）。

## 25.8 训练诊断：看懂 loss 曲线

| 现象 | 诊断 | 对策 |
| --- | --- | --- |
| train↓ val↓ 然后一起平 | 正常收敛 | 保存最优 checkpoint |
| **train↓ val↑** | 过拟合 | 减 epoch、加数据、加 dropout、降 `r`、早停 |
| 两者都不降 | lr 太小 / 数据格式错 / 模板不匹配 / label 全 -100 | 查 `apply_chat_template`、打印一条 tokenized 样本 |
| loss 一开始就极低 | label 泄漏 / 数据太简单 / 全量算 loss 但答案极短 | 检查 labels 构造 |
| loss 尖峰 / NaN | lr 太大 / fp16 溢出 | warmup、bf16、梯度裁剪、降 lr |
| 训练很快但效果没变 | LoRA 没挂上 / target_modules 名字不对 | `print_trainable_parameters()` 必须 >0；用 `model.named_modules()` 核对层名 |
| 显存 OOM | batch/seq 太大 | 梯度累积、`gradient_checkpointing`、缩 `max_len`、QLoRA |

- [ ] 固定 `seed`（`TrainingArguments(seed=42)` + `torch.manual_seed`）；
- [ ] 记录 base model 精确版本/commit、数据集 hash、完整超参、依赖版本；
- [ ] 保存 tokenizer + chat template + adapter；
- [ ] 每次实验只改一个变量；
- [ ] 训练日志/曲线落盘（TensorBoard / wandb / MLflow）。

## 25.9 评测回归：防止"调好了业务、调坏了脑子"

这是最容易被跳过、也最容易在上线后翻车的一步。呼应第 16 章 Golden Set。

### 25.9.1 三层评测

```text
① 业务集（本次调优目标）  ── 必须变好 ✅
② 通用能力集（回归护栏）  ── 不能明显变差 ⚠️ 防灾难性遗忘
③ 安全集（拒答/越狱/PII）── 不能变差 🛡️
```

| 层 | 测什么 | 判据 |
| --- | --- | --- |
| 业务集 | 目标格式准确率、领域术语、任务成功率 | 相对基线显著提升 |
| 通用集 | 常识问答、简单推理、指令遵循 | 相对基线下降 **< 5%** |
| 安全集 | 越狱、隐私、有害请求拒答 | 零退化 |

### 25.9.2 可运行的前后对比脚本

```python
# 8_eval_compare.py —— 微调前后 A/B 对比（用第 23 章的 OpenAI 兼容端点更方便）
import json, statistics
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

GOLDEN = [json.loads(l) for l in open("eval/golden.jsonl", encoding="utf-8")]
# 每条: {"id":..., "input":..., "must_contain":[...], "must_not_contain":[...], "bucket":"biz|general|safety"}

def ask(model, q):
    return client.chat.completions.create(
        model=model, messages=[{"role": "user", "content": q}],
        temperature=0, max_tokens=200,
    ).choices[0].message.content

def evaluate(model):
    by_bucket = {}
    for c in GOLDEN:
        a = ask(model, c["input"])
        ok = all(k in a for k in c.get("must_contain", [])) and \
             not any(k in a for k in c.get("must_not_contain", []))
        by_bucket.setdefault(c["bucket"], []).append(int(ok))
    return {k: round(statistics.mean(v), 3) for k, v in by_bucket.items()}

before = evaluate("qwen2.5:0.5b")          # 原始模型
after  = evaluate("my-finetuned")          # 合并/部署后的微调模型
print("基线:", before)
print("微调:", after)
for k in before:
    delta = after[k] - before[k]
    flag = "⚠️ 退化" if delta < -0.05 else ("✅ 提升" if delta > 0 else "— 持平")
    print(f"  {k}: {before[k]} → {after[k]} ({delta:+.3f}) {flag}")
```

> **为什么必须做**：LoRA 尤其容易"过拟合到窄任务"，业务集从 0.6 涨到 0.95，但常识问答从 0.8 掉到 0.5。只看业务集会以为大获全胜，上线后用户随便问一句就露馅。
>
> 更进一步可接第 16 章的 **LLM-as-Judge**（rubric 打分、成对比较）与 pytest+CI 回归，把 `delta < -0.05` 设为 CI 红线。

### 25.9.3 灾难性遗忘的缓解

| 手段 | 说明 |
| --- | --- |
| 降低 `r` / 减少 epoch / 降 lr | 限制改动幅度 |
| **混入通用数据** | 训练集中掺 10~30% 通用指令样本 ⭐ 最有效 |
| 只训部分层 | 少挂几个 `target_modules` |
| KL 正则 / DPO 的 `beta` | 约束别偏离原模型 |
| 早停 | 按通用集指标而非 train loss 选 checkpoint |

## 25.12 常见踩坑

| 坑 | 症状 | 解决 |
| --- | --- | --- |
| **该用 RAG 却去做微调** | 事实仍错、知识仍过时、维护困难 | 微调教行为，RAG 教知识（25.1） |
| **chat template 拼错** | 微调后模型突然变笨/不停止 | 一律 `apply_chat_template`，训练推理同一套 |
| 全序列算 loss | 模型学"怎么问问题"、回答质量差 | completion-only，prompt 部分 `-100` |
| `target_modules` 名字不对 | trainable params = 0，白训 | `print_trainable_parameters()` 核对；打印 `named_modules()` |
| LoRA 用了全量 SFT 的 lr | 几乎学不到东西 | LoRA lr 大一个量级（1e-4~2e-4） |
| DPO 用了 SFT 的 lr | 模型崩坏 | DPO lr 小一个量级（~5e-6）、1 轮 |
| epoch 太多 / 数据太少 | val loss 反弹、输出复读 | 2~3 轮、加数据、早停、混入通用样本 |
| 评测集混进训练数据 | 分数虚高，上线翻车 | 严格去污染（25.3.2） |
| 只看业务集 | 通用能力悄悄崩了 | 三层评测 + CI 红线（25.9） |
| 忘存 tokenizer | 部署后乱码/模板丢 | `tok.save_pretrained()` 一起存 |
| `use_cache=True` + 梯度检查点 | 报错或显存异常 | 训练时 `config.use_cache = False` |
| Windows 上 bitsandbytes 装不上 | 无法 QLoRA | WSL2 / Linux，或改用非量化 LoRA + 小模型 |
| 直接合并 4bit 主干 | 精度明显下降 | 用 BF16 主干重新加载 adapter 再合并 |
| 把量化当训练 | 以为 4bit 模型"训过了" | 见 25.2.3 说明 |

## 25.13 面试高频问题

**Q1. 什么时候该微调，什么时候该用 RAG？**

A：RAG 解决**知识与时效**（可追溯、可更新、低成本），微调解决**行为与格式**（固定风格、领域表达、用小模型替代大模型的专门任务）。微调不能可靠地灌入大量新事实，硬塞会导致幻觉与不可维护。默认顺序：Prompt → RAG/工具 → 微调 → 继续预训练。

**Q2. LoRA 的原理？为什么能省这么多？**

A：冻结 \(W_0\)，用两个低秩矩阵 \(B(d×r)\)、\(A(r×k)\) 的乘积近似权重变化量 \(\Delta W\)，并按 \(\alpha/r\) 缩放。因为微调的 ΔW 内在秩很低，\(r\ll d,k\)，可训练参数常只占 0.1%~1%，连带梯度和优化器状态也几乎消失，所以显存从 60GB+ 降到十几 GB。

**Q3. QLoRA 相比 LoRA 多了什么？**

A：把冻结主干用 4-bit NF4 量化（+双重量化进一步省）、计算时反量化到 bf16、用 Paged Optimizer 在显存峰值时把优化器状态分页到 CPU。三者合起来让 7B 微调能在 8~12GB 消费级卡上跑。注意 QLoRA 是**在量化主干上训练旁路**，不是"量化即训练"。

**Q4. 为什么 LoRA 的学习率要比全量 SFT 大？**

A：全量微调更新全部参数，梯度信号强且容易破坏预训练表示，需小 lr（1e-5 量级）；LoRA 只更新少量随机初始化的旁路参数，需要更大 lr（1e-4~2e-4）才能有效学习。反之 DPO 因为要约束不偏离参考模型，lr 更小（~5e-6）。

**Q5. 什么是 completion-only loss？为什么重要？**

A：只把「assistant 回答」部分的 token 计入 loss，用户 prompt 与 system 部分的 label 设为 -100（cross_entropy 忽略）。否则模型会花容量去学"用户会怎么提问"，而不是"该怎么回答"，且短答案任务上 loss 会被 prompt 稀释。

**Q6. 什么是灾难性遗忘？怎么防？**

A：窄任务微调后模型在通用任务上明显退化。防护：混入 10~30% 通用指令数据、减小 `r`/epoch/lr、只训部分层、KL 正则（DPO 的 β）、按通用集指标早停，以及**在 CI 里把通用集/安全集退化设为红线**。

**Q7. SFT、RLHF、DPO 的关系？**

A：SFT 用示范数据教"标准答案长什么样"；RLHF 训奖励模型再用 PPO 优化偏好，效果好 but 复杂；DPO 把偏好优化转成直接的闭式损失，不需要单独奖励模型和在线采样，工程更轻，成为中小团队首选。GRPO 等变体适合数学/代码这类可自动验证的任务。

**Q8. 微调完怎么证明"真的变好了"？**

A：三层评测——业务集必须显著提升、通用能力集下降 <5%、安全集零退化；用固定 Golden Set 做 A/B，必要时叠加 LLM-as-Judge（第 16 章），并把阈值写进 CI。同时检查数据去污染，否则高分可能是背题。

**Q9. adapter 怎么上线？**

A：两种——运行时 `PeftModel` 热插拔（多业务共享一份主干），或 `merge_and_unload()` 合并成标准 HF 模型后交给 vLLM/SGLang，或转 GGUF 给 Ollama/llama.cpp（第 23 章）。合并 QLoRA 建议用非量化 BF16 主干重挂 adapter，避免量化误差。

**核心心法**：

> 调优不是"炼丹"，而是**数据工程 + 小幅参数改动 + 严格评测回归**。
> 真正决定成败的是「数据质量」和「有没有在通用能力上设护栏」，
> 而不是把 `r` 从 16 调到 32。
