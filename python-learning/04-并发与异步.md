## 4.1 并发与并行：先分清概念

| 概念 | 定义 | 类比 |
| --- | --- | --- |
| 并发（Concurrency） | 多个任务"交替执行"（宏观同时，微观轮流） | 一个人同时烧水、切菜、煮饭（轮着做） |
| 并行（Parallelism） | 多个任务"同时执行"（需要多核 CPU） | 三个人同时烧水、切菜、煮饭 |
| 阻塞（Blocking） | 任务在等待（IO/锁）时干等着 | 烧水时人坐在炉子前发呆 |
| 非阻塞/异步 | 等待时去做别的事，完成后再回来 | 烧水时去切菜，水开了再回来 |

```python
# 体验"并发执行"的最小例子（多线程）
import threading
import time

def task(name, seconds):
    print(f"{name} 开始")
    time.sleep(seconds)          # 模拟 IO 等待（sleep 会释放 GIL）
    print(f"{name} 结束")

start = time.time()
t1 = threading.Thread(target=task, args=("A", 2))
t2 = threading.Thread(target=task, args=("B", 2))
t1.start(); t2.start()
t1.join(); t2.join()             # 等两个线程结束
print(f"耗时 {time.time() - start:.1f}s")    # ~2s（并发执行，不是 4s）
```

## 4.2 GIL：Python 并发最大的"坑"（面试必问）

### 4.2.1 GIL 是什么

**GIL（Global Interpreter Lock，全局解释器锁）**：CPython 解释器规定**同一时刻只有一个线程能执行 Python 字节码**。

```python
import threading

counter = 0
def increment():
    global counter
    for _ in range(1_000_000):
        counter += 1

threads = [threading.Thread(target=increment) for _ in range(4)]
start = time.time()
for t in threads: t.start()
for t in threads: t.join()
print(f"counter = {counter}，耗时 {time.time()-start:.2f}s")
```

你可能会想：4 个线程各加 100 万，应该 400 万。但结果是**约 100 万~300 万之间且不确定**——`counter += 1` 不是原子的（读-改-写三步），线程被切换时互相覆盖。而且即使加锁，由于 GIL，**多线程跑纯计算不但不加速，反而比单线程慢**（锁切换开销）。

### 4.2.2 GIL 的影响与对策

| 场景 | 多线程效果 | 正确方案 |
| --- | --- | --- |
| IO 密集（网络请求/文件/数据库） | **有效加速**（IO 等待时释放 GIL，其他线程趁机执行） | 多线程 / asyncio |
| CPU 密集（纯计算/循环） | **不加速甚至更慢**（GIL 串行化字节码） | 多进程 multiprocessing |
| 混合 | 复杂 | 多进程 + 进程内多线程 |

```python
# 证明：纯计算多线程反而慢（CPython 下）
import threading, time

def cpu_task():
    total = 0
    for i in range(30_000_000):
        total += i
    return total

start = time.time()
cpu_task(); cpu_task()                        # 单线程串行
serial = time.time() - start

start = time.time()
ts = [threading.Thread(target=cpu_task) for _ in range(2)]
for t in ts: t.start()
for t in ts: t.join()
parallel = time.time() - start

print(f"串行 {serial:.2f}s vs 多线程 {parallel:.2f}s")   # 多线程更慢（GIL 切换开销）
```

> **面试总结一句话**：GIL 是 CPython 解释器级别的锁，保证内存安全、实现简单，代价是"纯计算多线程无法利用多核"；对策是**计算用多进程、IO 用多线程或 asyncio**。其他实现（Jython 无 GIL，PyPy 有 GIL，但 3.13+ 的实验性 free-threading 正在移除）。

### 4.2.3 与 Java 对比

| Java | Python |
| --- | --- |
| `new Thread(Runnable).start()` | `threading.Thread(target=fn).start()` |
| `thread.join()` | `t.join()` |
| `ExecutorService` | `ThreadPoolExecutor`（4.4） |
| `synchronized` / `ReentrantLock` | `Lock` / `RLock`（4.3） |
| `ConcurrentHashMap` / `AtomicInteger` | 见 4.3.4 |
| 线程池充分利用多核 | CPU 密集要上多进程/协程 |
| 虚拟线程（Project Loom） | asyncio 协程（思路类似） |

## 4.3 多线程 threading：创建、守护线程与安全

### 4.3.1 两种创建方式

```python
import threading
import time

# 方式1：直接传函数（最常用）
def worker(name, delay):
    time.sleep(delay)
    print(f"{name} 完成")

t = threading.Thread(target=worker, args=("任务A", 1))
t.start()
t.join()                       # 等待该线程结束（对应 Java 的 join）

# 方式2：继承 Thread 重写 run（适合封装有状态的线程对象，Java 风格）
class DownloadThread(threading.Thread):
    def __init__(self, url):
        super().__init__()
        self.url = url

    def run(self):                          # 重写 run，start() 会自动调用
        print(f"下载 {self.url}")
        time.sleep(1)

DownloadThread("https://example.com/a.zip").start()
```

### 4.3.2 守护线程 daemon 与线程信息

```python
import threading, time

def bg():
    while True:
        time.sleep(1)
        print("后台任务...")

t = threading.Thread(target=bg, daemon=True)   # 守护线程
t.start()
print(f"线程数：{threading.active_count()}")
print(f"当前线程：{threading.current_thread().name}")
time.sleep(2.5)
print("主线程结束")                            # 主线程退出，守护线程被强制终止（不用管它）
```

> **daemon=True**：主线程结束时直接终止，不等待。适用：心跳、监控、日志清理等"非核心后台任务"。**注意**：守护线程里别做重要收尾（可能被杀到一半）。

### 4.3.3 线程安全：锁 Lock / RLock

```python
import threading

balance = 0
lock = threading.Lock()                      # 普通互斥锁（对应 Java synchronized/Lock）

def deposit(amount):
    global balance
    for _ in range(10_000):
        with lock:                           # 等价 lock.acquire()/release()（推荐 with）
            balance += amount

ts = [threading.Thread(target=deposit, args=(1,)) for _ in range(5)]
for t in ts: t.start()
for t in ts: t.join()
print(balance)                               # 50000（有锁 → 结果正确）
```

| 锁/同步工具 | 说明 | 对应 Java |
| --- | --- | --- |
| `Lock` | 互斥锁（不可重入，同一线程重复 acquire 会死锁） | `synchronized` |
| `RLock` | 可重入锁（同线程可多次 acquire） | `ReentrantLock` |
| `Semaphore(n)` | 信号量（限制并发数） | `Semaphore` |
| `Condition` | 条件变量（生产者-消费者） | `Condition` |
| `Event` | 事件（线程间通知） | `CountDownLatch` 变体 |
| `threading.Timer` | 延时执行 | `ScheduledExecutorService` |

**条件变量 + 队列（生产者-消费者经典）**：

```python
import threading, time, random

queue = []                       # 简化演示用；生产用 queue.Queue
cv = threading.Condition()

def producer():
    for i in range(5):
        with cv:
            queue.append(f"item-{i}")
            print(f"生产 {i}")
            cv.notify()          # 唤醒一个消费者
        time.sleep(0.2)

def consumer():
    for _ in range(5):
        with cv:
            while not queue:     # 防御性：防止虚假唤醒
                cv.wait()        # 等待并释放锁
            item = queue.pop(0)
            print(f"消费 {item}")

threading.Thread(target=producer).start()
threading.Thread(target=consumer).start()
```

> **生产首选 `queue.Queue`**（自带锁，线程安全），不要手写列表 + 锁。

### 4.3.4 无锁安全方案（对应 Java AtomicInteger）

```python
# queue.Queue：线程安全队列（跨线程传数据首选）
import queue, threading

q = queue.Queue(maxsize=10)
q.put(1); q.put(2)
print(q.get(), q.get())            # 1 2（阻塞取）
print(q.empty(), q.qsize())        # True 0

# 只读共享数据天然安全；线程局部数据用 threading.local()
local = threading.local()
def set_name(name):
    local.name = name              # 每个线程独立，互不干扰
```

## 4.4 线程池 ThreadPoolExecutor（对应 Java ExecutorService）

**永远优先用线程池**而不是手动 `Thread()`：复用线程、限制并发、优雅关闭。生产代码 90% 并发场景就是这一节。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def fetch(url):
    time.sleep(1)                        # 模拟 IO 请求
    return f"{url} 的数据"

# 方式1：submit + as_completed（按完成顺序取结果，推荐）
with ThreadPoolExecutor(max_workers=5) as pool:
    futures = [pool.submit(fetch, f"http://api/{i}") for i in range(10)]
    for fut in as_completed(futures):    # 谁先完成先处理谁
        print(fut.result())

# 方式2：map（按传入顺序取结果，批量场景更简洁）
with ThreadPoolExecutor(max_workers=5) as pool:
    results = list(pool.map(fetch, [f"http://api/{i}" for i in range(10)]))
    print(results)

# 方式3：异常处理（result() 会抛出子线程异常，避免静默失败）
def risky(x):
    if x == 3:
        raise ValueError("参数错误")
    return x * 2

with ThreadPoolExecutor(max_workers=3) as pool:
    fs = [pool.submit(risky, i) for i in range(5)]
    for f in as_completed(fs):
        try:
            print(f.result())
        except ValueError as e:
            print("捕获异常:", e)

# 模块级全局池（App 级复用，避免反复创建销毁）
from concurrent.futures import ThreadPoolExecutor
executor = ThreadPoolExecutor(max_workers=8, thread_name_prefix="worker-")
# 使用完 shutdown()（with 语句自动做）
```

| Java | Python |
| --- | --- |
| `Executors.newFixedThreadPool(5)` | `ThreadPoolExecutor(max_workers=5)` |
| `submit(Callable)` | `pool.submit(fn)` |
| `Future.get()` | `fut.result()` |
| `CompletionService.take()` | `as_completed(futures)` |
| `executor.shutdown()` | `with ThreadPoolExecutor() as pool` 自动关闭 |

> **面试**：`map` 与 `submit+as_completed` 区别——map 按输入顺序返回、一批全做完才逐个 yield；as_completed 谁先完成谁先返回（做"进度优先"处理时用）。

## 4.5 多进程 multiprocessing（CPU 密集的唯一解）

每个进程有独立解释器和 GIL，**真正利用多核**。代价：进程创建开销大、进程间不共享内存（要 IPC）。

### 4.5.1 Process 与 Pool（对比 Java 的线程池/并行流）

```python
import multiprocessing as mp

def cpu_heavy(n):
    total = 0
    for i in range(n):
        total += i ** 2
    return total

# 方式1：Process 直接启动
if __name__ == "__main__":                    # Windows 必须！防止无限递归创建进程
    p = mp.Process(target=cpu_heavy, args=(10_000_000,))
    p.start()
    p.join()
    print("进程完成")

# 方式2：Pool 进程池（推荐，对应 ThreadPoolExecutor）
if __name__ == "__main__":
    with mp.Pool(processes=4) as pool:        # 4 个进程并行
        results = pool.map(cpu_heavy, [10_000_000] * 4)
        print(results)
```

> **Windows 必背**：多进程代码必须包在 `if __name__ == "__main__":` 里，否则子进程会重新执行整个模块（无限递归报错）。

### 4.5.2 进程间通信：Queue 与 Pipe

```python
import multiprocessing as mp

def worker(q):
    q.put("来自子进程的消息")                  # 放入队列

if __name__ == "__main__":
    q = mp.Queue()
    p = mp.Process(target=worker, args=(q,))
    p.start()
    print(q.get())                            # 来自子进程的消息
    p.join()
```

### 4.5.3 共享内存与锁（跨进程改数据）

```python
import multiprocessing as mp

def add(shared_value, lock):
    for _ in range(100_000):
        with lock:
            shared_value.value += 1

if __name__ == "__main__":
    shared = mp.Value("i", 0)                 # 共享整数（类型码 i=int）
    lock = mp.Lock()
    ps = [mp.Process(target=add, args=(shared, lock)) for _ in range(4)]
    for p in ps: p.start()
    for p in ps: p.join()
    print(shared.value)                       # 400000（跨进程累加正确）
```

> **多进程 vs 多线程速记**：IO 密集（网络/磁盘/数据库）→ 多线程（或 asyncio）；CPU 密集（计算/编码/图像处理）→ 多进程；数据要共享 → 进程内用线程 + 锁，进程间用 Queue/共享内存。

## 4.6 asyncio：异步协程（高并发 IO 的现代方案）

### 4.6.1 为什么需要 asyncio

一个线程执行 1000 个网络请求：多线程方案开 1000 个线程（线程开销大）；**协程方案一个线程"假装同时"跑 1000 个任务**——遇到 IO 就挂起让位，IO 完成再回来，线程数几乎不随任务数增长。

```
同步：请求1 等待2s → 请求2 等待2s → ...（1000 个 = 2000s）
asyncio：同时发起 1000 个 → 全部完成 ≈ 2s（一个事件循环轮转）
```

### 4.6.2 核心语法：async / await（3.5+）

```python
import asyncio

async def fetch_data(name, seconds):
    """async def = 协程函数；调用不执行，返回协程对象"""
    print(f"开始 {name}")
    await asyncio.sleep(seconds)             # await 挂起点：让出控制权
    print(f"完成 {name}")
    return f"{name} 的结果"

async def main():
    # 方式1：串行 await（不对）
    r1 = await fetch_data("A", 1)
    r2 = await fetch_data("B", 1)            # 总耗时 2s

    # 方式2：gather 并发（正确姿势）
    results = await asyncio.gather(
        fetch_data("A", 1),
        fetch_data("B", 1),
        fetch_data("C", 1),
    )                                        # 总耗时 ~1s
    print(results)

    # 方式3：create_task 任务（适合动态批量）
    tasks = [asyncio.create_task(fetch_data(f"T{i}", 1)) for i in range(5)]
    for t in tasks:
        await t

asyncio.run(main())                          # 3.7+ 统一入口：创建事件循环并运行
```

> **await 本质**：遇到 IO（sleep/网络/数据库）时把控制权还给事件循环，事件循环去跑别的协程；IO 完成回调再切回来。这就是第二章生成器 `send()` 机制的运用——**协程 = 生成器 + 事件循环**。

### 4.6.3 超时与异常

```python
import asyncio

async def slow():
    await asyncio.sleep(10)
    return "太慢了"

async def main():
    try:
        # 超时：asyncio.timeout（3.11+）
        async with asyncio.timeout(2):
            result = await slow()
    except TimeoutError:
        print("任务超时，已取消")

    # 旧写法（兼容）：wait_for
    try:
        await asyncio.wait_for(slow(), timeout=1)
    except asyncio.TimeoutError:
        print("超时")

    # gather 处理异常：return_exceptions=True 不让一个失败拖垮全部
    results = await asyncio.gather(
        might_fail(1), might_fail(2),
        return_exceptions=True,              # 异常作为结果返回，不抛出
    )

asyncio.run(main())
```

### 4.6.4 事件循环与任务调度

```python
import asyncio

async def main():
    # 获取当前事件循环
    loop = asyncio.get_running_loop()

    # run_in_executor：把"阻塞函数"丢到线程池执行（桥接同步代码，重要！）
    import time
    def blocking_work():
        time.sleep(1)                        # 阻塞 API（如 requests）
        return "阻塞任务完成"

    result = await loop.run_in_executor(None, blocking_work)   # None = 默认线程池
    print(result)

    # asyncio.to_thread（3.9+，更简洁）
    result = await asyncio.to_thread(blocking_work)
    print(result)

asyncio.run(main())
```

### 4.6.5 常用 asyncio API 速查

| API | 作用 |
| --- | --- |
| `asyncio.run(coro)` | 顶层入口：创建/关闭事件循环 |
| `await asyncio.sleep(0)` | 显式让出控制权（无 IO 时模拟切换） |
| `asyncio.gather(*coros)` | 并发运行多个协程，收集结果 |
| `asyncio.create_task(coro)` | 创建任务（返回 Task，可 await 或 cancel） |
| `asyncio.wait_for(coro, timeout)` | 带超时等待 |
| `asyncio.as_completed(coros)` | 谁先完成谁先返回（同线程池版本） |
| `asyncio.Queue()` | 异步队列（生产者-消费者） |
| `asyncio.Semaphore(n)` | 限制并发数（爬虫限速） |
| `asyncio.to_thread(fn)` | 阻塞函数 → 线程池（桥接） |
| `asyncio.run_in_executor(pool, fn)` | 指定线程池执行阻塞函数 |

**asyncio.Semaphore 限流示例（爬虫并发控制）**：

```python
import asyncio

async def fetch(sem, i):
    async with sem:                      # 最多 3 个同时进入
        await asyncio.sleep(0.1)
        return f"第{i}个完成"

async def main():
    sem = asyncio.Semaphore(3)
    results = await asyncio.gather(*(fetch(sem, i) for i in range(10)))
    print(len(results))                  # 10

asyncio.run(main())
```

## 4.7 并发选型决策表与实战

### 4.7.1 决策表（面试+工程核心）

| --- | --- | --- |

| 定时任务/后台任务 | asyncio + 定时器 / 框架任务调度 | — |

### 4.7.2 实战一：并发下载（asyncio + httpx，对比 Java HttpClient）

```bash
pip install httpx
```

```python
import asyncio
import httpx
import time

URLS = [f"https://httpbin.org/delay/{i}" for i in range(1, 4)]

async def download(client, url):
    resp = await client.get(url, timeout=10)     # await 异步 HTTP
    return f"{url} -> {resp.status_code}"

async def main():
    async with httpx.AsyncClient() as client:    # 复用连接（性能关键）
        results = await asyncio.gather(*(download(client, u) for u in URLS))
        for r in results:
            print(r)

start = time.time()
asyncio.run(main())
print(f"总耗时 {time.time() - start:.2f}s")      # 三个 delay 接口≈最大延迟，而不是和
```

### 4.7.3 实战二：多线程 + 队列批量处理文件（线程池 + 队列）

```python
import threading, queue, time
from concurrent.futures import ThreadPoolExecutor

def process_file(path):
    """模拟处理一个文件（耗时操作）"""
    time.sleep(0.5)
    return f"{path} 处理完成"

# 生产者：生成任务；消费者：线程池执行 —— 用 queue 解耦
tasks = queue.Queue()
for i in range(10):
    tasks.put(f"file_{i}.csv")

def worker():
    while not tasks.empty():
        path = tasks.get_nowait()
        try:
            print(process_file(path))
        finally:
            tasks.task_done()

with ThreadPoolExecutor(max_workers=4) as pool:
    futures = [pool.submit(worker) for _ in range(4)]
    tasks.join()                     # 等所有任务标记完成
```

### 4.7.4 实战三：CPU 密集并行（进程池计算哈希）

```python
import multiprocessing as mp
import hashlib

def hash_string(s: str) -> str:
    for _ in range(1_000_000):
        s = hashlib.sha256(s.encode()).hexdigest()
    return s

if __name__ == "__main__":
    data = [f"text-{i}" for i in range(8)]
    with mp.Pool(processes=4) as pool:     # 4 核真并行（GIL 无关）
        results = pool.map(hash_string, data)
    print(results[0][:16], "...")
```

### 面试高频问题清单

| 问题 | 答案要点 |
| --- | --- |
| GIL 是什么？影响？ | CPython 解释器锁，同一时刻仅一个线程执行字节码；纯计算多线程不加速；IO 密集不受影响 |
| 怎么绕开 GIL？ | 多进程；asyncio；C 扩展释放 GIL；3.13+ free-threading |
| 多线程 vs 多进程？ | 线程轻、共享内存、GIL 限制计算；进程重、独立内存、真并行 |
| 什么时候用线程池？ | IO 密集、任务数量可控、要控制并发度；ThreadPoolExecutor |
| asyncio 与多线程区别？ | 单线程事件循环 + 协程挂起，线程数不随任务数增长；适合高并发 IO |
| async/await 原理？ | 协程 = 生成器 + 事件循环；await 挂起让位，IO 完成回调恢复 |
| 为什么爬虫用 asyncio？ | 一个线程处理上万连接；对比开上万线程内存/上下文切换开销巨大 |
| 线程安全问题？ | `+=` 非原子；用 Lock/RLock 或 queue.Queue；局部数据用 threading.local |
| 死锁怎么产生/避免？ | 嵌套锁顺序不一致、可重入用 RLock；锁内避免调用带锁方法；超时 acquire |
| 阻塞函数在 asyncio 里怎么办？ | to_thread / run_in_executor 丢线程池；或换异步库（aiohttp/httpx） |
| 进程池为什么必须 `if __name__`？ | Windows 无 fork，子进程重新导入模块，会无限递归创建进程 |
| 生产者-消费者怎么做？ | queue.Queue + Condition/Event；asyncio.Queue 版本同理 |
| 有 1000 个任务、CPU 4 核，怎么选？ | IO 密集线程池/asyncio 扛千级；CPU 密集 4~8 进程池 |
| Java 虚拟线程 vs Python asyncio？ | 思路同源（轻量任务、阻塞让位），Java 自动调度，Python 显式 await |

### 本章小结

- **概念与 GIL**（4.1~4.2）：并发≠并行；GIL 限制纯计算多线程，对策"计算用进程、IO 用线程/协程"；
- **多线程**（4.3）：Thread 两种创建、daemon、Lock/RLock/Condition、queue.Queue 线程安全；
- **线程池**（4.4）：ThreadPoolExecutor 的 submit/as_completed/map 三件套（对应 ExecutorService）；
- **多进程**（4.5）：Pool 真并行、Queue 通信、共享内存 + 锁、Windows 必须 `__main__` 守卫；
- **asyncio**（4.6）：async/await、gather/create_task、超时、Semaphore 限流、to_thread 桥接阻塞代码；
- **选型实战**（4.7）：决策表 + 并发下载 / 队列批量处理 / 进程池哈希 三案例。
