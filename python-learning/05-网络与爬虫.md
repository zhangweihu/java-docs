## 5.1 HTTP 协议速览（爬虫的地基）

### 5.1.1 一次请求的完整旅程

爬虫本质就是：**模拟浏览器发 HTTP 请求 → 拿响应 → 解析出想要的数据**。所以先搞清楚 HTTP 协议：

```
┌──────┐  1. 建立连接（TCP 三次握手）  ┌────────┐
│ 爬虫  │ ──────────────────────────► │  服务器  │
│ 客户端 │  2. 发送请求（请求行+头+体）  │        │
│       │ ──────────────────────────► │        │
│       │  3. 返回响应（状态行+头+体）  │        │
│       │ ◄────────────────────────── │        │
└──────┘  4. 关闭/复用连接            └────────┘
```

**请求结构**（你发出去的东西）：

```
GET /search?q=python HTTP/1.1          ← 请求行：方法 + 路径?查询参数 + 协议版本
Host: www.example.com                  ← 请求头（Headers）：告诉服务器"我是谁、要什么"
User-Agent: Mozilla/5.0 ...            ← 尤其重要！服务器靠它识别"是浏览器还是爬虫"
Accept: text/html
Cookie: session=abc123                 ← Cookie：保持登录状态（会话）
                                       ← 空行
                                       ← 请求体（GET 一般没有，POST 表单/JSON 在这里）
```

**响应结构**（服务器还给你的东西）：

```
HTTP/1.1 200 OK                        ← 状态行：协议版本 + 状态码 + 原因短语
Content-Type: text/html; charset=utf-8 ← 响应头：告诉客户端"这是什么类型的数据"
Content-Length: 12345
Set-Cookie: session=abc123             ← 服务器下发 Cookie，客户端要存起来
                                       ← 空行
<!DOCTYPE html>...                     ← 响应体：HTML / JSON / 图片二进制等
```

### 5.1.2 必须背下来的状态码（面试常问）

| 状态码 | 含义 | 爬虫视角 |
| --- | --- | --- |
| 200 OK | 成功 | ✅ 正常拿数据 |
| 301/302 | 永久/临时重定向 | ⚠️ 地址变了，requests 默认自动跟随 |
| 403 Forbidden | 禁止访问 | 🚫 被反爬拦截了（最常见） |
| 404 Not Found | 资源不存在 | ⚠️ URL 写错或页面下线 |
| 429 Too Many Requests | 请求太频繁 | 🚫 触发限流，必须降速 |
| 500/502/503 | 服务器错误 | ⚠️ 服务器问题，可稍后重试 |

```python
import requests

resp = requests.get("https://httpbin.org/status/200")
print(resp.status_code)          # 200
print(resp.ok)                   # True（200-399 都是 True）
resp.raise_for_status()          # 非 2xx 直接抛异常（强烈建议写上）
```

### 5.1.3 GET 与 POST（两种最常用的请求）

```python
import requests

# GET：数据在 URL 的查询参数里（适合读操作）
resp = requests.get(
    "https://httpbin.org/get",
    params={"q": "python 爬虫", "page": 1},   # 自动编码成 ?q=python+爬虫&page=1
    timeout=10,
)
print(resp.url)    # 实际请求的完整 URL

# POST：数据在请求体里（适合写操作/提交表单）
resp = requests.post(
    "https://httpbin.org/post",
    json={"username": "admin", "password": "123456"},  # 自动转 JSON 并设置 Content-Type
    headers={"Authorization": "Bearer token123"},
    timeout=10,
)

# 表单提交（对应 HTML <form> 的默认编码）
resp = requests.post(
    "https://httpbin.org/post",
    data={"username": "admin", "password": "123456"},  # data= 是表单，json= 是 JSON
)
```

> **对比 Java**：`requests` 对应 OkHttp/HttpClient，但语法更简洁——不需要 Builder 模式、不需要手动处理 JSON 序列化，一个 `get()/post()` 搞定。

## 5.2 requests 进阶：响应的正确处理

### 5.2.1 响应内容四件套

```python
import requests

resp = requests.get("https://httpbin.org/json", timeout=10)

resp.status_code     # 200        状态码
resp.headers         # {'Content-Type': 'application/json', ...}  响应头（大小写不敏感）
resp.text            # '{"slideshow": ...}'  文本内容（自动按 charset 解码）
resp.content         # b'{"slideshow": ...}'  原始字节（下载图片/文件用这个）
resp.json()          # {'slideshow': {...}}  解析成 dict/list（接口返回 JSON 时）
resp.encoding        # 'utf-8'    实际使用的编码（乱码时手动改）
```

**乱码问题**（爬虫头号坑）：

```python
resp = requests.get("https://example.com", timeout=10)
print(resp.encoding)            # 服务器没给 charset 时默认 ISO-8859-1 → 中文乱码！
resp.encoding = "utf-8"         # 手动指定，再看 text 就正常了
# 或更稳：直接用字节 + 自己解码
html = resp.content.decode("utf-8", errors="ignore")
```

### 5.2.2 Session：保持会话（对应 Java 的 CookieStore）

爬虫连续访问多个页面时，**必须复用 Session**，否则每次都是新会话（登录态丢失、容易被封）：

```python
import requests

session = requests.Session()
session.headers.update({"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/126.0"})

# 第一次请求拿到 Cookie，自动存进 Session
resp1 = session.get("https://httpbin.org/cookies/set?name=python")
# 第二次请求自动带上 Cookie（就像浏览器里同一个会话）
resp2 = session.get("https://httpbin.org/cookies")

# 连接复用：同一主机的多次请求共用 TCP 连接，速度快很多
```

> **对比 Java**：`requests.Session()` 对应 `HttpClient` 的 Cookie 管理器 / OkHttp 的 `OkHttpClient` 实例复用。

### 5.2.3 超时、重试与代理（工程必备）

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

session = requests.Session()

# 重试策略：连接失败/超时重试 3 次，遇到 429/503 也重试（指数退避）
retry = Retry(
    total=3,
    backoff_factor=0.5,          # 每次重试间隔 0.5s * 2^n 递增
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["GET"],
)
adapter = HTTPAdapter(max_retries=retry)
session.mount("https://", adapter)
session.mount("http://", adapter)

# 超时（必须写！否则一个坏网站能卡住你几分钟）
resp = session.get("https://httpbin.org/delay/2", timeout=(3, 10))  # (连接超时, 读取超时)

# 代理（公司网络/反爬需要换 IP 时）
proxies = {"http": "http://127.0.0.1:7890", "https": "http://127.0.0.1:7890"}
resp = session.get("https://httpbin.org/ip", proxies=proxies, timeout=10)
```

## 5.3 正则表达式：文本处理的瑞士军刀

### 5.3.1 基础语法（10 个够用）

正则 = 用"模式"匹配"文本"的工具。爬虫里常用来**从 HTML/接口返回里抠数据**（比 Jsoup 更底层，但更灵活）。

| 语法 | 含义 | 示例 | 匹配 |
| --- | --- | --- | --- |
| `.` | 任意字符（除换行） | `a.c` | `abc`、`a1c` |
| `\d` | 数字（对应 Java `[0-9]`） | `\d{4}` | `2026` |
| `\w` | 字母数字下划线 | `\w+` | `python3` |
| `\s` | 空白（空格/换行/制表） | `a\sb` | `a b` |
| `*` | 前一个字符 0 次或多次 | `ab*c` | `ac`、`abbc` |
| `+` | 前一个字符 1 次或多次 | `ab+c` | `abc`、`abbc`（不匹配 `ac`） |
| `?` | 前一个字符 0 次或 1 次 | `ab?c` | `ac`、`abc` |
| `{n}` | 恰好 n 次 | `\d{11}` | 11 位手机号 |
| `[...]` | 字符集 | `[a-z0-9]` | 小写字母或数字 |
| `(...)` | 分组（捕获） | `(\d+)-(\d+)` | 抓出两个数字 |
| `^` `$` | 开头 / 结尾 | `^a` `z$` | 以 a 开头 / 以 z 结尾 |
| `\b` | 单词边界 | `\bpython\b` | 独立单词 python |

### 5.3.2 Python re 模块四件套

```python
import re

text = "联系方式: 13812345678, 备用: 010-88886666, 邮箱: john@example.com"

# 1. re.search：找第一处（对应 Java Pattern.matcher().find()）
m = re.search(r"(\d{11})", text)          # r"" 原始字符串：\d 不会被转义（必须用 r）
print(m.group(0))                          # 13812345678（整体）
print(m.group(1))                          # 13812345678（第 1 个分组）

# 2. re.findall：找全部，直接返回列表（爬虫最常用）
phones = re.findall(r"1[3-9]\d{9}", text)  # 13812345678
emails = re.findall(r"[\w.]+@[\w.]+\.\w+", text)   # john@example.com
print(phones, emails)

# 3. re.sub：替换（对应 String.replaceAll）
masked = re.sub(r"(\d{3})\d{4}(\d{4})", r"\1****\2", text)   # 手机号脱敏
print(masked)                              # 138****5678

# 4. re.split：按模式切分
parts = re.split(r"[,，;；\s]+", "a, b；c\nd")
print(parts)                               # ['a', 'b', 'c', 'd']
```

**贪心陷阱**（面试必考）：`.*` 默认贪心（匹配到最远），要加 `?` 变非贪心：

```python
html = "<b>标题一</b>和<b>标题二</b>"
# 贪心：.* 一路吃到最后一个 </b>
print(re.findall(r"<b>(.*)</b>", html))    # ['标题一</b>和<b>标题二'] ← 错！
# 非贪心：.*? 匹配到最近一个就停
print(re.findall(r"<b>(.*?)</b>", html))   # ['标题一', '标题二'] ← 对！
```

> **对比 Java**：Python 的 `re` 对应 `java.util.regex`，语法几乎一致（`\d`、`\w`、分组等通用）。区别是 Python 用 `r""` 原始字符串写正则更舒服，Java 写 `\\d` 双反斜杠很痛苦。

### 5.3.3 用正则还是用解析库？

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| HTML 页面里抽数据 | **BeautifulSoup** | HTML 结构复杂，正则容易写错、难维护 |
| 接口返回 JSON 里抽字段 | 直接 `resp.json()` | 根本不需要正则 |
| 日志/纯文本里抽模式（手机号/邮箱/IP） | **正则** | 无结构文本，正则就是为这个设计的 |
| 复杂嵌套（HTML 里的 HTML） | 解析库 + 正则配合 | 各取所长 |

**原则：能结构化解析就别用正则。** HTML 不是正则语言，用正则解析 HTML 会被套娃式的引号、属性顺序搞崩溃。

### 5.4.2 三大选择器（必须掌握）

```python
# 1. 标签选择：soup.标签名（只拿第一个）
print(soup.h2)                        # <h2><a href="/tester/repo1">repo1</a></h2>

# 2. 方法选择：find / find_all（最常用，对应 Jsoup 的 select）
print(soup.find("a").text)            # repo1（第一个 a 的文本）
print(soup.find("a")["href"])         # /tester/repo1（属性值）
all_links = soup.find_all("a")        # [<a ...>, <a ...>]（所有 a 标签）
for a in all_links:
    print(a.text, a["href"])

# 3. CSS 选择器：select（对应 Jsoup 的 select / CSS 语法）
repos = soup.select("div.repo")       # class="repo" 的所有 div
for repo in repos:
    title = repo.select_one("h2 a").text        # select_one：第一个
    desc = repo.select_one("p.desc").text
    star = repo.select_one("span.star").text.replace("⭐ ", "")
    print(title, desc, star)
# 输出：
# repo1 第一个仓库 1234
# repo2 第二个仓库 56
```

**get_text 与嵌套**：

```python
div = soup.find("div", class_="repo")     # 注意：class_ 带下划线（class 是关键字）
print(div.text)        # repo1\n第一个仓库\n⭐ 1234（所有后代文本）
print(div.get_text(strip=True))           # 去掉首尾空白
```

### 5.4.3 完整爬虫流程（requests + BeautifulSoup 最小可用版）

```python
import requests
from bs4 import BeautifulSoup

HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/126.0"}

def fetch_repos(page: int) -> list[dict]:
    url = f"https://github.com/search?q=python&type=repositories&p={page}"
    resp = requests.get(url, headers=HEADERS, timeout=10)
    resp.raise_for_status()
    soup = BeautifulSoup(resp.text, "lxml")

    repos = []
    for box in soup.select("div[data-testid='results-list'] > div"):
        a = box.select_one("a[href*='/'] h3") or box.select_one("a h3")
        title = a.text.strip().replace("\n", " ").strip() if a else "未知"
        link = (a.parent.get("href") if a else "") or ""
        repos.append({"title": title, "url": "https://github.com" + link})
    return repos

for repo in fetch_repos(1):
    print(repo)
```

> 真实网站的 DOM 结构经常变，写爬虫的常态就是"今天能跑，明天结构变了要改选择器"。所以**选择器要写得稳健**（优先 `data-testid` 等稳定属性，别依赖层级深的 `div > div > div`）。

## 5.5 实战一：静态页爬虫——图书排行榜采集（全流程）

以"某公开图书网站"为例，演示一个完整的小爬虫（教育用途）：

```python
"""采集图书排行榜：书名 / 作者 / 价格 / 评分，存成 CSV"""
import csv
import re
import requests
from bs4 import BeautifulSoup

BASE_URL = "https://example-books-site.com/top"
HEADERS = {"User-Agent": "Mozilla/5.0 ..."}
session = requests.Session()
session.headers.update(HEADERS)

def parse_book(row) -> dict:
    a = row.select_one("h3 a")
    title = a.get_text(strip=True) if a else ""
    link = (a["href"] if a and "href" in a.attrs else "") or ""
    price_text = row.select_one("p.price").get_text(strip=True)
    price = float(re.search(r"[\d.]+", price_text).group())   # "¥45.80" → 45.8
    rating = len(row.select("i.star"))                        # 星星图标个数 → 评分
    return {"title": title, "price": price, "rating": rating, "link": link}

books = []
for page in range(1, 4):                                     # 抓前 3 页
    resp = session.get(f"{BASE_URL}?page={page}", timeout=10)
    resp.raise_for_status()
    soup = BeautifulSoup(resp.text, "lxml")
    for row in soup.select("article.book"):                  # 每本书一个 article
        books.append(parse_book(row))
    print(f"第 {page} 页完成，累计 {len(books)} 本")

# 按价格排序取前 20 本
books.sort(key=lambda b: b["price"], reverse=True)
top20 = books[:20]

# 写入 CSV（用第三章的 csv 模块）
with open("top_books.csv", "w", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=["title", "price", "rating", "link"])
    writer.writeheader()
    writer.writerows(top20)

print(f"已保存 top_books.csv，共 {len(top20)} 条")
```

**写爬虫的黄金习惯**：`time.sleep(1)` 礼貌降速 + `try/except` 容错 + 结果落盘（断点续抓的基础）。

## 5.6 反爬机制与应对（合规前提下）

### 5.6.1 常见反爬手段（知己知彼）

| 反爬手段 | 原理 | 爬虫视角 |
| --- | --- | --- |
| User-Agent 检测 | 非浏览器 UA 直接拒绝 | ✅ 伪装成浏览器 UA |
| IP 频率限制 | 同一 IP 短时间大量请求 | ✅ 降速 / 代理池 |
| Cookie/会话校验 | 要求先访问首页拿 Cookie | ✅ Session 保持 |
| 验证码（图形/滑块） | 人机验证 | ⚠️ 打码平台 / 慎用 |
| 字体反爬 | 数字用自定义字体渲染，文本抓下来是乱码 | ⚠️ 解析字体文件映射 |
| JS 动态渲染 | 数据由 JS 异步加载（接口在 Network 里） | ✅ 直接抓接口 / Playwright |
| 请求头校验（Referer/Sign） | 校验来源、签名参数 | ⚠️ 分析签名算法（灰度地带） |

### 5.6.2 面对 JS 动态渲染的网站（两种主流方案）

**方案一：直接找接口（最优，省资源）**

F12 打开开发者工具 → Network 面板 → 刷新页面 → 找 XHR/Fetch 请求 → 那个返回 JSON 的接口才是数据源头：

```python
# 页面 HTML 里没有数据，但 Network 里看到这样一个接口：
# https://api.example.com/v1/books?page=2&size=50
resp = requests.get(
    "https://api.example.com/v1/books",
    params={"page": 2, "size": 50},
    headers={"User-Agent": "Mozilla/5.0 ...", "Referer": "https://example.com/"},
    timeout=10,
)
data = resp.json()          # 直接是结构化数据，连解析都省了
for book in data["items"]:
    print(book["name"], book["price"])
```

**方案二：浏览器自动化（Playwright，对应 Java 的 Selenium）**

接口太难找 / 签名太复杂时，直接开个"无头浏览器"模拟真人操作：

```bash
pip install playwright
playwright install chromium          # 首次安装浏览器内核
```

```python
import asyncio
from playwright.async_api import async_playwright

async def grab():
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=True)          # 无头模式
        page = await browser.new_page()
        await page.goto("https://example.com/top", timeout=30000)
        await page.wait_for_selector("article.book")              # 等 JS 渲染完
        titles = await page.eval_on_selector_all(
            "article.book h3 a", "els => els.map(e => e.textContent)")
        print(titles)
        await browser.close()

asyncio.run(grab())
```

> 方案对比：**接口爬虫**速度快、资源省，但要逆向前端逻辑；**浏览器自动化**什么都能爬（包括验证码前一步），但慢、吃资源、更容易被封。原则：**能拿接口绝不渲染浏览器**。

### 5.6.3 合规红线（比技术更重要）

爬虫是"技术中立"的，但工程师必须守住边界：

1. **遵守 robots.txt**：`https://网站/robots.txt` 里明确写了哪些路径允许/禁止抓取；
2. **遵守网站 ToS（服务条款）**：条款禁止采集的不要碰；
3. **控制频率**：像正常人一样浏览（几秒一次），绝不并发轰炸；
4. **只取公开数据**：不绕过登录付费墙、不抓个人隐私信息（手机号/身份证等）；
5. **数据用途合规**：不用于二次贩卖、不侵犯著作权；
6. **法律红线**：我国《数据安全法》《个人信息保护法》《反不正当竞争法》对爬虫有明确约束，**抓取后公开传播他人数据可能违法**。

> 一句话：**技术能力 × 使用边界 = 价值；技术能力 - 边界意识 = 风险。** 本章所有示例仅用于学习，实战请以公开授权数据源为准（如 GitHub API、政府开放数据平台）。

## 5.7 并发爬虫：把速度提升 10 倍（串起第四章）

### 5.7.1 为什么爬虫天然适合并发

爬虫 90% 的时间在等网络响应（IO 密集），符合第四章的结论：**用 asyncio 或线程池**。三个 URL 串行 3 秒，并发可能只要 1 秒多。

**方案一：线程池（简单直接，适合几百个 URL）**

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import requests

URLS = [f"https://httpbin.org/delay/1?n={i}" for i in range(20)]   # 每个都延迟 1s

def fetch(url: str) -> tuple[str, int]:
    resp = requests.get(url, timeout=10)
    return url, resp.status_code

with ThreadPoolExecutor(max_workers=10) as pool:    # 10 并发
    futures = [pool.submit(fetch, u) for u in URLS]
    for fut in as_completed(futures):
        url, code = fut.result()
        print(url, code)
# 20 个任务，串行要 20s，这里只要 ~2s
```

**方案二：asyncio + aiohttp（高并发首选，上千 URL）**

```python
import asyncio
import aiohttp

async def fetch(session: aiohttp.ClientSession, url: str) -> tuple[str, int]:
    async with session.get(url, timeout=aiohttp.ClientTimeout(total=10)) as resp:
        return url, resp.status

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, f"https://httpbin.org/delay/1?n={i}") for i in range(20)]
        results = await asyncio.gather(*tasks)
        for url, code in results:
            print(url, code)

asyncio.run(main())
```

> **注意**：`requests` 是同步阻塞库，在 asyncio 里会卡住事件循环，必须用异步版 `aiohttp`（或 httpx 的异步模式）。这点与第四章"阻塞函数丢线程池"的结论一致。

### 5.7.2 并发爬虫的降速（别把自己送进黑名单）

并发 ≠ 无脑全开。真实爬虫要**限流**：

```python
import asyncio
import aiohttp

async def bounded_fetch(session, sem: asyncio.Semaphore, url: str):
    async with sem:                                # 同时最多 5 个请求
        await asyncio.sleep(0.5)                   # 每次请求间隔 0.5s（礼貌降速）
        async with session.get(url, timeout=10) as resp:
            return url, resp.status

async def main():
    sem = asyncio.Semaphore(5)
    async with aiohttp.ClientSession() as session:
        urls = [f"https://httpbin.org/delay/1?n={i}" for i in range(30)]
        tasks = [bounded_fetch(session, sem, u) for u in urls]
        for coro in asyncio.as_completed(tasks):
            url, code = await coro
            print(url, code)

asyncio.run(main())
```

## 5.8 爬虫框架：Scrapy（专业级采集利器）

对个人学习，requests + BeautifulSoup 足够；但企业级大规模采集，会用 **Scrapy**：

### 5.8.1 Scrapy 架构（一次看懂）

```
                    ┌──────────┐
    Scheduler ◄─────┤  Engine   │◄───── Spider（你写的：定义怎么解析页面）
       │ 调度队列    └────┬─────┘        │
       │                 │            下载的响应
       ▼                 ▼              │
    Downloader ──► Downloader  ──►   Pipeline（清洗/存库/去重）
    （发请求）     Middlewares           │
                  （代理/UA/重试）     ──► 输出：JSON/CSV/数据库
```

核心概念（对照 Java 生态理解）：

| Scrapy 概念 | 作用 | Java 类比 |
| --- | --- | --- |
| Spider | 定义初始 URL + 解析规则 | 你自己写的解析逻辑 |
| Item | 定义数据结构 | POJO/DTO |
| Pipeline | 清洗、去重、存储 | 消息处理链 |
| Middleware | 全局拦截（代理、UA、重试） | Spring 拦截器/过滤器 |
| Scheduler | 请求队列管理（自动去重） | 消息队列 |
| Selector | 用 CSS/XPath 提取数据 | Jsoup 选择器 |

### 5.8.2 最小 Scrapy 项目（三步）

```bash
pip install scrapy
scrapy startproject books_spider
cd books_spider
scrapy genspider books example.com/books
```

`spiders/books.py`：

```python
import scrapy

class BooksSpider(scrapy.Spider):
    name = "books"
    start_urls = ["https://example.com/books"]        # 起始 URL

    def parse(self, response):
        # response.css = CSS 选择器；response.xpath = XPath
        for book in response.css("article.book"):
            yield {
                "title": book.css("h3 a::text").get(),
                "price": book.css("p.price::text").re_first(r"[\d.]+"),
                "url": book.css("h3 a::attr(href)").get(),
            }
        # 自动翻页：找到"下一页"继续爬（Scrapy 自动调度、去重）
        next_page = response.css("a.next::attr(href)").get()
        if next_page:
            yield response.follow(next_page, self.parse)
```

运行：

```bash
scrapy crawl books -O books.json        # 结果输出到 books.json
```

> **为什么企业用 Scrapy？** 自带并发调度（Twisted 异步内核）、请求自动去重、失败重试、分布式支持（scrapy-redis）、中间件生态——相当于把第五章前面所有内容（请求、解析、并发、降速、重试）全部内置了。

## 5.9 实战二：GitHub 热门仓库采集（综合实战，串起全章）

目标：抓取 GitHub 上 Python 相关的高星仓库，**并发采集 + 解析 + 落盘**（教育用途，遵守 GitHub 公开 API 限速：未认证 60 次/小时，带 Token 5000 次/小时）。

```python
"""GitHub 热门 Python 仓库采集器（requests + asyncio + csv）"""
import asyncio
import csv
import aiohttp

GITHUB_TOKEN = ""   # 可选：填了提高限速配额（GitHub Settings → Tokens）

async def fetch_repos(session: aiohttp.ClientSession, page: int) -> list[dict]:
    url = "https://api.github.com/search/repositories"
    params = {"q": "language:python", "sort": "stars", "order": "desc", "per_page": 30, "page": page}
    headers = {"Accept": "application/vnd.github+json"}
    if GITHUB_TOKEN:
        headers["Authorization"] = f"Bearer {GITHUB_TOKEN}"
    async with session.get(url, params=params, headers=headers, timeout=15) as resp:
        resp.raise_for_status()
        data = await resp.json()
        return [
            {
                "name": item["full_name"],
                "stars": item["stargazers_count"],
                "language": item.get("language"),
                "description": (item.get("description") or "")[:80],
                "url": item["html_url"],
            }
            for item in data["items"]
        ]

async def main():
    headers = {"User-Agent": "Mozilla/5.0 (learning-crawler)"}
    async with aiohttp.ClientSession(headers=headers) as session:
        sem = asyncio.Semaphore(3)                 # 最多 3 个并发（守 GitHub 限速）

        async def limited(page: int):
            async with sem:
                return await fetch_repos(session, page)

        pages = await asyncio.gather(*[limited(p) for p in range(1, 6)])   # 抓 5 页
        repos = [r for page in pages for r in page]
        repos.sort(key=lambda r: r["stars"], reverse=True)

        with open("github_top_python.csv", "w", newline="", encoding="utf-8-sig") as f:
            writer = csv.DictWriter(f, fieldnames=["name", "stars", "language", "description", "url"])
            writer.writeheader()
            writer.writerows(repos)

        print(f"共采集 {len(repos)} 个仓库，已保存 github_top_python.csv")
        for r in repos[:10]:
            print(f"{r['stars']:>6}★ {r['name']}")

asyncio.run(main())
```

**这个实战集成了全章要点**：HTTP 请求（aiohttp）、并发控制（Semaphore）、结构化数据处理、CSV 落盘、合规限速。把它跑通，你就具备了"接口型爬虫"的完整能力。

### 面试高频题

| 问题 | 回答要点 |
| --- | --- |
| requests 和 urllib 的区别？ | urllib 是标准库、API 繁琐；requests 是第三方、自动 JSON/编码/会话，业界事实标准 |
| 为什么爬虫要设置 User-Agent？ | 服务器靠 UA 区分浏览器与脚本，裸 UA 极易被 403 拒绝 |
| GET 和 POST 有什么区别？ | GET 参数在 URL、幂等、可缓存；POST 在请求体、非幂等；数据量大/敏感用 POST |
| 如何处理响应乱码？ | 检查响应头 charset；无 charset 时手动 `resp.encoding='utf-8'` 或对 `content` 解码 |
| Session 的作用？ | 复用 Cookie 保持会话状态、复用 TCP 连接，模拟"同一个浏览器" |
| 正则贪心与非贪心？ | `*` 默认贪心匹配最远，`*?` 非贪心最近；`<b>(.*?)</b>` 取单个标签内容 |
| 为什么不建议用正则解析 HTML？ | HTML 非正则语言，嵌套/属性顺序多变，正则难维护且易错；用 BeautifulSoup/Jsoup |
| find 和 find_all、select 的区别？ | find 返回第一个标签；find_all 返回列表；select 用 CSS 选择器语法 |
| 遇到 JS 动态渲染的网站怎么办？ | 优先 F12 找 XHR 接口直取；接口不可行再用 Playwright/Selenium 渲染 |
| 爬虫被 403/封 IP 怎么办？ | 伪装 UA/Referer、降速、Session 保持 Cookie、代理池轮换 IP、重试退避 |
| 如何提升爬虫速度？ | IO 密集用 asyncio/aiohttp 或线程池；配合 Semaphore 限流防封 |
| Scrapy 核心组件？ | Spider/Item/Pipeline/Middleware/Scheduler/Selector，内置并发与去重 |
| 爬虫有哪些法律风险？ | 违反 robots.txt 与 ToS、绕过付费墙、抓取个人隐私、公开传播数据（数据安全法/个保法） |
| asyncio 里能用 requests 吗？ | 不能（阻塞事件循环）；用 aiohttp 或 httpx.AsyncClient，或 to_thread 丢线程池 |

### 本章小结

- **HTTP 基础**（5.1）：请求行/头/体、响应状态码（200/403/429）、GET vs POST；
- **requests**（5.2）：text/content/json()、Session 会话、超时/重试/代理三件套；

- **并发爬虫**（5.7）：aiohttp + Semaphore 限流，10 倍提速且不封号；
- **Scrapy**（5.8）：企业级框架，架构与并发调度一次看懂；
