## 24.2 最小知识准备：PyTorch 训练五件套

已有第 14 章机器学习基础的读者，只需把 scikit-learn 的 `fit/predict` 映射到 PyTorch 的显式训练循环：

| 概念 | scikit-learn | PyTorch |
| --- | --- | --- |
| 数据 | `X, y` (NumPy) | `Tensor` + `Dataset/DataLoader` |
| 模型 | `model.fit(X, y)` | 手写 `forward()` |
| 损失 | 内置 | `loss = criterion(pred, target)` |
| 梯度 | 自动 | `loss.backward()` |
| 更新 | 自动 | `optimizer.step()` + `optimizer.zero_grad()` |

**五件套骨架**（后面所有代码都是它的展开）：

```python
for x, y in loader:              # 1. 取 batch
    optimizer.zero_grad()        # 2. 清梯度（PyTorch 默认累积）
    logits = model(x)            # 3. 前向
    loss = F.cross_entropy(...)  # 4. 算损失
    loss.backward()              # 5. 反向传播（autograd 自动求导）
    optimizer.step()             # 6. 更新参数
```

三个必须记住的 PyTorch 细节：

1. **`zero_grad()` 不能忘**——梯度是累加的，忘了等于用越来越大的梯度更新；
2. **张量形状是第一调试手段**——LLM 代码 80% 的 bug 是维度对不上，随时 `print(t.shape)`；
3. **设备要一致**——模型和 batch 必须在同一 device，否则 `Expected all tensors to be on the same device`。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

device = "cuda" if torch.cuda.is_available() else "cpu"
print("device:", device)
```

## 24.3 Tokenizer：把文本变成整数

### 24.3.1 三种粒度

| 粒度 | 词表 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 字符级 | 几十~几百 | 简单、无 OOV、教学首选 | 序列长，语义弱 |
| 词级 | 几万~几十万 | 直观 | OOV、词表爆炸、形态变化处理差 |
| **子词 BPE / SentencePiece** | 通常 3万~15万 | 工业标准，平衡长度与语义 | 需训练，中文/代码切分不直觉 |

> 第 19 章讲过「token ≠ 字符」：中文、代码、罕见专名的 token 数不能按字数估。工业模型都用 BPE 类 tokenizer；本章用**字符级**是因为它几十行就能写完且不依赖外部库。

### 24.3.2 可运行实现

```python
# 1_tokenizer.py —— 字符级 Tokenizer
class CharTokenizer:
    def __init__(self, text: str):
        # sorted(set(...)) 保证词表可复现（顺序稳定）
        self.chars = sorted(list(set(text)))
        self.stoi = {ch: i for i, ch in enumerate(self.chars)}
        self.itos = {i: ch for i, ch in enumerate(self.chars)}
        self.vocab_size = len(self.chars)

    def encode(self, s: str) -> list[int]:
        return [self.stoi[c] for c in s]          # 生产版要处理未知字符

    def decode(self, ids: list[int]) -> str:
        return "".join(self.itos[i] for i in ids)

    def __len__(self):
        return self.vocab_size

if __name__ == "__main__":
    tok = CharTokenizer("hello 世界")
    ids = tok.encode("hello")
    print(tok.vocab_size, ids, tok.decode(ids))   # 8 [..] hello
```

> **工程提醒**：真实 tokenizer 必须持久化（词表 + 特殊 token + 归一化规则），且**训练与推理必须用同一个**。词表一变，模型权重就废了。

## 24.4 数据管线：因果语言模型的 `x / y` 错位

自回归 LM 的任务是「给定前 n 个 token，预测第 n+1 个」。所以标签就是输入**右移一位**：

```text
输入 x: [t0, t1, t2, t3, t4]
标签 y: [t1, t2, t3, t4, t5]
          ↑ 位置 i 的 logits 负责预测 y[i]
```

**不需要手写标签生成器**——在一个长度为 `block_size+1` 的片段里，`x = data[i:i+T]`，`y = data[i+1:i+T+1]` 即可，一个 batch 内同时预测所有位置。

```python
# 2_data.py —— 构建 batch
import torch

def get_batch(data: torch.Tensor, block_size: int, batch_size: int, device: str):
    # 随机起点，保证每个 batch 覆盖语料不同位置
    ix = torch.randint(len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i : i + block_size] for i in ix])
    y = torch.stack([data[i + 1 : i + 1 + block_size] for i in ix])
    return x.to(device), y.to(device)     # x,y: [B, T]
```

**数据拆分（呼应第 14 章）**：

```python
text = open("corpus.txt", encoding="utf-8").read()
tok = CharTokenizer(text)
data = torch.tensor(tok.encode(text), dtype=torch.long)

n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]     # ⚠️ 必须切分，否则无法发现过拟合
```

> ⚠️ **别用随机打乱来切分时序文本**——会泄漏。语料类任务按连续片段切（如上）；指令类任务按"样本"切，但要保证同源样本不跨集（第 25 章详述）。

**样本打包（Packing）**：工业训练会把多条短样本拼成一条长序列以提高 GPU 利用率，中间用 `<eos>` 分隔，并配合 attention mask 防止跨样本注意力。教学版为了清晰省略。

## 24.5 手写 GPT：完整可运行实现

### 24.5.1 结构总览

```text
token ids ──► Token Embedding ──┐
                                ├──► + ──► N × Transformer Block ──► LayerNorm ──► LM Head ──► logits
pos ids   ──► Pos  Embedding ──┘                                                    [B,T,V]

Block:
  x ──► LayerNorm ──► Causal Multi-Head Self-Attention ──► +残差 ──► LayerNorm ──► FFN ──► +残差
```

与第 22 章的 MoE 对照：**本章 FFN 是 Dense 的**；把这里的 FFN 换成第 22 章的 `MoELayer`，就得到一个极简 MoE-GPT。

### 24.5.2 完整代码

```python
# 3_minigpt.py —— 手写 GPT（CPU 可跑）
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd: int, n_head: int, block_size: int, dropout: float):
        super().__init__()
        assert n_embd % n_head == 0, "n_embd 必须能被 n_head 整除"
        self.n_head = n_head
        self.head_dim = n_embd // n_head

        # 一次投影出 Q/K/V，再一次输出投影（效率优于三个独立 Linear）
        self.qkv = nn.Linear(n_embd, 3 * n_embd)
        self.proj = nn.Linear(n_embd, n_embd)
        self.attn_drop = nn.Dropout(dropout)
        self.resid_drop = nn.Dropout(dropout)

        # 因果掩码：下三角为 1，保证位置 i 只能看到 <= i 的 token
        # 注册为 buffer（不参与梯度，但会随模型 .to(device) / state_dict 保存）
        self.register_buffer(
            "causal_mask",
            torch.tril(torch.ones(block_size, block_size))
                .view(1, 1, block_size, block_size),
        )

    def forward(self, x):
        B, T, C = x.shape                       # batch, 序列长, 通道数
        qkv = self.qkv(x)                       # [B, T, 3C]
        q, k, v = qkv.split(C, dim=2)           # 各 [B, T, C]

        # 拆成多头: [B, T, C] -> [B, n_head, T, head_dim]
        def split_heads(t):
            return t.view(B, T, self.n_head, self.head_dim).transpose(1, 2)

        q, k, v = split_heads(q), split_heads(k), split_heads(v)

        # 缩放点积注意力: [B, h, T, T]
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        att = att.masked_fill(
            self.causal_mask[:, :, :T, :T] == 0, float("-inf")
        )
        att = F.softmax(att, dim=-1)
        att = self.attn_drop(att)

        y = att @ v                             # [B, h, T, head_dim]
        y = y.transpose(1, 2).contiguous().view(B, T, C)   # 合并多头
        return self.resid_drop(self.proj(y))


class Block(nn.Module):
    """Pre-LN Transformer Block：LN 在子层之前，训练更稳"""
    def __init__(self, n_embd, n_head, block_size, dropout):
        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = CausalSelfAttention(n_embd, n_head, block_size, dropout)
        self.ln2 = nn.LayerNorm(n_embd)
        self.ffn = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),      # ← 这里换成 MoELayer 就是 MoE-GPT
            nn.GELU(),
            nn.Linear(4 * n_embd, n_embd),
            nn.Dropout(dropout),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))          # 残差连接
        x = x + self.ffn(self.ln2(x))
        return x


class MiniGPT(nn.Module):
    def __init__(self, vocab_size, block_size=128, n_embd=128,
                 n_head=4, n_layer=4, dropout=0.1):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, n_embd)
        self.pos_emb = nn.Embedding(block_size, n_embd)
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.ModuleList(
            [Block(n_embd, n_head, block_size, dropout) for _ in range(n_layer)]
        )
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)

        # 权重共享（tie weights）：输入 embedding 与输出分类头共用，省参数且常更好
        self.lm_head.weight = self.tok_emb.weight
        self.apply(self._init_weights)

    def _init_weights(self, m):
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        assert T <= self.block_size, f"序列长 {T} 超过 block_size {self.block_size}"

        pos = torch.arange(T, device=idx.device)
        x = self.drop(self.tok_emb(idx) + self.pos_emb(pos))   # [B, T, C]
        for blk in self.blocks:
            x = blk(x)
        logits = self.lm_head(self.ln_f(x))                    # [B, T, V]

        loss = None
        if targets is not None:
            # cross_entropy 需要 [N, C] 与 [N]，所以展平前两维
            loss = F.cross_entropy(
                logits.view(-1, logits.size(-1)), targets.reshape(-1)
            )
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
        """自回归采样（呼应第 19 章的 temperature / top-p）"""
        for _ in range(max_new_tokens):
            cond = idx[:, -self.block_size:]      # 裁剪到上下文窗口内
            logits, _ = self(cond)
            logits = logits[:, -1, :] / max(temperature, 1e-8)
            if top_k is not None:
                v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
                logits[logits < v[:, [-1]]] = float("-inf")
            probs = F.softmax(logits, dim=-1)
            nxt = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, nxt], dim=1)
        return idx
```

### 24.5.3 三个最容易写错的地方

| 位置 | 常见错误 | 后果 |
| --- | --- | --- |
| **因果 mask** | 忘了 mask 或用 `triu` | 模型"偷看"未来 token，训练 loss 虚低，生成时完全崩 |
| **缩放** | 忘除以 `sqrt(head_dim)` | softmax 饱和、梯度消失 |
| **`view` 前 `contiguous()`** | transpose 后直接 view | 运行时报错；或更糟——形状对但语义错 |

> **调试口诀**：先用一个 `B=1, T=4` 的小 batch 单步跑通 forward + backward，再放大规模。形状对了，逻辑基本就对了。

### 24.5.4 参数量估算（呼应第 23 章显存公式）

```python
def count_params(model):
    return sum(p.numel() for p in model.parameters())

# 试一下
model = MiniGPT(vocab_size=100, block_size=128, n_embd=128, n_head=4, n_layer=4)
print(f"参数量: {count_params(model)/1e6:.2f}M")
```

主要参数来自：Embedding `V×C`、每 Block 的 `4C²`（QKV+proj）+ `8C²`（FFN）≈ `12C²·L`。**把 `n_embd` 翻倍，参数量约变 4 倍**——这就是第 22 章说的算力墙。

## 24.6 训练循环：从 loss 到 checkpoint

```python
# 4_train.py —— 完整训练脚本（CPU 可跑，GPU 更快）
import math, os, time, torch
from minigpt import MiniGPT          # 3_minigpt.py
from tokenizer import CharTokenizer  # 1_tokenizer.py
from data import get_batch           # 2_data.py

# ---------- 可复现（第 9 章工程化习惯）----------
SEED = 1337
torch.manual_seed(SEED)

device = "cuda" if torch.cuda.is_available() else "cpu"

# ---------- 超参 ----------
BLOCK_SIZE   = 128
BATCH_SIZE   = 32
N_EMBD       = 128
N_HEAD       = 4
N_LAYER      = 4
DROPOUT      = 0.1
MAX_ITERS    = 2000          # CPU 建议先 500 看效果
EVAL_INTERVAL= 200
EVAL_ITERS   = 50
LR           = 3e-4
WARMUP_ITERS = 100
MIN_LR       = 3e-5
GRAD_CLIP    = 1.0
OUT_DIR      = "ckpt"
os.makedirs(OUT_DIR, exist_ok=True)

# ---------- 数据 ----------
text = open("corpus.txt", encoding="utf-8").read()
tok = CharTokenizer(text)
data = torch.tensor(tok.encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]
print(f"语料 {len(text)} 字符 | 词表 {len(tok)} | 训练 {n} tokens")

model = MiniGPT(
    vocab_size=len(tok), block_size=BLOCK_SIZE,
    n_embd=N_EMBD, n_head=N_HEAD, n_layer=N_LAYER, dropout=DROPOUT,
).to(device)
print(f"参数量 {sum(p.numel() for p in model.parameters())/1e6:.2f}M")

# ---------- 优化器 ----------
# AdamW：权重衰减与梯度解耦，LLM 训练事实标准
optimizer = torch.optim.AdamW(
    model.parameters(), lr=LR, betas=(0.9, 0.95), weight_decay=0.1
)

def lr_at(it):
    """warmup + 余弦衰减（工业训练标配）"""
    if it < WARMUP_ITERS:
        return LR * (it + 1) / WARMUP_ITERS
    if it >= MAX_ITERS:
        return MIN_LR
    r = (it - WARMUP_ITERS) / (MAX_ITERS - WARMUP_ITERS)
    return MIN_LR + 0.5 * (LR - MIN_LR) * (1 + math.cos(math.pi * r))

@torch.no_grad()
def estimate_loss():
    model.eval()
    out = {}
    for split, d in [("train", train_data), ("val", val_data)]:
        losses = torch.zeros(EVAL_ITERS)
        for k in range(EVAL_ITERS):
            x, y = get_batch(d, BLOCK_SIZE, BATCH_SIZE, device)
            _, loss = model(x, y)
            losses[k] = loss.item()
        out[split] = losses.mean().item()
    model.train()
    return out

# ---------- 混合精度（GPU 有效；CPU 自动退化）----------
scaler = torch.amp.GradScaler("cuda", enabled=(device == "cuda"))
amp_dtype = torch.bfloat16 if (device == "cuda" and torch.cuda.is_bf16_supported()) else torch.float16

t0 = time.time()
model.train()
for it in range(MAX_ITERS + 1):
    lr = lr_at(it)
    for g in optimizer.param_groups:
        g["lr"] = lr

    if it % EVAL_INTERVAL == 0:
        losses = estimate_loss()
        print(f"iter {it:5d} | train {losses['train']:.4f} "
              f"| val {losses['val']:.4f} | ppl {math.exp(losses['val']):.2f} "
              f"| lr {lr:.2e} | {time.time()-t0:.0f}s")
        torch.save({
            "model": model.state_dict(),
            "optimizer": optimizer.state_dict(),
            "iter": it,
            "val_loss": losses["val"],
            "config": dict(vocab_size=len(tok), block_size=BLOCK_SIZE,
                           n_embd=N_EMBD, n_head=N_HEAD,
                           n_layer=N_LAYER, dropout=DROPOUT),
            "chars": tok.chars,          # ⚠️ tokenizer 必须一起存
        }, f"{OUT_DIR}/ckpt_{it:05d}.pt")

    x, y = get_batch(train_data, BLOCK_SIZE, BATCH_SIZE, device)
    with torch.amp.autocast(device_type=device, dtype=amp_dtype,
                            enabled=(device == "cuda")):
        _, loss = model(x, y)

    optimizer.zero_grad(set_to_none=True)
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), GRAD_CLIP)  # 防梯度爆炸
    scaler.step(optimizer)
    scaler.update()

print("训练完成，最优 checkpoint 见", OUT_DIR)
```

### 24.6.1 每个组件为什么存在

| 组件 | 作用 | 不加会怎样 |
| --- | --- | --- |
| **AdamW + betas=(0.9,0.95)** | 自适应学习率，LLM 常用配置 | 收敛慢/不稳 |
| **Warmup** | 起步用小 lr，避免初始大梯度炸掉 | 早期 loss 尖峰、NaN |
| **余弦衰减** | 后期小 lr 精细收敛 | 末期震荡 |
| **梯度裁剪 1.0** | 限制梯度范数 | Transformer 深层易梯度爆炸 |
| **混合精度 bf16/fp16** | 省显存、提速 | 显存翻倍、速度减半 |
| **GradScaler** | fp16 下防下溢（bf16 可省略） | fp16 梯度变 0 |
| **梯度累积**（下面） | 小显存模拟大 batch | batch 太小、梯度噪声大 |
| **checkpoint 含 optimizer/iter/config/chars** | 断点续训 + 可复现 | 中断即从头，且无法正确加载 |

```python
# 梯度累积：每 ACCUM 步才真正更新一次（等效 batch = BATCH_SIZE * ACCUM）
ACCUM = 4
for i, (x, y) in enumerate(loader):
    _, loss = model(x, y)
    (loss / ACCUM).backward()          # ⚠️ 要除以累积步数
    if (i + 1) % ACCUM == 0:
        optimizer.step(); optimizer.zero_grad()
```

> **⚠️ 训练显存 ≠ 推理显存**（呼应第 23 章 23.5.1）：推理只需权重 + KV Cache；全量训练还要存**梯度（≈权重×1）+ AdamW 优化器状态（≈权重×2）+ 激活值**，粗略是权重的 **4~8 倍**。7B 模型 BF16 全量训练需要上百 GB 显存，这就是第 25 章 LoRA 存在的理由。

## 24.8 评估：怎么知道"训好了"

| 指标 | 计算 | 判读 |
| --- | --- | --- |
| **train loss / val loss** | cross entropy | 两者都降 = 在学；train 降 val 升 = **过拟合** |
| **Perplexity (PPL)** | `exp(val_loss)` | 越低越好；可粗略理解为"平均在多少个候选里犹豫" |
| 生成人工抽查 | 看 20 条样本 | 重复、乱码、永远不结束都是典型问题 |

```python
print(f"val loss {v:.4f} -> PPL {math.exp(v):.2f}")
```

**过拟合对策**（第 14 章已建立概念）：加数据、加 dropout、减模型/训练步数、weight decay、早停（保存 val loss 最优的 checkpoint）。

> ⚠️ **训练集 loss 一直降不代表模型有用**。第 16 章的 Golden Set 思想在这里同样适用：最终要用**与目标任务匹配的独立评测集**判断，而不是看 loss 曲线自我感觉良好。

## 24.9 从教学模型到真实大模型：中间隔着什么

### 24.9.1 规模差距有多大

| 维度 | 本章 MiniGPT | 真实 7B 模型 | 差距 |
| --- | --- | --- | --- |
| 参数量 | ~1M | 7,000M | ~7000× |
| 训练 token | ~1M 字符 | 数万亿 token | ~10⁶× |
| 算力 | 笔记本几分钟 | 数千 GPU × 数月 | — |
| 词表 | 几十（字符） | 3万~15万（BPE） | — |
| 上下文 | 128 | 4K~128K+ | — |
| 数据治理 | 一个 txt | 采集/清洗/去重/过滤/合规全流水线 | — |

### 24.9.2 工业预训练流水线

```text
① 数据：多源采集 → 许可审查 → 语言识别 → 质量过滤 → MinHash/SimHash 去重
         → 隐私/PII 清除 → 毒性过滤 → 数据配比（代码/多语/书籍…）→ 去污染（去掉评测集）
② Tokenizer：在代表性语料上训 BPE → 固定词表与特殊 token
③ 训练：分布式并行（DP/TP/PP/EP + ZeRO/FSDP）→ bf16 混合精度
         → 梯度累积/检查点 → 故障自动恢复 → loss 尖峰检测与回滚
④ 中期：上下文扩展（长文本阶段）、高质量数据退火（annealing）
⑤ 后训练：SFT → 偏好对齐（DPO/RLHF）→ 安全红队 → 评测   ← 第 25 章
⑥ 发布：量化、推理服务、监控、模型卡与许可证           ← 第 23 章
```

### 24.9.3 Scaling Law 与 Chinchilla

早期经验法则认为"参数越多越好"，后续研究（Chinchilla 等）指出：**给定算力预算，参数量与训练 token 数应同步增长**，很多大模型其实「训得不够久」。粗略结论：

\[
N_{opt} \propto C^{0.5},\quad D_{opt} \propto C^{0.5}
\]

其中 \(C\) 是算力、\(N\) 参数量、\(D\) 训练 token 数。实践含义：**别只堆参数，数据量和质量同等重要**；也解释了为什么后来出现了更小但训得更充分的模型。

> 这也和第 22 章呼应：MoE 用稀疏激活把「总参数」和「每 token 计算量」解耦，是在同一算力约束下换一种扩展方式。

### 24.9.4 分布式训练四种并行

| 并行 | 切什么 | 解决 |
| --- | --- | --- |
| **DP / DDP** | 数据（每卡一份完整模型） | 吞吐 |
| **TP（Tensor Parallel）** | 单层矩阵按列/行切 | 单层放不下 |
| **PP（Pipeline Parallel）** | 层按段切到不同卡 | 模型太深 |
| **EP（Expert Parallel）** | MoE 专家切到不同卡 | 呼应第 22 章 |
| **ZeRO / FSDP** | 优化器状态/梯度/参数分片 | 显存不够（最重要） |

通信瓶颈：TP 需 All-Reduce、EP 需 All-to-All（第 22 章），所以多机训练必须有 NVLink / InfiniBand。

### 24.9.5 成本粗算（建立量级感）

训练算力近似：\(C \approx 6 \times N \times D\)（FLOPs，\(N\) 参数量、\(D\) token 数）。

```python
# 6_cost_estimate.py —— 量级估算（不是报价）
def train_days(params_b, tokens_t, gpu_tflops=400, mfu=0.4, gpus=8):
    """mfu: Model FLOPs Utilization，实际有效算力占比，工业界常 0.3~0.5"""
    C = 6 * params_b * 1e9 * tokens_t * 1e12
    effective = gpu_tflops * 1e12 * mfu * gpus
    return C / effective / 86400

for n, d in [(0.001, 0.000001), (0.1, 0.002), (7, 1), (7, 14)]:
    print(f"{n}B 参数 / {d}T tokens / 8 卡 ≈ {train_days(n, d):.2f} 天")
```

> 输出会让你直观看到：7B / 1T tokens 在 8 张卡上已是**数十天量级**，这还不含数据工程、失败重试、实验调参和评测。**这就是"个人不要从零训基础模型"的量化理由**。

### 24.9.6 现实的三种可行路径

| 路径 | 适合 | 说明 |
| --- | --- | --- |
| **教学模型从零训** | 学原理 | 本章，个人完全可行 ⭐ |
| **小模型继续预训练** | 垂域（法律/医学/代码） | 取开源小模型 + 领域语料，成本可控，但需防灾难性遗忘 |
| **微调 / 对齐** | 让模型听指令、懂业务 | **第 25 章，投入产出比最高** ⭐⭐ |
| 从零训有竞争力的基础模型 | 团队级 | 需算力、数据、评测、工程全栈，个人不可行 |

## 24.11 常见踩坑

| 坑 | 症状 | 解决 |
| --- | --- | --- |
| **忘因果 mask** | train loss 极低但生成全是乱码 | 检查 `tril` + `masked_fill(-inf)` |
| 忘 `zero_grad()` | loss 不降甚至爆炸 | 每步开头清梯度 |
| 忘缩放 `sqrt(d)` | 收敛极慢 | 注意力除以 `sqrt(head_dim)` |
| transpose 后直接 `view` | 运行时错误 | `.contiguous().view(...)` |
| cross_entropy 维度不对 | 报 shape 错 | 展平成 `[B*T, V]` 与 `[B*T]` |
| 序列超 `block_size` | 位置 embedding 越界 | `generate` 里裁剪 `idx[:, -T:]` |
| 词表/tokenizer 没存 | 加载后生成乱码 | checkpoint 一起存 chars + config |
| 没切验证集 | 无法发现过拟合 | 按 9:1 连续切分 |
| fp16 下 loss 变 NaN | 梯度下溢/上溢 | 用 bf16，或 `GradScaler` + 梯度裁剪 |
| CPU 上照抄大规模超参 | 跑到天荒地老 | 先 500 iter / 小 `n_embd` 验证流程 |
| 语料太小还训很久 | val loss 反弹、生成复读 | 加数据 / 早停 / 加 dropout |
| 以为训完就能对话 | 问它问题它继续编文本 | 预训练模型不会指令跟随 → 第 25 章 SFT |

## 24.12 面试高频问题

**Q1. 因果语言模型的标签怎么构造？为什么不需要单独标注？**

A：标签就是输入右移一位（`y[i] = x[i+1]`），在一个长度为 `T+1` 的片段里取 `x=data[i:i+T]`、`y=data[i+1:i+T+1]`。因为语料本身就是监督信号（自监督），所以无需人工标注；每个位置同时预测下一个 token，一个 batch 内产生 B×T 个训练信号。

**Q2. 为什么注意力要除以 \(\sqrt{d_k}\)？**

A：点积 \(q·k\) 的方差随维度 \(d_k\) 线性增长，不缩放会让 softmax 进入饱和区、梯度极小。除以 \(\sqrt{d_k}\) 把方差稳定在 1 附近，训练才稳定。

**Q3. 因果掩码为什么必须是下三角？**

A：自回归生成时位置 i 只能依赖 i 及之前的信息。若不 mask，训练时模型能"看见"答案，loss 会异常低但生成时完全没有这种信息，导致训练/推理分布不一致、生成崩溃。这是最经典的实现 bug。

**Q4. Pre-LN 和 Post-LN 有什么区别？**

A：Pre-LN 把 LayerNorm 放在子层之前（本章），残差路径是干净的恒等映射，梯度更稳、通常不需要 warmup 也能训深层；Post-LN 放在之后，原始 Transformer 论文用法，表达力略强但对 lr/warmup 更敏感。现代 LLM 普遍用 Pre-LN（或 RMSNorm 变体）。

**Q5. 全量训练显存为什么比推理大那么多？**

A：推理只需权重 + KV Cache + 少量激活；训练还要保存梯度（≈权重）、AdamW 的一阶/二阶动量（≈2×权重）、以及反向传播所需的全部激活值，总计约为权重的 4~8 倍（还随 batch/序列长增长）。这正是 LoRA/QLoRA 与 FSDP/ZeRO 存在的原因。

**Q6. Scaling Law / Chinchilla 结论是什么？实践含义？**

A：给定算力预算，最优参数量 \(N\) 与训练 token 数 \(D\) 应大致同步增长（都 \(\propto \sqrt{C}\)）。很多早期模型参数偏大但训练数据不足（under-trained）。含义是**别只堆参数，数据规模与质量同等关键**，也解释了"小模型训得更久能超越大模型"。

**Q7. 为什么权重共享（tied embeddings）？**

A：输入 token embedding 与输出 LM head 共享同一矩阵，能显著减少参数（尤其词表大时），并在实践中常带来轻微质量提升，因为输入/输出的 token 表示空间被约束为一致。

**Q8. 训练 loss 一直降，模型就一定变好了吗？**

A：不一定。要看验证集 loss/PPL 发现过拟合，更要用与任务匹配的独立评测集（第 16 章 Golden Set）判断实用能力；还要防数据污染（评测集混进训练语料）。生成质量必须人工抽查。
