## 8.1 自动化脚本的定位：把"重复劳动"交给代码

运维/开发日常的重复工作（清日志、备份、批量改文件名、定时拉数据）都适合写成 Python 脚本。**一条脚本 = 一个可重复执行、可定时触发、可交接的"自动化资产"**。

| 场景 | 手工成本 | 脚本后 |
| --- | --- | --- |
| 每天清理超过 7 天的日志 | 5 分钟 × 365 天 | 定时任务 1 秒跑完 |
| 批量重命名 1000 个文件 | 1 小时 | 1 秒 |
| 每周备份数据库 | 手动导出+传服务器 | 定时自动完成 |
| 每月生成报表 | 打开 Excel 折腾半天 | 脚本 + Pandas 秒出 |

**写好脚本的三个工程标准**：① 可重复（幂等，跑两遍结果一致）；② 可配置（参数/配置分离，不硬编码）；③ 有日志与容错（出错了能追溯、能重试）。

## 8.2 文件批量处理：pathlib + shutil 实战

### 8.2.1 批量重命名（对标 Files.move）

```python
from pathlib import Path

# 把目录下所有 .txt 改为 .md
folder = Path("docs")
for f in folder.glob("*.txt"):
    f.rename(f.with_suffix(".md"))

# 批量加前缀（如按日期归档）
import datetime
today = datetime.date.today().isoformat()
for f in folder.glob("*.log"):
    f.rename(f.parent / f"{today}_{f.name}")
```

### 8.2.2 遍历与统计（递归处理）

```python
from pathlib import Path

folder = Path(".")   # 当前目录（可用绝对路径）

# 递归找所有 .py 文件
for f in folder.rglob("*.py"):
    print(f)

# 统计各类文件数量与总大小
from collections import Counter
sizes = Counter()
counts = Counter()
for f in folder.rglob("*"):
    if f.is_file():
        counts[f.suffix or "(无后缀)"] += 1
        sizes[f.suffix or "(无后缀)"] += f.stat().st_size
for ext, n in counts.most_common():
    print(f"{ext}: {n} 个，{sizes[ext]/1024:.1f} KB")

# 找出超大文件（>100MB）
big = [f for f in folder.rglob("*") if f.is_file() and f.stat().st_size > 100 * 1024**2]
```

### 8.2.3 移动/复制/删除（对标 shutil ≈ commons-io）

```python
import shutil
from pathlib import Path

src = Path("data/old_file.csv")
dst = Path("archive/2026/file.csv")

shutil.copy2(src, dst)              # 复制（保留时间戳等元数据）
# shutil.copy(src, dst)             # 只复制内容
# shutil.move(src, dst)             # 移动/重命名
# shutil.rmtree(Path("tmp_dir"))    # 递归删除目录（危险！谨慎用）

# 安全删除：先移动到回收站式"待删除"目录，确认后再删
trash = Path("trash")
trash.mkdir(exist_ok=True)
shutil.move(str(src), str(trash / src.name))
```

> **工程习惯**：删除文件/目录**永远先确认**。生产脚本宁可"移入归档目录"也不直接 `unlink`/`rmtree`。

## 8.3 调用系统命令：subprocess（对标 ProcessBuilder）

### 8.3.1 基本用法

```python
import subprocess

# 1. 执行命令并等待完成，获取输出（最常用）
result = subprocess.run(
    ["dir"],                       # Windows；Linux/Mac 用 ["ls", "-l"]
    capture_output=True,           # 捕获 stdout/stderr（不回显到终端）
    text=True,                     # 输出转成 str（默认 bytes）
    encoding="utf-8",
    check=False,                   # True 则命令失败抛 CalledProcessError
    shell=True,                    # Windows 下 dir/echo 等内建命令需要
)
print("返回码:", result.returncode)      # 0 成功，非 0 失败
print("标准输出:", result.stdout[:200])
print("错误输出:", result.stderr)

# 2. 需要交互/长时间运行：用 Popen（不阻塞等待）
proc = subprocess.Popen(["ping", "127.0.0.1"], stdout=subprocess.PIPE, text=True)
for line in proc.stdout:                    # 逐行实时读取
    print(line.strip())
proc.wait()                                 # 等进程结束
```

### 8.3.2 实战：批量压缩文件（调用系统 zip/7z）

```python
import subprocess
from pathlib import Path

def zip_folder(folder: Path, output: str) -> bool:
    """调用系统 tar/7z 压缩目录（比 Python zipfile 对大目录更快）"""
    cmd = ["tar", "-czf", output, str(folder)]
    result = subprocess.run(cmd, capture_output=True, text=True)
    if result.returncode != 0:
        print(f"压缩失败: {result.stderr}")
        return False
    print(f"已压缩: {output} ({Path(output).stat().st_size/1024:.0f} KB)")
    return True
```

> **对比 Java**：`subprocess.run` ≈ `ProcessBuilder` + `waitFor()` + 读取输出流；`Popen` ≈ 不 `wait` 的异步进程。**注意**：永远传参数列表（`["ls", "-l"]`）而不是拼字符串，避免注入与转义问题（对应 Java 不推荐 `Runtime.exec(cmdString)`）。

## 8.4 定时任务：让脚本自己"到点上班"

### 8.4.1 方案对比

| 方案 | 平台 | 适合 |
| --- | --- | --- |
| Windows 任务计划程序 / Linux cron | 系统级 | **生产环境首选**，可靠、可审计 |
| `schedule` 库（Python 内） | 跨平台 | 脚本内自带的轻量调度（需进程常驻） |
| APScheduler | 跨平台 | 复杂调度（cron 表达式、持久化、多任务） |
| Docker + cron / K8s CronJob | 容器 | 容器化部署的定时任务 |

**原则：系统定时器（cron/任务计划）优先**——不依赖脚本常驻、重启自动恢复、日志由系统管理。

### 8.4.2 Linux cron（服务器标准）

```bash
# crontab -e 编辑；格式：分 时 日 月 周 命令
0 2 * * *  /usr/bin/python3 /opt/scripts/backup.py >> /var/log/backup.log 2>&1
#        ↑ 每天凌晨 2:00 执行；输出追加到日志
# 常用示例：
*/5 * * * *    # 每 5 分钟
0 9 * * 1-5    # 工作日 9 点
0 0 1 * *      # 每月 1 号凌晨
```

### 8.4.3 Windows 任务计划（PowerShell 注册）

```powershell
# 注册每天凌晨 2 点运行脚本
$action  = New-ScheduledTaskAction -Execute "python" -Argument "D:\scripts\backup.py"
$trigger = New-ScheduledTaskTrigger -Daily -At 02:00
Register-ScheduledTask -TaskName "DailyBackup" -Action $action -Trigger $trigger
```

### 8.4.4 Python 内 schedule 库（脚本自调度）

```python
# pip install schedule
import schedule
import time

def job():
    print("执行备份任务...")

schedule.every().day.at("02:00").do(job)          # 每天 2 点
schedule.every(30).minutes.do(job)                # 每 30 分钟
schedule.every().hour.do(job)                     # 每小时
schedule.every().monday.at("09:30").do(job)       # 每周一 9:30

while True:                      # 脚本需常驻（不能退出）
    schedule.run_pending()
    time.sleep(1)
```

> **APScheduler**（需要 cron 表达式/多任务/持久化时升级）：
> ```python
> from apscheduler.schedulers.blocking import BlockingScheduler
> sched = BlockingScheduler()
> sched.add_job(job, "cron", hour=2, minute=0)
> sched.start()
> ```

### 8.5.2 click：更优雅的第三方方案（对标 picocli）

```bash

```

```python
# cleaner.py
import click

@click.command()
@click.option("--dir", required=True, help="目标目录")           # 对应 argparse --dir
@click.option("--days", default=7, type=int, help="保留天数")
@click.option("--dry-run", is_flag=True, help="演练模式")
@click.argument("output", required=False)                        # 位置参数（不加 --）
def clean(dir, days, dry_run, output):
    """删除指定目录下超过 N 天的文件（自动化的瑞士军刀）"""
    click.echo(f"清理 {dir}，保留 {days} 天，dry-run={dry_run}")
    if output:
        click.echo(f"报告输出到: {output}")

if __name__ == "__main__":
    clean()
```

```bash
python cleaner.py --dir /data/logs --days 7 --dry-run
```

**对比 Java**：argparse/click 对应 **picocli**（`@Command` + `@Option` 注解）。Python 是装饰器/声明式，Java 是注解式，理念一致。

## 8.6 脚本的日志与容错：让脚本"会说话"

### 8.6.1 日志规范（对接第三章 logging）

```python
import logging
from logging.handlers import RotatingFileHandler

logger = logging.getLogger("backup")
logger.setLevel(logging.INFO)

# 同时输出到控制台 + 文件（文件 5MB 轮转，保留 3 份）
console = logging.StreamHandler()
file_handler = RotatingFileHandler("backup.log", maxBytes=5 * 1024 * 1024, backupCount=3)
fmt = logging.Formatter("%(asctime)s %(levelname)s %(message)s")
console.setFormatter(fmt); file_handler.setFormatter(fmt)
logger.addHandler(console); logger.addHandler(file_handler)

logger.info("任务开始")
logger.warning("磁盘剩余空间不足 20%")
logger.error("备份失败，稍后重试")
```

### 8.6.2 容错与重试（生产脚本必备）

```python
import time

def run_with_retry(fn, retries: int = 3, delay: float = 2.0):
    """通用重试包装：失败最多重试 retries 次"""
    for attempt in range(1, retries + 1):
        try:
            return fn()
        except Exception as e:
            logger.warning(f"第 {attempt} 次尝试失败: {e}")
            if attempt == retries:
                raise                    # 最后仍失败则抛出（由调用方处理/告警）
            time.sleep(delay * attempt)  # 指数退避

# 用法
def do_backup():
    subprocess.run(["backup_cmd"], check=True)

run_with_retry(do_backup, retries=3)
```

**兜底原则**：`main()` 包 try/except → 出错记日志 + 非零退出码（cron 才能感知失败）：

```python
def main():
    ...   # 业务逻辑

if __name__ == "__main__":
    try:
        main()
    except Exception:
        logger.exception("脚本异常退出")     # exception() 会带完整堆栈
        raise SystemExit(1)                  # 非零退出码，让 cron 感知失败并告警
```

## 8.7 实战：日志自动归档清理 + 数据库备份（综合实战）

把全章串成一个可直接用于生产（Linux cron / Windows 任务计划）的完整脚本：

```python
"""auto_cleanup.py —— 日志归档清理 + 数据库备份工具

用法示例：
  python auto_cleanup.py --dir /data/app/logs --days 7 --backup-db daily --dry-run
  python auto_cleanup.py --dir D:\\logs --days 14
"""
import argparse
import logging
import shutil
import subprocess
import time
import zipfile
from datetime import datetime, timedelta
from logging.handlers import RotatingFileHandler
from pathlib import Path

# ─── 日志 ───
logger = logging.getLogger("cleanup")
logger.setLevel(logging.INFO)
_fh = RotatingFileHandler("cleanup.log", maxBytes=5 * 1024 * 1024, backupCount=3)
_fh.setFormatter(logging.Formatter("%(asctime)s %(levelname)s %(message)s"))
logger.addHandler(_fh)

# ─── 参数（argparse）───
parser = argparse.ArgumentParser(description="日志归档清理与数据库备份")
parser.add_argument("--dir", required=True, help="待清理的日志目录")
parser.add_argument("--days", type=int, default=7, help="保留天数，默认 7 天")
parser.add_argument("--backup-db", choices=["daily", "weekly", "none"], default="none",
                    help="是否备份数据库")
parser.add_argument("--dry-run", action="store_true", help="演练模式：只打印不执行")
args = parser.parse_args()

def is_old(path: Path, days: int) -> bool:
    """判断文件修改时间是否超过 days 天"""
    mtime = datetime.fromtimestamp(path.stat().st_mtime)
    return mtime < datetime.now() - timedelta(days=days)

def archive_and_clean(log_dir: Path, days: int, dry_run: bool) -> int:
    """超过 N 天的 .log 文件先压缩归档再删除，返回处理数量"""
    archive_dir = log_dir / "archive"
    count = 0
    for f in log_dir.glob("*.log"):
        if not is_old(f, days):
            continue
        if dry_run:
            logger.info(f"[演练] 将归档: {f.name}")
            count += 1
            continue
        archive_dir.mkdir(exist_ok=True)
        zpath = archive_dir / f"{f.stem}_{f.stat().st_mtime:.0f}.zip"
        with zipfile.ZipFile(zpath, "w", zipfile.ZIP_DEFLATED) as zf:
            zf.write(f, arcname=f.name)          # 归档
        f.unlink()                                # 再删除（先归档后删，安全）
        logger.info(f"已归档并删除: {f.name} -> {zpath.name}")
        count += 1
    return count

def backup_database(dry_run: bool):
    """调用 mysqldump 备份数据库（演示：实际库名/密码从环境变量读）"""
    import os
    db = os.getenv("DB_NAME", "app_db")
    out = Path("backup") / f"{db}_{datetime.now():%Y%m%d_%H%M%S}.sql"
    out.parent.mkdir(exist_ok=True)
    cmd = ["mysqldump", "-u", os.getenv("DB_USER", "root"), "-p" + os.getenv("DB_PASSWORD", ""), db]
    if dry_run:
        logger.info(f"[演练] 将执行: {' '.join(cmd)} > {out}")
        return
    with open(out, "w", encoding="utf-8") as f:
        result = subprocess.run(cmd, stdout=f, stderr=subprocess.PIPE, text=True)
    if result.returncode == 0:
        logger.info(f"数据库备份成功: {out} ({out.stat().st_size/1024:.0f} KB)")
    else:
        logger.error(f"数据库备份失败: {result.stderr}")

def main():
    log_dir = Path(args.dir)
    if not log_dir.is_dir():
        logger.error(f"目录不存在: {log_dir}")
        raise SystemExit(2)                      # 参数错误退出码 2

    logger.info(f"开始清理 {log_dir}，保留 {args.days} 天，dry-run={args.dry_run}")
    n = archive_and_clean(log_dir, args.days, args.dry_run)
    logger.info(f"本次处理 {n} 个日志文件")

    if args.backup_db != "none":
        backup_database(args.dry_run)

if __name__ == "__main__":
    try:
        main()
    except Exception:
        logger.exception("脚本异常退出")
        raise SystemExit(1)
```

**挂到定时任务（Linux cron）**：

```bash
# 每天凌晨 3 点执行，保留 7 天日志 + 每日数据库备份
0 3 * * * cd /opt/scripts && /usr/bin/python3 auto_cleanup.py \
    --dir /data/app/logs --days 7 --backup-db daily >> cleanup.log 2>&1
```

**这个实战集成了全章要点**：argparse 参数化、pathlib 批处理、zipfile 归档、subprocess 调 mysqldump、logging 轮转日志、dry-run 演练模式、异常兜底 + 退出码——一个可交接给运维的"生产级脚本"。

### 面试高频题

| 问题 | 回答要点 |
| --- | --- |
| 为什么用 pathlib 不用 os.path？ | pathlib 面向对象、/ 拼接、parent/glob 更优雅；官方推荐 |
| shutil 有什么用？ | 复制（copy2 保留元数据）、移动、递归删目录；对标 commons-io |
| subprocess 注意什么？ | 传参数列表不拼字符串（防注入）；check=True 失败抛异常；text=True 转字符串 |
| 定时任务怎么做？ | 生产用 cron/Windows 任务计划（系统管）；脚本内轻量用 schedule；复杂用 APScheduler |
| cron 表达式怎么写？ | 分 时 日 月 周；`0 2 * * *` 每天 2 点；`*/5` 每 5 分钟 |
| argparse 和 click 区别？ | argparse 标准库零依赖；click 装饰器风格更简洁、交互更友好 |
| 脚本参数怎么设计？ | 必填用 required；默认值给安全值；加 --dry-run 演练模式是工程好习惯 |
| 敏感信息放哪？ | 环境变量 / .env 文件，绝不硬编码密码；代码仓库里只放占位符 |
| 日志怎么配置？ | RotatingFileHandler 轮转防日志撑爆；同时输出控制台+文件；级别 info 起 |
| 失败怎么让上层感知？ | 非零退出码（SystemExit(1)）；cron 靠退出码 + 日志；生产可接告警 |
| 删除文件的安全姿势？ | 先归档/移动再删；dry-run 先演练；绝不直接 rmtree 重要目录 |
| 重试怎么做？ | 指数退避重试（time.sleep(delay*attempt)）；最终失败抛出 + 告警 |
| 脚本如何幂等？ | 操作前检查状态（文件是否存在）；命名带时间戳避免覆盖；设计成可重复执行 |
