# 第十章：元编程与过程宏

> 目标：理解 `macro_rules!` 声明宏与三种过程宏（派生宏/属性宏/函数式宏），掌握 `syn`/`quote` 读写 Rust 语法树，完成一个**自定义派生宏**工程（`#[derive(Describe)]`）。
>
> 前置：[09-测试质量与发布.md](./09-测试质量与发布.md) ｜ 下一章：[11-unsafe与FFI.md](./11-unsafe与FFI.md)
>
> 本章属于**高级专题**。你几乎每天都在用宏（`println!`、`vec!`、`serde::Serialize` 派生、`#[tokio::main]`），但只有真正写过宏，才理解这些"语法魔法"背后的机制。

## 10.1 元编程全景：Rust 的两级宏

| 概念 | 是什么 | 类比 |
| --- | --- | --- |
| `macro_rules!` 声明宏 | 匹配 token 并展开，只能处理"结构化的文本模式" | C 宏增强版 / 没有注解处理的模板 |
| 过程宏（proc-macro） | 接收 token 流，用 `syn` 解析为语法树后**重新生成代码** | Java 注解处理器（APT）/ Lombok |
| 派生宏 `#[derive(X)]` | 给 struct/enum 自动实现 trait | Lombok `@Getter/@Builder` |
| 属性宏 `#[x(...)]` | 挂在 item/函数上做变换 | `@Transactional` + AOP 织入 |
| 函数式宏 `my_macro!()` | 像函数一样调用，返回任意代码 | 编译器插件 |

宏与函数的本质区别：**宏在编译期把"代码"当"数据"处理并生成新代码**，运行期零开销（展开完就没了）。

## 10.2 macro_rules!：声明宏

声明宏做的是"模式匹配 + 替换"：

```rust
macro_rules! hashmap {
    // $key:expr 匹配一个表达式；$(...),* 表示可重复 0..n 次（逗号分隔）
    ( $( $key:expr => $value:expr ),* ) => {
        {
            let mut m = std::collections::HashMap::new();
            $( m.insert($key, $value); )*
            m
        }
    };
}

fn main() {
    let scores = hashmap!("rust" => 90, "go" => 85);
    println!("{:?}", scores["rust"]);
}
```

常用片段指示符（fragment specifier）：

| 指示符 | 匹配 | 例 |
| --- | --- | --- |
| `expr` | 表达式 | `a + b` |
| `ty` | 类型 | `Vec<i32>` |
| `ident` | 标识符 | `my_var` |
| `pat` | 模式 | `Some(x)` |
| `tt` | 单个 token 树（万能） | 任意 token/括号组 |
| `literal` | 字面量 | `42`、`"s"` |

重复运算符：`*`（0+）、`+`（1+）、`?`（0 或 1）。

**把行为交给"表达式"，而不是写死语句**——这是声明宏设计良好的关键。看一个典型模式（默认值 + 覆盖）：

```rust
macro_rules! with_default {
    ($name:ident, $default:expr) => {
        struct $name(i32);
        impl $name {
            fn new() -> Self { $name($default) }      // default 在展开处求值
        }
    };
}
```

> 声明宏的局限：只能"照模式替换"，不能读结构体的字段列表、不能对 AST 做分析。一旦需要了解类型内部结构（字段名、trait 实现情况），就要上过程宏。

## 10.3 过程宏三兄弟

三种过程宏都在独立 crate（`proc-macro = true`）中实现，入口函数接收 `proc_macro::TokenStream`、返回 `TokenStream`。

| 类型 | 声明 | 输入 |
| --- | --- | --- |
| 派生宏 | `#[proc_macro_derive(MyTrait, attributes(my_helper))]` | 整个 struct/enum 定义 |
| 属性宏 | `#[proc_macro_attribute]` | 属性参数 + 所挂 item |
| 函数式宏 | `#[proc_macro]` | `!` 后括号内的 token |

常用生态：

- `#[derive(Serialize, Deserialize)]`（serde）——派生宏；
- `#[tokio::main]`——属性宏，把 `async fn main` 包进运行时；
- `#[async_trait]`——属性宏，把 async trait 方法改写为返回 `Pin<Box<dyn Future>>`；
- `sqlx::query!`——函数式宏，**编译期解析 SQL 并校验列**；
- `format_args!`/`vec!`——声明宏（语言内置）。

### 处理流程（以派生宏为例）

```
TokenStream（源代码）
   → syn::parse::<DeriveInput>()     # 解析为类型化 AST
   → 遍历字段/变体，构造要生成的代码
   → quote::quote! { ... }           # 反引号里写 Rust 代码，占位符 #ident
   → TokenStream::from(expanded)     # 交回编译器
```

## 10.4 实战工程：自定义派生宏 `#[derive(Describe)]`

**目标**：任何 `struct` 加上 `#[derive(Describe)]` 后自动获得 `fn describe(&self) -> String`，输出 `字段1 = 值, 字段2 = 值`（要求字段实现 `Debug`）。

### 第 1 步：workspace 结构（宏必须独立 crate）

```text
describe-demo/
├── Cargo.toml            # [workspace] members
├── describe-macros/      # 宏实现 crate（proc-macro）
└── app/                  # 使用方 crate
```

根 `Cargo.toml`：

```toml
[workspace]
members = ["describe-macros", "app"]
resolver = "2"
```

### 第 2 步：宏 crate

`describe-macros/Cargo.toml`：

```toml
[package]
name = "describe-macros"
version = "0.1.0"
edition = "2021"

[lib]
proc-macro = true                     # 关键：只能导出宏函数，不能导出普通函数/类型

[dependencies]
syn = { version = "2", features = ["full"] }
quote = "1"
```

`describe-macros/src/lib.rs`：

```rust
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, Data, DeriveInput, Fields};

#[proc_macro_derive(Describe)]
pub fn derive_describe(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput);
    let name = &ast.ident;

    // 只处理"命名结构体"，其他形态给出友好的编译错误
    let field_descriptions = match &ast.data {
        Data::Struct(data) => match &data.fields {
            Fields::Named(named) => named.named.iter().map(|f| {
                let field_name = f.ident.as_ref().unwrap();
                quote! { format!("{} = {:?}", stringify!(#field_name), self.#field_name) }
            }).collect::<Vec<_>>(),
            _ => vec![quote! { format!("<tuple/unit struct>") }],
        },
        _ => vec![quote! { format!("<enum not supported>") }],
    };

    let expanded = quote! {
        impl #name {
            pub fn describe(&self) -> String {
                // #(#field_descriptions),* ：逐个展开并用逗号连接
                vec![#(#field_descriptions),*].join(", ")
            }
        }
    };
    TokenStream::from(expanded)
}
```

> 不要怕 `quote!` 里的 `#`——它只是"把外层变量插入模板"的占位语法：`#name` 插入类型标识符，`#(#x),*` 展开序列。

### 第 3 步：使用方 crate

`app/Cargo.toml`：

```toml
[package]
name = "app"
version = "0.1.0"
edition = "2021"

[dependencies]
describe-macros = { path = "../describe-macros" }
```

`app/src/main.rs`：

```rust
use describe_macros::Describe;

#[derive(Describe)]
struct User {
    name: String,
    age: u8,
    active: bool,
}

fn main() {
    let u = User { name: "Alice".into(), age: 30, active: true };
    println!("{}", u.describe());
    // 输出：name = "Alice", age = 30, active = true
}
```

`cargo run` 直接可用。这就是你"生成了代码"，而不是手写样板。

## 10.5 三种进阶用法

### 1）属性宏：给函数加计时

属性宏接收两个参数：属性上的 token 与目标 item。

```rust
// timing-macros/src/lib.rs
use proc_macro::TokenStream;
use quote::quote;

#[proc_macro_attribute]
pub fn timed(_args: TokenStream, item: TokenStream) -> TokenStream {
    let input = syn::parse_macro_input!(item as syn::ItemFn);
    let name = &input.sig.ident;
    let block = &input.block;

    let expanded = quote! {
        fn #name() {
            let start = std::time::Instant::now();
            #block
            println!("{} 耗时 {:?}", stringify!(#name), start.elapsed());
        }
    };
    TokenStream::from(expanded)
}
```

使用方：

```rust
#[timed]
fn work() {
    std::thread::sleep(std::time::Duration::from_millis(50));
}
```

> 注意：属性宏拿到的是**语法块**，通常需要自己保留签名/参数并改造函数体，比派生宏"可以整段生成 impl"更绕。真正的生产属性宏（如 `#[tokio::main]`）复杂度都在"改写签名 + 包裹运行时"。

### 2）函数式宏：编译期校验的模板

`sqlx::query!("SELECT name FROM users WHERE id = ?", id)` 之所以能**在编译期发现 SQL 写错列名**，正因为它是一个函数式宏：宏从源码读 SQL 字面量 → 连库取 schema → 生成强类型的绑定/读取代码。你在 08 章用到的 `query_as!` 同样是宏功劳。

### 3）辅助属性 `attributes(...)` 与结构感知

派生宏可以在 `#[proc_macro_derive(MyTrait, attributes(serde))]` 里声明"允许消费者用 `#[serde(rename)]` 等辅助属性传递配置"，`syn` 会解析这些属性供宏读取——这是 serde 能提供 `#[serde(rename_all)]` 的机制。

## 10.6 调试宏：cargo expand

宏的痛点是不可见。**`cargo expand`** 展开宏后看生成的代码：

```bash
cargo install cargo-expand
cd describe-demo/app
cargo expand          # 输出展开后的完整 main.rs
```

你会看到编译器实际处理的代码——`derive_describe` 生成的 `impl User { fn describe... }` 原形毕露，定位"为什么生成的东西不对"非常有用。

其他经验：

- 编译错误里定位宏内问题：把宏生成的代码先手写一遍验证逻辑，再还原成 `quote!`；
- 报错位置不理想时，可在生成的代码里插入 `compile_error!` 或 `panic!` 无法用，改用 `syn::Error` 的 `to_compile_error()` 返回友好错误；
- 保持宏 crate 依赖最小（`syn`+`quote`+`proc-macro2`），**不要在里面调用业务逻辑**。

## 10.7 实战验收

1. 按 10.4 完整跑通 `#[derive(Describe)]`；
2. 给 `User` 增加 `#[derive(Describe)]` 到**枚举**上——看编译器如何报"不支持"，再把宏改造为给枚举生成 `match self { ... }` 的 `describe`（提示：遍历 `Data::Enum` 的变体）；
3. 实现自己的 `#[derive(DefaultLike)]`：对 `Vec`/`HashMap`/`Option` 字段生成 `Default`（用 `quote!` 构造）；
4. 用 `cargo expand` 查看第 2 步展开结果；
5. **思考题**：为什么过程宏必须放在独立 crate？为什么它不能定义普通 pub 函数？

> 关键收获：宏把"编译器能做但手写太啰嗦"的事自动化。`macro_rules!` 解决局部替换，过程宏解决"需要理解类型结构"的代码生成。生产中用宏的标准是**宁少勿滥**——它降低调用方样板的同时，也把复杂度转移到了宏作者身上。
