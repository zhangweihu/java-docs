## 5.1 为什么需要智能指针

普通引用 `&T` 只借用数据、不能决定数据存活。而"数据被多个所有者共享""递归结构""运行时才知道大小"等需求下，需要能**拥有**数据的指针。Rust 把这类类型叫智能指针：实现了 `Deref`（像引用一样用）与 `Drop`（离开作用域时自定义清理）的类型。

三个追问对应三种工具：

| 问题 | 工具 |
| --- | --- |
| 递归/动态大小类型需要间接层 | `Box<T>`（堆上分配，唯一所有权） |
| 单线程内共享只读数据 | `Rc<T>`（引用计数） |
| 多线程共享数据 | `Arc<T>`（原子引用计数） |
| 不可变引用下需要修改 | `RefCell<T>` / `Mutex<T>` / `RwLock<T>`（运行时借用/加锁检查） |

## 5.2 Box：堆上的唯一所有权

- 编译期类型大小未知但有界（递归结构）；
- 不想在栈上放大数据；
- 想把 trait 对象装箱（`Box<dyn Trait>`）。

```rust
// 递归类型必须间接：Box 让 size 确定
enum List {
    Nil,
    Cons(i32, Box<List>),   // Box 是指针，大小固定
}

impl List {
    fn len(&self) -> usize {
        match self {
            List::Nil => 0,
            List::Cons(_, tail) => 1 + tail.len(),
        }
    }
}
```

`Box` 实现 `Deref`，所以 `*box` 可解引用；实现 `Drop`，离开作用域自动释放堆内存。

## 5.3 Rc：单线程引用计数共享

一个值同时被多个"引用"指向且都能使用（如树的多个分支指向同一个共享节点）时，用 `Rc`。它计数：`clone` 加一，drop 减一，减到零才释放。**注意 `Rc` 不是 `Send`，不能跨线程**（计数非原子）。

```rust
use std::rc::Rc;

let a = Rc::new(String::from("shared"));
let b = Rc::clone(&a);                 // 计数 2
let c = Rc::clone(&a);                 // 计数 3
println!("强引用数: {}", Rc::strong_count(&a));   // 3
```

### 共享 + 可变：Rc<RefCell<T>>

`Rc` 只共享不可变数据。想要"多引用 + 能修改"，组合 `Rc<RefCell<T>>`：`Rc` 解决共享所有权，`RefCell` 提供**内部可变性**（把借用检查从编译期移到运行期）。

```rust
use std::cell::RefCell;
use std::rc::Rc;

type SharedConfig = Rc<RefCell<Config>>;

#[derive(Default)]
struct Config { timeout_ms: u64 }

fn main() {
    let config = Rc::new(RefCell::new(Config::default()));
    let handle1 = Rc::clone(&config);
    let handle2 = Rc::clone(&config);

    config.borrow_mut().timeout_ms = 3_000;      // 运行时可变借用
    {
        let c = handle1.borrow();                 // 不可变借用
        println!("timeout: {}", c.timeout_ms);
    } // borrow 结束，释放借用
    handle2.borrow_mut().timeout_ms = 5_000;      // 前一个 borrow 已结束，可再可变借用
}
```

**借用规则仍是单写多读**，只是从"编译期检查"变为"运行期检查"：违反会 panic（`borrow_mut` 与 `borrow` 重叠）。

- `Cell<T>`：单线程内部可变，只适用于 `Copy` 类型，无借用冲突；
- `RefCell<T>`：单线程内部可变，适用于非 `Copy`；
- `Mutex<T>`/`RwLock<T>`：**多线程**内部可变（见第六章）。

### 避免引用循环：Rc<Weak<T>>

父子互相持有 `Rc` 会形成引用循环，导致内存泄漏。打破方法是让**父持有 `Rc`（强引用）、子持有 `Weak`（弱引用，不参与计数）**：

```rust
use std::rc::Weak;
use std::cell::RefCell;

struct Parent { children: RefCell<Vec<Rc<Child>>> }
struct Child { parent: RefCell<Weak<Parent>> }    // 弱引用：不会阻止 Parent 释放

fn main() {
    let parent = Rc::new(Parent { children: RefCell::new(vec![]) });
    let child = Rc::new(Child { parent: RefCell::new(Rc::downgrade(&parent)) });
    parent.children.borrow_mut().push(Rc::clone(&child));

    // child 通过 weak 取父：升级为 Rc 后使用，失败说明父已释放
    if let Some(p) = child.parent.borrow().upgrade() {
        println!("父对象仍存活");
    }
}
```

## 5.4 Drop：离开作用域时的清理

`Drop` trait 决定值销毁时做什么。栈上值按声明逆序 drop；结构体先 drop 自身再 drop 字段。可以手动提前 drop 使用 `std::mem::drop`：

```rust
struct Logger;

impl Drop for Logger {
    fn drop(&mut self) {
        println!("Logger 已释放");
    }
}

fn main() {
    let a = Logger;          // "Logger 已释放"（main 结束 drop）
    let b = Logger;
    drop(b);                 // 立即释放 b（先于 a）
}
```

## 5.5 内存布局与指针的选择心法

- **默认**用栈上值 + 借用，不引入任何智能指针；
- 需要一个堆上拥有者、无需共享 → `Box<T>`；
- 单线程多处共享 → `Rc<T>`，还需修改 → `Rc<RefCell<T>>`，要防循环 → 加 `Weak`；
- 多线程共享 → `Arc<T>` + `Mutex<T>`/`RwLock<T>`；
- 数据多读少写且跨线程 → `Arc<RwLock<T>>`（读锁可并发）；
- 写多读少 → `Arc<Mutex<T>>`。

**铁律：能用编译期借用就不用运行期内部可变性**。`RefCell`/`Mutex` 是"让不可能变可变的逃生门"，使用它们等于把部分安全检查推迟到运行期（违反即 panic/死锁）。

## 5.6 实战 A：表达式树求值

用 `Box` 表达递归的算术表达式，用 `match` 求值：

```rust
#[derive(Debug)]
enum Expr {
    Num(f64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

impl Expr {
    fn num(n: f64) -> Self { Expr::Num(n) }
    fn add(a: Expr, b: Expr) -> Self { Expr::Add(Box::new(a), Box::new(b)) }
    fn mul(a: Expr, b: Expr) -> Self { Expr::Mul(Box::new(a), Box::new(b)) }

    fn eval(&self) -> f64 {
        match self {
            Expr::Num(n) => *n,
            Expr::Add(a, b) => a.eval() + b.eval(),
            Expr::Mul(a, b) => a.eval() * b.eval(),
        }
    }
}

fn main() {
    // (3 + 4) * 2
    let expr = Expr::mul(Expr::add(Expr::num(3.0), Expr::num(4.0)), Expr::num(2.0));
    println!("result = {}", expr.eval());   // 14
    println!("{expr:?}");
}
```

## 5.7 实战 B：共享可变的全局缓存

用 `Rc<RefCell<HashMap>>` 模拟一个可被多处共享并动态更新的配置/缓存中心（单线程演示内部可变性的价值）：

```rust
use std::cell::RefCell;
use std::collections::HashMap;
use std::rc::Rc;

struct Cache {
    store: RefCell<HashMap<String, String>>,
}

impl Cache {
    fn new() -> Rc<Cache> {
        Rc::new(Cache { store: RefCell::new(HashMap::new()) })
    }

    fn put(&self, key: &str, value: &str) {
        self.store.borrow_mut().insert(key.to_string(), value.to_string());
    }

    fn get(&self, key: &str) -> Option<String> {
        self.store.borrow().get(key).cloned()
    }
}

fn main() {
    let cache = Cache::new();
    let worker_a = Rc::clone(&cache);
    let worker_b = Rc::clone(&cache);

    worker_a.put("theme", "dark");
    worker_b.put("lang", "rust");
    println!("{}", worker_a.get("theme").unwrap_or_default());  // dark
    println!("{}", worker_b.get("lang").unwrap_or_default());   // rust
}
```

**注意为什么这里能同时共享且修改**：`Cache` 的方法接收 `&self` 就能改内部状态（`RefCell` 内部可变），于是多个 `Rc<Cache>` 副本都能调用修改方法——这在纯借用规则下做不到。

**验收清单**：

1. 表达式树实战运行输出 `14`；
2. 给 `Expr` 增加 `Sub`/`Div` 变体并扩展 `eval`（注意 `match` 必须穷尽新增变体）；
3. 缓存实战：解释 `Rc` 与 `RefCell` 各承担什么职责；若去掉 `Rc` 只用 `Cache`，为什么 `put` 仍然可用；
4. 说出：`Rc` 为什么不是 `Send`？`RefCell` 的可变借用违反时会怎样？

**扩展练习**：用 `Weak` 重写"父-子双向引用"模型（`Node` 含 `parent: RefCell<Weak<Node>>`、`children: RefCell<Vec<Rc<Node>>>`），构建一棵树后验证无内存泄漏（可配合 `Drop` 打印观察释放次数）。

> 关键收获：Rust 的智能指针不是"概念清单"，而是解决"所有权规则与真实业务形态的冲突"的配套工具。先想清楚数据结构的所有权形状，再决定要不要智能指针、用哪一种。下一章把它带到多线程世界：并发编程。
