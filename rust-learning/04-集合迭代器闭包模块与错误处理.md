## 4.1 常用集合一览

| 集合 | 说明 | 常用操作 |
| --- | --- | --- |
| `Vec<T>` | 可增长数组 | `push/pop`、`[i]`、`get`、`iter`、`sort`、`contains` |
| `String` | 可增长 UTF-8 字符串 | `push_str`、`+`、`format!`、`chars`、`split` |
| `HashMap<K, V>` | 键值对 | `insert`、`get`、`entry`、`remove` |
| `HashSet<T>` | 集合（无序、去重） | `insert`、`contains`、`union/intersection` |
| `BTreeMap/BTreeSet` | 有序键值对/集合 | 与上面类似但按键排序 |

### Vec

```rust
let mut scores = Vec::new();
scores.push(90);
scores.push(72);
let first = scores[0];                     // 直接下标，越界 panic
let second = scores.get(1);                // Option<&i32>，越界得 None，安全
let top = scores.iter().max().copied();    // Option<i32>
```

`iter()` 产生不可变迭代器；要修改元素用 `iter_mut()`；要取走所有权用 `into_iter()`。

### HashMap：entry 的用法是高频考点

```rust
use std::collections::HashMap;

let mut counters: HashMap<String, usize> = HashMap::new();

// entry 返回一个枚举，or_insert 处理"不存在"分支
*counters.entry("rust".to_string()).or_insert(0) += 1;
*counters.entry("rust".to_string()).or_insert(0) += 1;
assert_eq!(counters.get("rust"), Some(&2));
```

读取时避免复制数据，直接借用：

```rust
for (key, value) in &counters {              // (&String, &usize)
    println!("{key}: {value}");
}
```

### 更新集合值的两种惯用法

```rust
// 方法一：entry 流派（推荐，一次查找）
*counters.entry(key.clone()).or_insert(0) += 1;

// 方法二：get_mut 流派（需要两次查找）
if let Some(count) = counters.get_mut(&key) {
    *count += 1;
} else {
    counters.insert(key, 1);
}
```

## 4.2 迭代器与组合子

迭代器是惰性的——只有被消费（`collect`/`for`/`sum`/`count` 等）才真正执行。常用组合子：

- `map`：逐个转换（`|x| x * 2`）；
- `filter`：过滤（谓词返回 bool）；
- `take`/`skip`：取前 N 个/跳过 N 个；
- `flat_map`：展开嵌套迭代器；
- `enumerate`：带下标；
- `fold`/`reduce`：归约；
- `zip`：配对两个迭代器；
- `chain`：串联两个迭代器。

链式处理一脉相承，可读性很高：

```rust
let numbers = vec![1, 2, 3, 4, 5, 6];

// 偶数翻倍后求和
let sum: i32 = numbers
    .iter()
    .filter(|&&n| n % 2 == 0)
    .map(|&n| n * 2)
    .sum();
assert_eq!(sum, 24);

// 去重收集
let words = ["rust", "go", "rust", "java"];
let unique: std::collections::HashSet<&&str> = words.iter().collect();
assert_eq!(unique.len(), 3);
```

## 4.3 闭包

闭包是可以捕获环境变量的匿名函数。捕获方式由编译器按使用方式决定：借用、可变借用或获取所有权（可用 `move` 关键字强制）：

```rust
let base = 10;
let add = |n: i32| n + base;      // 捕获 base 的引用（或 Copy）
assert_eq!(add(5), 15);

let mut list = vec![1, 2, 3];
let mut push_5 = |n: i32| list.push(n);   // 可变借用捕获
push_5(5);

// move：把捕获的所有权移入闭包（多线程/异步场景常用）
let heavy = String::from("data");
let owned_closure = move || println!("{heavy}");
owned_closure();
```

与 `Fn`/`FnMut`/`FnOnce` 三个 trait 对应：`Fn` 只读捕获、`FnMut` 可变捕获、`FnOnce` 消耗捕获。函数参数声明闭包 trait bound 时按需选择。

```rust
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }
println!("{}", apply(|x| x + 1, 41));
```

## 4.4 模块与可见性

`mod` 声明模块，`pub` 控制可见性。Rust 的"面向对象封装"是靠可见性，不是 class 关键字。

```rust
// 定义一个模块（src/lib.rs 或文件内）
pub mod text_utils {
    pub fn word_count(text: &str) -> usize {
        text.split_whitespace().count()
    }

    fn secret_helper() {}          // 默认私有：仅模块内可见

    pub mod inner {                // 嵌套模块
        pub const LIMIT: usize = 10;
    }
}

use text_utils::word_count;        // 引入到当前作用域
fn main() {
    println!("{}", word_count("hello rust world"));
}
```

单文件项目常用结构：

```text
src/
├── main.rs        # 入口：mod 声明子模块
├── lib.rs         # 库入口（供 main 与外部使用）
├── models.rs
└── services.rs
```

```rust
// main.rs
mod models;
mod services;

fn main() {
    let task = models::Task::new(1, "hi");
    services::run(task);
}
```

### 测试组织

- **单元测试**放在同模块文件内的 `#[cfg(test)] mod tests`；
- **集成测试**放 `tests/` 目录，每个文件是一个独立 crate，通过 `use my_lib::...` 使用公开 API；
- `lib.rs` 暴露 `pub` API 后，`main.rs`/测试/外部 crate 才能用——这促使你设计清晰的公开接口。

## 4.5 Cargo workspace：多 crate 组织

多模块项目建议拆分为 workspace（一个仓库多个 crate），依赖更清晰、编译缓存更好：

```text
my-workspace/
├── Cargo.toml              # [workspace] + members
├── crates/
│   ├── core/               # 领域核心（无框架依赖）
│   │   └── Cargo.toml
│   ├── cli/                # 命令行入口
│   └── web-api/            # 后续 Web 服务
```

```toml
# 根 Cargo.toml
[workspace]
members = ["crates/core", "crates/cli", "crates/web-api"]
resolver = "2"
```

crate 间依赖：`crates/cli/Cargo.toml` 声明 `core = { path = "../core" }`。workspace 成员共享 `Cargo.lock` 与目标目录，也便于在 CI 一次构建全部。

## 4.6 工程化错误处理：thiserror 与 anyhow

- **库/领域代码**：用 `thiserror` 定义精确的错误类型，配合 `#[derive(Error)]` 生成 `Display` 与 `From`；
- **应用/入口代码**：用 `anyhow::Result`/`anyhow::Context` 给错误附加上下文，让日志可读；
- 核心函数尽量返回具体错误，边界处做一次包装转换。

```toml
[dependencies]
thiserror = "2"
anyhow = "1"
```

```rust
use thiserror::Error;

#[derive(Debug, Error)]
pub enum TaskError {
    #[error("任务不存在: {id}")]
    NotFound { id: u64 },
    #[error("非法状态迁移: {0}")]
    IllegalTransition(String),
    #[error("存储层错误")]
    Storage(#[from] std::io::Error),   // 自动实现 From<io::Error>
}

// 应用层：任何可打印错误都可被包装
pub fn load_task(file: &str, id: u64) -> anyhow::Result<Task> {
    let content = std::fs::read_to_string(file).with_context(|| format!("读取 {} 失败", file))?;
    parse(content, id).map_err(|e| anyhow::anyhow!(e))
}
```

原则：**领域错误进类型（可 match），基础设施错误给上下文（可读日志）**。这比"到处返回 Box<dyn Error>"可维护得多，也比 Java 的"全链路 checked exception"轻盈。

## 4.7 实战：单词频率统计 CLI

**需求**：读取一个文本文件（命令行参数指定路径），输出 Top N 高频词及其次数（忽略大小写与标点）。要求：库函数与 main 分离（便于测试）、错误用 `anyhow` 可读化、结构清晰。

```rust
// src/lib.rs
use std::collections::HashMap;

/// 清洗并统计词频，返回按次数降序的 (词, 次数)
pub fn top_words(text: &str, limit: usize) -> Vec<(String, usize)> {
    let mut freq: HashMap<String, usize> = HashMap::new();
    for raw in text.split(|c: char| !c.is_alphanumeric()) {
        if raw.is_empty() {
            continue;
        }
        let word = raw.to_lowercase();     // 忽略大小写
        *freq.entry(word).or_insert(0) += 1;
    }
    let mut items: Vec<(String, usize)> = freq.into_iter().collect();
    items.sort_by(|a, b| b.1.cmp(&a.1).then_with(|| a.0.cmp(&b.0))); // 次数降序、同次数字母升序
    items.truncate(limit);
    items
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn 统计并排序() {
        let out = top_words("Go Rust GO rust java", 2);
        assert_eq!(out, vec![("go".to_string(), 2), ("rust".to_string(), 2)]);
    }

    #[test]
    fn 忽略标点与空串() {
        assert_eq!(top_words("a, b! a?  ", 10).len(), 2);
    }
}
```

```rust
// src/main.rs
use anyhow::Context;
use word_freq::top_words;

fn main() -> anyhow::Result<()> {
    let mut args = std::env::args().skip(1);
    let path = args.next().context("用法: word-freq <文件> [TopN]")?;
    let limit: usize = args.next().unwrap_or_else(|| "10".to_string()).parse()?;

    let content = std::fs::read_to_string(&path)
        .with_context(|| format!("无法读取文件 {path}"))?;

    for (word, count) in top_words(&content, limit) {
        println!("{word:>12}: {count}");
    }
    Ok(())
}
```

**验收清单**：

1. `cargo test` 两个单测通过；
2. 对某个文本文件运行 `cargo run -- xxx.txt 5` 输出 Top 5；
3. 传入不存在的文件，得到包含文件路径的可读错误信息（验证 `anyhow` 上下文）；
4. 把 `top_words` 拆成 `split_words` + `count` 两个函数，用组合子重写第 12~18 行。

**扩展练习**：支持 `--top N --file path` 风格参数解析（可用手写 `match` 或引入 `clap` crate）；统计时输出占比；跳过停用词表（`["the","a","an","of"]`）。

> 关键收获：标准库集合 + 迭代器 + 闭包解决了"数据转换"的绝大多数问题；`thiserror`/`anyhow` 让错误从"字符串拼接"进化为"类型化的可 match 错误 + 可读的上下文"。下一章攻克 Rust 里最容易让人困惑的话题：智能指针与所有权如何共存。
