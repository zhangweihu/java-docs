# 第二章：所有权、借用与生命周期

> 目标：理解 Rust 内存安全的根基——所有权三规则、移动与 Copy、借用规则、切片、生命周期标注与省略，完成一个**文本统计工具**。
>
> 前置：[01-Rust环境与基础语法.md](./01-Rust环境与基础语法.md) ｜ 下一章：[03-结构体枚举trait与泛型.md](./03-结构体枚举trait与泛型.md)

## 2.1 为什么需要所有权

Java/Python 用 GC 自动回收内存，C/C++ 手动管理内存。Rust 选择第三条路：**在编译期通过所有权规则确定每个值的生存期**——值离开作用域即释放，不需要 GC，也不会出现悬垂指针。

没有 GC 也没有手工 free，靠的是三条规则（先记住，再理解）：

1. 一个值**同一时间只有一个所有者**；
2. 所有者离开作用域时，值会自动释放（调用 `drop`）；
3. 把值赋给变量、传给函数或从函数返回时，可能发生**所有权移动**。

```rust
fn main() {
    let s = String::from("hello");
    // s 是所有者，离开 main 末尾作用域时自动释放内存
}
```

## 2.2 移动（Move）与复制（Copy）

`String` 在堆上保存数据。把一个 `String` 赋给另一个变量，发生的是**移动（move）**——所有权转移，而不是深拷贝：

```rust
let first = String::from("hello");
let second = first;                // first 的所有权移动到 second
// println!("{first}");            // 编译失败：first 已被移动
println!("{second}");              // 正常
```

为杜绝"同一块堆内存被释放两次"，移动后旧绑定立即失效，编译器在**编译期**就拦截对 `first` 的使用。

而实现 `Copy` trait 的类型（整数、浮点、布尔、`char`、元组/数组等仅含 Copy 字段的组合）赋值时是**值拷贝**，旧变量依然可用：

```rust
let x = 42;
let y = x;                 // Copy：拷贝一份 42
println!("{x} {y}");       // 两个都有效
```

**判断口诀**：类型大小固定且只含 Copy 字段 → `Copy`；需要堆分配/可变缓冲（`String`、`Vec`、`Box`）→ 移动。

函数调用同理——传参即"赋值给函数参数"：

```rust
fn take_text(text: String) {          // 接收所有权
    println!("{text}");
}

fn main() {
    let message = String::from("hello");
    take_text(message);
    // println!("{message}");         // 编译失败：已移动进函数
}
```

返回值也可以归还所有权：

```rust
fn build_message(prefix: String) -> String {
    format!("{prefix}, Rust!")
}

fn main() {
    let m = build_message(String::from("hi"));
    println!("{m}");
}
```

> 不要把 `clone()` 当作解决所有权问题的默认答案：`clone()` 会复制数据，适合确实需要两份独立数据的场景。业务代码先判断能否传引用、移动所有权或重构数据结构。

## 2.3 借用（引用）

不想转移所有权、只读访问数据时，用**不可变引用 `&T`**：

```rust
fn word_count(text: &str) -> usize {        // &str 是 &String 的借用形式
    text.split_whitespace().count()
}

fn main() {
    let message = String::from("hello rust");
    let count = word_count(&message);       // 传借用，message 仍可用
    println!("{message}: {count} words");
}
```

需要修改且不转移所有权，用**可变引用 `&mut T`**：

```rust
fn append_mark(text: &mut String) {
    text.push('!');
}

fn main() {
    let mut message = String::from("hello");
    append_mark(&mut message);              // 必须变量可变才能取 &mut
    println!("{message}");
}
```

### 借用规则（编译器强制）

1. 同一时间可以有**任意多个不可变引用**；
2. 同一时间只能有**一个可变引用**；
3. 不可变引用与可变引用不能同时存在；
4. 引用必须始终有效，不能悬垂。

下面的代码**不能编译**——可变借用与不可变借用同时存在：

```rust,compile_fail
let mut message = String::from("hello");
let view = &message;          // 不可变借用
message.push('!');            // 同时想要可变借用 → 编译错误
println!("{view}");
```

解决方法通常是**缩短借用作用域**，或先完成读取再修改：

```rust
let mut message = String::from("hello");
println!("{}", message.len());   // 先完成不可变读取（借用结束）
message.push('!');               // 再修改
```

借用规则在**编译期**检查，不会有运行期开销，也从根本上杜绝了数据竞争（data race）。

## 2.4 切片：借用一段连续数据

切片是对集合中一段连续元素的**借用视图**，没有所有权：

```rust
fn main() {
    let words = vec![String::from("java"), String::from("rust"), String::from("go")];
    let head = &words[..2];        // 前两个元素：&[String]
    println!("{:?}", head);
}
```

字符串切片 `&str`：`&s[..]` 是整个字符串，`&s[0..4]` 取字节区间。**必须落在字符边界**，否则 panic：

```rust
let s = String::from("你好");
// let byte = &s[0..1];      // panic：切在 "你" 的字节中间
let all = &s[..];            // 安全：整个字符串
```

## 2.5 生命周期

生命周期（lifetime）描述**引用有效的范围**——它不是延长对象寿命，而是让编译器确认"引用不会比其指向的数据活得更久"。

最常见的情形：函数返回的引用必须与某个输入参数的生命周期一致：

```rust
fn longer<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}
```

含义：`left`/`right`/返回值被同一个 `'a` 约束——**返回的引用取自哪个输入，它的有效范围就不能超过哪个输入**。

大部分时候不需要手写生命周期。**省略规则**让编译器自动推断常见模式：

- 每个输入的引用参数都有自己的生命周期；
- 只有一个输入引用参数时，输出引用沿用它的生命周期：
  ```rust
  fn first_word(s: &str) -> &str { ... }   // 省略后等价于 <'a>(s: &'a str) -> &'a str
  ```
- 有 `&self` 时，输出引用沿用 `&self` 的生命周期。

需要在**结构体**里保存引用时，必须显式标注：

```rust
struct Excerpt<'a> {
    part: &'a str,          // 结构体不能活得比引用指向的数据更久
}

fn main() {
    let novel = String::from("hello world");
    let excerpt = Excerpt { part: &novel[..5] };   // excerpt 不能超过 novel 的作用域
    println!("{}", excerpt.part);
}
```

`'static` 生命周期表示"整个程序运行期间都有效"，常见于字符串字面量：

```rust
let s: &'static str = "hello";     // 字面量直接编译进二进制
```

> 初学建议：先掌握"函数参数与返回值之间引用关系" + "结构体存引用要标注"两个场景，其余让编译器推导。遇到生命周期报错时，遵循编译器建议修正，而不是滥用 `'static`。

## 2.6 常见借用错误的修复模式

**错误 1：函数内修改了集合又返回其中元素的引用**

```rust,compile_fail
fn bad(v: &mut Vec<i32>) -> &i32 {
    v.push(1);              // 可变借用（v 的整个借用期间）
    &v[0]                   // 返回的元素引用可能随扩容失效
}
```

修复：先做修改，再取引用并返回；或将"取引用"放到修改之后独立进行。

**错误 2：结构体中字段先借用、整体又要移动**

```rust,compile_fail
fn problem(users: Vec<String>) -> String {
    let first = &users[0];      // 借用 users
    users                          // 试图移动 users → 冲突
}
```

修复：取出需要的数据（`clone` 或先切片收集），再移动原集合。

**错误 3：方法链中 `self` 被先借用后移动**——多为"先存引用、再整体 move"的顺序问题，调整语句顺序即可。

> 通用心法：把每个值看作"有主之物"。谁拥有、谁借用、借用到什么时候结束，写代码时在脑子里过一遍这三问，大部分编译错误都能自愈。

## 2.7 实战：文本统计工具

**需求**：接收一个文本字符串，统计：字符数、单词数、行数、出现次数最多的单词。

**实现（不依赖第三方 crate）**：

```rust
use std::collections::HashMap;

/// 统计一个文本块：返回 (字符数, 单词数, 行数, 出现最多的单词)
fn analyze(text: &str) -> (usize, usize, usize, Option<(String, usize)>) {
    let chars = text.chars().count();
    let lines = text.lines().count();

    // 用 String 作 key：去标点后的单词拥有自己的数据，避开生命周期纠缠
    let mut freq: HashMap<String, usize> = HashMap::new();
    let mut word_count = 0;
    for raw in text.split_whitespace() {
        let clean: String = raw
            .chars()
            .filter(|c| c.is_alphanumeric())
            .collect();
        if !clean.is_empty() {
            word_count += 1;
            *freq.entry(clean).or_insert(0) += 1;
        }
    }

    let top = freq.into_iter().max_by_key(|&(_, count)| count);
    (chars, word_count, lines, top)
}

fn main() {
    let text = "Rust 是内存安全的语言。\nRust 没有 GC。\nRust 的借用检查器在编译期工作。";
    let (chars, words, lines, top) = analyze(text);
    println!("字符数: {chars}, 单词数: {words}, 行数: {lines}");
    if let Some((word, count)) = top {
        println!("出现最多的词: {word}（{count} 次）");
    }
}
```

> 为什么 key 用 `String` 而不是 `&str`？如果把 `clean`（每次循环新产生的 `String`）的借用放进 `HashMap<&str, _>`，循环结束后借用就悬垂了——编译器不允许。`HashMap<String, usize>` 让 map **拥有** key 数据，是"跨函数返回统计结果"这类场景的正解；仅当文本与统计都在同一作用域内时才适合用 `&str` 借用。

**验收清单**：

1. 能对含中文与英文混合文本正确统计；
2. 统计"出现最多的词"时无生命周期/借用编译错误；
3. 尝试把 `let count = word_count(&message);` 改为 `let count = word_count(message);`，能解释为什么报错；
4. 解释下面代码为什么不能编译，并修复（提示：可变借用冲突）：
   ```rust,compile_fail
   let mut data = String::from("rust");
   let r = &data;
   data.push_str("!");
   println!("{r}");
   ```

**扩展练习**：把 `analyze` 改为接收文件路径（`std::fs::read_to_string`），统计 `.txt` 文件；思考 `read_to_string` 返回的 `String` 所有权去了哪里、为什么函数返回后数据不会悬垂。

> 关键收获：借用规则让"数据竞争"与"悬垂引用"在编译期消失。代价是学习曲线，回报是**无 GC 的并发安全**。下一章进入类型系统——用 struct/enum/trait 表达领域概念。
