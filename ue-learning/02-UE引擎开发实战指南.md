## 2.1 引擎分层与模块系统（先搞懂代码怎么被编译）

### 2.1.1 三层代码结构

```text
┌─────────────────────────────────────────────────────┐
│ 你的项目 Game Module（Source/MyGame/）              │  ← 你写的业务 C++
├─────────────────────────────────────────────────────┤
│ 插件 Plugins（项目内 / 引擎内，可独立复用）          │
├─────────────────────────────────────────────────────┤
│ 引擎模块 Engine/Runtime/...（Core, Engine,          │
│   Renderer, NetCore, UMG, EnhancedInput, ...）      │
└─────────────────────────────────────────────────────┘
```

**规则**：UE 的代码以 **Module（模块）** 为单位组织，每个模块一个 `.Build.cs` 声明依赖。想用某个功能，先加模块依赖，否则链接报错。

### 2.1.2 `.Build.cs`：模块依赖清单

```csharp
// Source/MyGame/MyGame.Build.cs
using UnrealBuildTool;

public class MyGame : ModuleRules
{
    public MyGame(ReadOnlyTargetRules Target) : base(Target)
    {
        PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

        PublicDependencyModuleNames.AddRange(new string[] {
            "Core", "CoreUObject", "Engine", "InputCore",   // 基础四件套（模板自带）
            "EnhancedInput",        // UE5 输入系统
            "UMG", "Slate", "SlateCore",  // UI
            "GameplayAbilities", "GameplayTags", "GameplayTasks", // GAS（可选）
            "Niagara",              // 特效（可选）
            "NetCore",              // 网络（通常已间接包含）
        });

        PrivateDependencyModuleNames.AddRange(new string[] { });

        // 公共头文件里用到某模块 → Public；只在 .cpp 里用 → Private
        // 放错只会拖慢编译，不会报错，但规范很重要
    }
}
```

> **常见链接错误**：`unresolved external symbol` / `无法解析的外部符号` → 九成是 `.Build.cs` 少了模块。用了 `UUserWidget` 要 `UMG`；用了 `UInputAction` 要 `EnhancedInput`。

### 2.1.3 `.Target.cs`：构建目标

```csharp
// Source/MyGame.Target.cs —— 游戏目标
public class MyGameTarget : TargetRules {
    public MyGameTarget(TargetInfo Target) : base(Target) {
        Type = TargetType.Game;
        DefaultBuildSettings = BuildSettingsVersion.V5;
        ExtraModuleNames.Add("MyGame");
    }
}

// Source/MyGameEditor.Target.cs —— 编辑器目标（多了 Editor 模块）
public class MyGameEditorTarget : TargetRules {
    public MyGameEditorTarget(TargetInfo Target) : base(Target) {
        Type = TargetType.Editor;
        DefaultBuildSettings = BuildSettingsVersion.V5;
        ExtraModuleNames.Add("MyGame");
    }
}
```

还可以有 `TargetType.Server`（专用服务器）、`TargetType.Client`、自定义 `TargetType.Program`（命令行工具）。

### 2.1.4 UHT 与 UBT：为什么 C++ 里能写 `UCLASS()`

```text
你写的 .h（含 UCLASS / UPROPERTY / UFUNCTION 宏）
        │
        ▼  UnrealHeaderTool (UHT) 扫描头文件
Intermediate/Build/.../MyActor.generated.h   ← 反射元数据 + 胶水代码
Intermediate/Build/.../MyActor.gen.cpp       ← 类型注册、序列化、蓝图桥接
        │
        ▼  UnrealBuildTool (UBT) 调用 MSVC/Clang
Binaries/Win64/UnrealEditor-MyGame.dll
```

**由此得到四条铁律**（新手最容易踩）：

| 铁律 | 说明 |
| --- | --- |
| ① **每个 UCLASS 头文件最后必须 `#include "<类名>.generated.h"`** | 且必须是**最后一个 include**，前面不能有其他 include |
| ② `GENERATED_BODY()` 必须写在类体开头 | 展开成 UHT 生成的胶水 |
| ③ 文件名 = 类名（去掉 A/U/F 前缀） | `AMyActor` → `MyActor.h` |
| ④ 加/删 UPROPERTY、UFUNCTION 后要**重新生成**（Live Coding 常不够，需完整重编） | UHT 只在头文件变化时重跑 |

```cpp
// MyActor.h
#pragma once
#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "MyActor.generated.h"     // ⚠️ 必须最后一个

UCLASS()
class MYGAME_API AMyActor : public AActor
{
    GENERATED_BODY()              // ⚠️ 类体第一行
public:
    AMyActor();
    virtual void Tick(float DeltaTime) override;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Demo")
    float Speed = 100.f;

protected:
    virtual void BeginPlay() override;
};
```

> **对标 Java**：`UCLASS()` ≈ `@Component`，`UPROPERTY()` ≈ 带多重元数据的注解（GC 根 + 序列化 + 编辑器显示 + 网络复制），UHT ≈ 编译期注解处理器（Lombok / APT）。理解这点，UE 的"魔法"就不神秘了。

## 2.2 UObject：反射、GC 与对象模型

### 2.2.1 UE 的两套类

| 体系 | 前缀 | 是否反射/GC | 用途 |
| --- | --- | --- | --- |
| **UObject 体系** | `U`（UObject, UActorComponent, UDataAsset…）、`A`（Actor…） | ✅ 反射、序列化、GC、蓝图可见 | 游戏对象 |
| **普通 C++ 类** | `F`（FVector, FString, FHitResult…）、`T`（TArray, TMap…） | ❌ 纯值类型/模板，栈上或手动管理 | 数据结构、工具 |
| 接口 | `I` | — | `IInteractable` 等 |
| 枚举 | `E` | — | `EInputActionValueType` |

> **判断口诀**：**要被引擎管的（放场景里、被 GC、在蓝图里看见）→ U/A；只是数据 → F/T**。别给纯数据结构加 `UCLASS()`，反射是有成本的。

### 2.2.2 反射带来的能力

一个 `UCLASS` 自动获得：

- **类型信息**：`GetClass()`、`StaticClass()`、`IsA<T>()`、`Cast<T>()`；
- **序列化**：存档、复制、资产保存；
- **编辑器可见**：`UPROPERTY` 出现在 Details 面板；
- **蓝图可访问**：`BlueprintReadWrite` / `BlueprintCallable`；
- **GC 追踪**：引擎知道谁引用谁；
- **网络复制**：`Replicated` / `NetMulticast`；
- **按名查找/构造**：`NewObject<T>()`、`SpawnActor<T>()`、`FindObject`、`LoadObject`。

### 2.2.3 GC：UPROPERTY 就是"引用根"

UE 用**追踪式 GC**：从根集合出发，沿 `UPROPERTY` 标记的 UObject 引用可达的对象都存活，其余回收。

```cpp
UPROPERTY()
TObjectPtr<UStaticMeshComponent> MeshComp;   // ✅ UE5 推荐：被 GC 追踪

UStaticMeshComponent* RawComp;               // ❌ 没有 UPROPERTY → GC 可能回收它 → 悬空指针崩溃
```

**引用容器速查**（哪些写法会被 GC 追踪）：

| 写法 | GC 追踪 | 建议 |
| --- | --- | --- |
| `UPROPERTY() TObjectPtr<UTexture2D> Tex;` | ✅ | **UE5 首选** |
| `UPROPERTY() UTexture2D* Tex;` | ✅ | UE4 写法，UE5 仍可用 |
| `UPROPERTY() TArray<TObjectPtr<AActor>> Actors;` | ✅ | 数组元素也会被追踪 |
| 裸成员（无 UPROPERTY） | ❌ | 危险 |
| `TWeakObjectPtr<T>` | 不阻止回收 | 缓存"可能已销毁"的对象，用前 `IsValid()` |
| `TSoftObjectPtr<T>` / `TSoftClassPtr<T>` | 不自动加载 | 异步加载大资产，避免启动全加载 |
| `FGCObject` / `AddReferencedObjects` | 手动登记 | 非 UObject 类持有 UObject 时 |
| `AddToRoot()` / `RemoveFromRoot()` | 强制保活 | 慎用，容易内存泄漏 |

**常见崩溃**：`Access violation reading address 0x000...` 且对象是 UObject → 大概率是**没用 UPROPERTY 持有**。

### 2.2.4 对象创建与销毁

```cpp
// UObject（非 Actor）：NewObject
UMyDataAsset* Data = NewObject<UMyDataAsset>(GetTransientPackage());

// Actor：SpawnActor（只能在有 World 的上下文）
FActorSpawnParameters Params;
Params.Owner = this;
AMyPickup* P = GetWorld()->SpawnActor<AMyPickup>(
    AMyPickup::StaticClass(), SpawnLoc, SpawnRot, Params);

// 组件：CreateDefaultSubobject（构造函数里）/ NewObject（运行时）
MeshComp = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("Mesh"));
MeshComp->SetupAttachment(RootComponent);

// 销毁
P->Destroy();              // Actor：异步标记，帧末真正销毁
P->SetLifeSpan(3.f);       // 3 秒后自动销毁
// UObject：去掉所有 UPROPERTY 引用，等 GC 回收；不要 delete！
```

> ⚠️ **永远不要对 UObject 用 `new` / `delete` / `std::shared_ptr`**。UE 自己管内存。

### 2.2.5 有效性检查（写 UE 代码的日常）

```cpp
if (IsValid(SomeActor)) { ... }              // ✅ 推荐：判空 + 判 PendingKill
if (SomeActor && !SomeActor->IsPendingKillPending()) { ... }
if (auto* P = Cast<AMyPickup>(Hit.GetActor())) { ... }   // ✅ Cast 自带判空
```

> **对照 Unity**：Unity 里 `if (obj != null)` 是重载过的"假空"（对象已销毁但 C# 引用还在）；UE 里 `IsValid()` 承担类似职责，但底层是纯 C++ 指针，**忘记检查就是真崩溃**。

## 2.3 核心类继承树

```text
UObject
├── UActorComponent                     （无 Transform 的功能组件）
│   ├── USceneComponent                 （有 Transform，可挂子级）
│   │   ├── UPrimitiveComponent        （可渲染 / 可碰撞）
│   │   │   ├── UStaticMeshComponent
│   │   │   ├── USkeletalMeshComponent
│   │   │   └── UShapeComponent (UBoxComponent / USphereComponent / UCapsuleComponent)
│   │   ├── UCameraComponent
│   │   └── UAudioComponent
│   ├── UMovementComponent
│   │   └── UCharacterMovementComponent   （移动、跳跃、网络预测）
│   └── UInputComponent / UEnhancedInputComponent
├── AActor                              ⭐ 能放进关卡的对象
│   ├── APawn                           （可被 Controller 控制）
│   │   └── ACharacter                  （带 Capsule + Mesh + CharacterMovement）
│   ├── AController                     （意志，不是躯体）
│   │   ├── APlayerController           （本地玩家：输入、HUD、相机管理）
│   │   └── AAIController               （AI：行为树、寻路）
│   ├── AGameModeBase / AGameMode       ⭐ 规则（仅服务器存在）
│   ├── AGameStateBase / AGameState     ⭐ 全局状态（复制到所有客户端）
│   ├── APlayerState                    ⭐ 单个玩家的数据（分数、名字，会复制）
│   ├── AHUD
│   └── AVolume / ATriggerVolume / ALight ...
├── UDataAsset / UDataTable             （配置数据）
├── UUserWidget (UMG)                   （UI）
├── UGameInstance                       （跨关卡、进程级生命周期）
├── UWorld                              （关卡世界）
└─ UEngine / UGameViewportClient
```

**三条最重要的记忆线**：

1. `AActor` 是"能摆在场景里的东西"；`UActorComponent` 是"挂在 Actor 上的能力"；
2. `ACharacter` 是 UE 送你的"完整人形角色"（胶囊碰撞 + 骨骼网格 + 移动组件 + 跳跃 + 网络预测），做第三人称游戏直接从它派生；
3. `AGameMode` / `AGameState` / `APlayerState` / `APlayerController` 是**框架约定的职责分工**，见下一节。

## 2.4 Gameplay Framework：UE 的"约定大于配置"

这是 UE 与 Unity 最大的思维差异：Unity 给你空场景随便搭，UE 直接给你一套**已经分好工的类**，顺着用就省事，逆着用处处碰壁。

### 2.4.1 四类角色的职责（背下来）

| 类 | 谁拥有 | 存在于 | 放什么 | 典型内容 |
| --- | --- | --- | --- | --- |
| **AGameMode** | 服务器 | **仅服务器** | **规则** | 计分、胜负判定、生成玩家、切换关卡、允许的 Pawn 类 |
| **AGameState** | 服务器 → 复制 | 服务器 + 所有客户端 | **全局状态** | 比赛时间、当前比分、已收集物品数、阶段 |
| **APlayerState** | 每玩家 | 服务器 + 所有客户端 | **玩家数据** | 名字、个人得分、Ping、队伍 |
| **APlayerController** | 每玩家 | 服务器 + 所属客户端 | **意志/输入** | 处理输入、Possess Pawn、HUD、相机、RPC 入口 |
| **APawn / ACharacter** | 被 Possess | 服务器 + 客户端（复制） | **躯体** | 移动、动画、碰撞、血量（也可放 PlayerState） |
| **UGameInstance** | 进程 | 本地 | **跨关卡** | 存档、设置、在线会话、全局管理器 |

```text
                    ┌──────────────┐
                    │  GameMode    │  仅服务器：规则 / 计分 / 生成
                    └──────┬───────┘
                           │ 写入
                    ┌──────▼───────┐
                    │  GameState   │──── Replicate ───► 所有客户端
                    └──────────────┘
   PlayerController（输入/意志） ──Possess──► Pawn/Character（躯体）
          │                                        │
          └── PlayerState（分数/名字，Replicate）────┘
```

### 2.4.2 一次登录发生了什么（时序）

```text
客户端连接
  → GameMode::PreLogin（可拒绝）
  → GameMode::Login（创建 PlayerController）
  → GameMode::PostLogin
  → GameMode::RestartPlayer（Spawn 默认 Pawn）
  → PlayerController::Possess(Pawn)
  → Pawn::BeginPlay / 客户端 OnRep_Controller
  → GameMode::HandleMatchHasStarted（StartPlay）
```

> 找"玩家刚进游戏"的钩子：**`PostLogin`（服务器）/ `BeginPlay`（Pawn）/ `OnPossess`**，不要全塞进 `BeginPlay`。

### 2.4.3 默认类在哪配

`Project Settings → Maps & Modes`：

- `Default GameMode` → 你的 `AGameMode` 子类；
- `Default Pawn Class`（在 GameMode 构造函数里设）→ 你的 `ACharacter` 子类；
- `Player Controller Class`、`Game State Class`、`Player State Class`、`HUD Class`。

也可以在 C++ 构造函数里指定：

```cpp
AMyGameMode::AMyGameMode()
{
    DefaultPawnClass      = AMyCharacter::StaticClass();
    PlayerControllerClass = AMyPlayerController::StaticClass();
    GameStateClass        = AMyGameState::StaticClass();
    PlayerStateClass      = AMyPlayerState::StaticClass();
    HUDClass              = AMyHUD::StaticClass();
}
```

> **对标 Spring Boot**：GameMode ≈ `@Configuration` + 规则服务，GameState ≈ 共享的 Application 作用域 Bean，PlayerState ≈ Session 作用域 Bean，Controller ≈ 请求入口。不同点：UE 里的"作用域"是**网络拓扑**决定的，不是 IoC 容器。

## 2.5 生命周期与初始化顺序

### 2.5.1 Actor 生命周期

```text
【构造函数】        UObject 构造，CDO（类默认对象）也走这里
   │                ✅ CreateDefaultSubobject、设默认值
   ▼
【PostInitializeComponents】  组件都已创建，可安全互相引用
   ▼
【BeginPlay】       ⭐ 游戏开始时（或 Spawn 时）；Spawn 参数已生效
   ▼
【Tick(DeltaTime)】 每帧（可关闭）
   ▼
【EndPlay】         ⭐ 销毁前；原因参数 EEndPlayReason::Type
   ▼
【BeginDestroy / GC】
```

```cpp
AMyActor::AMyActor()
{
    PrimaryActorTick.bCanEverTick = true;      // 默认 false！不开就不会 Tick
    PrimaryActorTick.TickInterval = 0.f;

    Root = CreateDefaultSubobject<USceneComponent>(TEXT("Root"));
    RootComponent = Root;
    Mesh = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("Mesh"));
    Mesh->SetupAttachment(Root);
}

void AMyActor::BeginPlay()
{
    Super::BeginPlay();                         // ⚠️ 永远先调 Super
    UE_LOG(LogTemp, Warning, TEXT("BeginPlay: %s"), *GetName());
}

void AMyActor::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    AddActorWorldOffset(FVector::ForwardVector * Speed * DeltaTime);
}

void AMyActor::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
    // 解绑委托、清定时器、释放资源
    Super::EndPlay(EndPlayReason);
}
```

**Construction Script / OnConstruction**：编辑器里拖动/改属性时重跑（`virtual void OnConstruction(const FTransform& Transform) override`），适合做"程序化摆件"，**不要在这里写游戏逻辑**。

### 2.5.2 Pawn / Character 额外钩子

| 钩子 | 时机 |
| --- | --- |
| `PossessedBy(AController*)` | 服务器：被 Controller 控制 |
| `OnRep_Controller()` | 客户端：Controller 复制到位 |
| `SetupPlayerInputComponent(UInputComponent*)` | 输入组件就绪，**绑定输入的地方** ⭐ |
| `Restart()` | 重生 |
| `Landed(const FHitResult&)` | 落地（Character） |
| `OnMovementModeChanged` | 移动模式切换（走/飞/游泳） |

### 2.5.3 常见初始化坑

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 在构造函数里 `GetWorld()` / 找别的 Actor | 世界还没就绪，返回 null | 放 `BeginPlay` |
| 构造函数里 `SpawnActor` | CDO 也会执行，产生幽灵对象 | 放 `BeginPlay` 或 `PostInitializeComponents` |
| 忘 `Super::BeginPlay()` | 父类初始化缺失，玄学 bug | 全部重写函数第一行调 Super |
| 忘 `PrimaryActorTick.bCanEverTick = true` | Tick 不跑 | 构造函数开启 |
| Tick 里 `GetAllActorsOfClass` / `Cast` 大循环 | 帧率暴跌 | 缓存引用、事件驱动、定时器 |
| 忘乘 `DeltaTime` | 帧率不同速度不同 | 一切"每帧变化"乘 DeltaTime |

## 2.6 UE 常用类型与容器（C++ UE 方言）

### 2.6.1 字符串三兄弟

| 类型 | 用途 | 注意 |
| --- | --- | --- |
| `FString` | 可变字符串、拼接、日志 | 类似 `std::string`；`TEXT("中文")` 宏包起来 |
| `FName` | 标识符（名字、标签），**大小写不敏感、比较极快** | 存为全局表，适合频繁比较；不适合拼接 |
| `FText` | **面向玩家显示的文本**（可本地化） | UI 一律用 FText |

```cpp
FString Name = TEXT("玩家");
FString Msg = FString::Printf(TEXT("分数: %d"), Score);
UE_LOG(LogTemp, Warning, TEXT("%s"), *Msg);     // ⚠️ *Msg 解引用成 TCHAR*
FName BoneName(TEXT("spine_03"));
FText Title = FText::FromString(TEXT("开始游戏"));
FText Localized = NSLOCTEXT("MyGame", "StartBtn", "Start Game");
```

> ⚠️ `UE_LOG` 里 `%s` 必须配 `*FString`，这是新手编译错误第一名。

### 2.6.2 容器

```cpp
TArray<int32> Nums = {1, 2, 3};
Nums.Add(4);
Nums.RemoveAt(0);
for (int32 N : Nums) { }

TMap<FName, int32> Scores;
Scores.Add(TEXT("Alice"), 10);
if (auto* V = Scores.Find(TEXT("Alice"))) { }

TSet<AActor*> Visited;
TArray<TObjectPtr<AActor>> Tracked;   // UPROPERTY 里用 TObjectPtr
```

| 容器 | 对标 | 说明 |
| --- | --- | --- |
| `TArray` | `List` / `vector` | 最常用，连续内存 |
| `TMap` | `HashMap` / `dict` | 无序 |
| `TSet` | `HashSet` | 去重 |
| `TQueue` / `TDoubleLinkedList` | — | 特殊场景 |
| `TOptional<T>` | `Optional` | 可空值 |

> 与 STL 互转一般不必要；UE 容器自带内存分配器与序列化支持，**在 UE 代码里优先用 T 系列**。

### 2.6.3 数学类型

```cpp
FVector  Loc(0, 0, 100);                 // 位置/方向 (double 精度在 UE5 大型世界)
FRotator Rot(0, 90, 0);                  // Pitch/Yaw/Roll
FTransform T(Rot, Loc, FVector(1));      // 旋转+平移+缩放
FQuat Q = Rot.Quaternion();              // 四元数（避免万向节死锁）
FVector Dir = FRotationMatrix(Rot).GetUnitAxis(EAxis::X);

float D = FVector::Distance(A, B);
FVector Lerp = FMath::Lerp(A, B, 0.5f);
float Clamped = FMath::Clamp(V, 0.f, 1.f);
```

## 2.7 委托与事件（UE 的"回调"）

对标 C# `event/delegate`、Java 函数式接口、Qt 信号槽。

| 类型 | 说明 | 典型 |
| --- | --- | --- |
| `DECLARE_DELEGATE` | 单播，纯 C++ | 内部回调 |
| `DECLARE_MULTICAST_DELEGATE` | 多播，纯 C++（**不序列化、蓝图不可见**） | 模块内广播 |
| `DECLARE_DYNAMIC_MULTICAST_DELEGATE` | 多播，**可序列化、蓝图可绑定、可用于复制** ⭐ | `OnComponentBeginOverlap`、自定义 `OnPickedUp` |
| `DECLARE_DYNAMIC_DELEGATE` | 单播动态 | 蓝图事件 |
| `BlueprintAssignable` | UPROPERTY 标记，让蓝图能 Bind | 组件事件 |

```cpp
// 声明（.h 类外）
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnPickedUpSignature, AActor*, PickupActor);

UCLASS()
class MYGAME_API AMyPickup : public AActor
{
    GENERATED_BODY()
public:
    UPROPERTY(BlueprintAssignable, Category = "Events")
    FOnPickedUpSignature OnPickedUp;      // 蓝图里可 Add Event / Bind
};

// 触发
OnPickedUp.Broadcast(this);

// C++ 绑定
SomePickup->OnPickedUp.AddDynamic(this, &UMyWidget::HandlePickedUp);   // 函数必须 UFUNCTION()
// 解绑（EndPlay 里！）
SomePickup->OnPickedUp.RemoveDynamic(this, &UMyWidget::HandlePickedUp);
```

**三条规则**：

1. `AddDynamic` 绑定的函数**必须标记 `UFUNCTION()`**（动态委托依赖反射）；
2. 绑定对象销毁前要 `RemoveDynamic` / 或用 `AddUObject` + `TWeakObjectPtr`；
3. **Tick 里不要反复 Bind**，会累积成 N 次触发。

> 定时器、异步回调也建议用 `TWeakObjectPtr` 捕获，避免对象已销毁还回调。

## 2.8 C++ 与蓝图互操作（商业项目最常用分工）

**推荐架构**：`C++ 基类（性能敏感逻辑、数据、网络） → 蓝图派生（表现、调参、组装）`。

### 2.8.1 暴露给蓝图的完整标记表

```cpp
UCLASS(Blueprintable, BlueprintType)        // 可派生为蓝图 / 可作为蓝图变量类型
class MYGAME_API AMyActor : public AActor
{
    GENERATED_BODY()
public:
    // 属性
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Combat")
    float MaxHealth = 100.f;

    UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Combat")
    TObjectPtr<UStaticMeshComponent> Mesh;

    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Combat")
    TObjectPtr<USoundBase> PickupSound;

    // 函数：蓝图可直接调用
    UFUNCTION(BlueprintCallable, Category = "Combat")
    void TakeDamage(float Amount);

    // 函数：C++ 实现，蓝图可覆盖（有默认实现）
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "Combat")
    void OnDeath();
    virtual void OnDeath_Implementation();     // ⚠️ 必须实现 _Implementation

    // 事件：C++ 只声明，蓝图实现（C++ 不写实现）
    UFUNCTION(BlueprintImplementableEvent, Category = "Combat")
    void OnScoreChanged(int32 NewScore);

    // 纯函数（无副作用，蓝图里是纯节点）
    UFUNCTION(BlueprintPure, Category = "Combat")
    float GetHealthPercent() const;
};
```

### 2.8.2 `UPROPERTY` 说明符速查

| 说明符 | 含义 |
| --- | --- |
| `EditAnywhere` | Details 面板可编辑（实例 + 原型） |
| `EditDefaultsOnly` | 只能在蓝图默认值/原型里改（实例不可改） |
| `EditInstanceOnly` | 只能改关卡里的这个实例 |
| `VisibleAnywhere` / `VisibleDefaultsOnly` / `VisibleInstanceOnly` | 只读显示 |
| `BlueprintReadWrite` / `BlueprintReadOnly` | 蓝图读写 / 只读 |
| `Category = "X\|Y"` | 分组（`|` 表示子分类） |
| `Replicated` / `ReplicatedUsing=OnRep_X` | 网络复制 |
| `Transient` | 不序列化 |
| `meta = (ClampMin = "0", UIMin = "0")` | 编辑器约束 |
| `meta = (AllowPrivateAccess = "true")` | private 成员也可蓝图访问 |
| `meta = (ExposeOnSpawn = "true")` | Spawn 节点上可直接填 |

### 2.8.3 `UFUNCTION` 说明符速查

| 说明符 | 含义 |
| --- | --- |
| `BlueprintCallable` | 蓝图可调用 |
| `BlueprintPure` | 纯函数（无执行引脚） |
| `BlueprintImplementableEvent` | 蓝图实现，C++ 不实现 |
| `BlueprintNativeEvent` | C++ 有默认实现（`_Implementation`），蓝图可覆盖 |
| `BlueprintAuthorityOnly` | 仅服务器执行 |
| `Server` / `Client` / `NetMulticast` | RPC（见 2.12） |
| `Exec` | 可在控制台输入调用 |
| `CallInEditor` | Details 面板上放按钮 |

### 2.8.4 互操作的性能与规范

| 建议 | 原因 |
| --- | --- |
| **每帧逻辑放 C++**，蓝图只做事件响应 | VM 字节码调用开销约 C++ 的 10 倍以上 |
| 蓝图里避免大 `ForLoop`、复杂数学 | 同上 |
| C++ 用 `BlueprintPure` 提供确定性查询 | 蓝图侧保持可读 |
| 资产引用用 `TSoftObjectPtr` + 异步加载 | 避免蓝图硬引用把整个资源树拉进内存 |
| 避免在蓝图里 `Cast` 到重型类形成循环引用 | 用接口 `UINTERFACE` 解耦 |
| 用 `UINTERFACE(Blueprintable)` 定义交互接口 | `IInteractable`，比 Cast 更干净 |

## 2.9 输入：Enhanced Input（UE5 默认）

UE5 用 **Input Action (IA) + Input Mapping Context (IMC)** 取代 UE4 的 Axis/Action 映射。

```text
IA_Interact（数字/布尔）
IA_Move（Axis2D）, IA_Look（Axis2D）
        │
        ▼
IMC_Default：把按键映射到 IA，可加 Modifier（Negate/Swizzle/Scale）
             + Trigger（Pressed/Released/Hold/Tap/Chord）
        │
        ▼
PlayerController / Character 里 AddMappingContext
        │
        ▼
UEnhancedInputComponent->BindAction(IA, ETriggerEvent::Triggered, this, &Func)
```

### 2.9.1 代码绑定

```cpp
#include "EnhancedInputComponent.h"
#include "EnhancedInputSubsystems.h"
#include "InputAction.h"
#include "InputMappingContext.h"

// --- 角色 .h ---
UPROPERTY(EditDefaultsOnly, Category = "Input")
TObjectPtr<UInputMappingContext> DefaultMappingContext;

UPROPERTY(EditDefaultsOnly, Category = "Input")
TObjectPtr<UInputAction> MoveAction;

UPROPERTY(EditDefaultsOnly, Category = "Input")
TObjectPtr<UInputAction> LookAction;

UPROPERTY(EditDefaultsOnly, Category = "Input")
TObjectPtr<UInputAction> InteractAction;

void Move(const FInputActionValue& Value);
void Look(const FInputActionValue& Value);
void Interact();

// --- 角色 .cpp ---
void AMyCharacter::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    Super::SetupPlayerInputComponent(PlayerInputComponent);

    // 1. 添加映射上下文（本地玩家才有 Subsystem）
    if (APlayerController* PC = Cast<APlayerController>(Controller))
    {
        if (UEnhancedInputLocalPlayerSubsystem* Sub =
                ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(PC->GetLocalPlayer()))
        {
            Sub->AddMappingContext(DefaultMappingContext, 0);   // 优先级 0
        }
    }

    // 2. 绑定 Action
    if (UEnhancedInputComponent* EI = Cast<UEnhancedInputComponent>(PlayerInputComponent))
    {
        EI->BindAction(MoveAction,     ETriggerEvent::Triggered, this, &AMyCharacter::Move);
        EI->BindAction(LookAction,     ETriggerEvent::Triggered, this, &AMyCharacter::Look);
        EI->BindAction(InteractAction, ETriggerEvent::Started,   this, &AMyCharacter::Interact);
    }
}

void AMyCharacter::Move(const FInputActionValue& Value)
{
    const FVector2D V = Value.Get<FVector2D>();
    const FRotator Yaw(0.f, Controller->GetControlRotation().Yaw, 0.f);
    AddMovementInput(FRotationMatrix(Yaw).GetUnitAxis(EAxis::X), V.Y);
    AddMovementInput(FRotationMatrix(Yaw).GetUnitAxis(EAxis::Y), V.X);
}

void AMyCharacter::Look(const FInputActionValue& Value)
{
    const FVector2D V = Value.Get<FVector2D>();
    AddControllerYawInput(V.X);
    AddControllerPitchInput(-V.Y);
}
```

> **操作流程**：Content Browser 右键 `Input → Input Action` 建 IA；`Input → Input Mapping Context` 建 IMC 并绑定按键/Modifier；在角色蓝图默认值里把 IA/IMC 填进上面的 UPROPERTY；`Project Settings → Input → Default Classes` 确认 Enhanced Input 类已启用。
>
> **UE4 提示**：UE4 用 `BindAxis("MoveForward", ...)` + `DefaultInput.ini` 里的 AxisMappings，无 IMC/Subsystem 概念。

### 2.10.3 射线检测（交互/射击的核心）

```cpp
void AMyCharacter::Interact()
{
    if (!Controller) return;

    FVector Start;
    FRotator Rot;
    Controller->GetPlayerViewPoint(Start, Rot);           // 从相机出发
    const FVector End = Start + Rot.Vector() * 500.f;     // 5 米（厘米单位！）

    FCollisionQueryParams Params(SCENE_QUERY_STAT(Interact), /*bTraceComplex*/ true);
    Params.AddIgnoredActor(this);

    FHitResult Hit;
    const bool bHit = GetWorld()->LineTraceSingleByChannel(
        Hit, Start, End, ECC_Visibility, Params);

    if (bHit)
    {
        // 方式一：接口（推荐，解耦）
        if (IInteractable* It = Cast<IInteractable>(Hit.GetActor()))
        {
            It->Interact(this);
        }
        // 方式二：直接 Cast
        else if (AMyPickup* P = Cast<AMyPickup>(Hit.GetActor()))
        {
            P->Collect(this);
        }
    }

    DrawDebugLine(GetWorld(), Start, End, bHit ? FColor::Green : FColor::Red,
                  false, 1.5f, 0, 1.f);                  // 需 #include "DrawDebugHelpers.h"
}
```

| 检测函数 | 用途 |
| --- | --- |
| `LineTraceSingleByChannel` | 单条射线，第一个命中 |
| `LineTraceMultiByChannel` | 返回所有命中（穿透） |
| `SweepSingleByChannel` | 带形状扫掠（球形检测） |
| `OverlapMultiByObjectType` | 范围查询（爆炸、AOE） |
| `KismetSystemLibrary` 系列 | 蓝图友好版，带可视化调试 |

> **调试技巧**：先用 `DrawDebugLine` 把射线画出来，90% 的"射线打不中"是起点/方向/通道/Collision Profile 四者之一错了。

## 2.11 定时器、异步与 UMG

### 2.11.1 定时器

```cpp
FTimerHandle RespawnHandle;

// 一次性
GetWorldTimerManager().SetTimer(RespawnHandle, this, &AMyActor::Respawn, 3.f, false);

// 循环
GetWorldTimerManager().SetTimer(RespawnHandle, this, &AMyActor::TickEveryHalfSec, 0.5f, true);

```

### 2.11.3 UMG（UI）

```
UUserWidget（蓝图派生，Widget Blueprint 里设计布局）
   ├── 用 UPROPERTY(meta=(BindWidget)) 绑定控件
   ├── NativeConstruct() ≈ 构造后初始化
   └── 由 PlayerController / HUD 用 CreateWidget + AddToViewport 创建
```

```cpp
// .h
UCLASS()
class MYGAME_API UMyHUDWidget : public UUserWidget
{
    GENERATED_BODY()
public:
    UPROPERTY(meta = (BindWidget))
    TObjectPtr<UTextBlock> ScoreText;        // 名字必须与 Widget 蓝图里的控件一致

    UFUNCTION(BlueprintCallable)
    void SetScore(int32 NewScore);

    virtual void NativeConstruct() override;
};

// 创建（PlayerController::BeginPlay）
UPROPERTY(EditDefaultsOnly)
TSubclassOf<UUserWidget> HUDWidgetClass;

HUDWidget = CreateWidget<UMyHUDWidget>(this, HUDWidgetClass);
if (HUDWidget) { HUDWidget->AddToViewport(); }
```

> **对标 Java**：`meta=(BindWidget)` ≈ `@Autowired` 按名字注入，但实际是 UHT + 序列化绑定，名字对不上会在运行时报错并提示。
>
> UI 数据更新**用事件驱动**（委托广播 → Widget 更新），不要在 `NativeTick` 里每帧刷文本。

## 2.12 网络复制与 RPC（联机必过的一关）

### 2.12.1 三条铁律

1. **服务器是权威**：所有影响游戏状态的判定必须在服务器做；
2. **只复制结果，不复制过程**：血量、分数、位置由服务器算出并同步；
3. **客户端不信任**：客户端发来的 RPC 服务器要校验。

### 2.12.2 开启复制

```cpp
AMyPickup::AMyPickup()
{
    bReplicates = true;                       // ⚠️ 必须
    bReplicateMovement = true;                // 需要同步移动时
    // SetReplicateMovement(true); 运行时也可
}

void AMyPickup::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AMyPickup, bCollected);
    DOREPLIFETIME_CONDITION(AMyPickup, SecretData, COND_OwnerOnly);  // 条件复制
}
// ⚠️ .cpp 必须 #include "Net/UnrealNetwork.h"
```

### 2.12.3 `UPROPERTY(ReplicatedUsing)` 与 OnRep

```cpp
UPROPERTY(ReplicatedUsing = OnRep_Collected, BlueprintReadOnly)
bool bCollected = false;

UFUNCTION()
void OnRep_Collected();    // ⚠️ 必须 UFUNCTION

void AMyPickup::OnRep_Collected()
{
    SetActorHiddenInGame(bCollected);     // 客户端收到新值后做表现
}
```

> **注意**：OnRep **只在客户端**触发。服务器上改完值要自己调一次表现逻辑（或写成两边都调用的公共函数）。

### 2.12.4 三种 RPC

| 标记 | 从哪调用 | 在哪执行 | 典型 |
| --- | --- | --- | --- |
| `UFUNCTION(Server, Reliable, WithValidation)` | 客户端（拥有该 Actor） | **服务器** | 开火、交互请求、使用道具 |
| `UFUNCTION(Client, Reliable)` | 服务器（拥有者） | **该客户端** | 专属提示、UI 反馈 |
| `UFUNCTION(NetMulticast, Unreliable)` | 服务器 | **服务器 + 所有客户端** | 特效、音效、命中反馈 |

```cpp
// .h
UFUNCTION(Server, Reliable, WithValidation)
void ServerRequestCollect(AMyPickup* Target);

UFUNCTION(NetMulticast, Unreliable)
void MulticastPlayPickupFX();

// .cpp
bool AMyCharacter::ServerRequestCollect_Validate(AMyPickup* Target)
{
    return IsValid(Target);               // 防作弊：简单校验
}

void AMyCharacter::ServerRequestCollect_Implementation(AMyPickup* Target)
{
    if (!HasAuthority() || !IsValid(Target)) return;

    // 距离校验（别信客户端）
    if (FVector::Dist(GetActorLocation(), Target->GetActorLocation()) > 300.f) return;

    Target->Collect(this);                // 只改服务器状态
    MulticastPlayPickupFX();              // 广播表现
}

void AMyCharacter::MulticastPlayPickupFX_Implementation()
{
    // 播特效/音效（本地表现，不改游戏状态）
}
```

> ⚠️ **RPC 的 `_Implementation` 后缀是 UHT 要求的**，调用时写 `ServerRequestCollect(...)`，实现写 `ServerRequestCollect_Implementation(...)`。
> `Reliable` 保证到达但占带宽（重要事件）；`Unreliable` 可能丢（特效）。`WithValidation` 在新版本可用 `Server` 自带校验替代，写法随版本略有差异，以你所用版本的编译提示为准。

### 2.12.5 权限判断

```cpp
if (HasAuthority()) { ... }                    // 是否在服务器
if (GetLocalRole() == ROLE_Authority) { ... }
if (IsLocallyControlled()) { ... }             // 是否本地控制（做输入/相机/UI）
if (GetNetMode() == NM_Standalone) { ... }     // 单机（PIE 里常见）
```

**常见 bug 速查**：

| 症状 | 原因 |
| --- | --- |
| 客户端改了变量但服务器没变 | 客户端 RPC 没调 / 没在 Owning Actor 上调 |
| 只有主机看到效果 | 用了本地逻辑而非 `NetMulticast` |
| OnRep 不触发 | 忘 `bReplicates` / 忘 `DOREPLIFETIME` / 服务器值没真变 |
| 编译报 `GetLifetimeReplicatedProps` 未定义 | 忘 `#include "Net/UnrealNetwork.h"` |
| 客户端能作弊改分数 | 判定写在客户端了，应只发请求、服务器裁决 |

## 2.13 GAS 与 UE5 渲染/世界构建（了解层）

### 2.13.1 GAS（Gameplay Ability System）

大型项目做"技能/属性/状态效果"的事实标准框架，代价是学习曲线陡。

| 概念 | 作用 |
| --- | --- |
| **AbilitySystemComponent (ASC)** | 挂在 Actor 上的核心组件 |
| **UGameplayAbility (GA)** | 一个技能（火球、冲刺），有激活条件/冷却/消耗 |
| **UAttributeSet** | 属性（Health、Mana、Speed），支持复制 |
| **UGameplayEffect (GE)** | 改属性的统一方式（伤害、Buff、回血），Instant/Duration/Infinite |
| **FGameplayTag** | 层次化标签（`State.Stunned`、`Cooldown.Skill.Fire`），替代布尔地狱 |
| **GameplayCue** | 表现层（特效/音效），与逻辑解耦且自动网络同步 |
| **AbilityTask** | 异步技能流程（播放蒙太奇、等待事件） |

> 启用：`.Build.cs` 加 `GameplayAbilities`、`GameplayTags`、`GameplayTasks`；插件启用 **Gameplay Ability System**。**小项目不要一上来用 GAS**，普通 `float Health` + 函数足够，等技能数量爆炸再重构。

### 2.13.2 UE5 渲染三件套

| 特性 | 解决什么 | 什么时候关 |
| --- | --- | --- |
| **Nanite** | 虚拟几何体，超高面数模型自动 LOD，几乎不用手工做 LOD | 移动端/低配、半透明/蒙皮网格（支持有限）、需要逐像素顶点动画时 |
| **Lumen** | 动态全局光照 + 反射，无需烘焙 Lightmap | 低配/移动端；追求极致性能时改烘焙光照或 SSGI |
| **Virtual Shadow Maps** | 高分辨率阴影，配合 Nanite | 低配、VR |

```text
Project Settings → Rendering
  ├─ Dynamic Global Illumination Method: Lumen
  ├─ Reflection Method: Lumen
  ├─ Shadow Map Method: Virtual Shadow Maps
  └─ Generate Mesh Distance Fields: ✅（Lumen 软件追踪需要）
```

> **和 [opengl-learning](../opengl-learning/README.md) 连起来看**：Nanite 本质是 GPU 驱动的可见性/LOD 与簇剔除，Lumen 是屏幕空间 + 距离场/光线追踪的混合 GI，VSM 是分块页表式阴影贴图——都是"用空间换时间 + 只算看得见的"这一图形学老思路的工程化。

### 2.13.3 World Partition / One File Per Actor

- **World Partition**：大世界自动网格化，按距离流式加载单元；
- **One File Per Actor (OFPA)**：每个 Actor 存独立文件 → 多人同时编辑同一关卡不再冲突（配合 Perforce/Git LFS）；
- **Data Layers / HLOD**：分层加载与远距离代理；
- 小项目不必开，普通关卡更简单。

## 2.17 常见踩坑总表

| 坑 | 症状 | 解决 |
| --- | --- | --- |
| 忘 `#include "X.generated.h"` 或不在最后 | C1083 / 编译怪错 | 每个 UCLASS 头文件最后一个 include |
| UObject 成员没 `UPROPERTY` | 随机崩溃、悬空指针 | 用 `TObjectPtr` + `UPROPERTY`，或 `AddToRoot` |
| 对 UObject 用 `new/delete` | 崩溃 | `NewObject` / `SpawnActor` / 去引用等 GC |
| 构造函数里访问 World / SpawnActor | null、幽灵对象 | 挪到 `BeginPlay` |
| 忘 `Super::BeginPlay()` | 玄学 bug | 重写函数第一行调 Super |
| 忘 `bCanEverTick` | Tick 不跑 | 构造函数开启 |
| 忘乘 `DeltaTime` | 帧率影响速度 | 每帧变化乘 DeltaTime |
| `UE_LOG` 里 `%s` 没写 `*FString` | 编译错 | `*Msg` |
| 忘 `.Build.cs` 模块 | unresolved external | 加 `EnhancedInput` / `UMG` / `GameplayAbilities` |
| 改头文件后 Live Coding | 崩溃 | 关闭编辑器完整重编，必要时删 `Intermediate`/`Binaries` |
| 客户端改状态不同步 | 只有主机看到 | `bReplicates` + `DOREPLIFETIME` + OnRep / Multicast |
| OnRep 服务器不触发 | 主机 UI 不刷新 | 主动在服务器调一次表现/广播 |
| RPC 客户端调了没反应 | 未在 Owning Actor 调 | Server RPC 只能由拥有该 Actor 的客户端发起 |
| `AddDynamic` 没解绑 | 重复触发、崩溃 | `EndPlay` 里 `RemoveDynamic` |
| 蓝图硬引用大资产 | 启动慢、内存爆 | `TSoftObjectPtr` + 异步加载 |
| Tick 里 `GetAllActorsOfClass` / `Cast` | 掉帧 | 缓存 + 事件驱动 |
| 单位/坐标轴搞错 | 模型位置不对 | UE：cm、Z-up、左手系；Unity：m、Y-up |
| UI 每帧刷文本 | 无谓开销 | 委托事件驱动 |
| Shipping 里 `stat`/日志失效 | 排查困难 | 用 Development 版复现，或自建日志上报 |

## 2.18 面试高频问题

**Q1. 为什么 UE 要搞 UHT/反射，而不是直接用标准 C++？**

A：为了获得序列化、GC 追踪、编辑器属性面板、蓝图互操作、网络复制、按名查找等能力。UHT 扫描 `UCLASS/UPROPERTY/UFUNCTION` 宏生成 `*.generated.h` 与 `*.gen.cpp` 注册元数据，UBT 再编译。代价是必须遵守宏与文件命名约定、编译变慢。

**Q2. UPROPERTY 除了"编辑器可见"还承担什么？**

A：四件事——GC 引用根（决定对象是否被回收）、序列化（存档/资产保存）、蓝图可见性、网络复制标记。漏写 UPROPERTY 持有 UObject 是 UE 最常见的悬空指针崩溃来源。

**Q3. GameMode / GameState / PlayerState / PlayerController 的分工？**

A：GameMode 只存于服务器管规则；GameState 复制到所有客户端存全局状态；PlayerState 存每个玩家的数据并复制；PlayerController 是玩家意志（输入、Possess、HUD、RPC 入口）；Pawn/Character 是躯体。**"规则只在服务器、状态要复制"**是核心。

**Q4. Server RPC 为什么常常"调了没反应"？**

A：Server RPC 只能由**拥有该 Actor 的客户端**向服务器发起。常见错误是在一个客户端不拥有的 Actor（如别人的 Pawn、非拥有的世界 Actor）上调用，或未开 `bReplicates`。应把请求发到玩家自己拥有的 PlayerController/Pawn，由服务器转发处理。

**Q5. `BlueprintNativeEvent` 和 `BlueprintImplementableEvent` 区别？**

A：前者 C++ 提供默认实现（写 `FuncName_Implementation`），蓝图可覆盖；后者 C++ 只声明不实现，必须由蓝图实现。两者都是 C++ → 蓝图方向的扩展点。

**Q6. UE5 的 Enhanced Input 相比 UE4 改进在哪？**

A：把"按键 → 语义动作"解耦成 Input Action + Input Mapping Context，支持运行时按优先级动态增删映射（如载具/菜单切换输入）、Modifier（Swizzle/Negate）与 Trigger（Hold/Tap/Chord），无需在 ini 里写死 Axis 映射。

**Q7. Tick 里该避免什么？怎么替代？**

A：避免 `GetAllActorsOfClass`、复杂循环、高频 `Cast`、字符串操作、同步加载资产、刷 UI。替代：缓存引用、事件/委托驱动、定时器、异步加载、`bCanEverTick=false`、对象池。

**Q8. 客户端上改了 Replicated 变量为什么不生效？**

A：复制是**服务器 → 客户端单向**的。客户端改本地副本会被服务器下一次复制覆盖，且不会传播。正确做法：客户端发 Server RPC，服务器校验后改状态，再由 `OnRep` / Multicast 同步表现。
