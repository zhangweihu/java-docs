>
> 面向：零基础转 UE 的程序员、从 Unity/Java/C# 转来的开发者、准备投 UE 岗位的读者。

## 3.1 先看岗位分工：不同角色要的东西完全不同

UE 项目是**强协作**工程，"学 UE"这四个字对不同岗位含义差别极大。先定位，再学习，能省掉大量无用功。

| 岗位 | 主要产出 | 核心技能 | 语言/工具 | 与本章关系 |
| --- | --- | --- | --- | --- |
| **Gameplay 程序** | 玩法、角色、战斗、任务、UI 逻辑 | Gameplay Framework、C++/蓝图、输入、碰撞、GAS、网络复制 | C++ + 蓝图 + UMG | ⭐ **本专题主目标** |
| **引擎程序** | 改引擎、定制模块、性能与内存、平台适配 | C++ 深度、渲染/物理/网络子系统、UBT/UHT、构建与 CI | 纯 C++、源码版引擎 | 3.3 进阶层 |
| **渲染 / 图形程序** | 材质、Shader、后处理、渲染特性 | HLSL、渲染管线、PBR、GPU 优化、Nanite/Lumen | HLSL + C++ + RenderDoc | 需补 [opengl-learning](../opengl-learning/README.md) |
| **网络程序** | 联机同步、专用服务器、反作弊 | Replication、RPC、预测回滚、网络协议、带宽优化 | C++ + Insights | 3.3 / 3.4 |
| **工具 / 管线程序** | 编辑器插件、自动化导入、构建流水线 | Slate、编辑器模块、Python Editor Scripting、UAT | C++ / Python | 3.4 |
| **技术美术 TA** | 材质体系、特效、性能与美术规范的桥 | 节点材质、HLSL 入门、Niagara、性能分析、DCC 工具 | 材质编辑器 + HLSL + Python | 3.3 图形学 |
| **关卡设计 LD** | 关卡、节奏、玩法布置 | 编辑器、World Partition、蓝图、光照、寻路 | 蓝图为主 | [第 01 章](./01-UE引擎使用与编辑器指南.md) |
| **3D / 动画 / 特效 / 音频** | 资产生产 | DCC 工具（Maya/Blender/Substance/Houdini）、骨骼绑定、规范 | 编辑器 + DCC | 本章只讲协作接口 |
| **策划** | 规则、数值、关卡文档 | 数据表、蓝图调参、GameMode 概念 | Excel / DataTable / 蓝图 | 3.2 基础层 |

> **给转行者的建议**：**先按 Gameplay 程序入门**（覆盖面最广、最能理解全貌），工作 1~2 年后再按兴趣分叉到引擎/渲染/网络/工具。一上来专攻渲染或引擎底层，容易因为不懂玩法框架而"写得出来但接不进项目"。

### 3.1.1 一张图看懂协作链

```text
策划（规则/数值 DataTable）
   │
   ├──► Gameplay 程序（C++ 基类 + 蓝图流程）◄──► 关卡设计（摆场景/脚本）
   │            │                                      │
   │            ▼                                      ▼
   │     引擎/网络/工具程序（框架支撑）          美术/TA（资产 + 材质 + 特效）
   │            │                                      │
   └────────────┴────────► 构建 / QA / 发布 ◄────────┘
```

**程序员必须理解的三个协作接口**：

1. **资产规范**：命名前缀（`SM_`/`SK_`/`M_`/`MI_`/`T_`/`BP_`/`WBP_`）、单位（cm）、坐标轴、LOD/碰撞体约定、纹理尺寸；
2. **数据表驱动**：策划改 `DataTable` / `DataAsset` 就能调数值，程序不要在 C++ 里写死常量；
3. **版本控制**：二进制 `.uasset` 无法文本合并 → **文件锁 / OFPA / 明确 ownership**，谁改哪个文件要沟通。

## 3.3 逐层知识点清单

### 3.3.1 L1 基础层

#### ① C++ 实用子集【必需】

UE 用的是"C++17 的一个方言"，**不需要先精通现代 C++ 全家桶**，但下面这些必须会：

| 知识点 | 要求 | 说明 |
| --- | --- | --- |
| 类 / 继承 / 虚函数 / override | 熟练 | ACharacter 派生、BeginPlay/Tick 重写 |
| 头文件与编译单元、前向声明 | 熟练 | 减少编译依赖，UE 编译很慢 |
| 指针 / 引用 / const | 熟练 | `TObjectPtr`、弱引用 |
| 模板基础 | 会读 | `TArray<T>`、`Cast<T>`、`NewObject<T>` |
| 构造/析构顺序 | 理解 | 构造函数 vs BeginPlay |
| `enum class` / `struct` | 熟练 | `EEnum`、`FHitResult` |
| Lambda / 函数对象 | 会写 | 定时器回调、异步委托 |
| 命名空间 / static | 会用 | 工具类、日志分类 |
| 内存模型（栈/堆/RAII） | 理解 | **但 UObject 不用 new/delete** |

**可以先跳过的**（用到再学）：移动语义细则、模板元编程、`std::` 容器全家桶、`std::shared_ptr`（UE 里基本不用）、协程、复杂 SFINAE。

> **给 Java/C# 读者的关键差异**：C++ 没有 GC（但 UE 的 UObject **有**自己的 GC）、值类型/引用类型由你决定、头文件要手动 include、编译期报错比运行时多、崩溃会直接进程退出而不是抛异常。**先接受"编译错误是朋友"**。

#### ② 3D 数学【必需】

| 知识点 | 用在哪 | 重要度 |
| --- | --- | --- |
| 向量（加减、点积、叉积、归一化、距离） | 移动、朝向、射线、AI | ⭐⭐⭐ |
| 坐标系与空间变换（世界/局部、MVP 概念） | 组件挂接、相机、模型对齐 | ⭐⭐⭐ |
| 矩阵（旋转矩阵、视图/投影直觉） | 相机、动画、Shader | ⭐⭐ |
| 角度与弧度、`FRotator` 的 Pitch/Yaw/Roll | 角色朝向、炮塔 | ⭐⭐⭐ |
| **四元数**（为什么能避免万向节死锁） | 平滑旋转、动画 | ⭐⭐ |
| 插值 `Lerp` / `Slerp` / 缓动 | 动画、相机跟随、UI | ⭐⭐⭐ |
| 射线与几何求交（射线/球体/AABB） | 射击、拾取、视线检测 | ⭐⭐ |
| 基础物理（速度、加速度、重力） | 移动、抛体 | ⭐⭐ |

**UE 特有约定（背下来）**：

```text
坐标系：左手系，X 前 / Y 右 / Z 上
单位：厘米（cm）—— 1 米 = 100 单位
角度：度（Degree），不是弧度
旋转顺序：FRotator(Pitch=绕Y, Yaw=绕Z, Roll=绕X)
```

> 从 Unity 转过来最容易在这里翻车（Unity：Y 上、米、右手系）。**先把"500 = 5 米"刻进脑子**。

#### ③ 图形学常识【推荐】

不必先学完 [opengl-learning](../opengl-learning/README.md)，但下面概念要"听得懂"：

| 概念 | 为什么需要 |
| --- | --- |
| 渲染管线（顶点 → 光栅化 → 片元 → 输出） | 理解材质、Shader、后处理在干什么 |
| DrawCall / 批处理 / LOD | 性能调优的第一语言 |
| 纹理、采样、UV、Mipmap | 材质与贴图问题定位 |
| 深度测试 / 混合 / 半透明排序 | 常见画面 bug |
| PBR（BaseColor/Metallic/Roughness/Normal） | UE 材质就是 PBR 参数化 |
| 光照与阴影基础 | Lumen / VSM 的选项含义 |
| GPU 瓶颈 vs CPU 瓶颈 | `stat unit` 判读前提 |

> **系统补图形学** → [opengl-learning/README.md](../opengl-learning/README.md)（本仓库 8 章专题）。

#### ④ 编辑器与工具链【必需】

| 项 | 要求 |
| --- | --- |
| 编辑器界面、视口导航、关卡与资产管理 | [第 01 章](./01-UE引擎使用与编辑器指南.md) 全章 |
| **VS 2022 + "使用 C++ 的游戏开发" 工作负载** | 能编译、能附加进程断点 |
| Git + **Git LFS**（或 Perforce 基础） | `.gitattributes` / 文件锁 / 不手改 uasset |
| 命令行基础、日志查看 | `Saved/Logs/`、UAT 脚本 |
| 读懂 `.uproject` / `.ini` 配置 | 项目设置排错 |

#### ⑤ 游戏开发通用概念【推荐】

- **Game Loop**（输入 → 更新 → 渲染）与 Tick/DeltaTime；
- **状态机**（角色状态、流程状态）、行为树基础；
- 组件模式 vs 继承（Unity 偏组合、UE 偏继承 + 组件，见 [unity-learning](../csharp-learning/unity-learning/README.md) 对照）；
- 帧率-independent 编程、固定步长 vs 可变步长；
- 事件驱动 vs 轮询；
- 对象池、资源生命周期。

## 3.5 四条目标导向学习路线

### 路线 A：Gameplay 程序（推荐默认，约 3~4 个月）

```text
第 1~2 周   L1：C++ 实用子集 + 3D 数学 + 第01章编辑器 + 跑通 PIE 与打包
第 3~6 周   L2 前半：UObject/反射/GC → 继承树 → Gameplay Framework → 生命周期
            （每节都在自己工程里写一个最小类验证）
第 7~9 周   L2 后半：C++↔蓝图 → Enhanced Input → 碰撞射线 → 委托 → UMG
            ★ 完成第02章 2.16 完整实战（单机版）
第 10~12 周 L3：网络复制 + RPC → 把实战改成双客户端同步 → 调试与 stat
            构建/打包/CI → 自动化测试
之后        按兴趣选 L4：GAS（战斗）/ 动画 / AI / 渲染
```

**里程碑**：能独立交付一个"第三人称角色 + 交互拾取 + 计分 HUD + 双人联机 + 打包可运行"的小项目。

### 路线 B：渲染 / TA（约 6 个月+）

```text
L1 → [opengl-learning 全 8 章]（GPU 管线、GLSL、光照、后处理）
   → UE 材质编辑器 / Material Instance / 自定义 HLSL 节点
   → HLSL + 材质编译流程 → 后处理与自定义 Pass
   → Nanite / Lumen / VSM 原理与取舍 → GPU Profiling
   → Niagara 特效 / 程序化内容
```

### 路线 C：引擎 / 工具程序（约 6 个月+）

```text
L1 + 现代 C++ 深化 → L2（理解框架约定）→ L3 构建/CI/性能
   → 获取源码版 UE 并成功编译 → 阅读 Engine/Source/Runtime 模块
   → 插件与编辑器模块（Slate、Details 定制、AssetTypeActions）
   → UBT 定制 / 自动化工具 / 资产管线
```

### 路线 D：只做原型 / 独立开发（约 3~6 周）

```text
第01章（编辑器 + 蓝图 + 材质 + 打包）
   → 模板改造（第三人称 / 第一人称）
   → 蓝图完成玩法 + UMG + DataTable 调数值
   → 需要性能/复杂算法时，再针对性补 C++
```

> 独立开发**完全可以只用蓝图**。别被"C++ 才叫 UE 开发"误导——先做出可玩的东西比先精通反射更重要。

## 3.6 与已有知识的迁移对照（Java / C# / Unity / Python）

| 你已会 | 迁移到 UE 的映射 | 需要特别注意的差异 |
| --- | --- | --- |
| Java Spring | `UCLASS`≈`@Component`；UHT≈编译期注解处理；GameMode≈配置/规则服务 | UE 无 IoC 容器，对象由引擎创建；"作用域"由网络拓扑决定 |
| C# / .NET | `UPROPERTY`≈属性 + 特性；委托≈`event` | **GC 不同**：UE 只沿 UPROPERTY 追踪；UObject 不能 new/delete |
| Unity | GameObject≈AActor；Component≈UActorComponent；Prefab≈Blueprint Class；`Time.deltaTime`≈DeltaSeconds | UE 是继承体系 + 强框架约定；C++ 无空引用保护；单位 cm / Z-up / 左手系 |
| Python | 快速原型思维 → 蓝图；脚本化 → Editor Utility / Python Scripting | UE 是编译型、类型严格，改名/改结构要重编 |
| 图形学（本仓库 OpenGL 专题） | 渲染管线 → 材质/Shader → Nanite/Lumen | 引擎把管线封装了，重点是"选项与取舍"而非手写 API |

**三个最容易翻车的迁移点**：

1. **内存**：以为有 GC 就随便存对象 → 必须 `UPROPERTY`/`TObjectPtr`；
2. **空指针**：以为会像 C# 抛 NullReference → UE 直接崩溃，必须 `IsValid()`；
3. **框架约定**：把逻辑全塞进一个 Actor → 应按 GameMode/GameState/Controller 分工。

## 3.9 面试高频问题（知识地图版）

**Q1. 用 UE 开发需要哪些技能？请分层说明。**

A：L1 基础（C++ 实用子集、3D 数学、图形学常识、编辑器与工具链）、L2 核心（UObject 反射与 GC、Gameplay Framework、C++/蓝图互操作、输入/碰撞/UI、委托、UE 类型）、L3 进阶（网络复制、调试性能、构建 CI、异步加载、编辑器扩展）、L4 专精（渲染/引擎/网络/动画/工具/TA/GAS）。并说明不同岗位权重不同：**Gameplay 重 L2，渲染重图形学 + HLSL，引擎程序重 C++ 与源码**。

**Q2. 从 Unity/Java 转 UE，最容易踩的三个坑？**

A：① 内存——UE 的 GC 只沿 `UPROPERTY` 追踪，漏写会悬空崩溃，且 UObject 不能 new/delete；② 空指针——没有 C# 的"假空"保护，`IsValid()` 是日常；③ 框架约定——GameMode/GameState/Controller 有固定分工，不能自己随便塞。另外单位（cm）、Z-up、左手系也是高频错误源。

**Q3. UE 里为什么要同时会 C++ 和蓝图？**

A：商业项目典型分工是 **C++ 定基类、性能敏感与网络逻辑，蓝图派生做表现、调参、流程组装**。C++ 性能高、可版本控制 diff、能做引擎扩展；蓝图迭代快、设计师可改、适合关卡交互。二者通过 `UPROPERTY`/`UFUNCTION` 说明符互操作，不是二选一。

**Q4. Gameplay 程序和引擎程序的技能差异？**

A：Gameplay 面向玩法，核心是框架约定、输入/碰撞/UI/网络复制、与策划美术协作；引擎程序面向引擎本身，需要深入 C++、模块与构建系统、内存/GC、渲染或物理子系统、平台适配，通常要编译源码版 UE。前者要求"用得对"，后者要求"改得动"。

**Q5. 学 UE 需要先把 C++ 学通透吗？**

A：不需要。先掌握**实用子集**（类/继承/虚函数/指针引用/模板基础/构造析构/Lambda），配合 UE 的反射宏就能开始写；移动语义、模板元编程、STL 深水区等用到再补。但**内存模型与编译模型**必须早理解，否则调试成本极高。

**Q6. 3D 数学里最必须的是哪几块？**

A：向量运算（点积/叉积/归一化/距离）、世界与局部空间变换、旋转表示（`FRotator` vs 四元数）、插值与缓动、射线与几何求交。再加上 UE 特有的 cm / Z-up / 角度制约定。

**Q7. 网络方向要补什么？**

A：`bReplicates` / `DOREPLIFETIME` / OnRep / 三种 RPC / `HasAuthority` / 条件复制，进一步是**服务器权威 + 反作弊校验**、CharacterMovement 的客户端预测与回滚、带宽优化（NetUpdateFrequency、Replication Graph / Iris）、专用服务器与 Online Subsystem。

**Q8. 怎么判断自己"UE 入门了"？**

A：能不看文档独立交付一个闭环小项目——第三人称角色、Enhanced Input、射线交互、可拾取物、UMG HUD、GameState 计分、双客户端同步、打包可运行；并能解释每一处为什么用 UPROPERTY、为什么放 BeginPlay、为什么判定在服务器、为什么用事件而非 Tick。

## 3.10 本章小结

| 你学到了 | 关键点 |
| --- | --- |
| 岗位分工 | 9 类角色差异巨大，**先定位再学习**；默认按 Gameplay 程序入门 |
| 四层技能树 | L1 基础 → **L2 核心（最重点）** → L3 进阶 → L4 专精 |
| L1 清单 | C++ 实用子集、3D 数学、图形学常识、编辑器、版本控制 |
| L2 清单 | 反射/GC、继承树、Gameplay Framework、生命周期、C++↔蓝图、输入/碰撞/UI、委托 |
| L3 清单 | 网络复制、性能、构建 CI、异步、编辑器扩展、数据驱动 |
| L4 方向 | 渲染/引擎/网络/动画/物理/AI/GAS/工具/TA |
| 四条路线 | Gameplay(默认) / 渲染 TA / 引擎工具 / 纯原型（蓝图即可） |
| 迁移对照 | Java/C#/Unity/Python → UE 的映射与三大翻车点 |
| 自检 | L1 20 分 + L2 30 分 + L3 20 分，附判读标准 |

**核心心法**：

> "学 UE"不是学一门语言，而是学 **① C++ 的一个方言 + ② 一套强约定的框架 + ③ 一条资产/构建/协作的工业管线**。
> 三者里，**L2 框架约定最容易被低估，也最决定你能不能真的进项目干活**。
