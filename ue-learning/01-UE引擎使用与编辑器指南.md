# 第一章 UE 引擎使用与编辑器指南（使用文档）

> 本章目标：**零代码**把 Unreal Engine 用起来——从安装、建项目，到认识编辑器每一个面板、编辑关卡、管理资产、调材质、用蓝图写第一句逻辑、PIE 预览、打包出可运行程序。学完你应该能独立完成"新建项目 → 摆一个场景 → 加个交互 → 打包给别人玩"的完整闭环。
>
> 前置知识：任意一门语言的编程经验即可。对标 Unity：本章相当于 Unity 的编辑器基础 + 场景 + Prefab + Build Settings。
>
> 版本：UE 5.x（5.3+）。UE4 差异以「UE4 提示」标注。

---

## 1.1 认识 Unreal Engine：它到底是什么

### 1.1.1 一个引擎，三样东西

| 组成 | 说明 | 你会接触到的 |
| --- | --- | --- |
| **引擎运行时（Runtime）** | 真正跑游戏的部分：渲染、物理、网络、GC、反射 | C++ 代码、打包后的 exe |
| **编辑器（Editor）** | 可视化的创作工具，本身也是用引擎写的 | Unreal Editor（本章主体） |
| **工具链（Toolchain）** | 编译、烘焙（Cook）、打包、自动化 | UBT / UHT / AutomationTool / CI |

> **重要认知**：UE 编辑器**不是**一个"导出器"，它本身就是运行在引擎之上的一个大型 C++ 程序。你在编辑器里拖的每个 Actor，和打包后游戏里的对象是同一套类。这也是为什么 C++ 类加个宏就能在编辑器里看见。

### 1.1.2 UE vs Unity 的第一层差异

| 维度 | Unity | Unreal |
| --- | --- | --- |
| 脚本语言 | C# | **C++（主）+ 蓝图（可视化）** |
| 对象模型 | GameObject + Component（组合优先） | **AActor 继承体系 + Component**（框架预设了 ACharacter/APawn 等） |
| 项目起点 | 空场景，自己搭一切 | **模板自带 GameMode/Pawn/输入**，开箱即玩 |
| 资源单位 | Assets / Prefab | **Content Browser 资产 / Blueprint Class** |
| 渲染 | URP/HDRP 自选 | **UE5 默认 Nanite + Lumen**（次世代管线开箱即用） |
| 开源 | 闭源（部分源码可见） | **完整 C++ 源码可获取**（Epic GitHub） |
| 收费 | 订阅/收入分成模式曾变动 | 游戏营收超阈值后收分成；**学习、开发期免费** |

> **给 Java/C# 读者的第一句话**：UE 不是"写个 main 然后调库"，而是"**把你的类注册进一个已经跑起来的框架**"。框架负责 Tick、渲染、序列化、网络；你负责填回调。心态上更像写 Spring Boot 应用（约定大于配置），而不是写独立程序。

## 1.2 安装与硬件准备

### 1.2.1 硬件建议

| 档位 | CPU | 内存 | GPU | 体验 |
| --- | --- | --- | --- | --- |
| 最低 | 4 核 | 16 GB | 4 GB 显存 / DX11 | 能开编辑器，Shader 编译慢 |
| **推荐** | 8 核+ | **32 GB** | **8 GB+ 显存 / DX12** | 学习与中小项目流畅 |
| 舒适 | 12 核+ | 64 GB | 12 GB+ / RTX 30 系以上 | 大世界、Lumen、多开 |
| 编译源码版 | 同上 | **64 GB 建议** | — | 全量编译可能 1~2 小时 |

> **三个最容易被低估的开销**：① **磁盘**（引擎本体 30~100GB，项目含 DerivedDataCache 可再吃几十 GB，**务必放 SSD**）；② **Shader 编译**（首次打开项目会跑几千个，CPU 吃满属正常）；③ **内存**（编译 C++ + Shader 编译时 16GB 很容易 OOM）。

### 1.2.2 安装步骤（Windows，最常见）

1. 下载并安装 **Epic Games Launcher**（https://www.epicgames.com/store/download）；
2. 登录 Epic 账号（免费）；
3. 顶部 **Unreal Engine → Library → ENGINE VERSIONS 的 `+`** 选择版本（选 5.x 最新稳定版）；
4. 安装选项里勾选：
   - ✅ **Core Components**（必选）
   - ✅ **Starter Content**（新手强烈建议，含基础材质/模型）
   - ✅ **Templates & Feature Packs**（模板，含第三人称等）
   - ✅ 目标平台支持（Android / iOS 按需，会显著增大体积）
5. 安装盘选 SSD；等待下载 + 安装（几十 GB）。

> **源码版**（改引擎、调试引擎内部、做定制构建才需要）：绑定 Epic 账号到 GitHub → clone `EpicGames/UnrealEngine` → 运行 `Setup.bat` → `GenerateProjectFiles.bat` → 用 VS 编译。新手**不建议**一上来就走这条路。

### 1.2.3 必备开发环境（要写 C++ 时）

```text
Visual Studio 2022
  └─ 工作负载勾选「使用 C++ 的游戏开发」(Game development with C++)
  └─ 单个组件确认：MSVC v143、Windows 10/11 SDK、C++ CMake 工具
```

| 工具 | 用途 | 必需？ |
| --- | --- | --- |
| Visual Studio 2022 | MSVC 编译器 + 调试 | Windows 写 C++ 必需 |
| JetBrains Rider | 更强的 UE 代码导航（可选替代） | 可选 |
| VS Code | 轻量看代码 / 蓝图不便 | 可选 |
| Git + **Git LFS** | 版本控制（二进制资产必须 LFS） | 团队协作必需 |
| Perforce (Helix Core) | 大团队 UE 事实标准 | 大型项目 |
| RenderDoc / Unreal Insights | 帧调试 / 性能分析 | 进阶 |

> **UE4 提示**：UE4 用 VS2019 亦可；UE5 建议 VS2022 + MSVC v143。若装完 VS 后新建 C++ 项目报"找不到编译器"，九成是缺 SDK 或工作负载没勾全。

## 1.3 创建第一个项目

### 1.3.1 项目创建向导关键选项

启动 Unreal Editor → **New Project**，需要决定 5 件事：

| 选项 | 建议 | 说明 |
| --- | --- | --- |
| **模板 Template** | 新手选 **Third Person**（自带可跑角色 + 相机 + 输入） | Games → Third Person；Blank 是真空项目，学习曲线陡 |
| **语言** | **C++** 或 **Blueprint** | 想学第 02 章开发就选 C++；纯关卡/原型可选 Blueprint |
| **Starter Content** | ✅ 勾上 | 自带材质、形状、粒子，省得第一章就卡在没资源 |
| **目标平台** | Desktop / Maximum Quality | 移动端会影响默认渲染设置 |
| **画质预设** | Maximum Quality（Lumen/Nanite 开） | 老机器可改 Scalable 降负载 |
| **项目路径** | **全英文、无空格、路径短** | `D:\UEProjects\MyFirstUE`，中文路径易触发编译/打包问题 ⚠️ |

> ⚠️ **第一大坑**：项目路径含中文或空格，可能导致 UBT 编译失败、Cook 失败。**永远用纯英文短路径**。

### 1.3.2 C++ 项目会自动发生什么

选 C++ 模板后，UE 会：

1. 生成 `Source/<ProjectName>/` 里的 `.h/.cpp` + `.Build.cs` + `.Target.cs`；
2. 调用 **UHT** 处理 `UCLASS()` 等宏，生成反射代码（`Intermediate/` 下）；
3. 调用 **UBT** 编译出编辑器模块 DLL；
4. 首次启动花几分钟编译 Shader。

**目录结构**（认识一下，第 02 章会反复用到）：

```text
MyFirstUE/
├── MyFirstUE.uproject          # 项目描述文件（JSON，别手改结构）
├── Config/
│   ├── DefaultEngine.ini       # 引擎/渲染/地图/网络设置
│   ├── DefaultGame.ini         # 游戏设置
│   └── DefaultInput.ini        # 输入映射（UE5 更多在资产里）
├── Content/                    # ⭐ 所有资产（.uasset/.umap），编辑器里的内容浏览器
│   ├── ThirdPerson/
│   └── StarterContent/
├── Source/                     # ⭐ C++ 源码（仅 C++ 项目）
│   ├── MyFirstUE.Target.cs
│   ├── MyFirstUEEditor.Target.cs
│   └── MyFirstUE/
│       ├── MyFirstUE.Build.cs  # 模块依赖清单
│       ├── MyFirstUE.cpp
│       └── MyFirstUEGameModeBase.h/.cpp
├── Binaries/                   # 编译产物（可删，勿提交）
├── Intermediate/               # UHT 生成物、临时文件（可删，勿提交）
├── DerivedDataCache/ (DDC)     # 派生数据缓存（可删，会重算）
└── Saved/                      # 日志、自动保存、配置（可删，勿提交）
```

**应该提交到 Git 的**：`Config/`、`Content/`、`Source/`、`*.uproject`、`.gitignore`、`Plugins/`（若有）。

### 1.3.3 最小 `.gitignore`（UE 项目标配）

```gitignore
# 生成物 / 缓存（都不提交）
Binaries/
Intermediate/
DerivedDataCache/
Saved/
.vs/
obj/
*.sln
*.suo
*.user
*.VC.db
*.opensdf
*.sdf

# 但保留这些
!Content/
!Config/
!Source/
!Plugins/

*.uproject

# 大文件交给 Git LFS（.gitattributes 里配）
```

`.gitattributes`（**重要**，否则仓库会被二进制撑爆）：

```gitattributes

*.umap   filter=lfs diff=lfs merge=lfs -text
*.fbx    filter=lfs diff=lfs merge=lfs -text
*.png    filter=lfs diff=lfs merge=lfs -text
*.wav    filter=lfs diff=lfs merge=lfs -text
```

```bash
git lfs install
git lfs track "*.uasset" "*.umap" "*.fbx" "*.png" "*.wav"
```

## 1.5 视口导航与关卡编辑

### 1.5.1 视口操作（第一周就要形成肌肉记忆）

| 操作 | 效果 |
| --- | --- |
| **右键 + WASD** | 飞行漫游（最常用），滚轮调速 |
| **右键 + Q/E** | 下降 / 上升 |
| **左键拖拽** | 前后移动 + 左右转向（选中物体时是移动物体，注意区分） |
| **中键拖拽** | 平移视图 |
| **Alt + 左键拖拽** | 环绕选中物体旋转 |
| **Alt + 右键拖拽** | 推近 / 拉远 |
| **F** | 聚焦（把选中物体移到视野中心） |
| **G** | 切换 **Game View**（隐藏编辑器图标/线框，看真实画面） |
| **Alt + 拖动 Transform 箭头** | 快速复制一份 Actor |

> 视口右上角可切换 **Perspective / Top / Front / Side** 正交视图，摆场景时用正交视图对齐更准。

### 1.5.2 Transform 与吸附

选中 Actor 后，Details 顶部就是 **Transform**（Location / Rotation / Scale）：

| 工具 | 快捷键 | 说明 |
| --- | --- | --- |
| 选择 | Q | 默认 |
| 移动 | **W** | 三轴箭头 |
| 旋转 | **E** | 三轴圆环 |
| 缩放 | **R** | 三轴方块 |
| 切换坐标系 | 工具栏地球/立方体图标 | 世界 vs 本地 |

**吸附（Snapping）**：工具栏的网格/角度/缩放吸附开关。摆关卡时开启「网格吸附 10/50/100」能避免物体错位。

### 1.5.3 放第一个场景：三步

1. **Place Actors 面板**（或从 Content Browser）拖一个 **Cube** 到视口 → 得到一个 StaticMeshActor；
2. Details 里把 Scale 改成 `(4, 4, 0.5)` 当地板；
3. 再拖一个 **Directional Light** + **Sky Light** + **Sky Atmosphere** + **Exponential Height Fog**（模板关卡通常已自带，从 World Outliner 能看到）；
4. `Ctrl+S` 保存关卡为 `Content/Maps/L_MyFirst`。

> **空白场景一片黑？** 检查有没有 **Sky Light / Sky Atmosphere / Directional Light**；UE5 用 Lumen 动态全局光照，但完全没光源依然全黑。也可在视口左上角 **Lit → Unlit** 临时确认物体是否存在。

### 1.5.4 关卡（Level）与 World Partition

| 概念 | 说明 |
| --- | --- |
| **Level / Map (.umap)** | 一个关卡文件，存 Actor 列表与设置 |
| **Persistent Level** | 主关卡，始终加载 |
| **Streaming Sublevel** | 子关卡，按需加载（大世界） |
| **World Partition（UE5）** | 把大世界自动切成网格，按距离流式加载；新建大世界模板默认开启 |
| **Level Instance / Packed Level Actor** | 可复用的关卡片段 |

> **UE4 提示**：UE4 用 **World Composition / Level Streaming**；UE5 主推 World Partition。小项目不必开 World Partition，普通关卡更简单。

**设置默认启动地图**：`Edit → Project Settings → Maps & Modes → Default Maps`，把 Editor Startup Map 和 Game Default Map 指向你的 `.umap`。**这是新手最常漏的一步**——打包后黑屏/进错关卡，多半是这里没设。

## 1.6 Content Browser：资产管理

### 1.6.1 资产类型速查

| 后缀/类型 | 说明 | 类比 Unity |
| --- | --- | --- |
| **Static Mesh** | 静态模型 | Mesh / FBX |
| **Skeletal Mesh** | 带骨骼模型（角色） | Skinned Mesh |
| **Material / Material Instance** | 材质 / 材质实例 | Material / Material Variant |
| **Texture** | 贴图 | Texture |
| **Blueprint Class** | 蓝图类（可视化脚本 + 组件） | Prefab + MonoBehaviour |
| **Level (.umap)** | 关卡 | Scene |
| **Animation Sequence / Montage / Blend Space** | 动画资源 | Animation Clip |
| **Data Asset / Data Table** | 配置数据 | ScriptableObject |
| **Niagara System / Cascade** | 粒子特效 | Particle System |
| **Sound Cue / MetaSound** | 音频 | AudioClip / AudioMixer |
| **Input Action / Input Mapping Context** | UE5 Enhanced Input 资产 | Input Actions |

### 1.6.2 高频操作

| 操作 | 方法 |
| --- | --- |
| 导入资源 | 直接把 FBX/PNG/WAV **拖进 Content Browser**，或 `Add → Import` |
| 新建资产 | 右键 → 对应类别；蓝图选 `Blueprint Class`，再选父类（Actor / Character / GameMode…） |
| 查找资产 | 搜索框；支持 `Name:`、`Type:`、`Path:` 过滤 |
| **看谁引用了它** | 右键 → **Reference Viewer**（依赖关系图，删除资产前必看） |
| **看它引用了谁** | 右键 → **Size Map**（查包体膨胀神器） |
| 替换引用 | 右键 → **Replace References** |
| 移动/重命名 | 直接在 Content Browser 里拖/改名，UE 会生成 **Redirector（重定向器）** 保持引用不断 |
| 清理重定向器 | 右键文件夹 → **Fix Up Redirectors in Folder**，然后保存 |
| 迁移到别的项目 | 右键 → **Asset Actions → Migrate**（会自动带上依赖） |
| 收藏 | 右键 → Add to Favorites，或建 Collections（不改路径的逻辑分组） |

> ⚠️ **不要在 Windows 资源管理器里手动移动/删除 `.uasset`**！引用会断。一切资产操作走 Content Browser。

### 1.6.3 重定向器（Redirector）是什么

移动 `Content/Weapons/Sword.uasset` 到 `Content/Props/Sword.uasset` 后，原位置会留下一个**很小的重定向器文件**，让所有旧引用仍能找到它。它是好事，但会累积：

```text
移动前: A → Content/Weapons/Sword
移动后: A → Redirector(Weapons/Sword) → Content/Props/Sword
修复后: A → Content/Props/Sword，Redirector 被删除
```

**提交前记得 Fix Up Redirectors + 保存**，否则团队协作时别人的引用可能出问题。

## 1.7 材质编辑器入门（不写代码也能改画面）

双击一个 **Material** 打开材质编辑器。核心思路：**用节点图算出一个最终颜色/粗糙度/法线，喂给输出节点**。

```text
[Texture Sample] ──► Base Color
[Constant 0.3]   ──► Roughness
[Constant3Vector]──► Emissive Color
                       │
                       ▼
                 [Material 输出节点]
```

**第一个实用材质：可调颜色的发光材质**

1. Content Browser 右键 → `Material`，命名 `M_Glow`；
2. 双击打开，在图表里右键搜 `VectorParameter`，命名 `BaseColor`，默认值设成橙色；
3. 再建一个 `ScalarParameter` 命名 `GlowIntensity`，默认 `5`；
4. `BaseColor × GlowIntensity` → 连到 **Emissive Color**；
5. 保存（左上角 Apply / Save）；
6. **右键该材质 → Create Material Instance** 得到 `MI_Glow_Red`；双击它，直接改参数而无需重编译材质。

> **黄金实践**：**基类 Material 定逻辑，Material Instance 调参数**。材质改一次要重编 Shader（慢），改实例参数是秒级。项目里 90% 的"换个颜色"都应该用实例。

| 输出引脚 | 控制 | 直观效果 |
| --- | --- | --- |
| Base Color | 固有色 | 物体是什么颜色 |
| Metallic | 金属度 (0/1) | 塑料 vs 金属 |
| Roughness | 粗糙度 | 镜面 vs 磨砂 |
| Normal | 法线贴图 | 表面凹凸细节 |
| Emissive Color | 自发光 | 灯、屏幕、特效 |
| Opacity | 不透明度 | 需 Blend Mode 设 Translucent |

## 1.8 蓝图：不写 C++ 也能写逻辑

蓝图（Blueprint）是 UE 的**可视化脚本**，本质是 UObject 的可视化子类，编译成字节码（也可最终转 C++ 打包）。

### 1.8.1 第一个蓝图：旋转的立方体

1. Content Browser 右键 → `Blueprint Class` → 父类选 **Actor**，命名 `BP_SpinningCube`；
2. 双击打开 → 左上角 **Components → Add → Static Mesh**，选 `Shape_Cube`；
3. 切到 **Event Graph**，看到默认三个事件：`Event BeginPlay` / `Event ActorBeginOverlap` / `Event Tick`；
4. 从 `Event Tick` 的执行引脚拖出，搜 **Add Actor Local Rotation**；
5. 把 `Delta Seconds`（Tick 给的时间差）× `90` 做成 Z 轴旋转，连到 Delta Rotation；
6. **Compile → Save**，把蓝图从 Content Browser 拖进关卡；
7. 点工具栏 **▶ Play**，立方体开始转。

```text
Event Tick ──► AddActorLocalRotation
                  ▲ Delta Rotation = (0, 0, 90 × DeltaSeconds)
```

> **DeltaSeconds 是必须的**：不乘它，帧率不同的机器转速不同。对标 Unity 的 `Time.deltaTime`、第 02 章 C++ 里的 `DeltaTime`。

### 1.8.2 蓝图编辑器四块区域

| 区域 | 作用 |
| --- | --- |
| **Components**（左上） | 组件树（StaticMesh / BoxCollision / Camera…），相当于"这个 Actor 由什么组成" |
| **My Blueprint**（左中） | 变量、函数、宏、事件分发器列表 |
| **Details**（右） | 选中变量/组件的详细属性 |
| **Event Graph / Construction Script**（中） | 事件图表 / 构造脚本（编辑器里改属性时重跑） |

### 1.8.3 常用节点速查

| 节点 | 作用 |
| --- | --- |
| `Print String` | 打日志（新手调试第一神器） |
| `Branch` | if |
| `Sequence` | 顺序执行多条 |
| `For Each Loop` / `For Loop` | 循环 |
| `Delay` / `Set Timer by Function Name` | 延时 / 定时 |
| `Cast To <Class>` | 类型转换（尽量避免高频 Cast，见第 02 章） |
| `Get All Actors Of Class` | 找场景里所有某类 Actor（慢，别放 Tick） |
| `Spawn Actor from Class` | 生成 Actor |
| `Destroy Actor` | 销毁 |
| `Line Trace By Channel` | 射线检测 |
| `Event BeginOverlap` | 触发器事件 |
| `Timeline` | 做插值动画（开门、渐变） |

### 1.8.4 蓝图 vs C++ 怎么分

| 场景 | 推荐 |
| --- | --- |
| 玩法原型、关卡交互、UI 表现、调参数 | **蓝图**（快，设计师可改） |
| 性能敏感循环、复杂算法、网络底层、引擎扩展 | **C++** |
| 需要被大量继承复用的基类 | **C++ 定基类 → 蓝图派生** ⭐ 最常见分工 |
| 团队协作（程序 + 策划） | C++ 暴露 `BlueprintCallable` 函数，蓝图组装流程 |

> 第 02 章会给出完整的 C++/蓝图互操作规范。**不要觉得"用蓝图不算开发"**——商业项目里蓝图承担了大量玩法逻辑。

## 1.9 PIE 预览与调试

### 1.9.1 播放模式

工具栏 **▶ Play** 的下拉里：

| 模式 | 说明 |
| --- | --- |
| **Selected Viewport（PIE）** | 在视口里跑，最常用 |

| **Simulate** | 只跑物理/世界，不生成玩家（看物理效果） |

**运行中的关键操作**：

| 快捷键 | 作用 |
| --- | --- |
| `Shift+F1` | 释放鼠标，回到编辑器（**必记**，否则鼠标被锁） |
| `F8` | **Eject**：从玩家身上弹出，自由飞行检查场景 |
| `F8` 再按 | Possess 回玩家 |
| `~` | 打开控制台（输命令） |
| `Esc` | 停止 PIE |

### 1.9.2 常用控制台命令

```text
stat fps              显示帧率
stat unit             显示 Game/Draw/GPU 各阶段耗时（性能第一命令）
stat rhi              显示 DrawCall / 三角形数
stat memory           内存概览
show Collision        显示碰撞体
r.Nanite.Visualize 1  Nanite 可视化
profilegpu            抓一帧 GPU 分析

```

### 1.9.3 看日志与断点

- **Output Log**（`Window → Developer Tools → Output Log`）：所有 `UE_LOG` 与蓝图 `Print String` 都在这里；可按分类过滤、搜关键词；
- **蓝图断点**：在节点上右键 → Add Breakpoint，PIE 时会停下并可查看变量；
- **C++ 断点**：VS/Rider 附加到 `UnrealEditor.exe`，第 02 章详述；
- 崩溃时看 `Saved/Logs/<Project>.log` 与 `Saved/Crashes/`。

## 1.11 打包发布

### 1.11.1 打包流程

```text
Platforms 下拉 → 目标平台（Windows / Android / …）
   → Packaging Settings（或 File → Package Project）
   → 选择输出目录
   → UE 自动执行：编译 → Cook（把 uasset 转成平台格式）→ Stage → Package → Archive
   → 输出 WindowsNoEditor/ 或 .apk/.ipa
```

**打包前检查清单**：

- [ ] `Project Settings → Maps & Modes` 里 Game Default Map 正确；
- [ ] `Packaging → List of maps to include in a packaged build` 加入了所有需要的地图（**漏了就进不去**）；
- [ ] 默认 GameMode 设置正确；
- [ ] 关闭 Development 专用内容（调试关卡、作弊命令）；
- [ ] 目标平台 SDK 已装（Android 需 SDK/NDK/JDK，iOS 需 Mac + 证书）；
- [ ] 配置 `Build Configuration = Shipping`（正式发布）；
- [ ] 图标、Splash、包名、版本号设置好。

### 1.11.2 三种构建配置

| 配置 | 用途 | 特点 |
| --- | --- | --- |
| **DebugGame** | 调试游戏逻辑 | 符号全，慢 |
| **Development** | 日常开发 ⭐ | 有编辑器外日志、`stat` 命令、可调试 |
| **Shipping** | 正式发布 | 优化最全，去掉大量日志与作弊命令，不可 `stat` |

### 1.11.3 常见打包失败排查

| 报错关键词 | 常见原因 |
| --- | --- |
| `Cook failed` / `Missing map` | 地图没加入 Cook 列表、资产引用断了 |
| `Unable to find SDK` | 目标平台 SDK 未装/路径没配 |
| `LogLinker: Warning: Failed to load ...` | 资产引用丢失（重定向器未修复 / 资源管理器里手工删过文件） |
| `Shader compilation error` | 材质节点非法、自定义 HLSL 出错 |
| `MSB... / compiler not found` | VS 工作负载/Windows SDK 缺组件 |
| 打包成功但黑屏 | Default Map 没设 / 关卡没光源 / GameMode 为空 |

> 排查入口永远是 `Saved/Logs/` 下最新日志，从下往上找第一条 `Error:`。

## 1.12 常见报错与踩坑速查

| 坑 | 症状 | 解决 |
| --- | --- | --- |
| **路径含中文/空格** | 编译、Cook 各种玄学失败 | 项目放纯英文短路径（⚠️ 第一大坑） |
| **首次打开极慢** | Shader 编译几千个 | 正常，等；可设 `r.ShaderDevelopmentMode` 或增大 DDC 缓存 |
| **磁盘爆满** | DDC / Intermediate / Saved 几十 GB | 定期清理这三个目录（可安全删除，会重建） |
| **16GB 内存编译 OOM** | 编译 Shader/链接时崩溃 | 关掉其他程序、减少并行编译、加到 32GB |
| **视口一片黑** | 没光源 / 物体在地下 | 加 DirectionalLight + SkyLight；`G` 切 Game View 确认 |
| **Play 后鼠标出不来** | 被 PIE 锁住 | `Shift+F1` |
| **改了资产别人看不到** | 没保存 / 没提交 .uasset | `Ctrl+S` 全部保存；确认 Git LFS 已 track |
| **手工移文件后引用全断** | 红线报错 | 只用 Content Browser 移动；已断的用 Fix Up Redirectors 修 |
| **蓝图 Compile 报红但能跑** | 有未连的必需引脚 / Cast 失败 | 看 Compile 结果面板逐条修 |
| **C++ 改了代码不生效** | 没重新编译 / Live Coding 未刷新 | 工具栏编译按钮，或关闭编辑器用 VS 编译（第 02 章） |
| **打包后没进自己关卡** | Default Map / Cook 地图列表 | 见 1.11.1 清单 |
| **插件启用后崩溃** | 版本不匹配 | 确认插件支持的引擎版本，删 `Binaries/Intermediate` 重编 |

## 1.13 本章实操验收

按下面顺序做完，说明编辑器这一层已经通关：

1. ✅ 用 **Third Person (C++ 或 Blueprint)** 模板建一个纯英文路径项目，跑通 PIE；
2. ✅ 新建关卡 `L_MyFirst`，摆出地板 + 若干 Cube + 光源，设置成 Default Game Map；
3. ✅ 从 Content Browser 导入一张图片，做成材质 + 材质实例，贴在 Cube 上；
4. ✅ 新建 `BP_SpinningCube`，用 `Event Tick + DeltaSeconds` 让它旋转，并放进关卡；
5. ✅ 用 `stat unit` 看一次 PIE 的耗时分布，用 Output Log 找到自己打的 `Print String`；
6. ✅ 用 `Reference Viewer` 查看某资产的依赖，用 `Size Map` 看最大资产；
7. ✅ 配置 `.gitignore` + `.gitattributes` + Git LFS，把项目提交一次；
8. ✅ `File → Package Project → Windows` 打包成功，双击打包产物能进入自己的关卡。
