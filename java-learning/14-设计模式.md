# 第十四章 设计模式

> 本章掌握：面向对象六大原则、23 种经典设计模式中最常用的 12 种（单例/工厂/建造者/原型、代理/装饰器/适配器/外观、策略/模板方法/观察者/责任链），每种都带完整可运行代码 + 框架中的应用场景。
> 设计模式是**前辈踩坑总结的解决方案**，学它不是为了炫技，而是看懂框架源码、写出可维护代码。面试必考（尤其单例、代理、工厂）。

## 14.1 设计模式入门

### 14.1.1 什么是设计模式

设计模式（Design Pattern）是软件设计中**反复出现问题的通用解决方案**，最早由 GoF（四人组）在《设计模式》一书中总结出 23 种，分为三大类：

| 类别 | 关注点 | 模式 |
| --- | --- | --- |
| **创建型**（5 种） | 如何"创建"对象更合理 | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型**（7 种） | 如何"组合"类与对象 | 代理、装饰器、适配器、外观、组合、享元、桥接 |
| **行为型**（11 种） | 对象之间如何"协作" | 策略、模板方法、观察者、责任链、状态、迭代器等 |

### 14.1.2 设计原则（面试高频）

| 原则 | 一句话 | 举例 |
| --- | --- | --- |
| **开闭原则（OCP）** | 对扩展开放，对修改关闭 | 加新支付方式不用改旧代码，新增策略类即可 |
| 单一职责（SRP） | 一个类只做一件事 | Controller 只接收参数，Service 只写业务 |
| 里氏替换（LSP） | 子类必须能替换父类 | 用父类引用指向子类，行为不变 |
| 接口隔离（ISP） | 接口小而专 | 不要一个大接口塞所有方法 |
| 依赖倒置（DIP） | 面向接口编程 | Service 依赖接口而非具体实现 |
| 迪米特法则（LoD） | 最少知道原则 | 类与类之间尽量不直接打交道 |

> 设计模式是"手段"，**设计原则**才是"目的"。能说出"这个模式体现了开闭原则"是加分项。

## 14.2 创建型模式

### 14.2.1 单例模式（最常考）

**问题**：整个程序只需要**一个实例**（如配置类、连接池、工具类）。

**五种写法**（从差到好）：

```java
package com.example.pattern.singleton;

/**
 * 写法 1：饿汉式（类加载即创建）
 * 优点：线程安全、简单
 * 缺点：不用也创建，浪费内存
 */
public class SingletonEager {
    private static final SingletonEager INSTANCE = new SingletonEager();

    private SingletonEager() {}          // 构造器私有，禁止 new

    public static SingletonEager getInstance() { return INSTANCE; }
}
```

```java
package com.example.pattern.singleton;

/**
 * 写法 2：懒汉式 + 双重检查锁（DCL）—— 面试标准答案
 * 首次调用才创建，既懒加载又线程安全
 */
public class SingletonDCL {
    // volatile：防止指令重排序（创建对象 = 分配内存+初始化+引用赋值，可能重排）
    private static volatile SingletonDCL instance;

    private SingletonDCL() {}

    public static SingletonDCL getInstance() {
        if (instance == null) {                     // 第一次检查（不加锁）
            synchronized (SingletonDCL.class) {     // 加锁
                if (instance == null) {             // 第二次检查（防止重复创建）
                    instance = new SingletonDCL();
                }
            }
        }
        return instance;
    }
}
```

```java
package com.example.pattern.singleton;

/**
 * 写法 3：静态内部类（推荐）—— 懒加载 + 线程安全，无锁开销
 * JVM 保证类初始化是线程安全的
 */
public class SingletonHolder {
    private SingletonHolder() {}

    // 只有调用 getInstance() 时才加载内部类，才创建实例
    private static class Holder {
        private static final SingletonHolder INSTANCE = new SingletonHolder();
    }

    public static SingletonHolder getInstance() { return Holder.INSTANCE; }
}
```

```java
package com.example.pattern.singleton;

/**
 * 写法 4：枚举（《Effective Java》推荐，天然防反射/防序列化破坏）
 */
public enum SingletonEnum {
    INSTANCE;                     // 枚举常量本身就是单例

    public void doSomething() {
        System.out.println("枚举单例工作");
    }
}
```

```java
// 测试
package com.example.pattern.singleton;

public class SingletonTest {
    public static void main(String[] args) {
        System.out.println(SingletonEager.getInstance() == SingletonEager.getInstance());  // true
        System.out.println(SingletonDCL.getInstance() == SingletonDCL.getInstance());      // true
        System.out.println(SingletonHolder.getInstance() == SingletonHolder.getInstance()); // true
        SingletonEnum.INSTANCE.doSomething();
    }
}
```

**框架中的单例**：Spring 的 Bean 默认**单例**（一个类只有一个实例注入所有地方）。

### 14.2.2 工厂模式

**问题**：创建对象的逻辑复杂（根据类型创建不同对象），直接 `new` 散落各处，不好维护。

**简单工厂（不是 23 种之一，但最常用）：**

```java
package com.example.pattern.factory;

/**
 * 产品接口：支付
 */
public interface Payment {
    void pay(double amount);
}

class Alipay implements Payment {
    @Override
    public void pay(double amount) { System.out.println("支付宝支付：" + amount + " 元"); }
}

class WechatPay implements Payment {
    @Override
    public void pay(double amount) { System.out.println("微信支付：" + amount + " 元"); }
}

class BankCardPay implements Payment {
    @Override
    public void pay(double amount) { System.out.println("银行卡支付：" + amount + " 元"); }
}
```

```java
package com.example.pattern.factory;

/**
 * 简单工厂：根据参数创建对象，调用方不关心具体类
 */
public class PaymentFactory {

    // 新增支付方式只需在此加一个 case（其他调用方代码零改动）
    public static Payment create(String type) {
        return switch (type) {
            case "alipay" -> new Alipay();
            case "wechat" -> new WechatPay();
            case "bank" -> new BankCardPay();
            default -> throw new IllegalArgumentException("不支持的支付方式：" + type);
        };
    }
}
```

```java
// 测试：客户端只用工厂，不知道具体实现类
package com.example.pattern.factory;

public class FactoryTest {
    public static void main(String[] args) {
        Payment p1 = PaymentFactory.create("alipay");
        p1.pay(99.9);

        Payment p2 = PaymentFactory.create("wechat");
        p2.pay(5.5);

        // Spring 进阶版：按类型注入到 Map，switch 都不用写
        // 见 14.5 设计模式在框架中的应用
    }
}
```

**工厂方法 vs 抽象工厂**（概念）：工厂方法把"创建逻辑"下沉到子类；抽象工厂创建一族相关产品。了解概念即可。

### 14.2.3 建造者模式（Builder）

**问题**：对象字段多、可选字段多（如订单有 10 个字段只要填 3 个），构造器传参难以阅读。

```java
package com.example.pattern.builder;

/**
 * 建造者模式：链式设置字段，最后 build() 产出对象
 * Lombok 的 @Builder 生成的就是这个（第十章已见过）
 */
public class Order {
    private final String orderNo;      // 必填
    private final String product;      // 必填
    private final int count;           // 默认 1
    private final String address;      // 可选
    private final String coupon;       // 可选

    // 构造器私有，只允许 Builder 创建
    private Order(Builder builder) {
        this.orderNo = builder.orderNo;
        this.product = builder.product;
        this.count = builder.count;
        this.address = builder.address;
        this.coupon = builder.coupon;
    }

    // 静态内部类 Builder
    public static class Builder {
        private final String orderNo;    // final = 必填
        private final String product;
        private int count = 1;           // 默认值
        private String address;
        private String coupon;

        public Builder(String orderNo, String product) {
            this.orderNo = orderNo;
            this.product = product;
        }

        public Builder count(int count) { this.count = count; return this; }
        public Builder address(String address) { this.address = address; return this; }
        public Builder coupon(String coupon) { this.coupon = coupon; return this; }

        public Order build() { return new Order(this); }
    }

    @Override
    public String toString() {
        return "Order{orderNo='" + orderNo + "', product='" + product
                + "', count=" + count + ", address='" + address + "', coupon='" + coupon + "'}";
    }

    public static void main(String[] args) {
        // 链式创建，可选字段按需设置，阅读清晰
        Order order = new Order.Builder("NO20260818001", "iPhone 15")
                .count(2)
                .address("北京市朝阳区xx路")
                .build();
        System.out.println(order);
    }
}
```

### 14.2.4 原型模式（Prototype）

**问题**：创建对象成本高（如查库后组装），需要复制一份稍作修改。

```java
package com.example.pattern.prototype;

/**
 * 原型模式：实现 Cloneable + 重写 clone() 复制对象
 * 注意：浅拷贝只复制引用，深拷贝要逐个复制可变对象
 */
public class User implements Cloneable {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    protected User clone() throws CloneNotSupportedException {
        return (User) super.clone();   // Object 的 clone 做浅拷贝
    }

    public void setName(String name) { this.name = name; }

    @Override
    public String toString() { return "User{name='" + name + "', age=" + age + "}"; }

    public static void main(String[] args) throws CloneNotSupportedException {
        User u1 = new User("张三", 20);
        User u2 = u1.clone();          // 复制一份
        u2.setName("李四");             // 改副本不影响原对象
        System.out.println(u1);        // User{name='张三', age=20}
        System.out.println(u2);        // User{name='李四', age=20}
    }
}
```

## 14.3 结构型模式

### 14.3.1 代理模式（面试重点）

**问题**：不直接操作目标对象，通过一个"代理"间接操作，方便加额外逻辑（日志、权限、缓存）。

**静态代理：**

```java
package com.example.pattern.proxy;

/**
 * 目标接口
 */
public interface UserService {
    void save(String name);
}

/**
 * 真实业务类
 */
class UserServiceImpl implements UserService {
    @Override
    public void save(String name) {
        System.out.println("保存用户：" + name);
    }
}

/**
 * 静态代理：和目标实现同一接口，包一层做增强
 */
class UserServiceProxy implements UserService {
    private final UserService target;

    public UserServiceProxy(UserService target) { this.target = target; }

    @Override
    public void save(String name) {
        System.out.println("[代理] 开始：记录日志...");
        target.save(name);                      // 调用真实方法
        System.out.println("[代理] 结束：保存日志完成...");
    }
}

class ProxyTest {
    public static void main(String[] args) {
        UserService proxy = new UserServiceProxy(new UserServiceImpl());
        proxy.save("张三");   // 日志增强 + 真实保存
    }
}
```

**JDK 动态代理（框架原理）：** 运行时生成代理类，一个代理类可代理所有接口

```java
package com.example.pattern.proxy;

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

/**
 * JDK 动态代理：InvocationHandler 拦截所有方法调用
 * 注意：只支持接口（目标必须实现接口）
 */
public class DynamicProxyTest {

    public static void main(String[] args) {
        // 目标对象
        UserService target = new UserServiceImpl();

        // 创建动态代理：参数=类加载器、接口数组、处理器
        UserService proxy = (UserService) Proxy.newProxyInstance(
                DynamicProxyTest.class.getClassLoader(),
                new Class[]{UserService.class},
                new InvocationHandler() {
                    @Override
                    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                        System.out.println("[动态代理] 调用前：方法 = " + method.getName());
                        // 反射调用真实方法
                        Object result = method.invoke(target, args);
                        System.out.println("[动态代理] 调用后");
                        return result;
                    }
                });

        proxy.save("李四");
    }
}
```

**框架中的应用**：**Spring AOP**（事务 `@Transactional`、日志、权限）就是动态代理！接口用 JDK 代理，类用 CGLIB 子类代理。MyBatis 的 Mapper 也是动态代理生成实现。

### 14.3.2 装饰器模式

**问题**：动态给对象"叠加"功能（如咖啡加糖、加奶；IO 流包多层缓冲）。

```java
package com.example.pattern.decorator;

/**
 * 装饰器：包裹原对象，增强其行为，可层层叠加
 */
public interface Drink {
    double price();
    String desc();
}

class Coffee implements Drink {
    @Override public double price() { return 10; }
    @Override public String desc() { return "咖啡"; }
}

/**
 * 装饰器基类：持有被装饰对象
 */
abstract class DrinkDecorator implements Drink {
    protected Drink drink;
    public DrinkDecorator(Drink drink) { this.drink = drink; }
}

class MilkDecorator extends DrinkDecorator {
    public MilkDecorator(Drink drink) { super(drink); }
    @Override public double price() { return drink.price() + 3; }   // 加奶 +3
    @Override public String desc() { return drink.desc() + " + 牛奶"; }
}

class SugarDecorator extends DrinkDecorator {
    public SugarDecorator(Drink drink) { super(drink); }
    @Override public double price() { return drink.price() + 1; }   // 加糖 +1
    @Override public String desc() { return drink.desc() + " + 糖"; }
}

class DecoratorTest {
    public static void main(String[] args) {
        Drink drink = new Coffee();
        drink = new MilkDecorator(drink);     // 加奶
        drink = new SugarDecorator(drink);    // 再加糖
        System.out.println(drink.desc() + "：" + drink.price() + " 元");
        // 咖啡 + 牛奶 + 糖：14.0 元
    }
}
```

**框架中的应用**：`BufferedInputStream` 包 `FileInputStream` 增强缓冲；`HttpServletRequestWrapper` 包装请求加功能。

### 14.3.3 适配器模式

**问题**：接口不兼容，加一个"转接头"（如 220V → 5V；旧接口兼容新系统）。

```java
package com.example.pattern.adapter;

/**
 * 场景：老系统用 USB，新电脑只有 Type-C，需要一个转接头
 */
public interface TypeC {
    void charge();
}

class OldUsbCharger {
    public void chargeByUsb() {
        System.out.println("老式 USB 充电器充电中...");
    }
}

/**
 * 适配器：实现新接口 TypeC，内部持有并调用老接口
 */
class UsbToTypeCAdapter implements TypeC {
    private final OldUsbCharger charger;

    public UsbToTypeCAdapter(OldUsbCharger charger) { this.charger = charger; }

    @Override
    public void charge() {
        charger.chargeByUsb();     // 转接：新接口 → 老接口
    }
}

class AdapterTest {
    public static void main(String[] args) {
        TypeC adapter = new UsbToTypeCAdapter(new OldUsbCharger());
        adapter.charge();          // 新电脑（TypeC）用老充电器也能充
    }
}
```

**框架中的应用**：**SLF4J 就是适配器思想的集大成者**（第十一章）：每个日志实现提供一个适配层，统一对外暴露 slf4j 接口。

### 14.3.4 外观模式（门面 Facade）

**问题**：子系统太多，客户端要懂一堆类。提供一个**统一入口**。

```java
package com.example.pattern.facade;

/**
 * 场景：下单要调用库存、支付、物流三个子系统，客户端不该了解细节
 */
class StockService { public void reduce(String product) { System.out.println("扣减库存：" + product); } }
class PayService { public void pay(double money) { System.out.println("支付：" + money + " 元"); } }
class LogisticsService { public void ship() { System.out.println("发货"); } }

/**
 * 外观类：统一入口，封装子系统调用顺序
 */
class OrderFacade {
    private final StockService stock = new StockService();
    private final PayService pay = new PayService();
    private final LogisticsService logistics = new LogisticsService();

    // 客户端只需调这一个方法
    public void placeOrder(String product, double money) {
        stock.reduce(product);
        pay.pay(money);
        logistics.ship();
    }
}

class FacadeTest {
    public static void main(String[] args) {
        OrderFacade facade = new OrderFacade();
        facade.placeOrder("iPhone", 5999);   // 一句话完成整套流程
    }
}
```

**框架中的应用**：Controller → **Service 门面**（封装修多 Dao）→ Dao。就是三层架构！

## 14.4 行为型模式

### 14.4.1 策略模式（最实用）

**问题**：一个操作有多种算法（支付方式、优惠策略、压缩格式），`if-else` 满天飞，新增算法要改旧代码（违反开闭原则）。

```java
package com.example.pattern.strategy;

/**
 * 策略接口
 */
public interface DiscountStrategy {
    double calculate(double price);   // 计算优惠后价格
}

// 无优惠
class NoDiscount implements DiscountStrategy {
    @Override public double calculate(double price) { return price; }
}

// 满 100 减 20
class FullReduction implements DiscountStrategy {
    @Override public double calculate(double price) {
        return price >= 100 ? price - 20 : price;
    }
}

// 打 8 折
class PercentDiscount implements DiscountStrategy {
    @Override public double calculate(double price) { return price * 0.8; }
}
```

```java
package com.example.pattern.strategy;

/**
 * 上下文：持有策略，运行时切换
 */
public class PriceContext {
    private DiscountStrategy strategy;

    public PriceContext(DiscountStrategy strategy) { this.strategy = strategy; }

    public void setStrategy(DiscountStrategy strategy) { this.strategy = strategy; }

    public double price(double original) {
        return strategy.calculate(original);
    }

    public static void main(String[] args) {
        PriceContext context = new PriceContext(new NoDiscount());
        System.out.println("无优惠：" + context.price(150));       // 150

        context.setStrategy(new FullReduction());
        System.out.println("满减：" + context.price(150));          // 130

        context.setStrategy(new PercentDiscount());
        System.out.println("8折：" + context.price(150));           // 120
        // 新增"买一送一"只需新增一个策略类，其他代码零改动 → 开闭原则
    }
}
```

**Spring 进阶：策略模式 + Map 注入（企业标准写法）**

```java
package com.example.demo.service;

import org.springframework.stereotype.Component;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;
import java.util.function.Function;
import java.util.stream.Collectors;

/**
 * 支付策略接口
 */
public interface PayStrategy {
    String type();                       // 策略标识：alipay / wechat / bank
    void pay(double amount);
}

@Component
class AlipayStrategy implements PayStrategy {
    @Override public String type() { return "alipay"; }
    @Override public void pay(double amount) { System.out.println("支付宝支付 " + amount); }
}

@Component
class WechatStrategy implements PayStrategy {
    @Override public String type() { return "wechat"; }
    @Override public void pay(double amount) { System.out.println("微信支付 " + amount); }
}

@Service
class PayService {
    // Spring 把所有 PayStrategy 实现注入成 Map：key = Bean 名
    private final Map<String, PayStrategy> strategyMap;

    public PayService(List<PayStrategy> strategies) {
        // 按 type() 转成 Map：{"alipay": AlipayStrategy, "wechat": WechatStrategy}
        this.strategyMap = strategies.stream()
                .collect(Collectors.toMap(PayStrategy::type, Function.identity()));
    }

    // 新增支付方式：加一个 @Component 类即可，本类零改动（开闭原则）
    public void pay(String type, double amount) {
        PayStrategy strategy = strategyMap.get(type);
        if (strategy == null) throw new IllegalArgumentException("不支持的支付方式：" + type);
        strategy.pay(amount);
    }
}
```

### 14.4.2 模板方法模式

**问题**：一个流程的**骨架固定**，但某些步骤不同实现（如：取数 → 处理 → 保存，处理逻辑各不同）。

```java
package com.example.pattern.template;

/**
 * 模板方法：父类定义流程骨架，子类实现可变步骤
 * 继承的经典应用
 */
public abstract class DataProcessor {

    // 模板方法（final 防止子类修改流程）
    public final void process() {
        load();            // 步骤1：取数据（固定）
        transform();       // 步骤2：转换（抽象，子类实现）
        save();            // 步骤3：保存（固定）
        log();             // 步骤4：打日志（钩子，可覆盖）
    }

    private void load() { System.out.println("读取原始数据"); }
    private void save() { System.out.println("保存到目标库"); }
    protected void log() { System.out.println("记录默认日志"); }   // 钩子：默认实现

    protected abstract void transform();   // 子类必须实现
}

class UserDataProcessor extends DataProcessor {
    @Override protected void transform() { System.out.println("把用户 JSON 转成实体"); }
    @Override protected void log() { System.out.println("记录用户处理专属日志"); }  // 覆盖钩子
}

class OrderDataProcessor extends DataProcessor {
    @Override protected void transform() { System.out.println("把订单数据汇总统计"); }
}

class TemplateTest {
    public static void main(String[] args) {
        new UserDataProcessor().process();
        System.out.println("-----");
        new OrderDataProcessor().process();
    }
}
```

**框架中的应用**：`JdbcTemplate` 流程固定、`Spring` 的 `AbstractApplicationContext.refresh()`、servlet 的 `service()` 分发 doGet/doPost。

### 14.4.3 观察者模式

**问题**：一个对象状态变化，通知多个依赖它的对象（如：下单后 → 发短信、发邮件、更新库存）。

```java
package com.example.pattern.observer;

import java.util.ArrayList;
import java.util.List;

/**
 * 观察者接口
 */
public interface Observer {
    void update(String event);
}

// 具体观察者 1：短信通知
class SmsObserver implements Observer {
    @Override public void update(String event) { System.out.println("发短信通知：" + event); }
}

// 具体观察者 2：邮件通知
class EmailObserver implements Observer {
    @Override public void update(String event) { System.out.println("发邮件通知：" + event); }
}

// 具体观察者 3：记录日志
class LogObserver implements Observer {
    @Override public void update(String event) { System.out.println("记录日志：" + event); }
}

/**
 * 被观察者（主题）：维护观察者列表，状态变化时广播
 */
class OrderSubject {
    private final List<Observer> observers = new ArrayList<>();

    public void addObserver(Observer o) { observers.add(o); }
    public void removeObserver(Observer o) { observers.remove(o); }

    // 状态变化：通知所有观察者
    public void orderCreated(String orderNo) {
        System.out.println("订单创建：" + orderNo);
        for (Observer o : observers) {
            o.update("新订单 " + orderNo);   // 广播
        }
    }
}

class ObserverTest {
    public static void main(String[] args) {
        OrderSubject subject = new OrderSubject();
        subject.addObserver(new SmsObserver());      // 注册短信
        subject.addObserver(new EmailObserver());    // 注册邮件
        subject.addObserver(new LogObserver());      // 注册日志

        subject.orderCreated("NO20260818001");
        // 订单创建后，三个观察者自动执行，无需修改订单类
    }
}
```

**框架中的应用**：**Spring 事件监听**（`ApplicationEvent` + `@EventListener`）、Spring Boot 启动监听、`MouseListener`。

### 14.4.4 责任链模式

**问题**：一个请求需要多个处理器**依次处理**，谁处理得了谁处理（如请假审批、日志级别过滤、Spring Security 过滤器链）。

```java
package com.example.pattern.chain;

/**
 * 责任链：每个处理器决定"自己处理 or 交给下一个"
 * 场景：请假审批（组长 ≤3 天，经理 ≤7 天，总监无限制）
 */
public abstract class Approver {
    protected Approver next;              // 下一级
    protected String name;

    public Approver(String name) { this.name = name; }

    // 设置下一级
    public Approver setNext(Approver next) {
        this.next = next;
        return next;                       // 返回 next 便于链式设置
    }

    // 处理（模板方法）：能处理就处理，否则交给下一个
    public final void handle(int days) {
        if (canApprove(days)) {
            System.out.println(name + " 批准了 " + days + " 天请假");
        } else if (next != null) {
            System.out.println(name + " 无权处理，转交 " + next.name);
            next.handle(days);
        } else {
            System.out.println("无人有权处理，驳回");
        }
    }

    protected abstract boolean canApprove(int days);
}

class TeamLeader extends Approver {
    public TeamLeader() { super("组长"); }
    @Override protected boolean canApprove(int days) { return days <= 3; }
}

class Manager extends Approver {
    public Manager() { super("经理"); }
    @Override protected boolean canApprove(int days) { return days <= 7; }
}

class Director extends Approver {
    public Director() { super("总监"); }
    @Override protected boolean canApprove(int days) { return true; }
}

class ChainTest {
    public static void main(String[] args) {
        // 组装责任链：组长 → 经理 → 总监
        Approver chain = new TeamLeader();
        chain.setNext(new Manager()).setNext(new Director());

        chain.handle(2);    // 组长 批准了 2 天请假
        chain.handle(5);    // 组长无权 → 经理批准
        chain.handle(15);   // 组长、经理无权 → 总监批准
    }
}
```

**框架中的应用**：Spring Security 过滤器链、Tomcat 过滤器、MyBatis 拦截器、日志级别过滤。

## 14.5 设计模式在 Spring 框架中的应用（面试加分）

| Spring 特性 | 对应设计模式 |
| --- | --- |
| Bean 单例 | **单例模式** |

## 14.6 小结与练习

**本章重点**：
- 设计原则：开闭原则最重要
- 创建型：单例（DCL/静态内部类/枚举）、工厂、建造者（= @Builder）
- 结构型：代理（= AOP）、装饰器（= IO 流）、适配器（= SLF4J）、外观（= Service 层）
- 行为型：策略（Map 注入写法）、模板方法、观察者（= 事件）、责任链（= 过滤器链）

**面试题参考**：
1. 手写单例模式（DCL 为什么要 volatile？）
2. JDK 动态代理和 CGLIB 的区别？（JDK 要接口，CGLIB 是子类）
3. 策略模式和 if-else 的取舍？Spring 中如何用 Map 注入策略？
4. 代理模式和装饰器模式的区别？（代理控制访问，装饰器增强功能）
5. 观察者模式和发布订阅的区别？
6. 说出 5 个 Spring 中用到的设计模式？

**课后练习**：
1. 用静态内部类写单例，并用多线程（10 线程各调 1000 次 getInstance）验证只创建一个实例。
2. 用策略模式重构：运费计算（按地区：本省/外省/海外，不同费率），用 Spring Map 注入版本。
3. 用责任链实现敏感词过滤（一级过滤脏话、二级过滤政治敏感词、三级过滤广告词）。
4. 手写 JDK 动态代理给业务方法加"打印耗时"切面，对比 Spring AOP。
5. 观察你写过的项目代码，找出至少 3 处可以用设计模式改进的地方。
