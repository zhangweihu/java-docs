# 第十一章 日志框架：SLF4J / Log4j2 / Logback

> 本章掌握：日志框架的生态与选型、SLF4J 门面思想、Logback 与 Log4j2 的配置、日志最佳实践。
> 日志是生产环境排障的**唯一眼睛**，Java 日志生态（SLF4J + 实现框架）是每个开发者必会的技能，也是面试常考点。

## 11.1 为什么需要日志框架

### 11.1.1 System.out.println 的痛点

新手常用 `System.out.println` 调试，但生产环境根本不可用：

| 痛点 | 日志框架的解决 |
| --- | --- |
| 无法控制输出（上线后不想看 DEBUG） | **日志级别**：INFO/ERROR 过滤 |
| 无时间、类名、线程信息 | 格式化 pattern 自动带上 |
| 只能输出到控制台 | Appender 可写文件、按天滚动、发邮件 |
| 无法定位线上问题 | 保留堆栈、按级别检索 |
| 大量输出影响性能 | 异步日志、按级别丢弃 |

### 11.1.2 日志级别

```
TRACE → DEBUG → INFO → WARN → ERROR（级别从低到高）
```

- **TRACE**：最详细，跟踪代码执行路径（一般不用于生产）
- **DEBUG**：调试信息，开发期看，生产关掉
- **INFO**：关键业务节点（请求来了、订单创建成功）
- **WARN**：潜在风险，不影响主流程（配置缺失、重试）
- **ERROR**：错误，需要人工处理

**规则**：日志级别设 `INFO` 时，`DEBUG` 及其以下全部**不输出**，以此类推。

## 11.2 Java 日志生态：SLF4J + 实现框架

### 11.2.1 各框架关系（面试必考）

| 框架 | 类型 | 说明 |
| --- | --- | --- |
| **SLF4J** | 门面（接口） | Simple Logging Facade for Java，只定义 API，不干活 |
| Log4j 1.x | 实现 | 老牌框架，已停止维护 |
| **Logback** | 实现 | **Log4j 1.x 作者重写**，目前 Spring Boot 默认 |
| **Log4j2** | 实现 | Apache 重写的 Log4j，性能最强，异步日志优秀 |

```
       你的业务代码（只依赖 SLF4J 接口）
                    │
                 SLF4J（门面）
                    │ 运行时绑定一个实现
        ┌───────────┼───────────┐
     Logback    Log4j2     其他实现
```

**为什么要门面**：
1. **解耦**：代码只写 `LoggerFactory.getLogger(...)`，换实现框架不改业务代码
2. **统一**：项目里依赖的第三方库可能用不同日志框架，SLF4J + 桥接统一到一家
3. **现状**：**SLF4J + Logback** 是 Spring Boot 默认组合，也是使用最广的

### 11.2.2 快速开始（SLF4J + Logback）

```xml
<!-- pom.xml：只需引入 logback-classic，它会自动带上 slf4j-api -->
<dependency>
    <groupId>ch.qos.logback</groupId>
    <artifactId>logback-classic</artifactId>
    <version>1.5.6</version>
</dependency>
```

```java
package com.example.logdemo;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class HelloLog {

    // 标准写法：logger 命名为当前类，日志里能显示类名
    private static final Logger log = LoggerFactory.getLogger(HelloLog.class);

    public static void main(String[] args) {
        log.trace("trace 级别");
        log.debug("debug 级别");
        log.info("info 级别");
        log.warn("warn 级别");
        log.error("error 级别");

        // 占位符 {}：推荐，避免字符串拼接（无参数时零开销）
        String name = "张三";
        int age = 20;
        log.info("用户：{}，年龄：{}", name, age);

        // 打印异常：直接传异常对象，自动带完整堆栈
        try {
            int x = 1 / 0;
        } catch (Exception e) {
            log.error("计算失败", e);
        }
    }
}
```

默认输出（默认级别 DEBUG，无配置直接可用）：

```
21:00:01.001 [main] INFO com.example.logdemo.HelloLog - info 级别
21:00:01.002 [main] WARN com.example.logdemo.HelloLog - warn 级别
21:00:01.003 [main] ERROR com.example.logdemo.HelloLog - error 级别
...
```

## 11.3 Logback 配置详解

### 11.3.1 配置结构（logback.xml）

放在 `src/main/resources/logback.xml`，核心三要素：

```
<configuration>
  ├── <appender>   输出目的地（控制台 / 文件 / 滚动文件）
  ├── <logger>     按包/类设置级别
  └── <root>       根日志器（兜底）
```

### 11.3.2 基础配置：控制台 + 文件

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- ① 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <!-- pattern：%d 时间 | %level 级别 | %thread 线程 | %logger 类名 | %msg 消息 | %n 换行 -->
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- ② 文件输出（固定文件，会一直变大，生产一般用滚动文件见 11.3.3） -->
    <appender name="FILE" class="ch.qos.logback.core.FileAppender">
        <file>logs/app.log</file>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- ③ 指定包级别：com.example 全包 DEBUG，便于开发调试 -->
    <logger name="com.example" level="DEBUG"/>

    <!-- ④ 根日志器：全局级别 INFO，挂载两个 appender -->
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>

</configuration>
```

### 11.3.3 滚动文件：按天 + 按大小（生产标准配置）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- 控制台 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 滚动文件：日志按天切分，每天一个文件，保留 30 天 -->
    <appender name="ROLLING" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/app.log</file>                          <!-- 当前写入文件 -->
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <!-- 归档规则：按天生成 app-2026-08-18.log -->
            <fileNamePattern>logs/app-%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>                    <!-- 保留 30 天 -->
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 错误日志单独一个文件（排查问题只看 ERROR） -->
    <appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/error.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/error-%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>60</maxHistory>
        </rollingPolicy>
        <!-- 过滤器：只记录 ERROR 级别 -->
        <filter class="ch.qos.logback.classic.filter.LevelFilter">
            <level>ERROR</level>
            <onMatch>ACCEPT</onMatch>
            <onMismatch>DENY</onMismatch>
        </filter>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="ROLLING"/>
        <appender-ref ref="ERROR_FILE"/>
    </root>

</configuration>
```

### 11.3.4 pattern 常用占位符

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `%d{yyyy-MM-dd HH:mm:ss.SSS}` | 时间（自定义格式） | `2026-08-18 21:00:01.001` |
| `%level` / `%-5level` | 级别（-5 左对齐补空格） | `INFO ` |
| `%thread` | 线程名 | `main` |
| `%logger{36}` | 类名（超长截断） | `com.example.logdemo.HelloLog` |
| `%msg` | 日志消息 | `用户：张三` |
| `%n` | 换行 | |
| `%line` / `%L` | 行号 | `42` |
| `%method` | 方法名 | `main` |
| `%mdc{key}` | MDC 值（见 11.6.4） | `traceId` |

## 11.4 Log4j2 配置详解

Log4j2 是 Apache 重写的下一代日志框架，**性能最强**（异步日志吞吐量远超 Logback），大数据/高并发场景常用。

### 11.4.1 依赖（需要同时引入门面 + 实现）

```xml
<dependency>
    <groupId>org.apache.logging.log4j</groupId>
    <artifactId>log4j-slf4j2-impl</artifactId>   <!-- 把 SLF4J 绑定到 Log4j2 -->
    <version>2.23.1</version>
</dependency>
<dependency>
    <groupId>org.apache.logging.log4j</groupId>
    <artifactId>log4j-core</artifactId>
    <version>2.23.1</version>
</dependency>
```

> 业务代码**不用改**，依然写 `org.slf4j.Logger` / `LoggerFactory` —— 这就是门面的价值。

### 11.4.2 log4j2.xml（异步日志）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Configuration status="WARN">

    <!-- 控制台输出 -->
    <Appenders>
        <Console name="Console" target="SYSTEM_OUT">
            <PatternLayout pattern="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"/>
        </Console>

        <!-- 异步滚动文件 -->
        <RollingFile name="RollingFile" fileName="logs/app.log"
                     filePattern="logs/app-%d{yyyy-MM-dd}.log">
            <PatternLayout pattern="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"/>
            <Policies>
                <TimeBasedTriggeringPolicy/>     <!-- 按天触发滚动 -->
            </Policies>
            <DefaultRolloverStrategy max="30"/>  <!-- 保留 30 天 -->
        </RollingFile>
    </Appenders>

    <!-- 全局异步：AsyncLogger（性能关键，吞吐量高） -->
    <AsyncLogger name="com.example" level="DEBUG" additivity="false">
        <AppenderRef ref="Console"/>
        <AppenderRef ref="RollingFile"/>
    </AsyncLogger>

    <Root level="INFO">
        <AppenderRef ref="Console"/>
        <AppenderRef ref="RollingFile"/>
    </Root>

</Configuration>
```

### 11.4.3 Logback vs Log4j2 对比（面试题）

| 维度 | Logback | Log4j2 |
| --- | --- | --- |
| 出身 | Log4j 1.x 作者 | Apache |
| 配置格式 | logback.xml | log4j2.xml（支持 XML/JSON/YAML） |
| 性能 | 快 | **最快**（异步日志 10 倍以上差距） |
| 与 Spring Boot | **默认集成**，零配置 | 需排除默认依赖，手动引入 |
| 生态 | 最广 | 大数据（Spark/Flink）默认 |
| 选择建议 | 常规项目无脑选 | 高并发、日志量大的场景 |

## 11.5 异步日志

同步日志中，写磁盘/网络会**阻塞业务线程**；异步日志把日志交给独立线程，业务线程只负责"投递"，**高并发下吞吐量提升数倍**。

### 11.5.1 Logback 异步

```xml
<!-- ① 定义同步 appender（文件） -->
<appender name="ROLLING" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <!-- ...同 11.3.3 配置... -->
</appender>

<!-- ② 包一层 AsyncAppender -->
<appender name="ASYNC" class="ch.qos.logback.classic.AsyncAppender">
    <!-- 队列大小：日志量大时调大，默认 256 -->
    <queueSize>1024</queueSize>
    <!-- 丢弃策略：队列满时丢 TRACE/DEBUG，不丢 INFO 及以上 -->
    <discardingThreshold>0</discardingThreshold>
    <appender-ref ref="ROLLING"/>
</appender>

<root level="INFO">
    <appender-ref ref="ASYNC"/>
</root>
```

> 注意：**异常堆栈默认只保留第一行**，调试时需要 `<includeCallerData>true</includeCallerData>`（有性能损耗，生产慎开）。

## 11.6 日志最佳实践

### 11.6.1 基础规范

```java
package com.example.logdemo.service;

import lombok.extern.slf4j.Slf4j;   // Lombok 生成 log（等价手写 LoggerFactory）
import org.springframework.stereotype.Service;

@Slf4j
@Service
public class UserService {

    public void createUser(String name) {
        // ✅ 参数化日志：用 {} 占位，避免 "name=" + name 字符串拼接（GC 压力）
        log.info("开始创建用户：{}", name);

        // ❌ 不要：log.info("创建用户" + name);（即使不输出也会拼接字符串）
        // ❌ 不要：System.out.println(...)（生产不可控、无级别无时间）

        try {
            // 业务逻辑...
            log.info("用户创建成功：{}", name);
        } catch (Exception e) {
            // ✅ 必须带异常对象，否则只有一行消息没有堆栈
            log.error("用户创建失败：{}", name, e);
            // ❌ 不要：log.error("创建失败：" + e.getMessage());（丢堆栈）
        }
    }
}
```

### 11.6.2 敏感信息脱敏

```java
package com.example.logdemo.util;

/**
 * 日志脱敏工具：手机号/身份证只显示前后几位
 * 用法：log.info("用户手机号：{}", DesensitizeUtil.phone(phone));
 */
public class DesensitizeUtil {

    // 手机号：138****5678
    public static String phone(String phone) {
        if (phone == null || phone.length() < 7) return "****";
        return phone.substring(0, 3) + "****" + phone.substring(7);
    }

    // 身份证：110***********1234
    public static String idCard(String idCard) {
        if (idCard == null || idCard.length() < 10) return "****";
        return idCard.substring(0, 3) + "***********" + idCard.substring(idCard.length() - 4);
    }

    // 邮箱：zh***@qq.com
    public static String email(String email) {
        int at = email.indexOf('@');
        if (at <= 1) return "***";
        return email.substring(0, 2) + "***" + email.substring(at);
    }

    public static void main(String[] args) {
        System.out.println(phone("13812345678"));      // 138****5678
        System.out.println(email("zhangsan@qq.com"));  // zh***@qq.com
    }
}
```

### 11.6.3 MDC：全链路追踪（traceId）

微服务/分布式场景下，需要把一次请求的所有日志串起来 —— 用 **MDC**（Mapped Diagnostic Context，日志上下文），在请求入口设置 `traceId`，日志自动带上，排查时按 traceId 检索即可。

```java
package com.example.logdemo.filter;

import org.slf4j.MDC;

import java.util.UUID;

public class TraceUtil {

    public static final String TRACE_ID = "traceId";

    // 请求入口调用：生成 traceId 放入 MDC
    public static void begin() {
        MDC.put(TRACE_ID, UUID.randomUUID().toString().replace("-", "").substring(0, 16));
    }

    // 请求结束调用：清理，防止线程复用串号
    public static void end() {
        MDC.remove(TRACE_ID);
    }
}
```

```xml
<!-- pattern 中加 %mdc{traceId}，没有 traceId 时显示 "" -->
<pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%mdc{traceId}] %logger{36} - %msg%n</pattern>
```

输出效果：

```
21:10:00.123 [http-nio-8080-exec-1] INFO  [a3f2b1c9d8e7f6a1] com.example.demo.UserController - 请求开始
21:10:00.124 [http-nio-8080-exec-1] INFO  [a3f2b1c9d8e7f6a1] com.example.demo.UserService - 创建用户：张三
21:10:00.125 [http-nio-8080-exec-2] INFO  [b7e4a2d1c3f5b6a2] com.example.demo.UserController - 请求开始
```

## 11.7 Spring Boot 中的日志配置（衔接 9.9）

Spring Boot 默认用 **SLF4J + Logback**，`spring-boot-starter` 已自带，**零配置即可用**。

### 11.7.1 application.yml 配置

```yaml
logging:
  level:
    root: info                      # 全局级别
    com.example.demo: debug         # 指定包级别
    org.mybatis: warn               # 第三方库级别（压噪音）
  file:
    name: logs/app.log              # 输出文件（默认没有）
  pattern:
    console: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"
    file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"
```

### 11.7.2 logback-spring.xml（支持 Spring profile）

放在 `src/main/resources/logback-spring.xml`（**必须是 `-spring` 后缀**才能用 `springProfile`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- 开发环境：控制台 DEBUG -->
    <springProfile name="dev">
        <logger name="com.example.demo" level="DEBUG"/>
    </springProfile>

    <!-- 生产环境：INFO + 滚动文件 -->
    <springProfile name="prod">
        <appender name="ROLLING" class="ch.qos.logback.core.rolling.RollingFileAppender">
            <file>logs/app.log</file>
            <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
                <fileNamePattern>logs/app-%d{yyyy-MM-dd}.log</fileNamePattern>
                <maxHistory>30</maxHistory>
            </rollingPolicy>
            <encoder>
                <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%mdc{traceId}] %logger{36} - %msg%n</pattern>
            </encoder>
        </appender>

        <logger name="com.example.demo" level="INFO"/>
        <root level="INFO">
            <appender-ref ref="ROLLING"/>
        </root>
    </springProfile>

    <!-- 默认（未匹配 profile 时）：控制台 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
    </root>

</configuration>
```

### 11.7.3 切换实现：排除 Logback 引入 Log4j2

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-logging</artifactId>   <!-- 排除默认 Logback -->
        </exclusion>
    </exclusions>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-log4j2</artifactId>
</dependency>
```

### 11.7.4 第三方库日志统一（桥接）

项目里可能有老库用 Log4j 1.x 或 JUL（`java.util.logging`），它们的日志**收不进 SLF4J**，需要桥接依赖：

```xml
<!-- 把 Log4j 1.x 的日志路由到 SLF4J -->
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>log4j-over-slf4j</artifactId>
</dependency>
<!-- 把 JUL 的日志路由到 SLF4J -->
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>jul-to-slf4j</artifactId>
</dependency>
```

## 11.8 小结与练习

**本章重点**：
- 日志级别：TRACE < DEBUG < INFO < WARN < ERROR
- 生态：SLF4J（门面）+ Logback/Log4j2（实现），Spring Boot 默认 Logback
- Logback 核心：appender / logger / root + pattern + 滚动策略
- Log4j2：异步日志性能最强
- 最佳实践：参数化占位符、带堆栈、脱敏、MDC traceId、异步日志

**面试题参考**：
1. SLF4J 是什么？为什么用门面？
2. Logback 和 Log4j2 的区别？如何选型？
3. 生产环境如何排查线上问题（日志角度）？
4. 异步日志的原理和注意事项？

**课后练习**：
1. 写一个类，用五种级别各输出一条日志，观察配置为 INFO 时的输出。
2. 配置 logback.xml：控制台 + 按天滚动文件 + 独立 error.log，验证第二天的归档效果。
3. 为第九章的 Spring Boot 项目配置 logback-spring.xml（dev 控制台 DEBUG / prod 滚动文件）。
4. 给 Controller 加一个过滤器，在 MDC 写入 traceId，把 pattern 加上 `%mdc{traceId}`，用 Postman 连续请求两次，对比 traceId 不同。
