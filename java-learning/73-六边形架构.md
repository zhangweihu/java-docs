# 第七十三章 六边形架构（Ports & Adapters）

> **本章目标**：掌握六边形架构（端口与适配器）的工程落法，把"业务核心不依赖任何外部技术"的理念落到 Spring Boot。
>
> **前置知识**：第 72 章（整洁架构落地）、第 41 章（仓储/防腐层）、第 6 章（接口与实现分离）。

> 一句话：**六边形 = 整洁架构的简化工程表达**，用"端口与适配器"替代"同心圆"。

---

## 73.1 六边形起源：Alistair Cockburn 的动机

2005 年，Alistair Cockburn 在博客《Hexagonal Architecture》中提出：

> **应用应当像六边形一样：内部业务核心、四周被各种适配器环绕。外部技术（UI、DB、消息）变化时，业务核心不需要任何改动。**

核心隐喻：

```
            Web UI
              │
   CLI ──►  ┌────────┐ ◄── MQ Consumer
            │ 业务   │
            │ 核心   │
   DB  ──►  │ (六边形)│ ◄── 远程服务
            │       │
   Redis ──►└────────┘
            ▲      ▲
            │      │
        Adapter 1  Adapter 2
         (主适配)  (从适配)
```

## 73.2 四个核心概念

### 73.2.1 Inbound Port（入口端口 / 驱动端口）

业务核心**对外**暴露的能力。对应"做什么用例"。

```java
// 入口端口
public interface SubmitOrderPort {
    Long submit(SubmitOrderCommand cmd);
}
```

### 73.2.2 Outbound Port（出口端口 / 被驱动端口）

业务核心**需要**的外部能力。对应"需要外部做什么"。

```java
// 出口端口
public interface OrderRepositoryPort {
    void save(Order order);
    Optional<Order> findById(Long id);
}
```

### 73.2.3 主适配器（Driving Adapter）

**调用**业务核心的外部组件。Controller、CLI、MQ Consumer、定时任务。

```java
@RestController  // ← 主适配器
public class HexOrderController {
    private final SubmitOrderPort port;  // 注入入口端口

    @PostMapping("/hex/orders")
    public void create(@RequestBody SubmitOrderRequest req) {
        port.submit(toCommand(req));     // 调用入口端口
    }
}
```

### 73.2.4 从适配器（Driven Adapter）

**被**业务核心使用——实现出口端口。MyBatis 仓储、Redis 缓存、Feign 客户端。

```java
@Repository  // ← 从适配器
public class HexOrderRepositoryAdapter implements OrderRepositoryPort {
    @Override
    public void save(Order order) {
        // MyBatis 实现
    }
}
```

## 73.3 端口命名规范

| 端口类型 | 命名后缀 | 示例 |
| --- | --- | --- |
| 入口端口 | `*Port` | `SubmitOrderPort`、`CancelOrderPort` |
| 出口端口 | `*Port` | `OrderRepositoryPort`、`PaymentGatewayPort` |
| 主适配器 | `*Adapter` 或 `*Controller` | `HexOrderController`、`HexOrderCLIAdapter` |
| 从适配器 | `*Adapter` | `HexOrderRepositoryAdapter`、`HexPaymentGatewayAdapter` |

> 六边形与 DDD 四层的命名差异：
>
> - DDD：入口用 `*AppService`（具体类）
> - 六边形：入口用 `*Port`（接口）+ `*Service` 实现
>
> 命名上六边形更"边界意识"，DDD 更"OO 直觉"。

## 73.4 与整洁架构的关系

整洁架构与六边形本质同构，差异在表达方式：

| 维度 | 整洁架构 | 六边形 |
| --- | --- | --- |
| 图示 | 同心圆 | 六边形 + 周边适配器 |
| 内层 | Entities | Domain |
| 用例层 | Use Cases | 入口端口（Port） |
| 跨边界 | Interface Adapters | 适配器（Adapter） |
| 关注点 | 依赖规则（同心圆） | 端口与适配器（命名） |
| 提出者 | Robert C. Martin | Alistair Cockburn |

> **一句话**：**整洁是"几何视角"，六边形是"工程视角"**。两者落地产物几乎等价，区别只在文档叙事。

## 73.5 实战：订单上下文的六边形实现

### 73.5.1 包结构

```
com.ddd.hex.order/
├── domain/                         ← 业务核心
│   ├── Order.java                  ← 聚合根
│   └── OrderItem.java
├── application/                    ← 实现入口端口
│   ├── OrderService.java           ← implements SubmitOrderPort
│   └── SubmitOrderCommand.java
├── ports/
│   ├── in/SubmitOrderPort.java     ← 入口端口
│   └── out/OrderRepositoryPort.java ← 出口端口
├── adapters/
│   ├── in/
│   │   ├── web/HexOrderController.java   ← 主适配器（REST）
│   │   └── cli/OrderCLIAdapter.java       ← 主适配器（CLI）
│   └── out/
│       ├── persistence/HexOrderRepositoryAdapter.java   ← 从适配器（DB）
│       └── cache/HexOrderCacheAdapter.java              ← 从适配器（缓存）
└── DddHexApplication.java          ← Spring Boot 主类
```

### 73.5.2 入口端口（业务核心对外）

```java
package com.ddd.hex.order.ports.in;

import com.ddd.hex.order.application.SubmitOrderCommand;

/**
 * 入口端口。
 *
 * <p>业务核心"能做什么"的标准清单。任何主适配器（Controller / CLI / MQ）
 * 都通过实现/调用此端口与业务核心交互。
 */
public interface SubmitOrderPort {
    Long submit(SubmitOrderCommand cmd);
    void cancel(CancelOrderCommand cmd);
    OrderView findById(Long orderId);   // 读侧：返回 View 而非领域实体

    /** 读视图（端口返回值类型，避免领域实体穿透）。 */
    record OrderView(Long orderId, String status, BigDecimal total) {}
}
```

### 73.5.3 业务核心实现（实现入口端口）

```java
@Service
public class OrderService implements SubmitOrderPort {

    private final OrderRepositoryPort repositoryPort;     // 依赖出口端口（接口）
    private final PaymentGatewayPort paymentGatewayPort;   // 依赖另一个出口端口

    public OrderService(OrderRepositoryPort repositoryPort,
                        PaymentGatewayPort paymentGatewayPort) {
        this.repositoryPort = repositoryPort;
        this.paymentGatewayPort = paymentGatewayPort;
    }

    @Override
    @Transactional
    public Long submit(SubmitOrderCommand cmd) {
        Order order = Order.create(cmd.customerId(), toItems(cmd.items()));
        repositoryPort.save(order);
        return order.id();
    }

    @Override
    public void cancel(CancelOrderCommand cmd) {
        Order order = repositoryPort.findById(cmd.orderId()).orElseThrow();
        order.cancel();
        repositoryPort.save(order);
    }

    @Override
    public OrderView findById(Long orderId) {
        Order order = repositoryPort.findById(orderId).orElseThrow();
        return new OrderView(order.id(), order.status().name(), order.total().amount());
    }
}
```

### 73.5.4 出口端口（业务核心对外）

```java
public interface OrderRepositoryPort {
    void save(Order order);
    Optional<Order> findById(Long id);
}

public interface PaymentGatewayPort {
    PaymentResult charge(PaymentRequest request);
}
```

### 73.5.5 主适配器（REST Controller）

```java
@RestController
@RequestMapping("/hex/orders")
public class HexOrderController {

    private final SubmitOrderPort submitOrderPort;   // 依赖入口端口

    @PostMapping
    public ResponseEntity<Long> submit(@RequestBody SubmitOrderRequest req) {
        Long id = submitOrderPort.submit(toCommand(req));
        return ResponseEntity.status(HttpStatus.CREATED).body(id);
    }

    @GetMapping("/{id}")
    public OrderView findById(@PathVariable Long id) {
        return submitOrderPort.findById(id);
    }
}
```

### 73.5.6 从适配器（MyBatis 实现）

```java
@Repository
public class HexOrderRepositoryAdapter implements OrderRepositoryPort {

    private final OrderMapper orderMapper;
    private final OrderPOAssembler assembler;

    @Override
    public void save(Order order) {
        OrderPO po = assembler.toPO(order);
        if (po.getId() == null) {
            orderMapper.insert(po);
        } else {
            orderMapper.updateById(po);
        }
    }

    @Override
    public Optional<Order> findById(Long id) {
        OrderPO po = orderMapper.selectById(id);
        return Optional.ofNullable(po).map(assembler::toDomain);
    }
}
```

## 73.6 多入口适配器：同一 UseCase 多种触发方式

### 73.6.1 REST 入口（已实现）

```java
@RestController
public class HexOrderController { /* 见 73.5.5 */ }
```

### 73.6.2 CLI 入口

```java
@Component
public class HexOrderCLIAdapter implements CommandLineRunner {

    private final SubmitOrderPort submitOrderPort;

    @Override
    public void run(String... args) {
        if (args.length == 0 || !"--create-order".equals(args[0])) return;

        SubmitOrderCommand cmd = new SubmitOrderCommand(
            1L,
            List.of(new SubmitOrderCommand.ItemCommand(1L, "测试商品", 1, BigDecimal.TEN))
        );
        Long orderId = submitOrderPort.submit(cmd);
        System.out.println("[CLI] 已创建订单：" + orderId);
    }
}
```

### 73.6.3 消息消费者入口

```java
@Component
public class HexOrderMQAdapter {

    private final SubmitOrderPort submitOrderPort;

    @RabbitListener(queues = "order.create.queue")
    public void onMessage(OrderCreateMessage message) {
        SubmitOrderCommand cmd = new SubmitOrderCommand(
            message.customerId(),
            message.items().stream()
                .map(i -> new SubmitOrderCommand.ItemCommand(
                    i.productId(), i.productName(), i.quantity(), i.unitPrice()))
                .toList()
        );
        submitOrderPort.submit(cmd);
    }
}
```

> **关键收益**：业务核心 OrderService **没有任何改动**，就同时支持 REST、CLI、MQ 三种入口。这就是六边形架构的核心价值。

### 73.7.1 MySQL 适配器

```java
@Repository
@Profile("mysql")

```

### 73.7.2 Redis 缓存适配器

```java
@Repository
@Profile("redis")
public class RedisOrderRepositoryAdapter implements OrderRepositoryPort {

    private final StringRedisTemplate redis;

    @Override
    public Optional<Order> findById(Long id) {
        String json = redis.opsForValue().get("order:" + id);
        return Optional.ofNullable(json).map(this::deserialize);
    }

    @Override
    public void save(Order order) {
        redis.opsForValue().set("order:" + order.id(), serialize(order), Duration.ofHours(1));
    }
}
```

### 73.7.3 Mock 适配器（测试用）

```java
@Repository
@Profile("mock")
public class MockOrderRepositoryAdapter implements OrderRepositoryPort {
    private final Map<Long, Order> store = new ConcurrentHashMap<>();
    @Override public Optional<Order> findById(Long id) { return Optional.ofNullable(store.get(id)); }
    @Override public void save(Order order) { store.put(order.id(), order); }
}
```

## 73.8 端口契约设计："边界友好"原则

业务核心与外部适配器交互时，参数与返回类型应**避免**传递以下内容：

| 反例 | 隐患 | 正例 |
| --- | --- | --- |
| `Map<String, Object>` | 字段名拼错、运行时才发现 | 强类型 `record` / `class` |
| JPA 实体 | 触发懒加载、Session 状态泄漏 | 领域实体 + Assembler |
| 数据库 PO | 列名耦合、SQL 依赖泄漏 | 领域实体 |
| Spring `HttpServletRequest` | 把业务核心绑死在 Web | 命令对象（Command） |
| 第三方 SDK 实体 | 业务核心被 SDK 升级绑架 | 自家值对象 + 适配器转 |

### 73.8.1 一个反面教材

```java
// ❌ 反例：把第三方 SDK 类型直接写进端口
public interface UserServicePort {
    com.tencent.cloud.User getWxUser(String openid);  // 业务核心被绑定到腾讯云
}

// ✅ 正例：用自家类型 + 适配器转
public interface UserServicePort {
    UserProfile getUserProfile(String userId);  // 自家类型

    record UserProfile(String userId, String nickname) {}
}
```

### 本章小结

- 六边形架构 = 整洁架构的简化工程表达。
- 4 个核心概念：入口端口、出口端口、主适配器、从适配器。
- 业务核心只依赖端口**接口**，不依赖任何具体适配器实现。
- 多入口适配器（REST/CLI/MQ 共享同一 UseCase）是六边形最大价值之一。
- 端口契约必须"边界友好"——避免传递第三方 SDK / 数据库 PO 类型。
