## 77.2 库存三态模型：可用 / 预留 / 已售

### 77.2.1 为什么需要三态？

| 单态模型问题 | 三态解决方案 |
| --- | --- |
| 下单直接扣减 → 用户不付款，库存永久丢失 | 下单=预留，付款=扣减，取消=释放 |
| 高并发下单时"看似有货，实际抢不到" | 预留即扣减"可用"，防超卖在预留点完成 |
| 退款时无法恢复库存 | 退款反向走"释放预留"路径 |

### 77.2.2 三态字段设计

```sql
CREATE TABLE t_inventory (
    product_id   BIGINT     NOT NULL,    -- 商品 ID
    available    INT        NOT NULL,    -- 可用库存（用户可下单）
    reserved     INT        NOT NULL DEFAULT 0,  -- 已预留（已下单未付款）
    sold         INT        NOT NULL DEFAULT 0,  -- 已售（已付款/已发货）
    version      INT        NOT NULL DEFAULT 0,  -- 乐观锁版本号
    updated_at   TIMESTAMP  NOT NULL,
    PRIMARY KEY (product_id),
    CHECK (available >= 0 AND reserved >= 0 AND sold >= 0)
);
```

**不变量**：`available + reserved + sold = 总库存`，任一字段 `≥ 0`。

## 77.3 Inventory 聚合：预留 / 扣减 / 释放行为

### 77.3.1 完整 Inventory 聚合根

```java
public class Inventory {

    private final Long productId;
    private int available;
    private int reserved;
    private int sold;
    private long version;                  // 乐观锁
    private Instant updatedAt;

    public Inventory(Long productId, int initialQuantity) {
        if (initialQuantity < 0) {
            throw new IllegalArgumentException("初始库存不能为负");
        }
        this.productId = productId;
        this.available = initialQuantity;
        this.reserved = 0;
        this.sold = 0;
        this.version = 0;
        this.updatedAt = Instant.now();
    }

    /** 仓储层重建（含 version）。 */
    public Inventory(Long productId, int available, int reserved,
                     int sold, long version, Instant updatedAt) {
        if (available < 0 || reserved < 0 || sold < 0) {
            throw new IllegalArgumentException("库存字段不能为负");
        }
        this.productId = productId;
        this.available = available;
        this.reserved = reserved;
        this.sold = sold;
        this.version = version;
        this.updatedAt = updatedAt;
    }

    // ===== 行为方法 =====

    /** 预留：available → reserved。 */
    public void reserve(int quantity) {
        requirePositive(quantity);
        if (available < quantity) {
            throw new InsufficientInventoryException(productId, available, quantity);
        }
        this.available -= quantity;
        this.reserved += quantity;
        this.updatedAt = Instant.now();
    }

    /** 扣减：reserved → sold（订单付款确认后调用）。 */
    public void commit(int quantity) {
        requirePositive(quantity);
        if (reserved < quantity) {
            throw new IllegalStateException(
                "预留数量不足，无法扣减：" + productId);
        }
        this.reserved -= quantity;
        this.sold += quantity;
        this.updatedAt = Instant.now();
    }

    /** 释放：reserved → available（订单取消时调用）。 */
    public void release(int quantity) {
        requirePositive(quantity);
        if (reserved < quantity) {
            throw new IllegalStateException(
                "预留数量不足，无法释放：" + productId);
        }
        this.reserved -= quantity;
        this.available += quantity;
        this.updatedAt = Instant.now();
    }

    /** 补货：直接增加 available。 */
    public void replenish(int quantity) {
        requirePositive(quantity);
        this.available += quantity;
        this.updatedAt = Instant.now();
    }

    private void requirePositive(int quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("数量必须为正：" + quantity);
        }
    }

    // ===== Getter =====

    public Long productId() { return productId; }
    public int available() { return available; }
    public int reserved() { return reserved; }
    public int sold() { return sold; }
    public long version() { return version; }
    public Instant updatedAt() { return updatedAt; }

    /** 库存不足异常。 */
    public static class InsufficientInventoryException extends RuntimeException {
        private final Long productId;
        private final int available;
        private final int requested;

        public InsufficientInventoryException(Long productId, int available, int requested) {
            super("库存不足：" + productId + "（可用 " + available + "，需要 " + requested + "）");
            this.productId = productId;
            this.available = available;
            this.requested = requested;
        }

        public Long productId() { return productId; }
        public int available() { return available; }
        public int requested() { return requested; }
    }
}
```

## 77.4 防超卖：领域级原子操作 + 仓储 SQL 双重防线

### 77.4.1 第一道防线：领域层不变量

`Inventory.reserve()` 方法内的 `if (available < quantity)` 是领域层的第一道防线。

### 77.4.2 第二道防线：SQL 原子条件更新

```java
@Repository
public class MybatisInventoryRepository implements InventoryRepository {

    private final InventoryMapper mapper;

    @Override
    @Transactional
    public void reserve(Long productId, int quantity) {
        // 单条 SQL 完成"判断 + 更新"，避免 Java 层 TOCTOU
        int affected = mapper.atomicReserve(productId, quantity);
        if (affected == 0) {
            // SQL 未命中 → 库存不足或商品不存在
            Inventory inv = mapper.selectById(productId);
            int available = inv == null ? 0 : inv.getAvailable();
            throw new InsufficientInventoryException(productId, available, quantity);
        }
    }

    @Override
    public Optional<Inventory> findByProductId(Long productId) {
        return Optional.ofNullable(mapper.selectById(productId)).map(this::toDomain);
    }
}
```

### 77.4.3 Mapper XML 关键 SQL

```xml
<!-- 原子预留 -->
<update id="atomicReserve">
    UPDATE t_inventory
    SET available = available - #{quantity},
            reserved = reserved + #{quantity},
            version = version + 1,
            updated_at = NOW()
    WHERE product_id = #{productId}
        AND available >= #{quantity}     <!-- 关键条件 -->
</update>

<!-- 原子扣减 -->
<update id="atomicCommit">
    UPDATE t_inventory
    SET reserved = reserved - #{quantity},
            sold = sold + #{quantity},
            version = version + 1,
            updated_at = NOW()
    WHERE product_id = #{productId}
        AND reserved >= #{quantity}
</update>

<!-- 原子释放 -->
<update id="atomicRelease">
    UPDATE t_inventory
    SET reserved = reserved - #{quantity},
            available = available + #{quantity},
            version = version + 1,
            updated_at = NOW()
    WHERE product_id = #{productId}
        AND reserved >= #{quantity}
</update>
```

### 77.4.4 双重防线的意义

| 防线 | 防什么 | 为什么必须 |
| --- | --- | --- |
| 领域层 | 单进程内的 TOCTOU | 业务不变量校验 |
| SQL 层 | 高并发场景（多进程） | 数据库原子条件，乐观锁 |

**没有 SQL 层**：1000 个并发请求同时通过领域层校验，再扣减，最后超卖。

**没有领域层**：业务规则散落在 SQL，未来加规则就难以维护。

## 77.5 库存领域事件

### 77.5.1 三个核心事件

```java
public sealed interface InventoryEvent
    permits InventoryReservedEvent, InventoryCommittedEvent, InventoryReleasedEvent {

    Long productId();
    int quantity();
    Instant occurredAt();
}

public record InventoryReservedEvent(Long productId, int quantity, String orderNo, Instant occurredAt)
    implements InventoryEvent {}

public record InventoryCommittedEvent(Long productId, int quantity, String orderNo, Instant occurredAt)
    implements InventoryEvent {}

public record InventoryReleasedEvent(Long productId, int quantity, String orderNo, Instant occurredAt)
    implements InventoryEvent {}
```

### 77.5.2 应用服务发布事件

```java
@Service
public class InventoryAppService {

    private final InventoryRepository repository;
    private final ApplicationEventPublisher events;

    @Transactional
    public void reserve(Long productId, int quantity, String orderNo) {
        Inventory inv = repository.findByProductId(productId)
            .orElseThrow(() -> new InventoryNotFoundException(productId));

        // 领域层校验 + 行为
        inv.reserve(quantity);

        // 仓储层原子更新（再次校验 + 乐观锁）
        repository.save(inv);

        // 发布事件（异步通知）
        events.publishEvent(
            new InventoryReservedEvent(productId, quantity, orderNo, Instant.now()));
    }

    @Transactional
    public void commit(Long productId, int quantity, String orderNo) {
        Inventory inv = repository.findByProductId(productId)
            .orElseThrow(() -> new InventoryNotFoundException(productId));
        inv.commit(quantity);
        repository.save(inv);
        events.publishEvent(
            new InventoryCommittedEvent(productId, quantity, orderNo, Instant.now()));
    }

    @Transactional
    public void release(Long productId, int quantity, String orderNo) {
        Inventory inv = repository.findByProductId(productId)
            .orElseThrow(() -> new InventoryNotFoundException(productId));
        inv.release(quantity);
        repository.save(inv);
        events.publishEvent(
            new InventoryReleasedEvent(productId, quantity, orderNo, Instant.now()));
    }
}
```

## 77.6 与订单的最终一致：领域事件订阅 + 异步处理

### 77.6.1 订单上下文触发库存动作

| 订单事件 | 库存动作 | 同步/异步 |
| --- | --- | --- |
| `OrderCreatedEvent` | reserve（每个 item） | **同步**（同事务强一致） |
| `OrderPaidEvent` | commit（每个 item） | 异步（事件订阅） |
| `OrderCancelledEvent` | release（每个 item） | 异步（事件订阅） |
| `OrderRefundedEvent` | release（每个 item） | 异步 |

> "创建订单"时同步调用 InventoryPort.reserve，确保下单一定有库存；
> 付款/取消是异步触发，对账系统可以补救。

### 77.6.2 异步事件订阅示例

```java
@Component
public class InventoryOrderEventListener {

    private final InventoryAppService appService;
    private final OrderQueryService orderQueryService;

    @EventListener
    @Async
    @Transactional
    public void onOrderPaid(OrderPaidEvent event) {
        OrderView order = orderQueryService.findById(event.orderId().value())
            .orElseThrow();
        for (OrderItemView item : order.items()) {
            appService.commit(item.productId(), item.quantity(), order.orderNo());
        }
    }

    @EventListener
    @Async
    @Transactional
    public void onOrderCancelled(OrderCancelledEvent event) {
        OrderView order = orderQueryService.findById(event.orderId().value())
            .orElseThrow();
        for (OrderItemView item : order.items()) {
            appService.release(item.productId(), item.quantity(), order.orderNo());
        }
    }
}
```

## 77.7 实战：库存应用服务 4 个用例

### 77.7.1 应用服务端口（对外暴露）

```java
/** 库存端口（供其他上下文调用）。 */
public interface InventoryPort {
    void reserve(Long productId, int quantity, String orderNo);
    void commit(Long productId, int quantity, String orderNo);
    void release(Long productId, int quantity, String orderNo);
    boolean checkAvailable(Long productId, int quantity);
}
```

### 77.7.2 端口实现

```java
@Service
public class InventoryPortAdapter implements InventoryPort {

    private final InventoryAppService appService;

    public InventoryPortAdapter(InventoryAppService appService) {
        this.appService = appService;
    }

    @Override
    public void reserve(Long productId, int quantity, String orderNo) {
        appService.reserve(productId, quantity, orderNo);
    }

    @Override
    public void commit(Long productId, int quantity, String orderNo) {
        appService.commit(productId, quantity, orderNo);
    }

    @Override
    public void release(Long productId, int quantity, String orderNo) {
        appService.release(productId, quantity, orderNo);
    }

    @Override
    public boolean checkAvailable(Long productId, int quantity) {
        return appService.checkAvailable(productId, quantity);
    }
}
```

### 77.7.3 应用服务 4 个用例

```java
@Service
public class InventoryAppService {

    private final InventoryRepository repository;
    private final ApplicationEventPublisher events;

    // ===== 用例 1：初始化库存 =====
    @Transactional
    public void initialize(Long productId, int quantity) {
        if (repository.findByProductId(productId).isPresent()) {
            throw new BusinessException("INVENTORY_EXISTS", "库存已存在：" + productId);
        }
        repository.save(new Inventory(productId, quantity));
        events.publishEvent(new InventoryInitializedEvent(productId, quantity, Instant.now()));
    }

    // ===== 用例 2：补货 =====
    @Transactional
    public void replenish(Long productId, int quantity) {
        Inventory inv = repository.findByProductId(productId)
            .orElseThrow(() -> new InventoryNotFoundException(productId));
        inv.replenish(quantity);
        repository.save(inv);
    }

    // ===== 用例 3：批量预留 =====
    @Transactional
    public void batchReserve(List<ReserveCommand> commands) {
        for (ReserveCommand cmd : commands) {
            reserve(cmd.productId(), cmd.quantity(), cmd.orderNo());
        }
    }

    // ===== 用例 4：查询可用库存 =====
    @Transactional(readOnly = true)
    public boolean checkAvailable(Long productId, int quantity) {
        return repository.findByProductId(productId)
            .map(inv -> inv.available() >= quantity)
            .orElse(false);
    }

    // reserve / commit / release 已展示于 77.5

    public record ReserveCommand(Long productId, int quantity, String orderNo) {}
}
```

## 77.8 单元测试：边界场景

```java
class InventoryTest {

    @Test
    void should_reserve_successfully_when_available_sufficient() {
        Inventory inv = new Inventory(1L, 100);
        inv.reserve(30);
        assertEquals(70, inv.available());
        assertEquals(30, inv.reserved());
        assertEquals(0, inv.sold());
    }

    @Test
    void should_reject_reserve_when_insufficient() {
        Inventory inv = new Inventory(1L, 10);
        assertThrows(Inventory.InsufficientInventoryException.class,
            () -> inv.reserve(20));
    }

    @Test
    void should_commit_release_reserved_to_sold() {
        Inventory inv = new Inventory(1L, 100);
        inv.reserve(30);
        inv.commit(20);
        assertEquals(70, inv.available());
        assertEquals(10, inv.reserved());
        assertEquals(20, inv.sold());
    }

    @Test
    void should_release_recover_available() {
        Inventory inv = new Inventory(1L, 100);
        inv.reserve(30);
        inv.release(20);
        assertEquals(90, inv.available());
        assertEquals(10, inv.reserved());
    }

    @Test
    void should_reject_negative_quantity() {
        Inventory inv = new Inventory(1L, 100);
        assertThrows(IllegalArgumentException.class, () -> inv.reserve(-1));
        assertThrows(IllegalArgumentException.class, () -> inv.reserve(0));
    }

    @Test
    void should_replenish_increase_available() {
        Inventory inv = new Inventory(1L, 100);
        inv.replenish(50);
        assertEquals(150, inv.available());
    }
}
```

### 本章小结

- 库存三态模型：可用 / 预留 / 已售。
- 不变量：任一字段 ≥ 0；总和 = 总库存。
- 防超卖双重防线：领域层校验 + SQL 原子条件。
- 4 个行为方法：reserve / commit / release / replenish。
- 与订单上下文通过 InventoryPort 端口 + 领域事件集成。
