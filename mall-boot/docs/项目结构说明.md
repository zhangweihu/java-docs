# mall-boot 项目结构说明（文件夹职责）

> 本文档说明**每个文件夹**的职责与设计理由。文件级说明见《文件说明.md》。

## 一、包结构总览

```
com.mall
├── MallApplication.java        # 启动类（入口）
├── common/                     # 【通用层】被所有模块依赖，禁止反向依赖业务
├── config/                     # 【配置层】Spring 各类配置类
├── controller/                 # 【表现层】接收请求、返回 Result，无业务逻辑
├── service/                    # 【服务层】业务接口定义
├── service/impl/               # 【服务层实现】核心业务逻辑所在
├── mapper/                     # 【数据访问层】MyBatis-Plus Mapper
├── entity/                     # 【领域层】数据库实体（与表一一对应）
├── dto/                        # 入参传输对象（请求体，带校验注解）
├── vo/                         # 出参视图对象（响应体，只暴露需要的字段）
├── util/                       # 【工具层】无状态静态工具
├── interceptor/                # 【横切层】登录拦截器等
├── runner/                     # 【启动层】应用启动后的自检任务（Redis 连通性）
└── job/                        # 【任务层】定时任务
```

## 二、各文件夹职责说明

### 2.1 `common/` — 通用层
| 内容 | 说明 |
| --- | --- |
| Result | 统一响应体，所有接口返回 `Result<T>` |
| ResultCode | 返回码枚举，前后端契约 |
| BusinessException | 业务异常，Service 直接抛出 |
| GlobalExceptionHandler | 全局兜底，Controller 零 try-catch |

**设计理由**：统一返回结构是前后端协作的基础；异常与返回体耦合，便于前端按 code 分支处理。

### 2.2 `config/` — 配置层
| 内容 | 说明 |
| --- | --- |
| RedisConfig | Redis 序列化（key 字符串 / value JSON） |
| MybatisPlusConfig | 分页插件、乐观锁插件、公共字段自动填充 |
| WebMvcConfig | 注册拦截器 + 白名单 |
| JwtConfig | JWT 配置属性绑定（mall.jwt.*） |

### 2.3 `controller/` — 表现层
- `UserController` / `ProductController` / `OrderController` / `CartController` / `RedisVerifyController`（Redis 对接自检）
- 职责：参数校验（@Valid）、调用 Service、返回 Result。**禁止写业务逻辑**。
- 关键约定：`userId` 一律从 `UserContext`（拦截器写入的 ThreadLocal）取，**禁止前端传参**，从源头防越权。

### 2.4 `service/` + `service/impl/` — 服务层
- 接口定义行为契约（面向接口编程，便于 Mock 与替换实现）；
- impl 为业务核心：注册登录、缓存治理、下单三件套、支付状态机。
- 事务注解 `@Transactional` 在 impl 方法上（自调用不生效，注意方法拆分）。

### 2.5 `mapper/` — 数据访问层
- 继承 `BaseMapper<T>` 即得单表 CRUD；复杂 SQL 用注解或 XML。
- `ProductMapper.deductStock` 演示"乐观扣减"原生 SQL——防超卖的关键所在。

### 2.6 `entity/` — 实体层
- 与数据库表一一对应，使用 Lombok `@Data` + MyBatis-Plus 注解（@TableName/@TableId/@TableLogic）。
- 实体与 VO 分离：实体可含内部字段（deleted），VO 只暴露前端字段。

### 2.7 `dto/` / `vo/` — 传输对象
- dto：入参，带 `jakarta.validation` 校验注解；
- vo：出参，隐藏敏感字段（如密码）、聚合展示字段。

### 2.8 `util/` — 工具层
- `JwtUtil`：Token 签发/解析；`OrderNoGenerator`：订单号；`RedisKeyUtil`：Key 规范统一入口。
- 均为无状态静态方法或注入单例，避免散落各处导致 Key 命名不一致。

### 2.9 `interceptor/` — 横切层
- `JwtInterceptor` 校验请求头 Token 并写入 `UserContext`（ThreadLocal），请求结束必须清理，防止线程池复用串号。

### 2.10 `job/` — 任务层
- `OrderTimeoutJob` 定时扫描超时未支付订单并关闭。演示 Spring `@Scheduled`，生产可替换 XXL-Job / 延迟消息。

## 三、资源目录 `src/main/resources/`
| 文件/文件夹 | 说明 |
| --- | --- |
| application.yml | 主配置：端口、激活 profile、JWT、MyBatis-Plus、Swagger |
| application-dev.yml | 开发环境：本地 MySQL/Redis，打印 SQL |
| application-prod.yml | 生产环境：全部走环境变量（DB_PASSWORD 等），关闭 SQL 日志 |

## 四、根目录其他文件夹
| 文件夹 | 说明 |
| --- | --- |
| sql/ | 建库建表脚本，Docker/K8s/Helm 首次启动自动执行 |
| docker/ | 镜像构建（含 SkyWalking 探针）+ 一键编排 + 可选 SkyWalking 编排 |
| k8s/ | Kubernetes 部署清单（namespace/configmap/secret/mysql/redis/app/ingress） |
| helm/ | Helm Chart：应用 + 可选 MySQL/Redis，参数化一键部署 |
| docs/ | 本文档 + 文件说明文档 |
| src/test/ | 单元/冒烟测试 + Redis 集成测试 |
| target/ | Maven 构建产物（git 已忽略，勿提交） |
