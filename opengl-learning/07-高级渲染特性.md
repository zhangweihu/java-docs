## 7.1 先回顾：一个“开关”驱动的状态机

OpenGL 很多高级功能是**一个开关 + 少量参数**。老调重弹一次状态机心智：

| 功能 | 打开 | 主要配套 |
| --- | --- | --- |
| 深度测试 | `glEnable(GL_DEPTH_TEST)` | `glDepthFunc(GL_LESS)`、每帧清深度 |
| 面剔除 | `glEnable(GL_CULL_FACE)` | `glCullFace(GL_BACK)` / `glFrontFace(GL_CCW)` |
| 混合 | `glEnable(GL_BLEND)` | `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)` |
| 模板测试 | `glEnable(GL_STENCIL_TEST)` | 模板缓冲写入/比较配置 |
| 多重采样 | 创建窗口时 hint | `glEnable(GL_MULTISAMPLE)` |

后面几节我们一一打开并解释为什么需要。

## 7.2 深度测试的细节与 z-fighting

### 7.2.1 深度缓冲不是线性的

深度缓冲存的是 [0,1]，但**精度分布不均匀**：近处精度高、远处精度低（透视除法把精度“挤”到近处）。这带来两个工程结论：

1. `near` 别设太小、`far` 别太大（0.1/100 就好），否则远处物体“糊成一片/闪烁”；
2. 两个表面几乎重叠（如两张贴很近的纸）时，谁在前取决于浮点精度 → **z-fighting**：远处像素疯狂闪烁。

### 7.2.2 动手做：复现并缓解 z-fighting

在第六章的光照场景中，把两个立方体放在几乎相同位置（`translate(0,0,0.001)`），你会看到表面闪烁。

缓解手段（按优先级）：

```cpp
// 1) 让 near/far 比例别太夸张：near 0.1 → 调到 0.3 附近
glm::mat4 proj = glm::perspective(glm::radians(45.0f), aspect, 0.3f, 100.0f);

// 2) 深度比较用 GL_LEQUAL 略宽容
glDepthFunc(GL_LEQUAL);
```

- 根治方案是**多边形偏移（Polygon Offset）**或投影矩阵的深度精度优化（对数深度），超出本专题范围，遇到再查；
- 了解“深度精度近高远低”对调 near/far 很有指导意义。

## 7.3 面剔除：省一半像素

大多数模型是**封闭体**：背向摄像机的面永远看不见。OpenGL 按**三角形绕序**判断正反面（默认逆时针 CCW 为正面）：

```cpp
glEnable(GL_CULL_FACE);
glCullFace(GL_BACK);          // 剔除背面
glFrontFace(GL_CCW);          // 逆时针 = 正面（默认，可不用写）
```

- **绕序错乱的模型剔除后“透明/消失”**：这是 3D 模型最经典的“为什么我看不见”原因之一；
- 4.8 的立方体顶点表按正面逆时针排，直接开剔除即可——你可以顺手把某行两顶点交换，观察“一个面消失”来理解绕序；
- 规则物体 + 球体开剔除 ≈ 节省 50% 片元开销。

## 7.4 混合（Blending）：透明度

### 7.4.1 公式：源颜色 × α + 目标颜色 × (1-α)

混合需要**每个片元带 Alpha**。给片元着色器加输出 Alpha 值：

```glsl
FragColor = vec4(color.rgb, alpha);   // alpha=0.5 → 半透明
```

开启混合并设置“普通透明度”的混合函数：

```cpp
glEnable(GL_BLEND);
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
// 结果 = 当前片元 × α + 已画内容 × (1-α)
```

### 7.4.2 排序陷阱（重点坑）

半透明物体混合结果依赖绘制顺序。OpenGL 不排序，因此：

1. **先画所有不透明物体**；
2. **再画半透明物体**，且**从远到近排序**（远处先画）；
3. 若半透明物体互相穿插（没有明确前后），只能接受小瑕疵——引擎里也是这么处理的。

> 一个简单演示：场景里放一个不透明地面 + 几个半透明方块，先“先画方块后画地面”（错）对比“先地面后方块”（对），你会立刻理解排序为什么重要。

## 7.5 模板测试（Stencil Test）：描边效果的经典实现

模板缓冲是又一个“每像素缓冲”，记录每像素的“编号/计数”。典型用途：**对象描边**——先把物体写进模板，再放大画一遍只有“没被模板覆盖”的轮廓部分亮起来。

思路：

```cpp
// 第 1 遍：正常画物体，同时写模板（模板值+1）
glEnable(GL_STENCIL_TEST);
glStencilOp(GL_KEEP, GL_KEEP, GL_REPLACE);      // 通过深度时写入
glStencilFunc(GL_ALWAYS, 1, 0xFF);              // 总是通过，把模板写成 1
glStencilMask(0xFF);                            // 允许写
DrawObject();

// 第 2 遍：放大物体、描边色，但只画“模板值≠1”的像素（即轮廓带）
glStencilFunc(GL_NOTEQUAL, 1, 0xFF);            // 只画不是 1 的地方
glStencilMask(0x00);                            // 禁止再写
glDisable(GL_DEPTH_TEST);                       // 避免边缘被自己挡住
ScaleUpAndDrawObjectOutline();                  // 模型矩阵放大 1.08 倍

glStencilMask(0xFF);
glDisable(GL_STENCIL_TEST);
```

- 每帧记得清模板缓冲：`glClear(GL_STENCIL_BUFFER_BIT)`（或写进清屏位）；
- 模板是“每像素的一次性标记”，很多引擎的 UI 遮罩、阴影体积也用它；
- 概念理解优先级高于背 API：记住“**先在模板里画记号，再按记号决定第二遍画不画**”。

## 7.6 多重采样抗锯齿（MSAA）

直边三角形在低分辨率屏幕上是“锯齿”楼梯。多重采样让每个像素内采样多个点再平均，边缘变平滑。

创建窗口时开启（GLFW）：

```cpp
glfwWindowHint(GLFW_SAMPLES, 4);          // 请求 4x MSAA
```

初始化时（若驱动支持）：

```cpp
glEnable(GL_MULTISAMPLE);                 // 默认已开，显式写便于阅读
```

- MSAA 只对**几何边缘**有效；着色器内部产生的锯齿（如高光边缘）要后期用 FXAA/TAA 处理——那是第八章后处理与引擎的内容了；
- 若要用**离屏渲染 + MSAA**，需要手动创建多重采样帧缓冲，第八章末尾提一句即可。

## 7.7 综合实战与验收

1. **描边效果**：在 7.5 的思路上，给第六章受光立方体加一圈白色描边，并把半透明方块放进场景，实现“描边 + 半透明”组合；
2. **绘制顺序实验**：一个场景含不透明物体 + 若干半透明物体，体会 7.4.2 的顺序规则；试着解释“引擎为什么把透明物体单独一个 Pass 排序”；
3. **开启/关闭对照**：分别开关 `GL_CULL_FACE`、`GL_DEPTH_TEST`、`GL_STENCIL_TEST`，观察每个开关对画面的独立影响——这是理解状态机的最好练习；
4. **验收标准**：能说出四个开关各自的“打开后少了/多了什么”；能解释半透明为什么必须排序、模板描边为什么需要画两遍。

## 本章小结

- 深度：近精度高远精度低 → near/far 别极端；z-fighting 靠调近裁剪面/`GL_LEQUAL` 缓解；
- 面剔除：背面永远看不见 → 绕序即正反面，一开省一半；
- 混合：`src*α + dst*(1-α)`，不透明先画、透明从远到近；
- 模板：第一遍写标记，第二遍按标记画局部；
- 下一章把这些“开关”升级为完整的**离屏渲染框架**：先画到纹理，再贴回屏幕——后处理滤镜与天空盒的基石。
