# 第四章：变换与坐标系统

> 目标：引入 GLM 数学库，理解模型(Model)/视图(View)/投影(Projection)三大矩阵如何把 3D 世界一步步压成屏幕 2D；打开深度测试，让两个立方体**真的叠出前后关系**。

## 4.1 为什么要矩阵：把“把物体摆进世界再看”翻译成数学

上一章物体永远画在原点、没有立体感。要让物体能动、能转、有透视，需要**把顶点坐标按顺序乘上三个矩阵**：

```text
   模型矩阵 Model      × 视图矩阵 View     × 投影矩阵 Projection
   物体自己的坐标 ──► 世界坐标 ──► 摄像机视角坐标 ──► 裁剪空间 NDC ──► 屏幕
   (摆位/旋转/缩放)   (移动“世界”)          (透视/正交压缩)
```

顶点着色器里最终只写一行：

```glsl
gl_Position = projection * view * model * vec4(aPos, 1.0);
```

- 矩阵乘法**从右往左读**：先乘 `model`、再 `view`、最后 `projection`；
- 向量写成 4 维 `(x,y,z,w)` 是为了能表达**平移**（3×3 矩阵表达不了平移）；
- 本章让模型矩阵转起来（动）、投影矩阵产生透视，是“3D 感”的来源。

## 4.2 安装 GLM（header-only，无需编译）

GLM 是纯头文件库，放进去就能用：

- 方式 A：clone/下载 `glm`（GitHub `g-truc/glm`，releases 取 `glm-1.0.x` 的 zip）到 `third_party/glm/`（内含 `glm/` 头目录）；
- 方式 B（FetchContent，CMake 自动下载）——在第一章 `CMakeLists.txt` 里 `add_subdirectory(third_party/glfw)` 前面追加：

```cmake
include(FetchContent)
FetchContent_Declare(glm
    URL https://github.com/g-truc/glm/releases/download/1.0.1/glm-1.0.1-light.zip)
FetchContent_MakeAvailable(glm)      # 提供 header-only 的 glm::glm 目标
```

若用方式 B，给 `playground` 链接：

```cmake
target_link_libraries(playground PRIVATE glad glfw glm::glm)
```

`main.cpp` 顶部 include：

```cpp
#include <glm/glm.hpp>
#include <glm/gtc/matrix_transform.hpp>   // perspective/lookAt/rotate 等
#include <glm/gtc/type_ptr.hpp>           // value_ptr：glm 矩阵 ↔ 数组
```

> GLM 默认就是**列主序**存储，与 OpenGL 期望一致；`value_ptr` 直接取内部数据指针喂给 `glUniformMatrix4fv`，不用转置。

## 4.3 动手做 1：让物体自己转（模型矩阵 × 时间）

沿用第三章工程（纹理矩形/棋盘 + 着色器），把着色器 `.vert` 改成接受矩阵：

### 修改 `shaders/textured.vert`

```glsl
#version 330 core
layout (location = 0) in vec3 aPos;
layout (location = 1) in vec2 aTexCoord;

uniform mat4 uModel;          // 模型矩阵：位置/旋转/缩放
uniform mat4 uView;
uniform mat4 uProjection;

out vec2 vTexCoord;

void main()
{
    gl_Position = uProjection * uView * uModel * vec4(aPos, 1.0);
    vTexCoord = aTexCoord;
}
```

### 修改 `src/main.cpp` 主循环绘制区

```cpp
        // 时间（秒）
        float t = (float)glfwGetTime();

        // 模型矩阵：先绕 Z 轴转，X/Y 稍倾斜，看起来更有立体感
        glm::mat4 model = glm::mat4(1.0f);                    // 单位矩阵
        model = glm::rotate(model, t, glm::vec3(0.0f, 1.0f, 0.0f));  // 绕 Y 转
        model = glm::rotate(model, 0.5f, glm::vec3(1.0f, 0.0f, 0.0f)); // 再绕 X 倾斜

        // 视图矩阵：先把世界往后退 3 米（“摄像机在 (0,0,3) 看向原点”）
        glm::mat4 view = glm::mat4(1.0f);
        view = glm::translate(view, glm::vec3(0.0f, 0.0f, -3.0f));

        // 投影矩阵：45° 视场角透视，4:3 宽高比，近/远裁剪面
        glm::mat4 projection = glm::perspective(
            glm::radians(45.0f), 800.0f / 600.0f, 0.1f, 100.0f);

        glUseProgram(program);
        glUniformMatrix4fv(glGetUniformLocation(program, "uModel"),
                           1, GL_FALSE, glm::value_ptr(model));
        glUniformMatrix4fv(glGetUniformLocation(program, "uView"),
                           1, GL_FALSE, glm::value_ptr(view));
        glUniformMatrix4fv(glGetUniformLocation(program, "uProjection"),
                           1, GL_FALSE, glm::value_ptr(projection));

        // ...绑定纹理、VAO，glDrawElements 同第三章...
```

**预期结果**：一个转动的“纸片”——绕 Y 轴转时你能看到它从一条线翻成整面。这就是“只有正面没有厚度”的 2D 物体旋转效果。

## 4.4 深度测试：谁在前，谁在后

现在只有一面“纸片”，看不出前后。**深度缓冲（Z-Buffer）**为每个像素记录“离相机多近”，后画的像素若更深就不覆盖前面——这样任意顺序绘制都正确遮挡。

开启只需两行（初始化区）：

```cpp
glEnable(GL_DEPTH_TEST);          // 打开深度测试
```

每帧清屏时**必须连深度一起清**，否则上一帧深度残留会让画面闪烁：

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

## 4.5 动手做 2：一个真正的 3D 立方体（6 面贴纹理）

把矩形的顶点换成 **36 个顶点 = 12 个三角形 × 3 顶点 × 5 分量**（每面两个三角形、各面分别指定纹理坐标，让棋盘 6 面朝向一致）。这里直接给完整顶点数组（相对 4.3，把 `vertices/indices/EBO` 换成“无 EBO、直接 36 顶点”）：

```cpp
    // 一个边长 1 的立方体：每行 = 位置(3) + 纹理坐标(2)
    float vertices[] = {
        // 前面（z = +0.5）
        -0.5f, -0.5f,  0.5f,  0.0f, 0.0f,
         0.5f, -0.5f,  0.5f,  1.0f, 0.0f,
         0.5f,  0.5f,  0.5f,  1.0f, 1.0f,
        -0.5f, -0.5f,  0.5f,  0.0f, 0.0f,
         0.5f,  0.5f,  0.5f,  1.0f, 1.0f,
        -0.5f,  0.5f,  0.5f,  0.0f, 1.0f,
        // 右面、左面、顶面、底面、背面…（共 6 面，每面如上 6 行）
        // —— 完整列表较长，见文末“常用参考”提示，或直接下载示例顶点文件 ——
    };
```

为了不让你手抄 36 行（易错），可以这样写完整立方体——把 8 个角定义成 `cubePositions`，然后程序化生成 36 顶点（**推荐，可读且不易错**）：

```cpp
    // 8 个角（±0.5）
    const float C = 0.5f;
    // 每面：4 角 + 正确朝向的 2 个三角形 + 各自 uv
    // 这里给出“前、后”两面的写法，其余 4 面结构完全相同、换坐标即可
    float vertices[36 * 5];
    // 前 (z=+C)：(-,-,+), (+,-,+), (+,+,+), (-,+,+)
    // 后 (z=-C)：(-,-,-), (+,-,-), (+,+,-), (-,+,-)
    // 右 (x=+C)：左/右面互换 u 轴方向即可
    // … 完整 36 顶点建议直接参考 LearnOpenGL“立方体”一节的顶点表
```

> 抄写 36 顶点最容易错的是**三角形绕序**（正面逆时针）与**uv 朝向**。一个小技巧：先画一面前/后确认朝向，再复制修改坐标。

或者更省事：**用 8 顶点 + 24 下标**的“索引立方体”不适合直接贴 6 张不同朝向的图，但**棋盘纹理任意面都能接**，所以沿用第三章 EBO 思路做一个“8 顶点、每顶点带 uv、用 36 下标连 12 三角形”的立方体是可行折衷——uv 重复不理想但能跑。本章建议直接用 36 顶点硬表。

主循环里改为绘制 36 顶点（去掉 EBO 分支）：

```cpp
        glDrawArrays(GL_TRIANGLES, 0, 36);
```

绘制前给立方体一点旋转（看起来更立体）：

```cpp
        model = glm::rotate(model, t * 0.6f, glm::vec3(0.6f, 1.0f, 0.0f));
```

**预期结果**：一个持续自转、6 面都贴着棋盘纹理、能看到明暗不同面的 3D 立方体。若某面“透视穿帮”或颜色发黑，多半是顶点绕序或 uv 有误。

## 4.6 概念反刍：坐标系统的五站旅程

一个顶点的坐标，画到屏幕前要经过 5 个坐标系：

| 阶段 | 名称 | 含义 |
| --- | --- | --- |
| 1 | 局部坐标 Local | 物体自己的建模坐标（如立方体中心在原点） |
| 2 | 世界坐标 World | 乘 `model` 后摆进大世界（多个物体各就各位） |
| 3 | 观察坐标 View | 乘 `view` 后以“摄像机”为原点 |
| 4 | 裁剪坐标 Clip | 乘 `projection` 后，落在 [-1,1]³ 内才算可见 |
| 5 | 屏幕坐标 Screen | GPU 自动透视除法 + 视口变换到像素 |

- 前面教程省略了 `view/projection`，顶点直接落在裁剪空间，所以没有透视；
- `glm::perspective(fov, aspect, near, far)`：fov 是视场角、aspect 是宽高比、near/far 是可见深度范围；
- **w 分量的戏法**：透视投影把“远小”写进 w，GPU 做透视除法（除以 w），近大远小就出来了。

## 4.7 实战与验收

1. **摆多个立方体**：把 4.5 的绘制重复 4 次，每次乘一个不同的 `translate`/`rotate`（如绕 Y 每隔 90° 放一个），得到“旋转木马”效果——理解同一份 VBO 数据 + 不同 `uModel` = 画很多物体；
2. **正交 vs 透视**：把 `glm::perspective` 换成 `glm::ortho(-2.0f, 2.0f, -1.5f, 1.5f, 0.1f, 100.0f)`，立方体立刻失去近大远小——观察“透视感”到底是谁给的；
3. **缩放/位移**：把 `model` 里加 `glm::scale(model, glm::vec3(0.5f))` 与 `glm::translate`，确认矩阵乘法顺序影响结果（先缩放再平移 vs 先平移再缩放）；
4. **验收标准**：能闭眼画出 M→V→P 的顺序图并说明各自作用；能解释深度测试为什么要 `GL_DEPTH_BUFFER_BIT` 一起清。

## 本章小结

- `gl_Position = projection * view * model * pos` 是 3D 变换的总开关；
- 深度测试 = 1 行 `glEnable` + 清屏带 `GL_DEPTH_BUFFER_BIT`；
- 投影决定透视，模型矩阵让物体各就各位并旋转；
- 下一章把 `view` 矩阵交给“可移动的摄像机”，配合鼠标键盘，你就进入场景里自由漫游了。
