## 12.1 .NET 生态全景图

```text
                            .NET
        ┌──────────┬──────────┼──────────┬────────────┐
        Web       桌面/移动    云原生       AI/数据        游戏
   ASP.NET Core  WinForms    Azure      ML.NET       Unity
    Blazor       WPF         Azure      Semantic     Godot
    Minimal API  MAUI        Functions  Kernel       (C# 脚本)
    gRPC / SignalR           容器/K8s   .NET for
                                  Spark
```

- **Web**：ASP.NET Core（Minimal API / MVC / Razor Pages）、Blazor（C# 写前端）、SignalR（实时通信）、gRPC（高性能 RPC）——你已经掌握主干；
- **桌面**：WinForms（老牌快速）、WPF（XAML + 数据绑定，企业桌面主流）、MAUI（一套代码 Win/macOS/iOS/Android）；
- **游戏**：Unity 脚本、Godot 的 C# 支持、MonoGame 等；
- **云原生**：Azure 全家桶、AWS/GCP SDK、Kubernetes（`dotnet` 官方镜像成熟）、Serverless（Azure Functions / AWS Lambda）；
- **AI/数据**：ML.NET（.NET 原生机器学习）、Semantic Kernel（大模型编排）、.NET for Apache Spark、OpenAI .NET SDK、向量库客户端；
- **高性能方向**：NativeAOT、无 GC/低分配服务、`System.Numerics`/SIMD、GPU（ComputeSharp）。

## 12.2 快速巡礼：三个“看一眼就能用”的方向

### 12.2.1 Blazor：C# 写前端

```bash
dotnet new blazor -o MyBlazorApp && cd MyBlazorApp && dotnet run
```

Blazor WebAssembly / Server 允许用 C# + Razor 组件（.razor）写交互式 UI，不必切 JavaScript 全家桶。适合“全栈 C# 团队”。


本地也可用 `func start` 跑。适合事件处理、定时任务、Webhook。

## 12.3 Source Generators：C# 的“元编程”

**源生成器（Source Generator）** 在编译期“看代码并生成代码”，类似 Java 注解处理器 / 宏 / Rust 过程宏：

- 经典例子：`System.Text.Json` 的源生成序列化（`[JsonSerializable]`）、`Regex` 源生成（`[GeneratedRegex]`）、`Dapper.AOT`、EF Core 编译模型；
- 收益：**零反射、启动更快、编译期即可发现错误**——这是 .NET 8+ 越来越强调的“AOT 友好”路线。

```csharp
using System.Text.RegularExpressions;

public partial class MyRegex
{
    // 编译期把正则编译成专用代码（而不是每次运行时解释）
    [GeneratedRegex(@"^[\w.-]+@[\w.-]+\.\w+$")]
    public static partial Regex EmailRegex();
}
```

> 想自己写 Source Generator：建一个 `netstandard2.0` 类库引用 `Microsoft.CodeAnalysis.CSharp`，实现 `IIncrementalGenerator`，然后被应用工程引用。作为进阶课题，建议先理解“它能做什么”，不必一上来就手写。

## 12.5 常见“学了 C# 后”的追问

**问：C# 和 Java 到底选哪个？**
答：两者工程理念几乎同构，选择更多看生态与岗位：Java 在超大企业存量系统/微服务生态深厚；C# 在 Windows 桌面、微软云、游戏（Unity）、高性价比全栈（性能常更优）有优势。学透一门，迁移另一门通常只需 1~2 周熟悉 API。

**问：我该继续学 WPF/Blazor/Unity 还是深入 .NET 内部？**
答：按职业目标选：做 Web/后端 → 深入 ASP.NET Core + 云 + 性能；做桌面 → WPF/MAUI；做游戏 → Unity；做全栈 → Blazor。底层（11 章）是所有方向共用的加分项，不必一次学完。

**问：怎么保持熟练？**
答：给自己造持续更新的“玩具工程”：记账工具 → 博客后端 → 爬虫 + 数据报表 → 带认证的服务。每加一个功能就补一条单测与一次 CI。**保持“每周产出一个能跑的新东西”。**
