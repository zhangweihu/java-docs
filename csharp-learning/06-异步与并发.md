# 第六章 异步与并发

> 本章目标：理解“程序为什么需要同时做很多事”，掌握 C# 的两套武器——**`async/await` 异步**（IO 密集型）与**多线程/任务**（CPU 密集与并行），理解锁、并发集合与常见陷阱。
> 前置：第一至五章。Web 请求天然就是“等网络/等数据库”，所以这一章是第九章的基础。

## 6.1 为什么要异步：一次说清

**同步**程序做事“一件一件排队等”：

```csharp
// 同步下载三个文件：假设每个等 2 秒，总共 6 秒
DownloadFile("a.zip");   // 卡 2 秒
DownloadFile("b.zip");   // 卡 2 秒
DownloadFile("c.zip");   // 卡 2 秒
```

等待期间 CPU 其实闲着（在等网络）。如果期间能“挂起当前任务、先去干别的”，三个文件就能并发下载 ≈ 2 秒。这就是**异步**的价值：**不阻塞线程，把等待时间让给别的任务**。

- **IO 密集型**（网络、文件、数据库、HTTP）：用 `async/await`（不占线程地等待）；
- **CPU 密集型**（大量计算、视频编码、数学运算）：用多线程/`Parallel`（真·并行计算）。

## 6.2 async / await：异步入门

### 6.2.1 第一个 async 方法

```csharp
// 模拟一个耗时 IO：返回 Task<string>
Task<string> FetchRemoteAsync(string url)
{
    return Task.Run(() =>
    {
        Thread.Sleep(2000);                    // 模拟网络等待
        return $"数据来自 {url}";
    });
}
```

`Task<T>` 表示“将来会有一个 T 的结果”。消费它有两种方式：阻塞等待（`Result`/`Wait`，简单但**不推荐**）或优雅的 **await**：

```csharp
// Program.cs 顶级语句天然支持 await
Console.WriteLine("开始下载...");

string data = await FetchRemoteAsync("http://a.com");   // 挂起等待，但不冻结整个进程
Console.WriteLine(data);

Console.WriteLine("结束");
```

要点：

- `async` 修饰方法；方法内用 `await` 等待一个 `Task`；
- `await` 处**方法返回控制权**给调用者（线程不被占用），结果回来后继续往下走；
- 返回类型规则：有返回值用 `Task<T>`，无返回值用 `Task`，事件处理器用 `async void`（**只在事件里用**）；
- 顶级语句里可以直接 `await`（控制台示例最简单）。

### 6.2.2 并发等待多个任务

```csharp
Task<string> t1 = FetchRemoteAsync("http://a.com");
Task<string> t2 = FetchRemoteAsync("http://b.com");
Task<string> t3 = FetchRemoteAsync("http://c.com");

string[] results = await Task.WhenAll(t1, t2, t3);   // 等全部完成
Console.WriteLine(string.Join("\n", results));

// 只要最快的：WhenAny（如“多个数据源谁先回来用谁”）
Task<string> first = await Task.WhenAny(t1, t2, t3);
Console.WriteLine($"最快完成：{await first}");
```

### 6.2.3 真实网络示例（HttpClient）

`Console.ReadLine` 那套“同步等待”与网络世界格格不入。真实请求几乎都是异步的：

```csharp
using HttpClient client = new();
client.DefaultRequestHeaders.UserAgent.ParseAdd("learning-csharp/1.0");

Console.Write("输入一个国家/地区代码（如 cn、us）：");
string code = Console.ReadLine()!.Trim().ToLower();

// 同步世界里会卡住 UI 的请求，async 版轻松等待
string json = await client.GetStringAsync($"https://restcountries.com/v3.1/alpha/{code}");
Console.WriteLine(json[..200]);   // 只看前 200 个字符（完整 JSON 解析在第 7 章）
```

> **重要**：`HttpClient` 应该复用（用 `using static` 或单例/DI），不要在循环里 new——否则会耗尽 socket。

## 6.3 线程基础与并发共享数据

### 6.3.1 Thread 与 ThreadPool

```csharp
Thread t = new(() =>
{
    for (int i = 0; i < 5; i++)
    {
        Console.WriteLine($"线程 {Thread.CurrentThread.ManagedThreadId}: {i}");
        Thread.Sleep(100);
    }
});
t.Start();
t.Join();               // 等 t 结束（把代码想成“并发两支队伍”）

// 现代代码很少直接 new Thread：线程昂贵，应该用线程池/任务
```

线程创建有开销，.NET 内置**线程池**，`Task.Run` 会自动从池里取线程：

```csharp
Task task = Task.Run(() => HeavyCompute());   // 扔给线程池干 CPU 活
await task;
```

### 6.3.2 共享数据要加锁：lock

多个线程同时改同一变量会“打架”（丢更新）。用 `lock` 让同一时刻只有一个线程进入关键区：

```csharp
class Counter
{
    private int _count;
    private readonly object _lock = new();     // 锁对象（可以是任意引用类型）

    public void Increase()
    {
        lock (_lock)                            // 同一时刻只有一个线程能进来
        {
            _count++;
        }
    }

    public int Value => _count;
}

// 验证：
var counter = new Counter();
var tasks = Enumerable.Range(1, 1000)
    .Select(_ => Task.Run(() => { for (int i = 0; i < 100; i++) counter.Increase(); }))
    .ToArray();
Task.WaitAll(tasks);
Console.WriteLine(counter.Value);   // 不加锁会 < 100000；加锁后稳定 100000
```

- `lock` 保证互斥，但锁粒度要小（别锁住整个大循环）；
- 更现代的替代：`Interlocked.Increment`（原子自增）、`lock (obj)` 的 C# 13 新语法 `Lock` 类型、`ConcurrentDictionary` 等并发集合（6.4）；
- **能用并发集合就别手写锁**。

## 6.4 并发集合与并行

### 6.4.1 线程安全集合（System.Collections.Concurrent）

```csharp
using System.Collections.Concurrent;

var bag = new ConcurrentBag<string>();          // 无序线程安全集合
var dict = new ConcurrentDictionary<string, int>();
var queue = new ConcurrentQueue<int>();         // 线程安全队列（生产者/消费者）

// 经典：生产者消费者
Task producer = Task.Run(() =>
{
    for (int i = 1; i <= 10; i++)
    {
        queue.Enqueue(i);
        Thread.Sleep(20);
    }
});

var consumer = Task.Run(() =>
{
    while (queue.TryDequeue(out int item))
        Console.WriteLine($"消费 {item}");
});
await Task.WhenAll(producer, consumer);
```

> 场景记忆：多线程写同一个 `Dictionary` → 换 `ConcurrentDictionary`；多线程“放任务/取任务” → `ConcurrentQueue`。绝大多数时候不用手写锁。

### 6.4.2 Parallel：CPU 密集任务的简单并行

```csharp
// 对大数据做并行计算
int[] data = Enumerable.Range(1, 1_000_000).ToArray();

long sumSync = 0;
foreach (var x in data) sumSync += x * x;        // 单线程

long sumParallel = 0;
var gate = new object();
Parallel.ForEach(data, x =>
{
    long part = (long)x * x;
    lock (gate) sumParallel += part;              // 并行里改共享变量仍需锁/原子
});
Console.WriteLine($"{sumSync} == {sumParallel}"); // 结果应相等
```

- `Parallel.For` / `Parallel.ForEach` / `PLINQ`（`.AsParallel().Where(...)`）适合**纯计算**且无共享状态的任务；
- **用并行前先确认瓶颈在 CPU**：IO 任务用 async，CPU 任务用 Parallel——两者别混用（并行里跑 async 会浪费线程池线程）。

## 6.5 async 的常见陷阱（必看）

### 陷阱 1：async void（除了事件别用）

```csharp
// 危险：async void 的异常无法被 await 捕获，直接崩进程
async void BadMethod() { throw new Exception("boom"); }

// 正确：返回 Task，让异常可以被 await 观察到
async Task GoodMethod() { throw new Exception("boom"); }
```

### 陷阱 2：.Result / .Wait() 阻塞等待

在同步上下文里 `.Result` 容易死锁（UI/ASP.NET 环境）；即使控制台没死锁，也白白占线程。**一路 async/await 到底**：

```csharp
// 坏
var r = SomeAsync().Result;
// 好：向上 await
var r = await SomeAsync();
```

### 陷阱 3：在循环里 await 串行

```csharp
// 慢：一个个排队下载（每个都等完再发下一个）
foreach (var url in urls)
    await DownloadAsync(url);

// 快：先全部发起，再一次 await
var tasks = urls.Select(DownloadAsync).ToArray();
await Task.WhenAll(tasks);
```

### 陷阱 4：忘记 CancellationToken

网络/数据库操作应支持取消（用户关闭页面、请求超时）：

```csharp
async Task<string> DownloadWithTimeoutAsync(string url, int ms)
{
    using var cts = new CancellationTokenSource(ms);   // ms 后自动取消
    using HttpClient client = new();
    return await client.GetStringAsync(url, cts.Token);
}

// 演示超时
try
{
    await DownloadWithTimeoutAsync("https://httpbin.org/delay/10", 2000);
}
catch (OperationCanceledException)
{
    Console.WriteLine("下载超时，已取消");
}
```

## 6.6 完整可运行示例：并发任务调度器

需求：模拟一家小店给 8 个订单备货，每单耗时不同，店员们（4 个并发“工人”）同时干活，统计总耗时。

```csharp
using System.Collections.Concurrent;

// 模拟备货耗时（秒）
int Ship(int orderNo)
{
    int cost = (orderNo % 3) + 1;
    Thread.Sleep(cost * 500);
    return cost;
}

// 并发执行 + 进度跟踪
var progress = new ConcurrentDictionary<int, string>();
var gate = new object();
int done = 0;

async Task RunWorkerAsync(int workerId, ConcurrentQueue<int> orders)
{
    while (orders.TryDequeue(out int orderNo))
    {
        int cost = await Task.Run(() => Ship(orderNo));   // CPU/模拟活给线程池
        lock (gate) { done++; }
        Console.WriteLine($"工人{workerId} 完成订单#{orderNo}（耗时{cost}）进度 {done}/8");
    }
}

// 主流程
var orders = new ConcurrentQueue<int>(Enumerable.Range(1, 8));
var sw = System.Diagnostics.Stopwatch.StartNew();

var workers = Enumerable.Range(1, 4).Select(id => RunWorkerAsync(id, orders)).ToArray();
await Task.WhenAll(workers);

sw.Stop();
Console.WriteLine($"全部完成！总耗时 {sw.Elapsed.TotalSeconds:F1} 秒（同步逐单大约要更多）");
```

> 体会：8 单、4 个并发工人，总耗时远小于逐单排队。`.NET` 里这种“调度并发任务”正是消息队列/后台服务的原型。

## 6.8 小结

异步让你的程序**不空等**，并发让你的程序**能并行**。C# 把这两件事统一在 `Task` 模型下：网络/数据库/文件用 async/await，计算密集型用 Parallel/线程池，共享数据用并发集合或锁。第九章 Web 服务会看到它们的真实战场。
