# 第十章 测试、质量与发布

> 本章目标：把“能跑”升级为“敢交付”。掌握 xUnit 单元/数据驱动测试、测试替身（Moq）、Web 集成测试（WebApplicationFactory）、覆盖率与静态分析，并用 GitHub Actions + Docker 一键构建发布。
> 前置：主线 1~9 章（尤其第九章 Web）。建议用一个真实小工程边学边加测试。

## 10.1 为什么必须写测试

- 改代码不怕改坏（回归保护）；
- 测试即文档：别人看测试就知道“这个类该有什么行为”；
- 有测试才能放心重构；
- **测试金字塔**：底层单元测试多且快，上层集成/E2E 少且慢。

```text
         /\    E2E（少，贵）
        /  \   集成测试（中）
       /    \  单元测试（多，快，地基）
      /______\
```

**TDD 小流程**：先写一个失败的测试（红）→ 写最少代码让它过（绿）→ 重构。先体会一遍，再决定日常用多狠。

## 10.2 工程结构：测试项目怎么摆

```text
解决方案/
├── src/TodoApi/                  # 应用（被测试对象）
└── tests/TodoApi.Tests/          # 测试工程（引用应用工程）
```


## 10.3 xUnit：单元测试入门

### 10.3.1 一个能测的“纯逻辑”

第九章把业务写在路由里不利于测试。先看最理想的被测对象——纯逻辑类：

```csharp
// src/TodoApi/Domain/TodoRules.cs
namespace TodoApi.Domain;

public static class TodoRules
{
    public static bool IsValidTitle(string? title)
        => !string.IsNullOrWhiteSpace(title) && title.Trim().Length <= 50;

    public static string NormalizeTitle(string? title)
        => title?.Trim() ?? "";
}
```

### 10.3.2 写测试

```csharp
using TodoApi.Domain;
using Xunit;

public class TodoRulesTests
{
    // [Fact]：普通单测
    [Fact]
    public void IsValidTitle_空白标题_返回False()
    {
        Assert.False(TodoRules.IsValidTitle(null));
        Assert.False(TodoRules.IsValidTitle("   "));
    }

    [Fact]
    public void IsValidTitle_正常标题_返回True()
    {
        Assert.True(TodoRules.IsValidTitle("学习 C#"));
    }

    [Fact]
    public void NormalizeTitle_带首尾空格_被去掉()
    {
        Assert.Equal("学习 C#", TodoRules.NormalizeTitle("  学习 C#  "));
    }

    // [Theory]：数据驱动——一组数据跑同一断言
    [Theory]
    [InlineData(null, false)]
    [InlineData("", false)]
    [InlineData("   ", false)]
    [InlineData("a", true)]
    [InlineData(new string('长', 50), true)]
    [InlineData(new string('长', 51), false)]
    public void IsValidTitle_各种输入_结果符合预期(string? title, bool expected)
    {
        Assert.Equal(expected, TodoRules.IsValidTitle(title));
    }
}
```

常用断言速查：

| 断言 | 用途 |
| --- | --- |
| `Assert.Equal(a, b)` / `NotEqual` | 相等/不等 |
| `Assert.True/False` | 布尔 |
| `Assert.Null/NotNull` | 空判断 |
| `Assert.Contains/DoesNotContain` | 集合/字符串包含 |
| `Assert.Throws<T>(() => ...)` | 断言抛异常 |
| `Assert.Empty/Single` | 集合 |
| `Assert.InRange` | 数值范围 |

### 10.3.3 运行测试

```bash
cd tests/TodoApi.Tests
dotnet test            # 编译 + 跑测试 + 输出结果
dotnet test --filter "Category=Unit"   # 只跑某类（按 Trait 等过滤）
```

## 10.4 测试替身：Moq

被测类依赖了“发邮件/查支付/读配置”等重依赖时，用**替身**隔离：

```csharp
// 被测依赖的抽象
public interface INotifier { void Notify(string to, string msg); }

public class TodoCompleter
{
    private readonly INotifier _notifier;
    public TodoCompleter(INotifier notifier) => _notifier = notifier;

    public string Complete(Todo todo)
    {
        if (todo.IsDone) throw new InvalidOperationException("已完成");
        todo.IsDone = true;
        _notifier.Notify("admin", $"待办完成：{todo.Title}");
        return "完成";
    }
}
```

```csharp
// 测试工程
using Moq;

[Fact]
public void Complete_调用通知器_且消息正确()
{
    var notifier = new Mock<INotifier>();
    var completer = new TodoCompleter(notifier.Object);
    var todo = new Todo { Title = "写测试", IsDone = false };

    string result = completer.Complete(todo);

    Assert.Equal("完成", result);
    Assert.True(todo.IsDone);
    notifier.Verify(n => n.Notify("admin", It.Is<string>(m => m.Contains("写测试"))), Times.Once);
}

[Fact]
public void Complete_已完成待办_抛异常()
{
    var completer = new TodoCompleter(Mock.Of<INotifier>());
    var todo = new Todo { Title = "x", IsDone = true };
    Assert.Throws<InvalidOperationException>(() => completer.Complete(todo));
}
```

要点：`Mock<T>` 造替身 → 配置行为（`.Setup(...).Returns(...)`）→ 验证交互（`Verify`）；这让你能单测“会协作的类”而不碰真实邮件/数据库。

## 10.5 集成测试：连 Web 一起测

`WebApplicationFactory<Program>` 会真实启动应用（内存/测试库），直接发 HTTP 请求：

```csharp
using System.Net;
using System.Net.Http.Json;
using Microsoft.AspNetCore.Mvc.Testing;
using Xunit;

public class TodoApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;
    public TodoApiTests(WebApplicationFactory<Program> factory)
    {
        // factory 会自动找 Program 启动（须把 Program 设为 public：可在 csproj 加 InternalsVisibleTo 或用 public partial）
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task Get_根路径_返回200()
    {
        var resp = await _client.GetAsync("/");
        Assert.Equal(HttpStatusCode.OK, resp.StatusCode);
    }

    [Fact]
    public async Task Todo_全流程_增查改删()
    {
        // 增
        var create = await _client.PostAsJsonAsync("/api/todos", new { title = "集成测试任务", isDone = false });
        Assert.Equal(HttpStatusCode.Created, create.StatusCode);
        var todo = await create.Content.ReadFromJsonAsync<TodoDto>();
        Assert.NotNull(todo);

        // 查单个
        var get = await _client.GetAsync($"/api/todos/{todo!.Id}");
        Assert.Equal(HttpStatusCode.OK, get.StatusCode);

        // 标记完成
        var done = await _client.PostAsJsonAsync($"/api/todos/{todo.Id}/done", new { });
        Assert.Equal(HttpStatusCode.OK, done.StatusCode);

        // 删
        var del = await _client.DeleteAsync($"/api/todos/{todo.Id}");
        Assert.Equal(HttpStatusCode.NoContent, del.StatusCode);
    }

    public record TodoDto(int Id, string Title, bool IsDone);
}
```

小坑：当集成测试需要“干净库”时，测试里覆盖连接串指向临时文件或内存库；`WebApplicationFactory` 支持 `.WithWebHostBuilder(b => b.UseSetting("ConnectionStrings:Todo", ...))`。

## 10.6 覆盖率与代码质量

### 10.6.1 覆盖率

```bash
dotnet test --collect:"XPlat Code Coverage"          # 生成 coverage.cobertura.xml
dotnet tool install --global dotnet-coverage
dotnet test --collect:"XPlat Code Coverage"
# 用 VS 自带覆盖率窗口 / reportgenerator 转成 HTML 看
dotnet tool install --global dotnet-reportgenerator-globaltool
```

覆盖率不是目标本身——**先测关键业务规则**，再慢慢补；死磕 100% 常是低效的。

### 10.6.2 静态分析

```bash
dotnet format --verify-no-changes       # 代码风格（空格/换行等），CI 里可用
dotnet format analyzers                 # 跑内置 Roslyn 分析器
dotnet build -warnaserror               # 把警告当错误，强制质量
```

加上 `.editorconfig` 统一样式、启 `<TreatWarningsAsErrors>`、装社区分析器（如 `Microsoft.CodeAnalysis.NetAnalyzers`）即可形成团队质量基线。

## 10.7 GitHub Actions：CI 一键跑

在仓库建 `.github/workflows/ci.yml`：

```yaml
name: ci
on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'
      - name: Restore
        run: dotnet restore
      - name: Build
        run: dotnet build --no-restore -c Release
      - name: Test
        run: dotnet test --no-build -c Release --verbosity normal
      - name: Format check
        run: dotnet format --verify-no-changes
```

> `.NET` 官方镜像 `mcr.microsoft.com/dotnet/sdk:10.0` 常用于自建流水线；GitHub Actions 内置 `setup-dotnet` 更省事。

## 10.8 Docker 打包（多阶段）

```dockerfile
# Dockerfile（放工程根目录，即含 .csproj 的目录）
# 阶段 1：编译
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish TodoApi/TodoApi.csproj -c Release -o /app/publish

# 阶段 2：运行（精简运行时镜像，不含 SDK）
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS final
WORKDIR /app
COPY --from=build /app/publish .
ENV ASPNETCORE_HTTP_PORTS=8080
EXPOSE 8080
ENTRYPOINT ["dotnet", "TodoApi.dll"]
```

```bash
docker build -t todo-api .
docker run --rm -p 8080:8080 -v "$(pwd)/data:/app/data" todo-api
#           把 SQLite 数据目录挂出来，容器重建不丢数据
```

> SQLite 在容器里注意数据卷；生产通常换 PostgreSQL 之类的独立库。

## 10.9 NuGet 打包（造可复用库）

如果你写的是类库而非应用，`dotnet pack` 生成 `.nupkg` 即可发布到 NuGet 或私有源：

```bash
cd src/MyLib
dotnet pack -c Release -o ../../artifacts     # 生成 .nupkg
```

把 `dotnet nuget push` 接进 CI，实现“推 tag 自动发版”。
