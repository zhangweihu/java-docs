# 第五章 错误处理与调试

> 本章目标：系统掌握 C# 的异常机制（`try/catch/finally/throw`、自定义异常、常用异常类型）、防御式编程，并学会用调试器（断点/单步/监视/调用堆栈）与日志定位问题。
> 前置：第一至四章。程序跑起来很容易，**“出了问题不崩、崩了能查”才是工程师的能力分水岭。**

## 5.1 错误 vs 异常

程序出错分两大类：

1. **可预期分支**（用户输入非法、余额不足）→ 用**代码逻辑**处理（`if` 判断、返回结果），或抛**业务异常**让上层统一处理；
2. **不可预期故障**（磁盘满、网络断、bug 空引用）→ 用**异常**机制兜住，至少不“裸崩”，并记录日志。

C#（与 Java、Python 类似）用 `异常（Exception）` 表示运行时错误：程序“抛出（throw）异常”，调用方可以“捕获（catch）并处理”。

```text
代码抛异常
   │ throw new ...
   ▼
运行时沿调用栈向上找 catch
   │
找到能处理的 catch → 进入 catch 块
   │
finally 块（无论是否捕获都执行）
```

## 5.2 最基础的 try / catch / finally

```csharp
try
{
    Console.Write("输入一个数字：");
    int n = int.Parse(Console.ReadLine()!);   // 故意用 Parse：可能抛异常
    Console.WriteLine(100 / n);               // n=0 时抛 DivideByZeroException
}
catch (FormatException ex)
{
    Console.WriteLine($"格式错误：{ex.Message}");
}
catch (DivideByZeroException)
{
    Console.WriteLine("不能除以 0");
}
catch (Exception ex)                          // 兜底：其它所有异常
{
    Console.WriteLine($"出错了：{ex.GetType().Name} - {ex.Message}");
}
finally
{
    Console.WriteLine("无论成败都会执行到这里（常用于清理资源）");
}
```

- **多个 catch 按从上到下匹配**，更具体的（子类）放前面；
- `ex.Message` 是错误说明；`ex.StackTrace` 是调用栈（定位到哪一行出事）；
- `finally` 常用于释放文件/网络等资源（现代代码更多用 `using`，见 5.7）。

## 5.3 抛出异常 throw

发现不该发生的状态时，主动抛异常，把问题“喊出来”：

```csharp
int Divide(int a, int b)
{
    if (b == 0)
        throw new ArgumentException("除数不能为 0", nameof(b));
    return a / b;
}
```

- `ArgumentException` 家族：参数不合法（含 `ArgumentNullException`、`ArgumentOutOfRangeException`）；
- `InvalidOperationException`：对象当前状态不允许该操作（如“余额不足”）；
- `NotImplementedException`：还没实现（占位）；
- `TimeoutException`、`IOException`、`SqlException`（数据库）等按场景选。

> **经验法则**：拿不准用什么异常，优先业务场景对应的系统异常；要表达“你自己的业务规则”再自定义异常（5.5）。

## 5.4 常见异常类型速查

| 异常 | 何时出现 | 处理示例 |
| --- | --- | --- |
| `NullReferenceException` | 对 null 调成员 | 判空 / `?.` / `??`（第 3 章） |
| `IndexOutOfRangeException` | 数组越界 | 检查 Length |
| `FormatException` | `int.Parse("abc")` | 改用 `TryParse` |
| `DivideByZeroException` | 整数除以 0 | 先判 0 |
| `KeyNotFoundException` | Dictionary 取不存在的键 | `TryGetValue` |
| `InvalidOperationException` | 状态非法操作（如空集合 Average） | 先判空/业务校验 |
| `IOException` | 文件读写失败 | 见第 7 章 |
| `StackOverflowException` / `OutOfMemoryException` | 递归太深/内存耗尽 | 别去 catch，改代码 |

## 5.5 自定义异常

业务规则复杂时，自定义异常让错误语义更清晰：

```csharp
// 1) 定义异常类型（继承 Exception）
public class InsufficientBalanceException : Exception
{
    public decimal Need { get; }
    public decimal Have { get; }

    public InsufficientBalanceException(decimal need, decimal have)
        : base($"余额不足：需要 {need:C}，现有 {have:C}")
    {
        Need = need;
        Have = have;
    }
}
```

```csharp
public class Wallet
{
    public decimal Balance { get; private set; }
    public Wallet(decimal init) => Balance = init;

    public void Pay(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("金额必须为正数");
        if (amount > Balance)
            throw new InsufficientBalanceException(amount, Balance);   // 抛自定义异常
        Balance -= amount;
    }
}
```

```csharp
var w = new Wallet(100m);
try
{
    w.Pay(200m);
}
catch (InsufficientBalanceException ex)
{
    Console.WriteLine($"支付失败：{ex.Message}（差额 {ex.Need - ex.Have:C}）");
}
```

## 5.6 防御式编程：不让错误发生

最好的错误处理是**在源头就避免错误**。核心三板斧：

1. **能预判就用判断/安全 API**：

```csharp
// 不：int.Parse(可能非数字) + catch
// 好：先 TryParse
if (!int.TryParse(input, out int n)) { /* 提示重输 */ }

// 不：直接 scores[i]
// 好：先检查
if (i >= 0 && i < scores.Count) { /* 再取 */ }
```

2. **对不可信输入一律先校验**（Web API 的模型验证在第九章讲）：

```csharp
if (string.IsNullOrWhiteSpace(name)) throw new ArgumentException("名称不能为空");
if (age < 0 || age > 150) throw new ArgumentOutOfRangeException(nameof(age));
```

3. **方法开头集中校验（fail fast）**，避免错误值在系统里流转很久才爆。

**异常应不应该被 catch 后“吞掉”？**

```csharp
// 坏：吞异常（排查噩梦）
try { Do(); }
catch (Exception) { }

// 尚可：记录 + 提示
try { Do(); }
catch (Exception ex)
{
    Log.Error(ex, "Do 失败");
    // 让调用方知道失败了：返回 false / 重新抛 / 用 Result
}
```

## 5.7 using 与资源释放

文件、网络连接、数据库连接等“非托管资源”用完必须释放。C# 提供了 `using` 语句（自动调用 `Dispose`）：

```csharp
// 写法一：语句形式
using (var reader = new StreamReader("file.txt"))
{
    Console.WriteLine(reader.ReadToEnd());
}   // 出大括号自动释放（即使中途抛异常也会释放）

// 写法二：声明形式（C#8+，推荐）
using var writer = new StreamWriter("out.txt");
writer.WriteLine("hello");
// 作用域结束时自动释放
```

自己写一个可释放类型：实现 `IDisposable`（第 11 章深入讲）。

## 5.8 调试器：找到 bug 的显微镜

VS Code 或 Visual Studio 都支持调试。核心操作（务必动手练）：

| 操作 | 作用 |
| --- | --- |
| 设置断点 | 点行号左侧红点，程序跑到该行**暂停** |
| F10 单步跳过 | 逐行执行，不进入方法内部 |
| F11 单步进入 | 进入方法内部逐行执行 |
| Shift+F11 跳出 | 跑完当前方法，回到调用处 |
| F5 继续 / 停止 | 继续跑到下一断点 / 结束调试 |
| 监视（Watch） | 盯住某变量/表达式的变化 |
| 调用堆栈 | 看当前执行到的方法调用链 |
| 鼠标悬停变量 | 快速看值 |

练习场景：把 5.2 的除零代码打断点，观察异常抛到哪一行、`StackTrace` 内容，理解“栈”。

**命令行也能调试？** 生产环境无法交互调试时用日志与诊断（5.9）。

## 5.9 日志：程序运行的黑匣子

小工具用 `Console.WriteLine` 打点即可，但专业应用要用日志库。.NET 内置了 `Microsoft.Extensions.Logging`（Web/宿主程序默认配置好）。入门先用结构化日志概念：

```csharp
// 控制台项目里可用 Serilog（第三方，最流行之一）快速体验：
// dotnet add package Serilog.Sinks.Console
// dotnet add package Serilog
// 顶部：
// using Serilog;
// Log.Logger = new LoggerConfiguration().WriteTo.Console().CreateLogger();

void Transfer(decimal from, decimal to, decimal amount)
{
    Log.Information("开始转账 {From}->{To} 金额 {Amount}", from, to, amount);
    try
    {
        // ... 业务
        Log.Information("转账成功");
    }
    catch (Exception ex)
    {
        Log.Error(ex, "转账失败 From={From} To={To}", from, to);
        throw;
    }
}
```

- 日志级别：`Trace < Debug < Information < Warning < Error < Critical`；
- 给每条日志带**上下文**（谁、哪个订单、哪个操作），不然排障像大海捞针；
- 正式项目把日志输出到文件/控制台/日志平台，**不要只在 catch 里 Console.WriteLine**。

## 5.10 完整可运行示例：健壮版待办记事本

把文件读写先用简单形式串起来（正式文件 API 在第 7 章细讲），练习异常处理：

```csharp
var todos = new List<string> { "买菜", "写 C# 作业", "锻炼" };

while (true)
{
    Console.WriteLine("\n===== 待办清单 =====");
    for (int i = 0; i < todos.Count; i++) Console.WriteLine($"{i + 1}. {todos[i]}");
    Console.WriteLine("命令：add <内容> | done <序号> | del <序号> | exit");

    string? line = Console.ReadLine();
    if (string.IsNullOrWhiteSpace(line)) continue;
    if (line == "exit") break;

    try
    {
        if (line.StartsWith("add "))
        {
            todos.Add(line[4..]);                       // 截取 add 后面的内容
        }
        else if (line.StartsWith("done ") || line.StartsWith("del "))
        {
            int idx = int.Parse(line.Split(' ')[1]) - 1;   // 转 0 基
            if (idx < 0 || idx >= todos.Count)
                throw new ArgumentOutOfRangeException(nameof(idx), "序号超出范围");
            if (line.StartsWith("done")) todos[idx] = "✅ " + todos[idx];
            else todos.RemoveAt(idx);
        }
        else
        {
            Console.WriteLine("无法识别的命令");
        }
    }
    catch (FormatException)
    {
        Console.WriteLine("序号必须是数字");
    }
    catch (ArgumentOutOfRangeException ex)
    {
        Console.WriteLine(ex.Message);
    }
    catch (Exception ex)
    {
        Console.WriteLine($"发生未预期错误：{ex.GetType().Name} {ex.Message}");
        // 真实程序这里要记日志而不是只打印
    }
}
Console.WriteLine("再见");
```

## 5.11 实战与验收

**必做**

1. 写 `int SafeDivide(int a, int b)`：b 为 0 时抛带信息的异常，调用方 catch 并提示；
2. 设计自定义异常 `ScoreOutOfRangeException`，在给 `Student.Score` 赋值越界时抛出并捕获；
3. 在 5.10 记事本上完成：序号非法（负数/超界/非数字）时都不崩溃且给友好提示；
4. 练习调试：给程序打断点，用 F10/F11 单步跟踪一个 for 循环，观察变量变化。

**进阶题（任选）**

- 把“读取文件失败”场景写出完整 `try/catch/finally`，并体验用 `using` 简化；
- 画一张“异常冒泡”图：A→B→C 三层方法，C 抛异常，A 捕获，说明 B 中间层如何处理（不做处理会怎样）；
- 用 Serilog 记录一次转账全过程的日志（Information/Error）。

**验收清单**

- [ ] 能说清 try/catch/finally 各自执行时机
- [ ] 知道常见异常的触发场景（空引用/越界/格式/除零）
- [ ] 能自定义异常并携带结构化数据（如差额）
- [ ] 不写“吞异常”的代码
- [ ] 会用断点 + 单步 + 监视排查一个实际 bug
- [ ] 明白日志级别与“记录上下文”的价值

## 5.12 小结

异常机制是程序最后的“安全网”，但更高级的工程实践是**防御式编程**（源头校验）+ **不吞异常** + **结构化日志**。遇到问题先冷静读异常类型与调用栈，再动手改——这是每个专业开发者的日常。
