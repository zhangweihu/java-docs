# 第四章 完整小游戏实战与发布

> 前置：第一~三章全部内容。本章把所学拼成一个**可玩的完整小游戏**：“接宝石”（Catch the Gem）——玩家左右移动挡板，接住天上掉下来的宝石，漏接会扣生命。它将使用：代码驱动场景、Update 逻辑、输入、难度曲线、UI 计分、生命周期管理、最终 Build 发布。
> 配套可运行工程：`demo-project/Assets/Scripts/Demos/CatchGame.cs`（按数字键 4 运行）。

## 4.1 需求分析与玩法拆解（先想后做）

游戏虽小，也用真实项目的工作方式：先定“玩法循环”，再拆对象，最后写代码。

**玩法**：
1. 天上持续掉落宝石（随机位置、随机颜色）；
2. 玩家用 ←/→ 或 A/D 移动底部挡板；
3. 接住宝石 +10 分；漏接扣 1 条命；
4. 生命为 0 → 游戏结束，按 R 重新开始；
5. 难度随时间上升：掉落更快。

**对象清单**（先列“需要什么”，再看“用什么组件”）：
| 对象 | 用什么表示 | 关键组件 |
| --- | --- | --- |
| 玩家挡板 | 一个 Cube（拉扁） | Transform 移动，无物理（纯逻辑移动更稳） |
| 宝石 | 大量 Sphere | Transform 每帧下移；本示例不挂物理，简化“下落”判定 |
| 世界 | 无地面（2D 式顶视/侧视） | 边界用世界坐标常量 |
| UI | IMGUI | 分数/生命/结束提示 |

**为什么不给宝石用 Rigidbody？** 这是刻意的“简化选择”：本游戏逻辑里宝石的“落到底部”是一条直线，用物理反而要处理落地反弹、碰撞体尺寸等噪声。**游戏开发中，能用简单逻辑解决就绝不引物理**——这是重要的工程判断。

## 4.2 游戏状态机（先定义状态再写代码）

小游戏虽小，但“状态”一定要清晰，否则逻辑会互相打架：

```text
Playing（游戏中）── 接住 → 加分，继续
Playing ── 漏接且生命>0 ──► Playing（生命-1）
Playing ── 生命==0 ──► GameOver（显示结束画面，等 R）
GameOver ── 按 R ──► Playing（重置分数/生命/速度）
```

在 C# 里我们用布尔/枚举表达：

```csharp
public enum GameState { Playing, GameOver }
GameState _state = GameState.Playing;
```

## 4.3 完整代码：接宝石 CatchGame

> 这是 `demo-project/Assets/Scripts/Demos/CatchGame.cs` 的浓缩精讲版。**先通读，再对照 demo 里实际文件看差异**（demo 文件还包含每帧生成计时、子对象遍历销毁等完整细节）。

### 4.3.1 字段与常量

```csharp
using UnityEngine;

public class CatchGame : MonoBehaviour
{
    // ---- 可调参数（Inspector 里想调就 public）----
    public float moveSpeed = 9f;          // 挡板速度
    public float fallBaseSpeed = 4f;      // 宝石基础下落速度
    public float minSpawnInterval = 0.4f; // 最快掉落间隔
    public int maxLives = 3;

    // ---- 内部状态 ----
    GameObject _paddle;                   // 挡板对象引用
    float _score;
    int _lives;
    float _spawnTimer;                    // 累计时间
    float _spawnInterval = 1.2f;          // 当前掉落间隔（随难度变小）
    bool _gameOver;

    // 世界边界（X 轴左右、Y 轴上下）
    const float MinX = -8f, MaxX = 8f;
    const float TopY = 9f, BottomY = -4f;
}
```

**读懂它**：
- `public` 字段 = Inspector 可调参（第二章）；
- 边界写成 `const` 常量，全脚本统一，改一处全部生效。

### 4.3.2 Start：搭建挡板（代码造对象）

```csharp
void Start()
{
    // 保证相机/灯光存在（AutoBoot 也会做，这里防御式再查一次）
    if (Camera.main == null) CreateCamera();

    // 生成挡板：一个拉扁的 Cube
    _paddle = GameObject.CreatePrimitive(PrimitiveType.Cube);
    _paddle.name = "Paddle";
    _paddle.transform.position = new Vector3(0, BottomY + 1f, 0);
    _paddle.transform.localScale = new Vector3(3.4f, 0.7f, 1f);
    _paddle.GetComponent<Renderer>().material.color = Color.cyan;

    _lives = maxLives;
}

void CreateCamera()
{
    var camGO = new GameObject("Main Camera");
    camGO.tag = "MainCamera";
    var cam = camGO.AddComponent<Camera>();
    cam.orthographic = true;                    // 正交相机：2D 游戏常用
    cam.orthographicSize = 7;                   // 上下视野半高=7
    cam.transform.position = new Vector3(0, 1, -10);
    cam.clearFlags = CameraClearFlags.SolidColor;
    cam.backgroundColor = new Color(0.12f, 0.12f, 0.25f);
}
```

**读懂它**：
- `GameObject.CreatePrimitive` 自动带 Collider + Renderer（第一章组件思维）；
- `cam.orthographic = true` 把 3D 相机变成 2D 游戏常用的“正交”视角——没有透视近大远小，适合挡板游戏；
- 相机是**侧视**：X 是左右、Y 是上下（宝石从顶部落下）。

### 4.3.3 Update：主循环（输入 + 生成 + 掉落判定）

```csharp
void Update()
{
    if (_gameOver)
    {
        if (Input.GetKeyDown(KeyCode.R)) Restart();
        return; // 游戏结束就不继续下面的逻辑
    }

    // 1) 移动挡板：读横向输入轴
    float h = Input.GetAxisRaw("Horizontal");
    Vector3 p = _paddle.transform.position;
    p.x += h * moveSpeed * Time.deltaTime;
    p.x = Mathf.Clamp(p.x, MinX, MaxX);       // 限制在左右边界内
    _paddle.transform.position = p;

    // 2) 计时生成宝石（难度随时间提高：间隔越来越短）
    _spawnTimer += Time.deltaTime;
    if (_spawnTimer >= _spawnInterval)
    {
        _spawnTimer = 0f;
        SpawnGem();
        _spawnInterval = Mathf.Max(minSpawnInterval, _spawnInterval - 0.02f);
    }
}
```

**读懂它**：
- 游戏结束分支放最前面并 `return`，避免状态错乱（4.2 状态机落地）；
- 移动挡板用 `GetAxisRaw + Time.deltaTime`（第二章句式）再用 `Mathf.Clamp` 夹边界；
- 生成计时用“计时器累加”模式：`_spawnTimer += dt`，攒够就触发——比每帧 `Random` 碰运气稳定、可调。

### 4.3.4 SpawnGem：造宝石

```csharp
void SpawnGem()
{
    var gem = GameObject.CreatePrimitive(PrimitiveType.Sphere);
    gem.name = "Gem";                          // 用名字在子对象里识别
    gem.transform.SetParent(transform);        // 成为本脚本对象的子级，方便统一管理
    gem.transform.localScale = Vector3.one * Random.Range(0.6f, 1.2f);
    gem.transform.position = new Vector3(Random.Range(MinX + 1f, MaxX - 1f), TopY, 0);
    gem.GetComponent<Renderer>().material.color = Random.ColorHSV();
}
```

**读懂它**：
- 把宝石设为当前对象子级：后续遍历子对象就能统一处理所有宝石（见下）；
- 随机颜色 `Random.ColorHSV()` 与随机大小让画面不单调；
- X 用 `Random.Range(MinX+1, MaxX-1)` 避开贴边。

### 4.3.5 掉落与接住判定（核心循环之二）

```csharp
void LateUpdate()
{
    if (_gameOver) return;

    // 从后往前遍历子对象，边销毁边遍历更安全
    for (int i = transform.childCount - 1; i >= 0; i--)
    {
        Transform gem = transform.GetChild(i);
        if (gem.name != "Gem") continue;       // 跳过非宝石子对象（如挡板不挂这里则无所谓）

        // 每帧下落
        Vector3 pos = gem.position;
        pos.y -= fallBaseSpeed * Time.deltaTime;
        gem.position = pos;

        // 接住判定：宝石中心进入挡板“顶部接收区”
        Vector3 paddlePos = _paddle.transform.position;
        bool caught = pos.y <= paddlePos.y + 0.6f &&
                      Mathf.Abs(pos.x - paddlePos.x) <= 2.0f;

        if (caught)
        {
            _score += 10;
            Destroy(gem.gameObject);           // 接住→消失（可在此播放特效）
            continue;
        }

        // 漏接：掉出底部边界
        if (pos.y < BottomY - 0.5f)
        {
            Destroy(gem.gameObject);
            _lives--;
            if (_lives <= 0)
            {
                _gameOver = true;
                Debug.LogWarning("游戏结束！按 R 重开");
            }
        }
    }
}
```

**读懂它**：
- 为什么用 `LateUpdate`？为了让“挡板 Update 先移动完、宝石再判定”，避免半帧延迟抖动——顺序控制的经典手法；
- **从后往前遍历**并直接 `Destroy`：因为 `Destroy` 是帧末才真正移除，反向遍历不会跳过元素（新手最容易踩的坑）；
- 用**名字**区分子对象（`gem.name != "Gem"`）——这也说明“给对象命名要规范”；
- 接住区用挡板中心 + 半宽近似，不引物理（见 4.1 判断）。

### 4.3.6 UI：OnGUI 计分与结束画面

```csharp
void OnGUI()
{
    GUI.color = Color.white;

    // 左上角计分栏
    string hud = $"分数:{_score}   生命:{_lives}   (←/→ 移动挡板)";
    GUI.Label(new Rect(10, 40, 400, 30), hud);

    // 游戏结束覆盖层
    if (_gameOver)
    {
        string over = $"游戏结束！  最终分数:{_score}\n按 R 重新开始";
        GUI.Box(new Rect(Screen.width / 2f - 150, Screen.height / 2f - 60, 300, 90), over);
    }
}
```

### 4.3.7 Restart：重置一切

```csharp
void Restart()
{
    // 销毁所有宝石（清空子对象）
    for (int i = transform.childCount - 1; i >= 0; i--)
        Destroy(transform.GetChild(i).gameObject);

    _score = 0;
    _lives = maxLives;
    _spawnInterval = 1.2f;
    _spawnTimer = 0f;
    _gameOver = false;
}
```

**读懂它**：重置 = “清掉动态对象 + 状态字段归零”。挡板不用重建（一直在），只重置它和宝石。

## 4.4 把整个游戏挂起来：AutoBoot / DemoManager 的配合

`demo-project` 里没有场景文件，靠两段“胶水代码”让游戏自启动：

1. `AutoBoot.cs` 用 `[RuntimeInitializeOnLoadMethod]` 在场景加载后自动创建 `DemoManager`；
2. `DemoManager.cs` `Start()` 里保证相机/灯光存在，并默认 `StartDemo(4)` 进入本游戏；`Update()` 监听数字键 1~4 切换**主线四章**演示（另有数字键 5 = 进阶第七章的 2D 演示）、Esc 清空；
3. 每次切换时 `Destroy(旧演示对象)` → `new GameObject + AddComponent<新演示>()`——这正是第一章“脚本=组件、对象=壳”的代码体现。

> 真实项目里你不需要这种“自举”，正常流程是：在编辑器搭好场景 → 把脚本挂到对象上 → Play。这里刻意用代码自举，是为了让配套工程“零资产可跑”、也让你看透对象/组件的本质。

## 4.5 打磨与扩展（留给你的跳板）

做游戏的价值在“改着玩”。以下扩展难度递增，建议都试：

1. **音效**：导入一段 `AudioClip`，接住宝石时 `AudioSource.PlayClipAtPoint`（第七章 .NET 无此知识，属 Unity 音频 API，文档一查即会）；
2. **特效**：接住瞬间 `Instantiate` 一个 0.3 秒后自毁的粒子/发光小球（用协程 `yield return new WaitForSeconds`）；
3. **特殊宝石**：10% 概率生成“金色大宝石 = 50 分”或“炸弹 = 掉血”，用 `public` 或子类表达类型；
4. **更高层抽象**：当逻辑变复杂后，把“挡板/宝石/管理器”拆成各自脚本挂在对应对象上（组件式），而不是全部塞一个类——这正是真实项目的演进方向；
5. **优化发布**：把 `Debug.Log` 用 `#if UNITY_EDITOR` 包起来，避免正式版刷日志影响性能。

## 4.6 发布：把游戏 Build 成可执行程序

### 4.6.1 基本流程
1. **保存并加入构建**：File → Build Profiles（Unity 6）/ Build Settings（旧版）→ Add Open Scenes，把主场景加进去（demo 场景为代码生成，仍需要一个空场景兜底）；
2. **选平台**：Windows / macOS / Linux / Android / iOS / WebGL，先在本机平台发布验证；
3. **Player Settings**：填公司名（Company Name）、产品名（Product Name）、图标（Icon，可选）、启动画面；
4. **点 Build**：选输出目录，Unity 会做“打包 + 编译脚本”几步，完成后在目录里双击生成的 `.exe` 即可运行。

### 4.6.2 踩坑清单（发布新手必看）
| 坑 | 原因与对策 |
| --- | --- |
| 游戏黑屏 | 场景没加进 Build；或相机没被任何场景/代码创建 |
| 字体重叠/发虚 | IMGUI 不缩放；正式 UI 用 uGUI + TextMeshPro |
| 报错 “XXXX has no platform support” | 缺对应 Build Support 模块，回 Unity Hub 补装 |
| 性能卡顿 | 每帧 `FindObjectOfType` / 日志过多；用缓存 + 少打印 |
| IL2CPP 首次构建慢 | 正常，二次增量快；发移动端默认走 IL2CPP |
| “未找到任何场景” | Build 前一定 Add Open Scenes |

### 4.6.3 移动端与 Web 的一个提醒
- **Android/iOS**：Input 系统建议用新输入系统做触屏（旧 Input 只有 `Input.touches`，较原始）；Unity 免费版可发移动端，但要装对应 Build Support；
- **WebGL**：可一键发到浏览器（尤其适合演示给朋友/面试官），体积偏大是正常现象。
