# 第三章 物理碰撞、输入与 UI

> 前置：第一章（对象/组件）+ 第二章（脚本生命周期）。本章让世界“真实”起来：物理引擎替你算重力与碰撞；输入系统听你的键盘鼠标；UI 显示分数与按钮。配套可运行工程：`demo-project/Assets/Scripts/Demos/PhysicsDemo.cs`、`InputDemo.cs`。

## 3.1 物理系统三件套：Rigidbody / Collider / Physic Material

### 3.1.1 刚体 Rigidbody

默认场景里的 Cube 是“死的”，不受重力。给它挂 **Rigidbody** 组件，它就被物理引擎接管：
- **受重力下落**（useGravity 默认开）；
- 能被碰撞弹开、推动（与其它 Collider 交互）；
- 有质量（mass）、速度、阻力等属性。

```csharp
using UnityEngine;

public class Thrower : MonoBehaviour
{
    public Rigidbody ballPrefab; // 拖一个带 Rigidbody 的球体预制体
    public float force = 10f;

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
        {
            var rb = Instantiate(ballPrefab, transform.position + transform.forward, Quaternion.identity);
            rb.AddForce(transform.forward * force, ForceMode.Impulse); // 瞬时冲量
        }
    }
}
```

> 新手高频错误：把物体的移动写在 `Update`，同时物体又挂了 Rigidbody——两者会“打架”，出现抖动/穿透。**用物理移动请写在 FixedUpdate 里，并通过 Rigidbody 接口（velocity / AddForce）驱动**；纯逻辑移动（如 demo 里挡板）用 transform + Update 即可。

```csharp
// 正确示例：用 Rigidbody 施加速度，写在 FixedUpdate
public class BallMover : MonoBehaviour
{
    Rigidbody _rb;
    public float speed = 5f;

    void Awake() => _rb = GetComponent<Rigidbody>();

    void FixedUpdate()
    {
        float h = Input.GetAxisRaw("Horizontal");
        _rb.velocity = new Vector3(h * speed, _rb.velocity.y, 0);
    }
}
```

### 3.1.2 碰撞体 Collider

**Collider** 定义物体的“物理外形”，形状越贴近真实越耗性能。常见：BoxCollider（盒子）、SphereCollider（球）、CapsuleCollider（胶囊，人形角色常用）、MeshCollider（网格，最精确也最贵）。

Collider 与 Collider 交互由物理引擎判定：
- 若至少一方有 Rigidbody，就会发生真实的碰撞反应（反弹、推动、倒下）；
- **触发器（Is Trigger = true）**：不产生物理阻挡，只发事件——用来做“捡金币”“走进区域”这类判定。

### 3.1.3 物理材质 Physic Material

给 Collider 指定“物理材质”（Physics Material，注意是 Phy**sic** Material 而非“Physics”），控制**摩擦（friction）与弹性（bounciness）**。做弹球时把 bounciness 调到 1，物体就会像皮球一样弹起。

## 3.2 碰撞与触发事件：你的代码如何“知道撞上了”

三个高频事件函数（挂在**带 Collider 且最好带 Rigidbody** 的对象脚本里）：

| 事件 | 触发条件 | 说明 |
| --- | --- | --- |
| `OnCollisionEnter(Collision other)` | 第一次碰撞接触 | 撞到东西，可拿到 `other.gameObject`、接触点 |
| `OnCollisionStay(Collision other)` | 持续接触每帧 | 压力、站在地面 |
| `OnCollisionExit(Collision other)` | 分开时 | 离开地面 |
| `OnTriggerEnter(Collider other)` | 进入触发器范围 | 金币检测、警戒区 |
| `OnTriggerStay / OnTriggerExit` | 持续 / 离开 | — |

```csharp
public class Coin : MonoBehaviour
{
    void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Player")) // 约定好给玩家对象打 Tag
        {
            Debug.Log("捡到金币！");
            Destroy(gameObject);       // 销毁自己（或播放特效后销毁）
        }
    }
}

public class Bouncer : MonoBehaviour
{
    void OnCollisionEnter(Collision hit)
    {
        if (hit.gameObject.CompareTag("Ground"))
        {
            Debug.Log("落地了，弹一下");
        }
    }
}
```

**要点**：
- 判定“是谁撞了我”，优先用 **Tag**（Inspector 顶部 Tag 下拉里可以自定义）或 `CompareTag`，少用字符串比较名字；
- `Trigger` 事件的回调签名是 `OnTriggerEnter(Collider)`（给的是对方 Collider）；`Collision` 事件签名是 `OnCollisionEnter(Collision)`，两者别写混，否则不触发（这是超高频 bug）；
- 检测碰撞时先判空：`if (other == null) return;`，防止对象已被销毁。

> 配套工程 `PhysicsDemo.cs` 就演示了“点鼠标生成带刚体的小球，让它们自己下落碰撞”。按数字键 3 运行它，然后**对着地面点鼠标**，看看物理引擎多省心。

## 3.3 输入系统：旧输入（Input）与新输入（Input System）

### 3.3.1 旧输入系统 Input（本专题采用，最简单）

Unity 内置了“古老但简单”的输入 API，默认新工程在 Project Settings → Player → Active Input Handling 里默认启用 Old Input（Unity 6 新建工程默认可能是 “Input Manager (Old)”）。

```csharp
// 轴输入：自动把键盘/手柄映射成 -1~1
float h = Input.GetAxis("Horizontal");   // A/D、←/→，平滑
float v = Input.GetAxisRaw("Vertical");  // Raw 版，无平滑（适合方格移动）

// 按键
if (Input.GetKeyDown(KeyCode.Space)) { }  // 按下瞬间（只触发一帧）
if (Input.GetKey(KeyCode.LeftShift)) { }  // 按住期间每帧 true
if (Input.GetMouseButtonDown(0)) { }      // 鼠标左键（0 左 1 右 2 中）
```

配套工程里的 `InputDemo.cs` 用 `Input.GetAxisRaw("Horizontal")` + `Time.deltaTime` 移动方块，`PhysicsDemo.cs` 用 `GetMouseButtonDown(0)` 生成小球。

### 3.3.2 新输入系统 Input System（了解，选学）

Unity 近年主推新包 `com.unity.inputsystem`：
- 用 **Input Actions Asset** 定义“动作”而非直接读按键（逻辑与键位解耦）；
- 一套动作同时支持键盘/手柄/触摸屏；
- 需要在 Package Manager 安装包并在 Player 设置里把 Active Input Handling 改成 Input System (New) 或 Both。

新工程若默认启用了新输入系统，`Input.GetKey` 会失效。**本专题为避免包管理与设置差异，统一用旧输入系统**；当你做真实项目建议学新输入系统（官方已向它迁移）。

## 3.4 代码驱动场景：让“没有场景”也能跑起来（附讲解）

我们的 demo 工程没有 `.unity` 场景，靠代码在运行时搭场景。你会在 `AutoBoot.cs` / `DemoManager.cs` 里看到三个技巧，这也是本专题“零资产跑通”的关键，请务必看懂：

```csharp
// 1) 场景加载完成后自动执行（静态方法 + 特性）
using UnityEngine;

public static class AutoBoot
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
    static void Boot()
    {
        // 若场景里还没有 DemoManager，就创建一个并挂上组件
        if (Object.FindFirstObjectByType<DemoManager>() == null)
        {
            new GameObject("DemoManager").AddComponent<DemoManager>();
        }
    }
}

// 2) DemoManager 保证相机/灯光存在，并把对应演示组件挂到新建对象上
//    核心代码：
//    Camera.main == null ? 新建相机并 tag="MainCamera"
//    FindFirstObjectByType<Light>() == null ? 新建方向光
//    root.AddComponent<Demos.CatchGame>();  // 用 AddComponent 动态加“行为”

// 3) 用旧输入在 Update 里读数字键切换演示、Esc 清理当前对象
```

**值得记住的三个 API**（本章/第四章都会用到）：
- `new GameObject("名字")` + `.AddComponent<T>()`：代码造对象/挂组件；
- `Object.FindFirstObjectByType<T>()`：找场景里某个组件（新版本 API，替代老的 `FindObjectOfType`）；
- `GameObject.CreatePrimitive(PrimitiveType.Cube)`：代码造内置几何体，自动带 Collider + Renderer。

> 为什么会自动带 Collider/Renderer？回到第一章“组件=能力”——Unity 的内置图元（Cube/Sphere/Plane）都预置好了这些组件。你给这个对象 AddComponent 自己的脚本，它就有了“行为”。

## 3.5 UI：显示分数与按钮

### 3.5.1 两套 UI 系统

| 系统 | 说明 | 适用 |
| --- | --- | --- |
| **uGUI**（Canvas 方案） | 场景里的画布，Text/Button/Image 组件，事件驱动，可做复杂界面 | 正式项目首选 |
| **IMGUI**（OnGUI） | 每帧立刻绘制，写法接近控制台时代的简易 GUI | 调试面板、极简原型；本专题用它保证“零依赖可跑” |

### 3.5.2 uGUI 快速上手（正式项目使用）

1. Hierarchy 右键 → **UI → Canvas**（会自动带 Canvas + EventSystem）；
2. 右键 Canvas → UI → Text（TextMeshPro 或旧版 Text）写“分数: 0”；
3. UI → Button 放“重新开始”按钮；
4. 用代码驱动：

```csharp
using UnityEngine;
using UnityEngine.UI;

public class ScoreUI : MonoBehaviour
{
    public Text scoreText;      // Inspector 把 Text 组件拖进来
    int _score;

    public void AddScore(int v)
    {
        _score += v;
        scoreText.text = "分数: " + _score;
    }

    // Button 的 onClick 事件面板里可直接把本对象拖进去，选 AddScore 方法
}
```

要点：uGUI 需要 `com.unity.ugui` 包（默认模板已含），在 `Assets` 创建时确保脚本引用 `UnityEngine.UI` 命名空间。

### 3.5.3 IMGUI（本专题演示采用）

IMGUI 不用建 Canvas，只要在 MonoBehaviour 里实现 `OnGUI()`，引擎每帧帮你画：

```csharp
public class Hud : MonoBehaviour
{
    int _score;
    string _status = "游戏中";

    void OnGUI()
    {
        // 左上角显示文字
        GUI.Label(new Rect(10, 10, 300, 30), $"分数:{_score}  状态:{_status}");

        // 画一个大按钮，点击返回 true（那一帧）
        if (GUI.Button(new Rect(Screen.width / 2 - 60, Screen.height / 2 - 20, 120, 40), "重新开始"))
        {
            _score = 0;
            _status = "游戏中";
        }
    }
}
```

配套工程的 `DemoManager.cs` 顶部那条操作提示就是 `GUI.Box` 画的，`CatchGame.cs` 的计分栏是 `GUI.Label` 画的——跑起来你在 Game 视图左上角就能看到。**IMGUI 的坐标是屏幕像素**（左上角 0,0），字体大小与分辨率相关，所以它适合调试与原型，正式 UI 用 uGUI。

## 3.6 完整示例：点击投球 + 地面碰撞（动手做）

结合 3.1~3.3 写一个完整小演示（思路与配套 `PhysicsDemo.cs` 一致）：

```csharp
using UnityEngine;

public class ClickThrower : MonoBehaviour
{
    public float force = 12f;
    public GameObject ballPrefab; // 建一个带 Rigidbody 的 Sphere 预制体拖进来

    void Update()
    {
        if (Input.GetMouseButtonDown(0)) ThrowBall();
    }

    void ThrowBall()
    {
        // 相机位置向屏幕中心方向发射
        GameObject ball = Instantiate(ballPrefab, transform.position + transform.forward * 2, Quaternion.identity);
        Rigidbody rb = ball.GetComponent<Rigidbody>();
        rb.AddForce(transform.forward * force, ForceMode.Impulse);
    }
}
```

配套工程里 `PhysicsDemo.cs` 更进一步——鼠标点击地面上的点，从点击处生成带刚体与随机速度的彩色小球，让物理自己演算它们下落、滚动、碰撞。看完它的代码你就理解：**真正要手写物理的游戏很少，大多时候你只是“摆放刚体、施加力、监听事件”**。

## 3.7 实战与验收

### 实战：迷你打靶场
在 demo 工程（按 3）或你自己的工程完成：

1. **地面 + 靶子**：代码/编辑器造一块地面（Plane），放 3~5 个带 BoxCollider 的方块当作“靶”；
2. **小球发射器**：写 `ClickThrower`，点鼠标从主相机向前生成带 Rigidbody 的小球，命中靶后……
3. **碰撞计分**：给靶挂 `OnCollisionEnter`，被击中后自己变色并向某管理器加 1 分（用静态字段 `Score.total` 最简单）；
4. **HUD**：用 `OnGUI` 在左上角显示“命中 X 次”；按 R 键重置全场（销毁所有小球，恢复靶色）。

## 3.8 本章小结与语言对照

| 概念 | 一句话 | 类比（后端/桌面） |
| --- | --- | --- |
| Rigidbody | 让物体被物理接管 | 相当于“交给物理线程的对象” |
| Collider | 定义物理外形 | 判断“边界” |
| Trigger | 不阻挡只发事件 | 事件总线/哨兵 |
| Input / Input System | 输入抽象 | 读取配置/外部事件 |
| OnGUI / uGUI | 简单/正式两套 UI | 控制台打印 / Web 页面 |
| AddComponent | 运行时给对象加能力 | 动态装配/依赖注入 |
