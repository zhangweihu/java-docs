# 第七章 2D 精灵与 2D 游戏开发

> 前置：第一~四章（尤其第三章物理/输入）。前六章几乎都在 3D 方块世界里打转，但 2D 游戏（像素风、横版、休闲小游戏）是 Unity 的另一大主场。本章讲 2D 的核心概念：**正交相机、精灵 Sprite、SpriteRenderer、排序与 2D 物理**，并用一个完全由代码生成的 2D 演示（`demo-project` 演示 5）说明“图片从哪来、怎么显示、怎么碰撞”。
>
> 配套可运行工程：`demo-project/Assets/Scripts/Demos/Sprite2DDemo.cs`（按数字键 5 运行）——**零美术资源**：精灵由代码现场绘制，是本专题“程序化资源”思路的 2D 版。

## 7.1 2D 与 3D 的根本区别：相机与观察方式

3D 用**透视相机**（近大远小）；2D 游戏用**正交相机（Orthographic）**——没有透视，物体大小与距离无关，就像从侧面看一张 XY 平面的纸。

- 在 2D 世界里，所有物体摆在一个 **XY 平面**（Z 只用于分层）；
- 正交相机的 `Size` 表示**视口半高**（世界单位），决定你能看到多少；
- 相机通常放在 `(0, 0, -10)` 看向原点（Z 轴正方向），这样世界 XY 正对屏幕。

创建 2D 工程时，Hub 选 **2D (Built-in/URP) 模板**即可，它会预设正交相机与适合 2D 的导入设置。**但 Unity 的 2D/3D 并不是两个引擎**——同一工程里 2D 与 3D 可混用（把相机切回透视即可）。

```csharp
// 代码里把相机切成 2D 正交视角（配合第二章 2.3 的组件思维）
Camera cam = Camera.main;
cam.orthographic = true;          // 正交：无透视
cam.orthographicSize = 7f;        // 视口半高 = 7 个单位
cam.transform.position = new Vector3(0f, 0f, -10f);  // 相机退后 10 看原点
```

## 7.2 精灵（Sprite）是什么

2D 里的“物体图像”叫**精灵（Sprite）**。与 3D 的 Mesh 不同，Sprite 就是一张**带透明通道的图片**，用 **SpriteRenderer** 组件显示。

| 组件/概念 | 作用 |
| --- | --- |
| Sprite 资源 | 一张 2D 图片（PNG 等），导入时 Texture Type 设为 `Sprite (2D and UI)` |
| `SpriteRenderer` | 挂在 GameObject 上，负责把某张 Sprite 画出来（2D 版“MeshRenderer”） |
| Sprite 的 PPU | Pixels Per Unit：多少像素 = 1 世界单位。64 PPU = 64px 的图占 1 个单位 |

> 场景里 2D 物体 = 空 GameObject + SpriteRenderer(+Sprite)。要想参与物理就再挂 2D 的刚体与碰撞体——这仍是你熟悉的“组件堆叠”思维，只是换了 2D 组件。

### 7.2.1 导入一张图并让它变成“游戏精灵”

1. 把 PNG 拖进 Project（如 `Assets/Art/player.png`）；
2. 选中它，Inspector 设置：
   - **Texture Type = Sprite (2D and UI)**；
   - **Sprite Mode**：Single（单图）或 **Multiple**（一张图里切多帧，如动画序列帧）；
   - **Pixels Per Unit**：设你期望的世界大小；
3. 点 **Apply**。之后可直接把资源拖进场景，或用代码 `spriteRenderer.sprite = 资源引用`。

### 7.2.2 序列帧动画（Sprite Animation）

Multiple 模式下用 **Sprite Editor** 把整张雪碧图切成若干小图（“切片”）。然后：
1. 全选这些切片，拖进 Hierarchy，Unity 自动生成一个带 **Animator** 的动画物体；
2. 或用代码按顺序换 `spriteRenderer.sprite` 手动逐帧播放（简单动画自己写循环即可）。

> 与第六章 Animator 的关系：2D 序列帧同样走 Animator 状态机。人形骨骼动画是 3D 的路数，2D 角色动画主流就是“一格格换图”。

## 7.3 谁画在上面：Sorting Order 与 Sorting Layer

2D 场景没有 Z 深度遮挡（正交投影不看远近），**谁遮挡谁**由“渲染顺序”决定：

| 概念 | 说明 |
| --- | --- |
| `SpriteRenderer.sortingOrder` | 同一层内，数字大的画在上面（默认 0） |
| **Sorting Layer** | 更大的“层”永远画在上层，与 order 无关 |

**代码控制顺序**（例如血条永远在角色上方）：

```csharp
sr.sortingOrder = 10;                       // 数字大 → 盖在上面
sr.sortingLayerName = "UI";                 // 或切换到更高层（Project Settings → Tags and Layers 里自定义）
```

> 2D 新手最常见的困惑“为什么新生成的角色跑到地面下面去了”——检查它的 `sortingOrder`，而不是 Z 坐标。

## 7.4 2D 物理：Rigidbody2D / Collider2D

第三章的 3D 物理有**一套平行 2D 版**，名字都带 2D 后缀，规则基本同构：

| 3D（第三章） | 2D（本章） | 差异注意点 |
| --- | --- | --- |
| Rigidbody | **Rigidbody2D** | 多一个 `Gravity Scale`（重力倍数，直接乘数，不用设重力矢量）；移动只有 XY |
| Collider | **Collider2D**（Box/Circle/Capsule/Polygon） | 形状受限在 2D 平面 |
| Physic Material | **Physics Material 2D** | 在 Assets 里 Create → Physics Material 2D，设 `Friction`/`Bounciness` |
| `OnCollisionEnter` | `OnCollisionEnter2D` | 事件函数带 2D 后缀 |
| `OnTriggerEnter` | `OnTriggerEnter2D` | 同上 |

`Rigidbody2D` 的 **Body Type** 与 3D 一致：Dynamic（受物理）/ Kinematic / Static。典型用法：

```csharp
// 地面：静态刚体 + 盒碰撞体（静态 = 不参与受力，只提供碰撞）
var ground = new GameObject("Ground");
var rb = ground.AddComponent<Rigidbody2D>();
rb.bodyType = RigidbodyType2D.Static;
ground.AddComponent<BoxCollider2D>();

// 角色：动态刚体，默认受重力下落，靠代码给速度
var player = new GameObject("Player");
player.AddComponent<Rigidbody2D>();          // 默认 Dynamic，GravityScale=1
player.AddComponent<CircleCollider2D>();
// 起跳：rb2d.velocity = new Vector2(rb2d.velocity.x, jumpForce);
```

> 注意事件函数名——**3D 与 2D 物理的事件签名不同**，写 `OnCollisionEnter2D` 而不是 `OnCollisionEnter`，否则 2D 碰撞时你的代码不会收到通知（静默失败，最坑）。

## 7.5 零美术自举：用代码生成精灵（本演示的核心）

正式项目里精灵来自美术画的图。但在 `demo-project` 里我们要**不依赖任何图片文件**——于是用代码“画”一张纹理再转成 Sprite。这是理解“Sprite 只是一张带透明像素的纹理”的绝佳示例：

```csharp
// —— 核心：像素数组 → Texture2D → Sprite ——
static Sprite MakeSolidSprite(int sizePx, bool circle)
{
    var tex = new Texture2D(sizePx, sizePx, TextureFormat.RGBA32, false);
    var pixels = new Color[sizePx * sizePx];

    float center = (sizePx - 1) * 0.5f;
    for (int y = 0; y < sizePx; y++)
    for (int x = 0; x < sizePx; x++)
    {
        bool inside = !circle || Vector2.Distance(
            new Vector2(x, y), new Vector2(center, center)) <= center;
        pixels[y * sizePx + x] = inside ? Color.white : Color.clear;  // 白 + 透明
    }
    tex.SetPixels(pixels);
    tex.Apply();          // 提交像素到 GPU 纹理

    // 关键：Sprite.Create。PPU = sizePx ⇒ 整张图 = 1×1 世界单位
    return Sprite.Create(tex, new Rect(0, 0, sizePx, sizePx),
        new Vector2(0.5f, 0.5f), sizePx);
}
```

拿到 Sprite 后给它一个 `SpriteRenderer`：

```csharp
var go = new GameObject("Gem");
var sr = go.AddComponent<SpriteRenderer>();
sr.sprite = _circle;                 // 上面生成的白色圆精灵
sr.color = Color.yellow;             // 白贴图 × 颜色 = 想要的颜色（一次生成多次复用）
```

> 技巧：**贴图只画“白 + 透明”**，要什么颜色由 `SpriteRenderer.color` 乘出来——一张纹理就能当所有纯色物品用。这也是“材质 = 贴图 × 颜色”思想的体现。

### 7.5.1 屏幕坐标 → 世界坐标（鼠标点击生成物体）

2D 下点击屏幕生成物体需要把**屏幕像素坐标**换算到世界 XY：

```csharp
Vector3 mouse = Input.mousePosition;              // 屏幕像素坐标（左下原点）
mouse.z = Mathf.Abs(cam.transform.position.z);     // 到 z=0 平面的距离（相机在 -10 → 10）
Vector3 world = cam.ScreenToWorldPoint(mouse);     // 现在 world 是落在 XY 平面上的点
world.z = 0f;
```

正交相机下 ScreenToWorldPoint 的 z 参数必须给“目标平面到相机的距离”，否则算出来不对。

## 7.6 完整示例：2D 彩球堆积沙盘（对应演示 5）

把 7.1~7.5 全部串起来：正交相机 + 代码生成的地面 + 点击生成受 2D 物理驱动的彩球。完整代码见
`demo-project/Assets/Scripts/Demos/Sprite2DDemo.cs`（按数字键 5 运行），要点结构如下：

```csharp
public class Sprite2DDemo : MonoBehaviour
{
    public float groundWidth = 30f;
    public float groundY = -6f;
    public int maxGems = 30;

    private Sprite _square, _circle;
    private Transform _gems;              // 所有彩球的父对象（便于统一清理/计数）

    private void Start()
    {
        // 1) 正交相机
        Camera cam = Camera.main;
        cam.orthographic = true;
        cam.orthographicSize = 7f;
        cam.transform.position = new Vector3(0f, 0f, -10f);

        // 2) 生成精灵贴图（方块 + 圆）
        _square = MakeSolidSprite(4, circle: false);
        _circle = MakeSolidSprite(64, circle: true);

        // 3) 彩球容器：挂在演示根对象下，Esc 清空演示时能一并销毁
        _gems = new GameObject("Gems").transform;
        _gems.SetParent(transform);

        // 4) 静态地面（Rigidbody2D Static + BoxCollider2D）
        var ground = NewSpriteObject("Ground", _square, new Color(0.7f, 0.7f, 0.7f));
        ground.transform.SetParent(transform);
        ground.transform.localScale = new Vector3(groundWidth, 1f, 1f);
        ground.transform.position = new Vector3(0f, groundY, 0f);
        var rb = ground.AddComponent<Rigidbody2D>();
        rb.bodyType = RigidbodyType2D.Static;
        ground.AddComponent<BoxCollider2D>();
    }

    private void Update()
    {
        if (Input.GetMouseButtonDown(0)) SpawnGemAtMouse();   // 左键生成彩球
    }

    private void SpawnGemAtMouse()
    {
        // 屏幕→世界（7.5.1）
        Vector3 mouse = Input.mousePosition;
        mouse.z = Mathf.Abs(Camera.main.transform.position.z);
        Vector3 world = Camera.main.ScreenToWorldPoint(mouse);
        world.z = 0f;
        if (world.y <= groundY + 0.8f) world.y = groundY + 0.8f;

        // 动态刚体 + 圆碰撞体 + 随机颜色
        var gem = NewSpriteObject("Gem", _circle,
            Random.ColorHSV(0f, 1f, 0.7f, 1f, 0.8f, 1f));
        gem.transform.SetParent(_gems);
        gem.transform.position = world;
        gem.AddComponent<Rigidbody2D>();         // Dynamic + 重力
        gem.AddComponent<CircleCollider2D>();    // 半径 0.5，匹配 1×1 圆精灵

        // 同屏上限：删最早那颗（Gems 下第一个子对象）
        if (_gems.childCount > maxGems)
            Destroy(_gems.GetChild(0).gameObject);
    }
}
```

**运行体验**：在 Game 视图里点几下——彩球从点击处落下、互相碰撞、在地面堆成小山，整个过程没有任何手写“运动代码”。你只做了三件事：**给物体贴精灵、挂刚体、挂碰撞体**，剩下的重力与碰撞由引擎 2D 物理演算。这就是“组件式开发”的终极形态。

## 7.7 更进一步：Tilemap 做关卡地图（选学）

2D 关卡地图常用 **Tilemap（瓦片地图）**：把一张大图切成小瓦片，像铺瓷砖一样“画”出关卡。

1. 菜单 **Window → 2D → Tile Palette**；
2. 准备一张瓦片集（Texture Type = Sprite + Multiple + Sprite Editor 切片）；
3. 在 Tile Palette 里建调色板 → 选中瓦片在场景里“刷”地面/墙；
4. 给 Tilemap 对象加 `Tilemap Collider 2D` 即自动生成碰撞体，玩家就能踩上去。

Tilemap 的关键收益：**碰撞体自动批量生成、刷关卡不用拖几百个 GameObject、资源省**。几乎所有 2D 平台的关卡都用它。

## 7.8 实战与验收

### 实战：2D 版「接宝石」

把第四章「接宝石」移植到 2D（要求用本章技能，禁止照抄 3D 版）：
1. 用 `SpriteRenderer` + 代码生成的精灵表示挡板与宝石（不用 Cube/Sphere 图元）；
2. 相机改为正交，XY 平面玩法与第四章一致：宝石下落、挡板左右接、计分/生命；
3. 给挡板与宝石加 2D 碰撞体，宝石与挡板用 `OnCollisionEnter2D` 或触发器判定“接住”；
4. 宝石颜色随机、可旋转（`sr.flipX` 或旋转精灵对象）；
5. 尝试用 7.2.2 的方式给宝石做 3 帧旋转动画（或 `sortingOrder` 表现“远近”）。

### 验收清单

- [ ] 所有物体是 SpriteRenderer 而不是 MeshRenderer；
- [ ] 2D 游戏里相机是正交的，且能看到完整的 XY 世界；
- [ ] 接住/漏接用 2D 后缀的事件函数写对（`OnCollisionEnter2D`）；
- [ ] 地面是 Static、挡板按玩法决定用 Dynamic 还是纯逻辑移动；
- [ ] 物体叠加顺序符合预期（会用到 `sortingOrder`）。

## 7.9 本章小结与语言对照

| 概念 | 说明 | 与你已学知识的对照 |
| --- | --- | --- |
| 正交相机 | 无透视的 2D 观察方式 | 观察“世界”的窗口配置 |
| Sprite / SpriteRenderer | 2D 图片及其显示组件 | “贴图 + 展示层”，同 3D 的 Mesh + Renderer |
| `Texture2D` → `Sprite.Create` | 代码生成图片 | 程序化资源，图形版的“工厂方法” |
| Sorting Order / Layer | 2D 遮挡顺序 | 层级(z-index)，比 Z 坐标更贴游戏语义 |
| Rigidbody2D / Collider2D | 2D 刚体与碰撞体 | 第三章 3D 物理的“平行世界”，API 同构 |
| Tilemap | 瓦片关卡编辑器 | 声明式数据驱动关卡，替代手摆对象 |
